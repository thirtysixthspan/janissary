# Restoring a file tree's view from the command line

**Complexity: 6/10** — spans server and client with a consolidated wire type, a parser rewrite, an in-order step evaluator with its own fallback rule, a joined browser round trip for `files print`, and a context-fed completer, across about a dozen modules plus specs and docs; remote trees are left out, which keeps it free of asynchronous restore state.

## Summary

Feature request (verbatim from `product/backlog/features.md`): "Restoring a file tree's view from the command line. `files` already takes `in <tab>`, `on <side>`, `with <detail>`, and a path (`file-navigator-tab.md` § `files in <label>`/`files on <side>`). A profile records four more things about a tree: the expanded directories, the cursor row, the range anchor, and the selected rows (`profiles.md` § Restoring a tree's view). `profile launch` replays them, but nothing on the command line can, so a runscript always opens a tree with nothing expanded or selected. Closing the gap would add four clauses to `files` that mirror the profile keys: `expand <paths>`, `cursor <path>`, `anchor <path>`, and `select <paths>`, each relative to the tree's root. Restoring would follow the profile rules. A path that no longer exists is dropped silently, and a restored selection never moves keyboard focus. The grammar is the hard part. The path is the command's last word, so a directory literally named `expand` or `select` must still parse as a path. A list of paths also needs a separator, and commas and spaces are both legal in file names. Complexity: low-medium."

A profile can bring a tree back with folders open and rows selected, but a runscript, a scheduled command, or a `send` from another tab can only open a bare tree. This plan adds clauses to `files` that set the same parts of a tree's view a profile's `files` entry sets, plus a `collapse` clause, on a local tree. They follow the same rules as the restore the profile launcher already runs. It also adds `files print <tab>`, which prints an open tree as the `files` command that would bring it back, and teaches Tab completion the new words.

## Design decisions

Each decision is settled by the feature text, by behavior the app already has, or by the user's answer, as stated.

### Clauses

1. **Five new clauses on `files`.** `expand <path>`, `cursor <path>`, `anchor <path>`, and `select <path>` mirror the profile keys `expanded`, `cursor`, `anchor`, and `selected` (`profiles.md` § Restoring a tree's view). The user chose the feature text's verbs over the profile key names. The user also brought a fifth into scope, `collapse <path>` (Design decisions 21 and 22). Keywords match without regard to case, like `in`, `on`, and `with`.
2. **A list is a repeated clause.** `expand`, `select`, and `collapse` take one path each and may be repeated as often as needed: `files expand src expand docs select src/a.ts select src/b.ts`. There is no separator, so commas and spaces in file names never need anything beyond quoting. The user chose this over a comma list and over a list running to the next keyword.
3. **A later `cursor` or `anchor` replaces an earlier one.** `files cursor a.ts cursor b.ts` puts the cursor on `b.ts`, with no error. The user chose this over an error and over today's rule for a repeated `with`, where the second clause becomes part of the path. Since a dropped path leaves its part as it was (Design decision 16), `cursor a.ts cursor gone.ts` leaves the cursor on `a.ts`. A repeated `in`, `on`, or `with` keeps today's behavior.
4. **The clauses combine with the existing ones, in any order.** They sit beside `in <label>`, `on <side>`, and `with <mode>` (`file-navigator-tab.md` § `files in <label>`/`files on <side>`), and the tree's path stays the command's last word: `files in claude on left with size expand src cursor src/a.ts docs`.
5. **Clauses also follow a leading bare side word.** Today a bare `left` or `right` ends clause parsing, so `files left with size` opens a directory named `with size`. Every clause, old and new, is now recognized both before and after a leading bare `left`/`right`, so `files left expand src` and `files left with size` both read as they look. A directory named `with size` stays reachable as `./with size`. The user chose fixing `with` along with the new clauses over keeping the quirk.
6. **A keyword that ends the line is the path.** The feature text requires that a directory literally named `expand` or `select` still parse as a path. A keyword with nothing after it is the path, the way `files with` already opens a directory named `with` (`parseFileNavigatorArgs` in `src/file-navigator/args.ts`). So `files expand` opens a directory named `expand`, and `files print` one named `print`. `files ./expand` always works. A keyword is recognized only as a bare word: a quoted token is never a keyword, so `files "select notes"` opens a directory named `select notes` (Design decision 9), and the quoted path the profile launcher now writes (Design decision 43) can never be taken for a clause. The user confirmed bare-only keywords over letting a quoted word match.

### Quoting

7. **A clause path with spaces is quoted.** A clause's path is one token, read the way `readToken` in `src/agent/command-parser.ts` reads one: bare up to the next space, or wrapped in single or double quotes, with a backslash escaping the quote character inside, and a quote that may open mid-word. So `expand "my dir"` names `my dir`. Because a quote may open mid-word, an apostrophe in a bare path opens a quote: `select it's.md` is an unterminated quote (Design decision 8), and the path is written `select "it's.md"`. The printer and the completer quote such a name for this reason (Design decisions 26 and 31), and the spec states it with this example. The user accepted this over a second quoting rule where a quote opens only at a word's start. `in`, `on`, and `with` keep reading their value as the next whitespace-delimited word, with no quote handling, as today.
8. **An unterminated quote in a clause's path is an error.** `files expand "src` prints `files: unterminated quote` in the transcript, and no tree is opened, focused, redocked, or changed. The user chose this plain line over one naming the clause and over reading the rest as the path.
9. **A fully quoted trailing path is unwrapped.** The trailing path is still the rest of the line, so `files my dir` opens `my dir` as today. When that rest is exactly one quoted token, read the same way a clause's path is, its quotes are removed, so `files expand "a b" "c d"` opens `c d`. Anything else keeps today's verbatim reading, quote marks included, and is never an error. The user chose this over leaving the trailing path verbatim.

### Paths

10. **Clause paths are relative to the tree's root, and a few other spellings are accepted.** A relative path is normalized: `./src`, `src/`, and `src//a` mean `src`, `src`, and `src/a`. `..` alone names the parent row, which a profile can save as the cursor. An absolute path, or one starting with `~` or `$root`, is expanded the way the `files` path argument expands it (`expandUserPath` in `src/paths.ts`) and converted to its tree-relative form when it lands inside the tree. Anything that lands outside the tree matches no row and is dropped silently. The tree's root itself is a valid path for `collapse` (Design decision 22) and names no row for the other clauses. The user chose this over normalized relative paths only and over exact matching.

### Applying the view

11. **Restoring follows the profile rules.** The clauses follow the rules of the restore `profile launch` already runs (`restoreTreeView` in `src/file-navigator/restore.ts`, reached through `FileNavigatorManager.restoreView`), through a command restore that shares its helpers (Design decision 36). A named directory that still resolves is expanded, and a named row is highlighted if it is visible when its clause is reached, with the cursor row scrolled into view. A directory or row that no longer exists is dropped silently, and nothing about the restore is reported. If nothing survives on a fresh tree, it has no cursor.
12. **Clauses apply in the order written.** Each `expand`, `collapse`, `cursor`, `anchor`, and `select` takes effect at its place in the line, against the rows visible at that point. So `collapse src expand src` reopens `src`, and `expand src collapse src` leaves it closed. A selection clause is checked against the rows visible when it is reached: `select a.ts expand src select src/b.ts` finds `a.ts` before `src` opens and `src/b.ts` after. Every `select` that survives adds its row, so the selection is every row the line selected, less any that a later `collapse` hides. The user chose the order written over running every collapse first, and over checking the selection clauses only after every folder clause.
13. **A named row inside a collapsed folder is dropped.** Only a row visible when its clause is reached is highlighted, so `cursor src/commands/files.ts` needs `expand src expand src/commands` before it. The user chose the profile rule over revealing the row's folders, so profile restore and the command behave identically.
14. **A later collapse applies the tree's usual fallback.** When a `collapse` hides a row an earlier clause on the line placed, the rule in `file-navigator-tab.md` § Keyboard interactions applies. Hidden selected rows drop out and the visible ones remain. A hidden cursor moves to its nearest visible ancestor. A hidden anchor resets to the cursor: the cursor the line set, or, when the line names none, the tree's current cursor, exactly as if the user had collapsed that folder by hand. On a fresh tree with no cursor, a hidden anchor clears. The user chose the tree's current cursor over leaving the anchor as it was.
15. **On a tree already open, the clauses touch only what they name.** When `files` lands on a tree already open on that root, it focuses or redocks it as today, and the clauses apply to it, the way `with` already does. `expand` opens folders and `collapse` closes them, and nothing else changes. `cursor`, `anchor`, and `select` each replace only their own part: `files expand src` leaves the user's selection alone, and `files cursor a.ts` moves the cursor and keeps the selection and anchor. The user chose this over replacing the whole view and over ignoring the clauses on an open tree.
16. **A part whose paths are all dropped is left as it was.** A dropped path counts as if it wasn't given. So on an open tree with the cursor on `a.ts`, `files cursor gone.ts` leaves the cursor on `a.ts`. A part with some survivors is replaced by them: `select a.ts select gone.ts` selects just `a.ts`. The user chose this over clearing a named part whose paths are all gone.
17. **A profile relaunch keeps replacing the whole selection.** A profile `files` entry that lands on a tree already open still replaces all three selection parts, clearing any its entry doesn't name, exactly as today. Only the command touches just what it names. The user chose this over giving profiles the command's rule. The profile restore and the command restore are separate functions (Design decision 36), so each applies its own rule.
18. **A restored selection never moves keyboard focus.** The clauses change which rows are highlighted and nothing else. Which tab is active, and whether the tree gets keyboard focus, stays exactly what the same `files` command without the clauses does today: a fresh center tree opens and takes focus, and a docked tree is never the active tab.
19. **A tree whose root does not exist yet restores nothing.** That is the profile rule for the waiting-for-path case (`profiles.md` § Restoring a tree's view), and it is not retried when the directory appears.
20. **The client applies a restore once.** Each restore carries a new `revision`, and `useFileNavigatorSelection` in `web/src/file-navigator/useFileNavigatorSelection.ts` applies a hint once per revision. So a selection restored by a command is applied once, and a later state broadcast never puts it back over a selection the user has changed by hand. A second restore on a tree that is already mounted applies the same way.

### Collapse

21. **`collapse <path>` closes a folder and every folder inside it.** The folder and every open folder beneath it leave the expanded set, so reopening it shows only its own children. That is stronger than clicking its row, which keeps the inner folders open but hidden (`toggleDir` in `src/file-navigator/navigation.ts`). The user chose this over closing only the named folder. It takes the same path rules as the other clauses (Design decision 10). A folder that isn't open, or doesn't exist, is left alone, so a `collapse` before any `expand` on a fresh tree does nothing.
22. **Collapsing the root closes everything.** `collapse .`, or any spelling that names the tree's root, closes every open folder, the same as the header's collapse-all button (`collapseAllDirs` in `src/file-navigator/navigation.ts`). The user chose this over dropping it.

### Remote trees

23. **The clauses are ignored on a remote tree.** When `files` opens, focuses, or redocks a remote tree (`files in <remote tab> …`), it does so exactly as today, and its `expand`, `collapse`, `cursor`, `anchor`, and `select` clauses are dropped silently, the way a profile silently leaves remote trees out (`profiles.md` § `profile save`). The clauses are still parsed, so a malformed one, such as an unterminated quote, is still an error. A remote tree's folder listings arrive over its SSH channel after it opens, so its rows can't be checked when the command runs, and restoring one would need a restore that waits for those listings. The user first chose to support remote trees, then, after the improvement passes rated that machinery the heaviest part of the plan, chose to drop it to keep the size down.

### Printing a tree's view

24. **`files print <tab>` prints a tree as a `files` command.** It prints one line in the issuing tab's transcript: a complete `files` command that would reopen the named tree with its root, dock, detail mode, and view. It opens, focuses, and changes nothing. The cursor, anchor, and selection live in the browser, so the command asks the connected client for them the way `profile save` does (`requestTreeSelections` in `src/file-navigator/selection-request.ts`, a 250 ms wait). When no window answers in time, as under `--no-open`, the line is printed without them and with no note. The user chose this form over printing every tree, and chose no note over adding one.
25. **The print form is strict.** `print` is recognized only as the first word after `files`, and takes exactly one name, quoted if it has spaces. The tree is found by label or alias through `resolveTarget` in `src/commands/resolve-target.ts`, as `close` finds a tab. The replies are exact:
    - `No tab named "<name>".` when no tab has that name.
    - `files: "<name>" is not a file navigator` when the tab isn't one.
    - `Usage: files print <tab>.` when more than one word follows `print`.
    - `files: unterminated quote` when the name's quote never closes.
    `<name>` is the name as typed, without its quotes. The user chose this over ignoring extra words.
26. **The printed line has a fixed shape.** The user chose this shape:
    - `files`, then `in <its remote tab>` for a remote tree only, then `on <side>` when the tree is docked, then `with <mode>` when the mode isn't `name`.
    - Then `expand <path>` for every open folder, in the sorted order `profile save` writes them (`expandedPathsOf` in `src/file-navigator/manager/profile.ts`), including open folders hidden inside a closed one.
    - Then `cursor <path>`, `anchor <path>`, and `select <path>` for each selected row, each only when present.
    - The root last. A root under the project reads `$root/…`, one elsewhere under home reads `~/…`, and anything else is absolute. A remote tree's root reads `$root/<rest>` against its remote workspace root, the form `remoteCwd` in `src/file-navigator/remote-cwd.ts` expands back.
    - A path containing a space or a quote is wrapped in double quotes, with each `"` escaped as `\"`.
    For example: `files on left with size expand src expand "src/my dir" cursor src/a.ts anchor src/a.ts select src/a.ts select src/b.ts $root/web`. A waiting tree has nothing open or selected, so it prints only its dock, mode, and root. A remote tree prints only `files in <its remote tab>`, its dock, its mode, and its root, with no view clauses, since a command can't restore them there (Design decision 23). It also skips the browser round trip. The user chose this over printing the view clauses anyway and over refusing remote trees.
27. **A printed root keeps `.janissary`.** `abbreviatePath` in `src/paths.ts`, which `profile save` uses for a tree's root, drops the `.janissary` segment: `<root>/.janissary/workspace/claude` reads `$root/workspace/claude`, and `expandUserPath` doesn't put it back. A tree opened with `files in <workspaced harness>` is rooted exactly there. So the printed root keeps the segment, `$root/.janissary/workspace/claude`, a form that reads back. The user chose this over also fixing `profile save` here and over printing such roots absolute. The same flaw in `profile save` is out of scope and goes to the bug backlog.
28. **One quoting gap is a known limitation.** `readToken` has no escape for a backslash, so a path that needs quotes and also ends in `\` prints in a form that doesn't read back. The user chose to leave it and record it in the spec, rather than add a `\\` escape that would also change the agent command parser's quoting.

### Completion

29. **Tab completes the fixed words and labels.** In a `files` line, Tab completes the clause keywords (`in`, `on`, `with`, `expand`, `collapse`, `cursor`, `anchor`, `select`) wherever a clause can start, the bare `left`/`right`, and `print` as the first word. After `with` it completes the four modes, after `on` it completes `left`/`right`, after `in` it completes tab labels, and after `print` it completes the labels of open file navigators. Where either a keyword or the trailing path could go, it offers matching keywords first, then matching paths, in one list. So `files s<Tab>` offers `select` then `src/`, `scripts/`, and the rest, while `files sr<Tab>` completes `src/` exactly as today. The user chose this over keywords only, and over keywords hiding paths.
30. **A clause path completes against the tree's root where that root is known.** When an earlier `in <label>` names a local tab, a clause's path completes against that tab's cwd rather than the issuing tab's. When it names a remote tab or a tab that doesn't exist, a clause's path completes nothing, since completion reads only the local disk. Without `in`, it completes against the issuing tab's cwd as today. The trailing path isn't known while a clause is being typed, so it plays no part. The user chose root-aware paths over keywords only, and chose nothing over falling back to the issuing tab's cwd.
31. **A completed name with a space or quote is offered quoted.** A path or label that needs quoting is offered wrapped in double quotes, so accepting it parses as one token. The completer reads quotes before the cursor itself, the way the ready arranging-tabs plan's `tab` completer does, and inside a quote that's still open nothing completes. The user chose this over offering it raw.

### Wording and scope

32. **The help row gains two sentences.** The `files` row in `help.md` reads exactly the following. No user-documentation commands table has a `files` row, so the file-navigator page carries the user-facing description instead.
    `` | `files` | `files [path]` opens a navigator here; `files <path> in <label>` targets another tab. Remote paths use that host's workspace. Add `with <name\|size\|modified\|permissions>` to choose a detail column, and `expand`, `collapse`, `cursor`, `anchor`, or `select <path>` to set its view. `files print <tab>` prints a tree as a `files` command | ``
    The user chose this over a compact slash list.
33. **Clearing the selection from the command line is left out.** The user left out a command-line form that clears an open tree's cursor and selection the way Escape does.

### How it runs

34. **Parse pure, execute effectful.** The `files` argument parser returns a structured value or `{ error }` and does no I/O (architecture principle 4). It is rewritten as one loop over the quoted-token reader: read a keyword, read its value, repeat, and stop at the first word that isn't a keyword, taking the rest of the line as the path. Today's trailing-`in`, bare-side, and keyword-ends-the-line rules carry over. Reading the five view clauses moves to a new module so `src/file-navigator/args.ts` stays small. The user chose this over keeping the regex loop and adding a second pass for quoted values.
35. **The quoted-token reader moves to `src/command/quoted-token.ts`.** This is the same move the ready plan `arranging-tabs-from-the-command-line.md` specifies: `readToken`, `skipSpaces`, and their `Token` type leave `src/agent/command-parser.ts` unchanged, and that module imports them. Whichever plan is implemented first does the move; the other only imports it. The user chose this over exporting it in place.
36. **The command gets its own restore beside the profile's.** `restoreTreeView` keeps serving `profile launch` with its replace-everything rule. A new command restore applies ordered steps with the touch-only-what's-named rule, the collapse step, and the fallback. The two share their directory-check and revision helpers, exported from `src/file-navigator/restore.ts`. The user chose two functions sharing helpers over one ordered-steps function serving both.
37. **The server has its own copy of the fallback rule.** The in-order fallback after a `collapse` (Design decision 14) needs the rule the client's `reconcileSelection` applies, so the server gets a pure module of its own for it, and the client's stays where it is. Each copy has its own tests. The user chose a server-side copy over one shared module, and separate tests over one shared case table. On the server a collapse always leaves the collapsed folder or one of its ancestors visible, so the copy needs only the nearest-visible-ancestor fallback, not the client's fallback by row index.
38. **The restore hint has one definition with per-part presence.** Each part becomes optional: absent means leave that part alone, `null` means clear it, and a value means set it. `selected` becomes optional too. One flag joins it: `anchorToCursor`, meaning reset the anchor to the tree's current cursor (Design decision 14). Today the shape is declared three times: `TreeRestoreHint` in `src/file-navigator/restore.ts`, an inline type on the files view in `src/tab/types.ts`, and a client copy in `web/src/file-navigator/file/navigator-selection.ts`. It becomes one named wire type in `src/tab/types.ts`, re-exported through `src/protocol.ts`, and the other two are deleted (architecture principle 7). The profile restore always sends all three parts, with `null` for a part that didn't survive, so profiles behave exactly as today. The user chose this over a mode field with the copies kept in step.
39. **The command restore runs on local trees only, and synchronously.** The manager skips it for a tree whose state has `remote` set (Design decision 23). A local tree's port lists synchronously (`LocalFileSystemPort`), so every listing a step needs is in the cache when the step runs, and the restore finishes in one pass with no pending state. Its ceiling is exactly that: should remote support come back, the restore must learn to wait for listings, which the improvement pass worked out before the cut. It would publish a pending hint, keep a pending record that carries its root on `FilesTabState`, settle it from `writeRebuiltPayload` on each rebuild (because `listingFor` in `src/file-navigator/filesystem-cache.ts:14` calls back only the first caller while a read is in flight), and drop it when `reRootTree` or `retarget` changes the root in place. The client would skip a pending revision once the user changed the selection.
40. **A print shares the selection request in flight.** `requestTreeSelections` today resolves an earlier request empty when a new one starts, so a `files print` during a `profile save` would lose one answer. A request made while one is outstanding now joins it and gets the same answer. Both callers want every navigator's selection at about the same moment, so one answer is right for both, and `profile save`'s own behavior is unchanged. The user chose this over keyed concurrent requests and over leaving it.
41. **`files print` is a pure formatter behind a manager method.** A pure module turns a tree's root, dock, mode, expanded set, selection, and remote owner into the line. A `FileNavigatorManager` method gathers those, awaiting the selection request, and returns the line or the reply. `src/commands/files.ts` stays the one definition of `files`: it sees the parsed print form, awaits the method, and appends the result. The user chose this over doing both in the command module.
42. **The completer is a new handler with a context object.** A new completion module handles `files` lines, placed in `completeCommandLine`'s chain ahead of the path fallback. It takes a context built in `src/controller/completion.ts`, the way `MonitorCompletions` is: the open navigators' labels, and a lookup from a label to its local cwd that answers nothing for a remote or unknown tab. Path positions call `completeFilePath` with the chosen base directory, and keyword matches are placed first. The user chose this over teaching the path completer about `files`.
43. **The profile launcher quotes the path it hands to `files`.** `openProfileFiles` builds a `files … <path>` command from an entry, and a relative `path` such as `select notes` would now parse as a clause. The launcher wraps the path in double quotes, escaping any `"`, so Design decision 9 unwraps it and it's always read as the path. Expanding `$root` and `~` is unchanged. A profile path that both needs quoting and ends in `\` hits Design decision 28's limitation. The user chose this over leaving the path raw.

## Proposed changes

### Server

- **`src/command/quoted-token.ts`** (new, unless the arranging-tabs plan has already created it). `readToken`, `skipSpaces`, and `Token` move here from `src/agent/command-parser.ts` unchanged, and that module imports them. Per `imports-and-barrel-files.md`, the old module doesn't re-export them.
- **`src/file-navigator/view-args.ts`** (new, pure). Exports the `ViewStep` type, a discriminated union of `expand`, `collapse`, `cursor`, `anchor`, and `select`, each carrying the path as typed with its quotes removed. Exports `VIEW_KEYWORDS`, the five keywords, for completion to import. Exports a reader that, given the line and an index at a keyword, returns the step and the index after its value, `undefined` when the keyword has no value after it (Design decision 6), or `{ error: 'files: unterminated quote' }`.
- **`src/file-navigator/args.ts`** (rewrite). `parseFileNavigatorArgs` becomes the token loop from Design decision 34 and returns one of three results. The open form carries `inLabel`, `missingInLabel`, `dock`, `details`, the ordered `steps`, and `target`. The print form carries `name`. The error form carries the exact line. A word counts as a keyword only when its token was read bare, never when it was quoted (Design decision 6). `in`, `on`, and `with` keep today's value rules and keep their "consumed at most once" behavior. A bare `left`/`right` is recognized once, at any clause position, while no `in` or `on` has been read, which keeps today's rule and adds the positions after other clauses (Design decision 5). The trailing `in <label>` rule and the `files: expected a tab label after "in"` reply are unchanged. The target is the rest of the line, with its quotes removed when it reads as exactly one quoted token (Design decision 9). `print` is checked only as the first word: one name token and nothing else gives the print form, more words give `Usage: files print <tab>.`, and an unterminated quote gives `files: unterminated quote`. Every pattern is a fixed word or character class with no nested quantifier, so `security/detect-unsafe-regex` stays quiet.
- **`src/file-navigator/view-paths.ts`** (new, pure). `toTreePath(input, root, expand)` turns a clause path into the tree-relative form row paths use, or `undefined` when it lands outside the tree, per Design decision 10. `expand` is the caller's `~`/`$root` expander, so the module stays free of managers and remote state. It returns `''` for the root itself and `..` for the parent row. It is a few calls to `path.posix.normalize`, `path.posix.isAbsolute`, and `path.posix.relative` (posix, matching row paths), with no hand-rolled segment handling.
- **`src/file-navigator/selection-fallback.ts`** (new, pure). The server's copy of the fallback rule (Design decision 37): given a working cursor, anchor, and selection and the rows visible after a collapse, it keeps the visible selected rows, moves a hidden cursor to its nearest visible ancestor, and resets a hidden anchor to the cursor. When the line named no cursor, it marks the anchor `anchorToCursor` instead. It walks ancestors with the existing `parentPath` (`src/file-navigator/index.ts:71`) rather than a new helper.
- **`src/file-navigator/navigation.ts`**. Add `collapseTree(port, state, relPath)` beside `toggleDir`. It removes `relPath` and every expanded path beneath it (`relPath` itself, or anything starting with `relPath/`) from the expanded set and unwatches each. For `''` it calls `dropExpandedWatchers` (`src/file-navigator/navigation.ts:47`), the half of `collapseAllDirs` that doesn't rebuild. It never rebuilds itself, since the command restore rebuilds once at the end.
- **`src/file-navigator/restore.ts`**. Keeps `restoreTreeView` for profiles. It now writes the shared hint type with all three parts present, `null` where nothing survived, so profile behavior is unchanged. It exports its directory check (`stillDirectory`) and a `nextRestoreRevision()` for the command restore. Its local `TreeRestoreHint` type is deleted in favor of the wire type.
- **`src/file-navigator/restore-command.ts`** (new). `applyViewSteps(port, label, steps)` is the command restore from Design decision 36. It snapshots the expanded set, applies `expand` (through `expandAndWatch`, after `stillDirectory`) and `collapse` (through `collapseTree`) in order, then evaluates the selection steps in order against a simulation from the snapshot. The simulation builds each step's visible rows with `buildRows` (`src/file-navigator/index.ts:43`), passing the simulated expanded set and a `readEntries` callback over `listingFor`, so it reads the real listing cache, which a local tree fills synchronously (Design decision 39). It doesn't go through `buildCachedRows`, because that also starts stat reads (`fillStats`) for rows the simulation never shows. A hidden row is handled by `selection-fallback.ts`, and dropped parts follow Design decision 16. It then sets `state.restore`, with a new revision from `nextRestoreRevision()`, carrying only the parts the line named. Every listing read it starts passes `() => port.rebuild(label)` as its `onReady`, as `restoreTreeView` does. It ends with `port.rebuild(label)`. If the module passes 200 counted lines, extract the simulation into its own module beside it rather than compacting.
- **`src/file-navigator/state.ts`**. `FilesTabState.restore` takes the wire hint type.
- **`src/tab/types.ts`** and **`src/protocol.ts`**. A named `FileNavigatorRestoreHint` replaces the inline `restore` type on the files view, with the optional parts and the one flag from Design decision 38. `src/protocol.ts` adds it to its existing `tab/types.js` re-export list (`src/protocol.ts:17`). `src/tab/types.ts` is at about 178 counted lines; if the named type takes it past 200, define the type in a new `src/tab/files-restore.ts` instead and re-export it from `src/protocol.ts` the same way.
- **`src/file-navigator/open-command.ts`**. `openFilesCommand` takes the already-parsed open form and the transcript `out` function instead of the raw command, so the file doesn't grow (it is at about 180 counted lines). Its return is unchanged: the label it opened, focused, or redocked, including a waiting tree's, and `undefined` when nothing opened. Keep the waiting tree's label: `placeInGroup` in `src/profile/files.ts` relies on it to move an undocked waiting tree into its group.
- **`src/file-navigator/manager.ts`**. `open(command, label)` parses. A parse error is appended the way today's `files: expected a tab label after "in"` is, through `managers.tab.append(label, { input: command, output })`, and nothing opens. Otherwise it calls `openFilesCommand`. When the steps aren't empty, a label came back, that tree isn't waiting for its root (its state has no `pollTimer`, which `pollForCreation` sets), and it isn't remote (its state has no `remote`), it normalizes each path with `toTreePath`, using `expandUserPath` with `managers.tab.launchDir` as the expander, and calls `applyViewSteps`. A path that `toTreePath` rejects is dropped from the steps. A remote tree gets nothing further, and nothing is printed about it (Design decision 23). A new `printView(name, issuingLabel)` resolves the name with `resolveTarget`, refuses a tab that isn't a navigator, awaits `requestTreeSelections` for a local tree only, and returns the formatted line. Both methods delegate their bodies to the modules above, so `manager.ts` gains only their signatures and calls.
- **`src/file-navigator/print-command.ts`** (new, pure). `formatFilesCommand(view)` builds the line from Design decision 26. Its root form is `abbreviatePath`'s, except that a root inside `<launch>/.janissary` keeps the segment (Design decision 27), and a remote root reads `$root/<rest>` against its workspace root (`state.remoteRoot`), with the owner tab (`state.ownerLabel`) in its `in` clause and no view clauses. It quotes and escapes a path containing a space or a quote, emits clauses in the fixed order, and leaves out `on`, `with name`, and absent selection parts.
- **`src/file-navigator/selection-request.ts`**. `requestTreeSelections` lets a call made while a request is outstanding join it and resolve with the same answer, under the first request's id and timer, instead of settling the earlier one empty and emitting a new `collect`. Its comment changes with it. The answer is keyed by tab index, as today, so `printView` looks its tree up with `managers.tab.findIndex(label)`, the way `src/profile/save/route.ts:74` uses `managers.tab.tabs.indexOf(tab)`.
- **`src/commands/files.ts`**. `run` parses the command to check for the print form. The print form awaits `managers.fileNavigator.printView` and appends one entry, with the command as input and the line or reply as output, through `appendCommandOutput` with the invocation, so a runscript capturing output gets the line. Anything else appends its empty-output entry as today and calls `open`, which parses again (the parser is pure and cheap) and reports a parse error itself, so a profile's call to `open` gets the same handling. `samples` gains `files print navigator` and `files expand src`, so `src/commands.test.ts` checks them for shadowing.
- **`src/profile/files.ts`**. `filesCommand` wraps `entry.path` in double quotes, escaping `"` (Design decision 43). The profile restore call is unchanged.
- **`src/completion/files.ts`** (new). `completeFilesCommand(cursor, labels, context, cwd)` implements Design decisions 29 to 31 with `completeWord`, `VIEW_KEYWORDS`, the mode and side words, and `completeFilePath` against the chosen base. It reads the text before the cursor's token with `readToken` to find the clause position, since `readCompletionCursor` splits on whitespace and knows nothing of quotes. Inside an open quote it returns the input unchanged with no matches. It returns `null` for any line that isn't `files`.
- **`src/completion/index.ts`** and **`src/controller/completion.ts`**. `completeCommandLine` takes an optional `FilesCompletions` context and calls `completeFilesCommand` ahead of the `completeFilePath` fallback. `complete` builds the context: the labels of open navigator tabs, and a lookup that gives `workingDirOf(label)` for a local tab and nothing for a remote or missing one.

## Out of scope

- Changing what `profile save` records, and saving or restoring remote trees through a profile.
- Restoring a view on a remote tree from the command line (Design decisions 23 and 39).
- Fixing `profile save`'s lost `.janissary` segment (Design decision 27), which goes to the bug backlog.
- Moving keyboard focus as part of a restore.
- Reporting dropped paths.
- Revealing a named row's collapsed folders (Design decision 13).
- Clearing an open tree's cursor and selection from the command line (Design decision 33).
- Changing what a repeated `in`, `on`, or `with` does (Design decision 3).
- Giving profile relaunches the command's touch-only-what's-named rule (Design decision 17).
- A backslash escape in quoted tokens (Design decision 28).
