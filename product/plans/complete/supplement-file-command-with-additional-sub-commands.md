# supplement file command with additional sub commands

**Complexity: 7/10** — ~630 added lines across 11 production files, 18 behavioral requirements and 30 test scenarios, with four new command modules and five new remote operations (p=7.474).

The `file` command already reads, globs, greps, writes, edits, and patches workspace files. This change adds the read-only questions people and agents most often ask about a path directly to that command: list a directory, describe a file, check whether it exists, and read just its first or last lines. The point is to answer those questions without reaching for a shell round trip or doing offset arithmetic on top of `file read`.

## Design decisions (from the feature text, existing behavior, and resolved questions)

- The backlog names the exact surface: `file list <path>` / `file ls <path>` for a directory listing, `file stat <path>` for size, mtime, type, and permissions, `file exists <path>` for a cheap existence/type check, and `file head <path> -n` / `file tail <path> -n` for the first or last N lines. The `list`/`ls` and `head`/`tail` pairs are aliases of one operation each. `head` and `tail` take the count on a single-dash `-n` flag as written in the backlog.
- All four operations are read-only. They share the root rule every existing `file` subcommand follows: a local tab resolves paths against its workspace, or the project directory when it has none, and a remote tab resolves them only inside its remote workspace, never on the local disk.
- The command's existing dispatch shape is settled by the code: `src/commands/file.ts` checks an `isFile…CommandLine` predicate per subcommand in a fixed order and falls through to `file read`. New subcommands join that chain as siblings, not as branches ahead of the command registry.
- Each existing subcommand is a self-contained module with a pure parser that returns arguments or a usage error, a tab executor that resolves the root and appends output, completion support, and an entry in the native command vocabulary so roles can grant it. The new operations follow that same shape.
- The four operations work on local and remote tabs alike. On a remote tab each one resolves paths only inside the remote workspace over the channel, matching read, glob, and grep. Each operation that lacks one gets its own read-only filesystem operation over the remote channel, and the protocol version is bumped once for the set.
- All four are native commands with full agent parity: each gets its own Enabled and Agent-access settings row under the `file` parent, the commands become grantable in roles, and the file tool's primer grows so agents can call them.
- The four operations live in four sibling feature modules (`src/file-list/`, `src/file-stat/`, `src/file-exists/`, `src/file-head-tail/`), each with a pure parser and an executor. The `list`/`stat` row formatter is one shared pure module used by both.
- Remote support adds one filesystem operation per command (`list-directory`, `stat-path`, `path-exists`, `head-lines`, `tail-lines`), each validated on the far side and each returning finished output text so local and remote wording cannot drift. The protocol version is bumped once for the set.
- `tail-lines` reads the file once on the far side, counts lines, and returns the last N numbered with their true absolute positions rather than probing a line count and re-reading. Locally and remotely the numbered output comes from `formatFileLines` in `src/file-read/format.ts:20`, called with `offset = total - N + 1` and `limit = N`; because N is at most 2000, this reuses the existing numbering and truncation rules without hitting the read cap.
- The new executors translate `FilePolicyFailure` from `src/file-read/policy.ts:11` into the one-word vocabulary: `Outside the workspace` and `Secret file` become `forbidden`, `File not found` becomes `missing`, and `Is a directory` becomes `notdir`. `Not a text file` and `File too large (>5 MB)` keep their existing verbose lines, since those describe the file rather than an access decision and the one-word set does not cover them.
- In an autonomous agent run, `gateAgentCommand` in `src/acp/tool-table.ts:162-173` refuses the four new commands with `Agent: command not permitted: <command>.`, exactly as it refuses glob, grep, and mutations today. Only `file read` remains runnable from an agent run's workspace; the new tools are for ACP sessions and typed use.
- `file list` filters entry names through `isSecretPath` from `src/file-read/policy.ts:24` before rendering; it does not skip dotfiles or `node_modules`.
- The built-in `ask` and `tell` roles both grant all four by default, so both primers gain the new text.
- `file list` prints a detailed, `ls -l` style row per entry: type, size, mtime, and permissions alongside the name. It uses both `readDirectory` and `statRows` from the tab's filesystem port.
- `file exists` prints only a single word and never echoes the path: the type word (`file`, `dir`, or `link`) on a hit, `missing` for a genuinely absent path, and `forbidden` for a path outside the workspace or a secret file. A miss and a refusal are normal answers, not error lines. `.git` and `.janissary` paths answer normally, as they do for `file read`. This one-word result is deliberately different from the verbose refusal lines the other `file` subcommands print.
- The new commands share a terse, one-word result vocabulary instead of the verbose refusal lines the older `file` commands print: `missing` for an absent path, `forbidden` for an out-of-workspace or secret path, and `notdir` when `file list` is pointed at a file. `file stat` works on both files and directories. These are normal answers, not error lines.
- `file list` on an empty directory prints `(empty directory)`.
- `file head` and `file tail` print numbered lines exactly as `file read` does. Head numbers from line 1; tail keeps absolute file line numbers. Both reuse the existing numbered-line reader and its truncation rules.
- `-n <count>` follows the path and is optional, defaulting to 10 when omitted. An empty file prints `(empty file)`; a count larger than the file prints every line; `-n 0`, a negative or non-numeric count, or a count above 2000 prints the usage line. Head and tail keep the `file read` rules here rather than the one-word vocabulary. Pointing head or tail at a directory prints `notdir`.
- `file list` includes dotfiles and `node_modules` entries, but never lists `.env`, other secret filenames, or credential locations. It follows `file glob`'s hard secret rule without adopting glob's default hidden-file skipping.
- Malformed arguments print one canonical usage line per command: `Usage: file list <path>`, `Usage: file stat <path>`, `Usage: file exists <path>`, and `Usage: file head <path> [-n <lines>]` (tail likewise). The `ls` alias prints the `list` usage line.
- `file stat` prints one row in exactly the same format as a `file list` row, so a single formatter serves both commands.
- A row uses readable fixed tokens in this order: word type, rwx permission string, byte size, ISO UTC mtime, then the name, as in `file -rw-r--r-- 1234 2026-11-19T13:50:00Z notes.md`. It does not humanize sizes, pad columns, or use locale-sensitive dates. The mtime string is the standard library's `Date(...).toISOString()` applied to the `modified` value from `RowStat`; the rwx string and type word are a few lines of bit checks on `mode`, with no new helper layer.

## Proposed changes

Add one module per operation, each with a pure parser that checks the literal `file <subcommand>` prefix and scans its arguments into a typed value or a usage error, and an executor that takes `Managers`, a tab label, and the raw line, resolves the root exactly as the existing file executors do, and returns the output string the dispatcher appends to the transcript. `file list` and `file ls` share one parser and executor, as do `file head` and `file tail`; the alias is recognized in the predicate and the output is identical. The new predicates join the ordered chain in `src/commands/file.ts` before the `file read` fall-through, and the command's `samples` list gains one example per new operation.

`file list` asks the tab's filesystem port for a sorted directory listing and the stat rows of those entries, filters out secret names, and renders one fixed-token row per entry or `(empty directory)`. `file stat` asks the port for one stat row and renders it with the same formatter. `file exists` uses `readRowStat` from `src/file-navigator/stats.ts:17` for its type word, after the policy checks decide between `missing` and `forbidden`, and prints only `file`, `dir`, `link`, `missing`, or `forbidden`. `file head` reuses `readWorkspaceLines` with a limit of N; `file tail` reads the file once, counts lines, and numbers the last N with their absolute positions, applying the same per-line formatting rules as `file read`. The `-n` count is optional, defaults to 10, and is validated with `positiveInteger` from `src/positive-integer.ts:1` plus a 2000 bound; missing, repeated, or malformed arguments print the command's canonical usage line.

Remote tabs get one new read-only filesystem operation per command: `list-directory`, `stat-path`, `path-exists`, `head-lines`, and `tail-lines`. Following the `read-lines` and `glob-paths` precedent, each request carries the path and the command's arguments, each answer is rooted at the remote workspace and carries the finished output text, and the far side enforces containment and the secret-file rules before formatting. A single protocol version bump covers the five operations. Because the finished text crosses the channel, local and remote wording cannot drift.

Register each new subcommand in `NATIVE_ACP_COMMANDS`; that single addition generates its native settings row with parent `file` through `src/application-commands.ts:48-51`, so `COMMAND_FORMS` needs no edit. Add the new names and their `-n` flag to the `FILE_SUBCOMMANDS` and per-subcommand branches in `src/completion/file-read.ts:8-45`, including the `ls` alias. Add their predicates and primers to the file tool entry and `filePrimer` in `src/acp/tool-table.ts`, their branches to `runWorkspaceCommandIn` in `src/acp/workspace-runner.ts`, and their refusal to `gateAgentCommand` as decided above. Each gets its own Enabled and Agent access setting under the `file` parent so disabling one refuses only that subcommand. Update `help/file.md`, `help/commands.md`, the alphabetical Commands table, and the behavior specs listed above. The built-in `ask` and `tell` roles grant all four by default, so both the typed command reference and the agent primer describe them.

The five remote operations need a frame union member and argument shape in `src/remote/protocol-frames.ts`, one operation descriptor module each beside `src/remote/filesystem/read-lines-operation.ts`, entries in `src/remote/filesystem/operations.ts` and `src/remote/filesystem/result-decoders.ts`, caller-side methods beside `remoteReadLines` in `src/file-navigator/remote/port-reads.ts` wired through `src/file-navigator/remote/port.ts`, and a version-history note in `src/remote/protocol.ts`. The far-side dispatcher at `src/remote/serve-file-navigator.ts:63` is generic and needs no edit. Keep `src/acp/tool-table.ts` under the 200-line limit by extracting `filePrimer` into its own module if the added blocks push it over.

## Tests

- Extend `src/commands/file.test.ts` with dispatcher cases: each new predicate matches its own line and its alias, a lookalike subcommand falls through to the read usage line, and each command appends one transcript entry with the exact typed input.
- Add colocated parser tests beside each new module, following `src/file-read/command.test.ts` and `src/file-glob/command.test.ts`: valid forms including the `-n` flag, missing and repeated arguments, malformed counts, and the usage error in each case.
- Add executor tests with a temporary directory for the local root and the fake remote channel harness already used in `src/commands/file.test.ts`: root choice for tabs with and without a workspace, missing paths and directories, containment and secret-file refusals, and parity of output wording between local and remote.
- Extend `src/completion/file-read.test.ts` so the new subcommands appear only when enabled and path completion follows their argument shape.
- Update `src/application-commands.test.ts` and the relevant ACP and remote suites for the new native command names and remote operations.

## Out of scope

- No new subcommands beyond the four named in the backlog. In particular no `file cp`, `file mv`, `file rm`, or other mutating additions.
- No change to the behavior of `file read`, `file glob`, `file grep`, `file write`, `file edit`, or `file patch` beyond adding new siblings to the dispatcher.
- No web UI beyond the existing command bar and transcript; the feature adds command behavior and transcript text only.
- No change to how a role's command grants are stored or edited beyond listing the new names among the native commands.
