# supplement file command with additional sub commands

**Complexity: 7/10** — ~630 added lines across 11 production files, 18 behavioral requirements and 30 test scenarios, with four new command modules and five new remote operations (p=7.474).

The `file` command already reads, globs, greps, writes, edits, and patches workspace files. This change adds the read-only questions people and agents most often ask about a path directly to that command: list a directory, describe a file, check whether it exists, and read just its first or last lines. The point is to answer those questions without reaching for a shell round trip or doing offset arithmetic on top of `file read`. What shipped covers local tabs with and without a workspace and remote tabs over five new read-only protocol operations, gives each answer its own native command with per-command settings and role grants, wires the ACP tool loop and workspace runner, refuses the new names in autonomous agent runs, and documents the whole surface in help and behavior specs.

## Design decisions (from the feature text, existing behavior, and resolved questions)

- The backlog names the exact surface: `file list <path>` / `file ls <path>` for a directory listing, `file stat <path>` for size, mtime, type, and permissions, `file exists <path>` for a cheap existence/type check, and `file head <path> -n` / `file tail <path> -n` for the first or last N lines. `list`/`ls` and `head`/`tail` are each one operation with two spellings or directions. `head` and `tail` take the count on a single-dash `-n` flag as written in the backlog. Five native command names are exposed (`file list`, `file stat`, `file exists`, `file head`, `file tail`); `file ls` stays a parser, completion, and ACP reply alias of `file list` and gets no settings row or role grant of its own.
- All operations are read-only. They share the root rule every existing `file` subcommand follows: a local tab resolves paths against its workspace, or the project directory when it has none, and a remote tab resolves them only inside its remote workspace, never on the local disk.
- The command's existing dispatch shape is settled by the code: `src/commands/file.ts` checks an `isFile…CommandLine` predicate per subcommand in a fixed order and falls through to `file read`. The new subcommands join that chain as siblings after glob, grep, and the mutations and immediately before the read fall-through, so their relative order is unchanged and lookalikes still fall through.
- Each operation follows the per-subcommand shape: a pure parser that checks the literal `file <subcommand>` prefix and scans arguments into a typed value or a usage error, and a tab executor that resolves the root and returns the output string the dispatcher appends. The four operations live in four sibling modules (`src/file-list/`, `src/file-stat/`, `src/file-exists/`, `src/file-head-tail/`).
- Below parsing and root resolution, each operation has one shared pure implementation used by both the local tab executor and the far-side remote handler: `listFiles` in `src/file-list/list-core.ts`, `statFile` in `src/file-stat/stat-core.ts`, `fileExists` in `src/file-exists/exists-core.ts`, and `headTail` in `src/file-head-tail/head-tail-core.ts`. They take already-parsed arguments plus a root and, where needed, a `FileSystemPort` defaulting to the local port, and return finished text. The `tab-*` executors and the far-side `run` functions are thin wrappers. Row wording, type words, and error mapping are therefore identical by construction rather than only by parity test.
- The one-word result vocabulary lives in one pure helper, `fileFailureLine` in `src/file-failure.ts`: `missing` for an absent path, `forbidden` for an out-of-workspace or secret path, and `notdir` when `list` targets a file. `Not a text file` and `File too large (>5 MB)` keep their existing verbose lines, since they describe the file rather than an access decision and the one-word set does not cover them. These are normal answers, not error lines. The `Protected file` member of `FilePolicyFailure` cannot arise on a read-only path (`checkProtectedPath` is mutation-only), so it has no token.
- `file list` and `file stat` render rows through one shared pure formatter, `formatFileRow` in `src/file-row.ts`: fixed tokens separated by single spaces in the order type word, rwx string, byte size, ISO UTC mtime, then name, as in `file -rw-r--r-- 1234 2026-11-19T13:50:00Z notes.md`. Sizes are not humanized, columns are not padded, and dates use `Date(...).toISOString()`; the type word and rwx string are bit checks on `mode` with no helper layer. `file stat` works on both files and directories.
- `file list` asks the tab's filesystem port for a sorted directory listing and the stat rows of those entries, filters names through `isSecretPath`, and prints one row per entry or `(empty directory)`. Dotfiles and `node_modules` stay visible; secret filenames never do. An entry that vanishes between listing and stat is rendered with a zero-valued `RowStat` so the row shape stays fixed. Filesystem read failures are classified like the reader's `loadBytes`: `ENOENT`/`ENOTDIR` answer `missing`, every other code (including `EACCES`, `EPERM`, `ELOOP`) answers `forbidden`, and a rejected `readDirectory` resolves to `forbidden` rather than propagating.
- `file exists` prints only one word and never echoes the path: `file`, `dir`, or `link` on a hit from the `lstat`-based `readRowStat` mode (so a dangling symlink answers `link`), `missing` for a genuinely absent plain path, and `forbidden` for a path outside the workspace or a secret file. Path policy runs before the type lookup. When `canonicalPath` of the requested path fails with `ENOENT`/`ENOTDIR`, the nearest existing ancestor is resolved and the missing tail rejoined, so an escaping symlink hidden behind an absent leaf is still `forbidden` while a dangling symlink keeps its own spelling. `.git` and `.janissary` paths answer normally.
- `file head` and `file tail` print numbered lines exactly as `file read` does through `formatFileLines`. Head calls `readWorkspaceLines` with offset 1 and limit N; tail reads the file once, counts its lines, and numbers the last N with their true absolute positions (`offset = total - N + 1`, `limit = N`), reusing the existing numbering and 2000-character line truncation. A directory target answers `notdir`, including a symlink whose resolved target is a directory; a symlink to a regular file is read normally. Other failures keep `file read`'s verbose lines.
- `-n <count>` follows the path, is optional, and defaults to 10. It is validated with `positiveInteger` plus a bound, and `FILE_HEAD_TAIL_MAX_LINES` is assigned from `file read`'s `FILE_READ_MAX_LIMIT` so the parser can never accept a count the formatter silently clamps. `-n 0`, a negative or non-numeric count, a repeated flag, or a count above the bound prints the command's canonical usage line. An empty file prints `(empty file)` and a count larger than the file prints every line.
- Malformed arguments print one canonical usage line per command: `Usage: file list <path>` (also for `ls`), `Usage: file stat <path>`, `Usage: file exists <path>`, `Usage: file head <path> [-n <lines>]`, and `Usage: file tail <path> [-n <lines>]`.
- Remote support adds five read-only operations to the existing filesystem channel — `list-directory`, `stat-path`, `path-exists`, `head-lines`, and `tail-lines` — inside the existing `filesystem-request` / `filesystem-reply` frames, with argument shapes `{ path }` for the first three and `{ path, count }` for the last two and `{ text }` answers. The protocol version advances once for the set, from 47 to 48, with one history note explaining that a version-47 peer refuses the new operations as unknown after the handshake has passed. No new frame type, binary field, or far-side dispatcher edit is needed.
- Each operation has one descriptor module beside `src/remote/filesystem/read-lines-operation.ts`, registered in `READ_OPERATIONS` and `resultDecoders`, with `rootDestination: true` so the far side treats every path as relative to its workspace. The far side enforces containment and the secret rules before formatting and returns finished output text, so local and remote wording cannot drift. Caller-side helpers beside `remoteReadLines` in `src/file-navigator/remote/port-reads.ts`, exposed as thin delegates on `RemoteFileSystemPort`, send each operation; each executor opens one session per call through `withRemoteTabPort` and returns `result.text` directly.
- Each of the five names is registered in `NATIVE_ACP_COMMANDS`, which generates its native settings row with parent `file` through `src/application-commands.ts`; `COMMAND_FORMS` needs no edit. Each gets its own Enabled and Agent-access setting, so disabling one refuses only that subcommand while disabling the parent refuses all. The built-in `ask` and `tell` roles grant all five by default (help/spec totals: 25 native commands, ask 17, tell 24); saved roles files are unchanged. `master` publishes `DEFAULT_ROLES` from `src/plugins/roles/default-roles.ts`, which `roles-file.ts` imports, so the grants are made there.
- `filePrimer` and its five primer strings live in their own pure module, `src/acp/file-primer.ts`, keeping `src/acp/tool-table.ts` under the 200-line limit. The file tool's reply-line predicate, `gateAgentCommand`, and `src/acp/workspace-runner.ts` use the shared line-detection predicates exported by the command modules (`isFileListCommandLine`, `isFileStatCommandLine`, `isFileExistsCommandLine`, `isFileHeadTailCommandLine`) rather than local regexes. In an autonomous agent run every new name, including `file ls`, is refused with `Agent: command not permitted: <command>.`, echoing the whole line, while `file read` remains the only file command such a run can execute. `nativeCommandName` rewrites a leading `file ls` to `file list` before native-name lookup, so a role session ending its reply with `file ls <path>` runs the listing; the reply line itself is returned and echoed unchanged.
- Five duplicated fake remote channel harnesses in the file tests are replaced by one test-only module, `src/testing/fake-remote-channel.ts`, exporting `RequestFrame` and `fakeChannel()` with the same listener accessor and filesystem-request guard, so a channel-protocol change is made in one place.
- The five new names are documented in the `file` row of `help/commands.md`, in the detailed `help/file.md` page, and in behavior specs. `master`'s per-subcommand rows in the Commands table are preserved: the new names are described in the `file` row rather than given separate table rows. `product/specs/file-exists.md` and `product/specs/file-head-tail.md` are new specs; `acp.md`, `agent-command.md`, `application-commands.md`, `remote-server.md`, `roles.md`, and `tab-completion.md` are extended. The spec-only correction to `acp.md`'s "File write and edit tools" paragraph makes its primer enumeration match the accurate "When a role grants file read" paragraph: read, glob, grep, mutation, patch, list, stat, exists, head, tail, each separated by a blank line.

## Proposed changes

One module per operation was added, each with a pure parser that checks its literal prefix and scans a typed value or a usage error and a tab executor that resolves the root and returns the output string the dispatcher appends. `file list` and `file ls` share one parser and executor, as do `file head` and `file tail`; the alias is recognized in the predicate and the output is identical. The new predicates join the ordered chain in `src/commands/file.ts` before the `file read` fall-through and the command's `samples` list gained an example per operation. Each dispatched invocation still appends exactly one transcript entry carrying the exact typed input.

`file list` asks the tab's port for a sorted listing and the stat rows, filters secret names, and renders one fixed-token row per entry or `(empty directory)`; vanished entries render with a zero-valued stat and filesystem failures resolve to `missing` or `forbidden`. `file stat` renders one row through the same formatter for a file or a directory. `file exists` runs the policy checks, resolves the nearest existing ancestor when the target is absent, then uses `readRowStat`'s mode for its one-word answer. `file head` reuses `readWorkspaceLines`; `file tail` reads once and numbers the last N with `formatFileLines`. The bodies below parsing and root resolution were extracted into the four `*-core.ts` modules; the `tab-*` executors and the far-side descriptors now call those same functions, and the shared `formatFileRow` and `fileFailureLine` own the row and one-word vocabularies.

Remote tabs gained one read-only filesystem operation per command (`list-directory`, `stat-path`, `path-exists`, `head-lines`, `tail-lines`): frame union members and argument shapes, one descriptor module each registered in `READ_OPERATIONS` and `resultDecoders`, caller-side helpers in `port-reads.ts` with thin `RemoteFileSystemPort` delegates, and a single version bump to 48 with its history note. Each executor opens one remote session through `withRemoteTabPort` and returns the far side's finished text. Nothing reaches the local disk on a remote tab.

All five names were registered in `NATIVE_ACP_COMMANDS`, generating their native rows and per-command Enabled and Agent-access settings under the `file` parent. `FILE_SUBCOMMANDS` and the per-subcommand branches in `src/completion/file-read.ts` gained the new names, the `ls` alias, path arguments, and the `-n` no-candidates rule. `src/acp/file-primer.ts` was extracted from the tool table and grew a primer block per name; the file tool's reply-line predicate, `gateAgentCommand`, and `runWorkspaceCommandIn` were extended using the shared line-detection predicates, with `nativeCommandName` resolving the `file ls` alias. The built-in `ask` and `tell` grants were added in `default-roles.ts`. The completed work also folded in the review repairs: absent-target and dangling-symlink handling in `file exists`, filesystem-failure classification in `file list`, symlinked-directory `notdir` in head and tail, the `FILE_READ_MAX_LIMIT`-derived count bound, the shared `file ls` reply alias, the one-impl-per-command core extraction, the shared detection predicates, and the single test-channel harness.

Help and specs were brought in line: `help/file.md` documents all usages, answers, and edge cases under **Listing and inspecting paths**, the `file` row of `help/commands.md` names the new subcommands, `product/specs/file-exists.md` and `product/specs/file-head-tail.md` were added, and `acp.md`, `agent-command.md`, `application-commands.md`, `remote-server.md`, `roles.md`, and `tab-completion.md` were extended. The Commands table stays alphabetical with a page for every row and `src/commands.test.ts` passes unchanged.

## Out of scope

- No new subcommands beyond the five native names (and the `file ls` alias): no `file cp`, `file mv`, `file rm`, or other mutating additions.
- No change to the behavior of `file read`, `file glob`, `file grep`, `file write`, `file edit`, or `file patch` beyond adding siblings to the dispatcher; no change to their failure messages, path policy helpers, or read cap.
- No separate native name, settings row, Commands-table row, or role grant for `file ls`; no change to how role grants are stored or edited beyond listing the new names, and no change to saved roles files.
- No new frame type, binary field, wire-encoding change, or far-side dispatcher edit for the five remote operations, and no protocol or version change in the sharing refactor.
- No web UI beyond the existing command bar and transcript; no generated documentation-site page edited in place of its `help/` source.
- No re-export barrels, no compaction to meet the 200-line source limit — `filePrimer` and the helper extraction were the answer — and no changes confined to the individual subplans' own staging scopes once folded here.
