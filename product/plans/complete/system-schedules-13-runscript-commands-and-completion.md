# System schedules 13: runscript commands and completion

**Complexity: 5/10**

This adds two top-level command routes over the runscript catalog and the existing system-shell FIFO. The subtle parts are preserving `edit` path precedence and keeping manual queue rows free of scheduled provenance.

## Goal

Add immediate `execute <name>`, existing-runscript fallback for `edit <name>`, and completion for both commands. Source: `product/plans/ready/add-system-schedules.md`.

## Decisions and dependencies

- Dependencies: completed 03/04 for `SystemShellManager.ensure()`, 07 for safe project-root reads/catalog and strict runscript names, 09 for the retained system-shell queue consumer and continue-after-error behavior, 11 for shared system queue/batch ownership, and 12 for the system runscript grammar/catalog completion precedent. Plan 01 already owns `tab focus`; this plan does not add its completion or change its behavior.
- Register one top-level `execute <name>` command. Validate one strict runscript name, read it afresh from the project-root catalog, and enqueue its complete parsed lines to the system shell immediately. Call `managers.systemShell.ensure()` before enqueueing; on failure, rely on its existing failure notice and leave the queue unchanged. A missing script prints exactly `No runscript named "<name>".` and changes nothing. An existing but unsafe or unreadable script uses `Could not read runscript "<name>".` and adds no rows. Success is silent; shell output belongs to the system tab. An empty existing script succeeds as a no-op. Do not add schedule notices, schedule entries, or schedule origin to manual rows.
- Manual run lines are ordinary `QueueEntry` strings. Reuse/extract the atomic whole-batch queue append seam that plan 11 uses, but preserve the distinction between a schedule batch carrying its existing schedule key and a manual batch carrying no provenance. Append a whole batch synchronously with one queue/state change so other producers cannot interleave its lines. Do not enqueue using repeated user-facing `queue` command calls.
- Every queued line goes through the existing system-shell consumer and normal command/shell dispatch. Shell commands therefore run in the no-workspace `system` shell even when `execute` was typed from a workspaced shell. Preserve plan 09's FIFO and continue-draining behavior after a shell or application command fails; do not add stop-on-error handling or a second runner.
- `agent ... execute ...` remains the agent parser's final clause; top-level `execute` claims only its own first-token command form and must not intercept agent input. Task-picker `execute ...` text continues to be inserted verbatim into bars/prompts; it does not launch a task or agent.
- Add runscript fallback only to the command-line `edit` route. First resolve the user target exactly as today: expand `$root` and home, resolve relative paths against the issuing tab's cwd, preserve explicit path and `:line` semantics, and honor an existing exact file target. Only if no exact target exists and the input is a bare valid runscript name (no path separators, extension, or line suffix) may it resolve to `<project>/.janissary/scripts/<name>.rs`. Open that existing file through the ordinary editor path. If the fallback does not exist, print exactly `No runscript named "<name>".` and do not register an editor buffer, create a file, or create the scripts directory. The plan's refusal decision overrides the source plan's stale claim that `edit <name>` creates a script; deliberate creation remains possible through existing explicit-file editor mechanisms.
- Preserve programmatic editor opens, profiles, links, and other direct `OpenFileManager` callers. Keep the fallback decision in `commands/edit.ts` or a focused injected-existence helper, rather than changing the general editor/open contract. An exact existing project file named like a runscript wins over the fallback; non-bare paths continue ordinary edit resolution even when missing.
- Extend the existing completion pipeline, which currently special-cases `schedule` with `completeSystemSchedule`. `execute` completes valid catalog names only in its single name slot, with no filesystem fallback. Bare-name `edit` completion offers catalog names alongside ordinary file completion; paths, extensions, and `:line` inputs keep ordinary filesystem completion. Use the project-root catalog, refresh it on each request, return no runscript suggestions for an absent or unsafe catalog, and do not change schedule grammar completion from 12.
- Audit the command registry and plugin command reservation: add exactly one `execute` command entry with non-shadowing `match` and canonical `samples`; do not add a dispatcher branch ahead of the registry or duplicate command definition. Check collision behavior against the agent parser's embedded `execute`, existing `edit`, and task-picker input. Add `execute` to generated available/reserved command behavior through the registry, not a parallel reserved-name list.
