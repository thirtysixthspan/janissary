# Remote run clone service and ACP routing extraction
**Complexity: 7/10** — ~250 added production lines, 2 existing files, 20 requirements, 83 scenarios (p=7.09)

## Goal

Add `RemoteRunClones` owned by the provisioned far-side workspace. It creates fresh shallow clones beside the main workspace, publishes directory lookup only after readiness, and releases its own clones through `WorkspaceManager.remove`. Extract the existing ACP and agent-resolution dispatcher to make room in `RemoteServer`. This service is a prerequisite for later frames and selectors; this unit adds neither.

Source: `product/plans/complete/subagent.md`, preserved unchanged as the canonical feature record. This is ordered subplan 14 of 23.

## Implementation steps

1. In `serve-run-clones.ts`, define `RemoteRunClones`, its private lifecycle entry type, and `RemoteRunCloneResult`. The result has three mutually exclusive outcomes: create success carries only `dir`, release success is empty, and failure carries only `error`. The constructor receives the existing `WorkspaceManager`, the merged `ProjectTokens`, and the main workspace label. `create(label)` and `release(label)` return promises of that result; ordinary refusals, thrown startup errors and readiness rejections become error results through `errorText`, never an unobserved rejection. `lookup(label)` returns a directory or undefined. The service mints no label; the later launcher supplies `subagent-<runId>`.

2. Validate labels with `workspaceLabelError` before deriving a path or touching the manager. Invalid create/release returns `invalidNameRefusal`; invalid lookup returns undefined. Reserve labels synchronously, comparing ownership with `sameLaunchName` so case variants cannot race into the same folder. Refuse a label matching the main label, a pending/ready/releasing service entry, a directory already tracked by the manager, or an existing target or `.tmp` sibling, with `Remote run clone "<label>" already exists.`. Never borrow, overwrite or remove these collisions and never clear a leftover for a generated run name. Unknown valid release is an idempotent empty success and touches no path; unknown lookup returns undefined. A stopping service refuses create with `Remote run clone service is stopping.` and hides all lookup results.

3. After reserving an entry, queue clone startup in a microtask so an immediate release or stop can cancel it before `WorkspaceManager.create` runs. Repeat the external occupied-path and manager-tracking checks immediately before starting. For an admitted attempt call `workspaces.create(label, tokens.github, workspaceCloneOptions(AGENT_CLONE_DEPTH))` exactly once. Keep its creator reference; no agent lease or main-provisioning call is involved. Observe the handle's readiness immediately and wait through all post-clone setup before returning create success or making lookup visible. Convert an error object without a handle into a failure without removal. Once a handle exists, retain it through failure, cancel or late completion; failed or released attempts remove their directory exactly once after the underlying readiness settles, while successful live clones remain owned. A failed attempt clears its reservation after cleanup so a later create may retry the label; use entry identity to prevent an old continuation from changing another attempt.

4. Release hides lookup and marks the entry cancelled before awaiting anything. During pending creation, cancel once with the handle's `cancel`, falling back to `WorkspaceManager.cancel(label)` when absent, then await the original readiness before `workspaces.remove(dir)`. Remember cancellation before handle installation and apply it to a late handle. Wait on startup/underlying readiness rather than the public create-result promise, since that promise itself waits for cleanup. Readiness that resolves after cancellation must not publish a directory or report create success: the create result is `git clone cancelled.`. A cancelled queued start creates nothing. Concurrent/repeated releases share cleanup, retain the reservation until it finishes and remove no directory twice. Readiness failure without cancellation preserves its original error text. Keep cancellation and the readiness wait in a try/finally relationship so a cancellation exception cannot skip draining or removal; report that exception on release without replacing an earlier create failure. Removal retains the manager's existing best-effort semantics and does not claim strict filesystem deletion.

5. Add idempotent `stop()` on the service. It closes admission synchronously, cancels/drains pending attempts through the same release ownership, and returns a promise only while that drain is pending; with no pending attempts it returns synchronously. Completed clones stay tracked for the server's guarded `removeAll`, so stop does not remove a directory from under a live ACP child. Construct the service only after successful main readiness in `provisionRemoteWorkspace`, using the already-merged tokens and main label, and return it as `ProvisionedWorkspace.runClones`. Preserve the main clone's existing depth, notice, token and idle behavior. No service is published for failed or stopped main provisioning.

6. Extract `dispatchAcpFrame` into `serve-acp-frames.ts`. It accepts a successfully decoded current `RemoteFrame`, imported directly from `protocol-frames.js`, the current `ProvisionedWorkspace` or undefined, and the current emitter, and returns whether it consumed the frame. Handle exactly `agent-resolve`, `acp-open`, `acp-run`, `acp-tool-result`, `acp-close` and `acp-cancel`; return false without side effects for all server-only ACP frames, `agent-resolve-result` and every other current frame. Dispatch by these six discriminants rather than an `acp-` prefix. With a workspace, preserve each existing method and argument, resolving tasks against its main `dir`. Without one, only `agent-resolve`, open and run emit `workspace-failed` with `No remote workspace has been provisioned.`; tool-result, close and cancel remain silent no-ops. A missing ACP record still follows `RemoteAcp`'s own existing behavior. No future `run-clone` discriminant or workspace-selector property appears in this module.

7. In `RemoteServer`, replace the four separate provisioned directory/process/file/ACP fields with one `ProvisionedWorkspace` field. Update their existing consumers in dispatch, attach, spawn, settleAt callbacks, detach and shutdown to read that owner; retain the root and `WorkspaceManager` fields. Pass the guarded `decodeFrame` result directly to `dispatchAcpFrame` immediately after successful decoding, without a `ClientFrame` assertion or a decoder change, then keep the existing non-ACP switch and its `Unexpected remote frame` default refusal. Remove the moved switch cases and direct resolver/ACP/process/file type imports rather than re-exporting anything. These specific changes reduce the current 196 counted lines before adding lifecycle coordination; keep serve.ts and both new modules at or below 200 counted lines without another extraction.

8. On shutdown, start `runClones.stop()` after setting `stopping` and before ACP disposal. Await both the pending clone drain and ACP disposal before the existing guarded `WorkspaceManager.removeAll`; run clones share that manager with the main clone. If ACP disposal returns false, preserve ready clones and the main workspace just as today. Keep shutdown's synchronous fast path when neither disposal nor clone drain is pending, its exit code and once-only behavior. For a provisioned peer, detach still clears the frame buffer, calls `acp.detachRuns()` and parks the peer: it does not stop the clone service, cancel its pending clones, release ready clones or add new cleanup frames. Preserve the existing rootless/relay detach-to-shutdown paths. A far side outliving a lost channel deliberately retains these clones until shutdown. Record the service ownership, dispatcher extraction, pending drain and preserved detach/shutdown limits in `product/specs/remote-server.md`; do not describe later wire or selector support as shipped.
