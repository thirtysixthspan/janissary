## Decisions

### SQLite display is separate from action identity

- Set only SQLite `ownerName` to the exact lowercase literal `global`, for both attributed and unattributed databases. `global` is the owning-tab column value only: the live row's `display` and list title stay `sqlite:<name>`, and `ownerName` is never derived from the tab title. Keep one row per open database, kind `sqlite`, unchanged database id/display/status, existing ordering timestamp, and ordinary live-row guards/schema.
- Preserve `ownerLabel` as the first attributed tab label, or the empty string when none is attributed. Preserve `focusTarget` as that same first attributed label, or absent. Never set either field to `global` to match the display. First means index order in `managers.tab.tabs` (strip order), not most recent activity or the active tab.
- Opening through a row intent or `connection[s] sqlite:<name>` still focuses that first attributed tab. An unattributed row still resolves successfully with `ownerLabel: ''` and no `focusTarget`, so both open routes return without changing the active tab. Global close still works with that empty action owner because the SQLite branch of `closeConnection` ignores the label.
- Keep current-row validation and stale-owner no-ops: `actOnLive` matches kind, id, and `ownerLabel` against a freshly composed row, so a stale or invented owner (including `global`) is a silent no-op, not a rejection. After attribution or strip order changes, actions carrying the former owner must not act on a different current row. Display-only changes must not create an alternate action route or bypass validation.
- UI `close` keeps the current row's action owner; command `closeCommand` keeps the invoking tab's label. Both ultimately close the database app-wide through the existing owner and retain existing notification behavior. Do not rewrite either action implementation.

### Full argument lookup without a new command language

- Trim the argument's outer whitespace once, then use that same trimmed string for both first-token tokenization and the lookup branch. Return the entire trimmed argument, preserving case, punctuation, repeated interior spaces, and interior tabs. Do not split and rejoin a title or lowercase the returned text.
- Both `connection <text>` and `connections <text>` use this same full-text lookup. A generated `ACP: explain this test` title must reach `newestTitle` intact. Matching remains whole-title equality ignoring case, not prefix, substring, fuzzy, or whitespace-normalized equality. The lookup text is the complete stored title including its generated `ACP:` or `Agent:` prefix; do not strip or add a prefix. A title containing two spaces must not silently match one containing one space.
- Preserve exact UUID support before other lookup, existing invoking-tab `acp:<model>` resolution, then live kind/id resolution before title fallback. Include collisions in tests so a title cannot shadow an existing target. A title containing a colon still reaches title fallback if its target interpretation finds nothing.
- Keep `acpRecordForOwner`'s existing `Idle`/`Running` eligibility and `newestTitle`'s status-agnostic, owner-agnostic search: a closed record or another tab's record can still win the title fallback. Keep `newestTitle`'s descending `updatedAt` comparator and the stable topic-row order for equal timestamps; do not add a tie-break or narrow lookup to open core ACP records.
- Keep reserved first-token grammar unchanged: bare forms open/focus the centre list; plural `left`/`right` docks; singular `left`/`right` remains lookup text; both aliases recognize `list` and `close`. Existing ignored trailing arguments on list, close, and plural docking remain ignored, including `LEFT extra`, `list extra`, and `close sqlite:id trailing`. Those compatibility rules do not justify truncating arbitrary lookup text.
- Keep close errors verbatim: `Usage: connections close <kind>:<id>`, `Invalid connection "<target>". Expected <kind>:<id>, e.g. sqlite:mydb.`, `Unknown connection kind "<kind>". Expected one of: sqlite, shell, acp, browser, ssh, terminal.`, and `Missing id in "<target>".`. Parser errors remain command notes, not plugin failures.
- Lookup misses remain `rejectRequest` with exactly `No connection matching "<text>".` using the complete trimmed text, including its original interior whitespace and case. Preserve ordinary command comment handling upstream. Add no quotation, escaping, tokenization, title generation, or completion feature.
