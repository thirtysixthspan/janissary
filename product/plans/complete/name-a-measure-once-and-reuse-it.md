# Name a measure once and reuse it

A chart carried a raw column and an aggregate and nothing else, so every turn re-derived the same quantity however it liked. Two charts in one tab could disagree about what the headline number was, the user had no way to say which was right, and there was no artifact to correct — the only fix was another sentence, and the prompt's twelve-turn window would eventually have forgotten the first. A Tableau Pulse metric definition is documented as "the single source of truth for all the metrics based on" it, and Databricks Genie's guidance is that structured definitions beat prose because it "applies the logic exactly as written rather than interpreting it from natural language". Both are about the same failure.

- `VisualizationMetric` in `src/protocol/visualizations.ts`: a name, a column, an aggregate, an optional percentile, a note, and synonyms. The definition never reaches the browser — the chart arrives with the column and aggregate already resolved, and the name is all a caption needs beside them.
- `src/visualizations/metrics.ts` holds the whole rule. `isMetricName` bounds a name to something a person can type and read back in a caption, a sentence and a prompt. `metricOf` and `isMetricList` read a definition defensively; a list is bounded at twelve and a name must be unique case-insensitively, because matching is case-insensitive and two definitions answering to one word is a coin flip rather than a choice. `remembered` folds a reply's definitions into the record, *replacing* a definition of the same name — a user who says "actually p95 latency means the p99" is correcting a measure and expects every chart of it to move.
- `measured` in `src/visualizations/charts.ts` resolves a chart's `metric` before it is drawn and refuses an unknown name rather than falling back to whatever column the reply also typed. A chart that draws successfully and means something other than what was asked for is the one failure a chart cannot make, and a measure that resolves to a column this data does not have is the same failure one step later. The resolved `y`, `aggregate` and `percentile` are stored beside the name, so nothing downstream of `place` knows a metric exists.
- The prompt lists the definitions under their own heading, with the column, the reduction and the other words — and leaves out any whose column this data does not have, because a prompt offering a name that cannot be drawn is a prompt inviting a refusal.
- The caption names the measure, which is the only place a reader can tell two identically-drawn charts apart: one is the p95 and the other a mean of the same column.
- The reply contract gains `metrics` and a per-chart `metric`. Definitions are applied before the charts are placed, so one turn can introduce a measure and draw with it. The chart shape is still required alongside the name, and the name wins.

`src/visualizations/metrics.test.ts` covers name shape and trimming, a definition read, synonym bounds, case-insensitive matching, both refusals, the replacement, the guard, and the prompt's three forms. `src/visualizations/store.test.ts` covers the round trip and a record that cannot be read back. `src/visualizations/agent.test.ts` covers a turn that defines a measure and a later turn that charts it, and the refusal of a name that does not exist. `src/visualizations/prompts.test.ts` covers the listing and the omission. `VisualizationChartCard.test.tsx` covers the caption. The spec gains a paragraph.
