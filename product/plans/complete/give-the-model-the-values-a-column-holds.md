# Give the model the values a column holds, and a way to ask which one was meant

`SAMPLE_ROWS` gave the model eight rows and nothing else, so a filter value was a guess: a request for "New York" against a `state` column is a coin flip, and a value differing by one character from every real value produced a chart with no marks — which, now that a mistyped value is refused rather than silently matched to nothing, is a refusal that blames the value instead of asking the question. Looker's agent calls sample data and fuzzy search against a field's values before composing a filter, with the reason stated concretely: "if the user asks for 'NY,' is that the City field or a State field? The agent may need to sample the data". QuickSight answers an unreadable value with a list of the interpretations it considered.

Two halves, because the model guessing and the model asking are different failures.

- `distinctValuesOf` in `src/visualizations/table.ts` lists what a column holds, in first-seen order, capped at twenty-four with the cap *stated* in the sentence beside the list — a list that stops quietly reads as the whole column, and a filter on a value that was never shown is a filter the model had no way to pick. A numeric column lists nothing: a measure is read off a chart and a column of numbers is not a vocabulary. An empty cell is a value of its own, said as `(empty)`, because "which regions have no data" is a question. It is computed when the prompt is built rather than stored, because the dataset table is already there and a per-column vocabulary would be disk for nothing.
- `clarify` in the reply contract is a question and up to four readings, bounded like the suggestions because a row of buttons is a row of buttons however many reasons there are for asking. It lives on the record, so it survives the next turn, and each reply replaces it — a second question while the first is unanswered is a conversation nobody can follow. `VisualizationChat.tsx` renders it as the suggestion row with the question above it, because it is the same shape of interaction, and a chosen reading is sent as an ordinary message, so answering it needs nothing new.

`src/visualizations/table.test.ts` covers first-seen order, the empty cell, a numeric column listing nothing, the cap and its note, and a column that is not there. `src/visualizations/prompts.test.ts` covers the listing, the absence of a measure's values, the note when a column is truncated, and the clarification's own parse rules. `src/visualizations/agent.test.ts` covers a question kept and then replaced. `VisualizationTab.test.tsx` covers the question rendering, a reading sending its own text, and the absence of the row when nothing is outstanding. The spec gains two paragraphs.

While wiring this, `store.ts` was over the file-size limit, so the workspace directories and their trust entry moved to `src/visualizations/store-workspace.ts`, and the chart-room arithmetic moved to `roomFor` in `charts.ts`. Neither is a change of behaviour; both are the extraction the size limit asks for rather than a compaction.
