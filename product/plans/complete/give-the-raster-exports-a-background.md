# Give the raster exports a background, which the code says they already have

`pixelsOf` in `web/src/plugins/visualizations/export/download.ts` set the fill from `getComputedStyle(svg).backgroundColor || '#ffffff'`, under a comment saying the page colour is laid down first because an exported chart with a transparent background looks broken in a viewer. Nothing gives an `svg` a background, so the computed value is `rgba(0, 0, 0, 0)` — which is truthy, so the `||` fallback never fired and the fill painted nothing. The default theme is dark, so a near-white title, tick and axis line landed on a transparent or white page and was effectively invisible, while the comment claimed the opposite was prevented. The style contract pins the custom-property list, and `--bg` is the first entry on it, so the value was in hand: the code just never asked for it.

- `backgroundOf` is the choice, stated once: the theme's own `--bg`, trimmed, or `#ffffff` when the theme declares nothing that can be painted with. It takes the style object rather than an element so it is a pure function, and a fill is not asked to decide a theme.
- Transparent is refused as well as empty. A theme may set `--bg: transparent` deliberately, for a surface that is dark whatever is behind it, and an exported file has no such surface — it lands in a viewer that draws white, which is the failure the line exists to prevent.
- Everything else in the module is unchanged. The colour is the same for PNG and PDF, and the vector export was never affected: an SVG carries its own resolved properties, and a background is a raster concern.

`web/src/plugins/visualizations/export/download.test.ts` is new and asserts the resolved `--bg` is used rather than the element's computed colour, that a declared value arrives without the whitespace a stylesheet gives it (a fillStyle of ` #101014` is not a colour the canvas accepts), that an absent or blank background falls back to white, that a transparent one does too, and that a value the canvas can paint with is kept as written.
