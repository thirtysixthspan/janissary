# Specify AI personas by role and move persona queries onto the core ACP pipeline

**Complexity: 7/10** — ~280 added lines across 32 production files, 13 requirements and 22 test scenarios, driven by replacing the persona format, widening core role names to custom roles, and moving both monitor and editor sessions onto the core ACP pipeline (p=7.37).

## Goal

AI persona files name a role on their first line instead of pinning a harness, model and variant plus a tools line. The role a persona names is the role of the ACP connection its query uses, and both monitor and editor persona queries run on the same core ACP pipeline that `ask` and `tell` use. The feature text is: "AI personas should specify a role instead of a model and tools. When the persona is used, the role must be used in the acp connection. Migrate editor agent support to the same acp pipeline that the ask and tell commands use."

## Requirements

1. "AI personas should specify a role instead of a model and tools." The first line is `[//]: # role:<name>` and no second config line is recognised; a missing directive throws `Persona "<name>" has no role directive. First line must be: [//]: # role:<name>.` and an empty one throws `Persona "<name>" has a malformed role directive.` (`src/persona-parsing.ts:3`).
2. "When the persona is used, the role must be used in the acp connection." The resolved `persona.role` is passed to `managers.acp.promptResult` at both the editor and monitor call sites (`src/editor-suggest/handler.ts:70`, `src/monitor/live-monitors.ts:118`).
3. "Migrate editor agent support to the same acp pipeline that the ask and tell commands use." Editor queries run through `AcpManager.promptResult` under the owning tab's label with `appendRefusalToTranscript: false` (`src/editor-suggest/handler.ts:70`).
4. "Fail persona load with an error" — an unknown role throws `Unknown role "<role>" in persona "<name>".` and opens no connection (`src/acp/ask-role.ts:85`).
5. "Fail the persona load" — a role whose entries are empty or all disabled throws `ACP: the <role> role lists no models.` before any connection opens (`src/acp/ask-role.ts:88`).
6. "Role-worded parallel strings": the four exact messages in Requirements 1, 4 and 5, plus the launcher reader's `ai/personas/launcher/summarizer.md has no role directive. First line must be: [//]: # role:<name>.` (`src/plugins/launcher/persona.ts:28`).
7. "Reuse the core refusal" — a persona query fired while that role's core prompt is active settles with `ACP: a prompt is already running.` and surfaces through the existing per-consumer failure notification; the active prompt is untouched. ACP sessions are per tab, so the collision is confined to one tab.
8. "Widen core to custom role names" — any role from the roles file in effect owns a core session. `AcpRole` is `string` (`src/acp/role.ts:3`), a leading role word is stripped by `afterRolePrefix` without interpolating a regex (`src/acp/role.ts:9`), the catalog enumerates roles-file names, the plugin mirror guards and ACP-record validation accept any non-empty role name, and `ask`/`tell` keep working unchanged. The two core client RPC decoders, `openAcpTranscript` and `openConnectionRecord`, validate the tab-scoped `acpRef.role` by trimmed non-empty shape instead of `ACP_ROLES` membership (`src/client-params/core.ts`), and the now-unused import is gone, so a custom-role row opens its own transcript and record.
9. "Extend generic close to any role" — `connections close acp:<role>:<model>` resolves any roles-file role (`src/connection/close.ts:16`), the row keeps the `acp:<role>:<provider/model>` form, an unrecognized id still falls back to `ask`, and no reset command or per-persona close target is added. Tab close settles and closes every core role held by that tab, including custom roles: `closeTab` snapshots the label's held role keys before the settlement callback deletes them (`src/acp/session-manager.ts:156`), and `closeAll`/`dispose` inherit it.
10. "All shipped personas use ask" — each of the eight files under `ai/personas/` starts with `[//]: # role:ask` and carries no tools line; `link-scout` keeps web access through the `ask` role's `web search` and `web fetch` grants.
11. "Drop persona rows; reuse core role rows" — a persona query uses the tab's existing core role row; there is no `<persona> (acp)` row, no editor-scope `AcpRef`, no `closeEditorConnection` route and no persona-specific close control.
12. "Monitors on the core pipeline" — every monitor prompt goes through the core role session; `spawnMonitorSession` and `src/monitor/acp.ts` are deleted; monitors are addressed by name-only `monitor:<name>` handle rows; stopping leaves the tab's core session alone; a reporting-tab reset closes that core session and re-primes the next prompt. `MonitorSub.coreSession` records the identity of the core session that last answered a flush: a later answered result with a different identity is the one reply from a replaced session, so it is discarded and the new session is re-primed on the next flush. A reset clears the recorded identity so the first flush on the fresh session delivers its suggestion, and a `resetGeneration` guard discards any result that settles after a reset on both the failed and successful paths, keeping the false `ACP session closed.` error line silent and the re-primed primer intact.
13. "Clean up the delivered shape" — the legacy `PersonaHarness` type lives locally in `src/acp/launch.ts:14` beside `acpLaunchFor`; editor-suggest test mocks use `{ name, role, body }`; the model manager is bound at both validation call sites; stale `editorAcp` fields are gone from test fixtures; the monitor-stop fixture uses the delivered `{ name, role, body }` persona shape (`src/monitor/stop.test.ts`); the behavior specs describe the delivered routing, and the pull request title and description were reconciled with it.

## Design decisions

- The persona's first line becomes `[//]: # role:<name>` ("role:<name> via roles.json"), replacing the harness/model/variant triple. `parseRoleDirective` is the only parser in `src/persona-parsing.ts`; `loadPersona` stays a pure file parser returning `{ name, role, body }` (`src/personas.ts:13`).
- Role resolution lives in `resolvePersonaRole` (`src/acp/ask-role.ts:80`), which calls `knownRoleSettings` — `readRoleSettings` is not used for this decision because it hides unknown names behind built-in defaults. Both call sites pass a bound wrapper, `(harness, model) => managers.models.isKnownModel(harness, model)`, so the catalog method keeps its receiver; a receiver-dependent stub test at each call site pins the regression.
- Old-format persona files are a hard break: only the eight shipped files were rewritten, with no compatibility shim, auto-migration or dual-format parser. Only the bodies are returned by the launcher's independent reader, which validates the same directive with launcher-worded errors and opens no connection.
- All three persona kinds use the role directive: `monitor`, `editor` and the launcher summarizer. Web tools now come from the role's `commands`, not a persona-file tools line.
- `AcpRole = string` keeps `'ask' | 'tell'` assignable; `ACP_ROLES` and `DEFAULT_ACP_ROLE = 'ask'` stay as built-in defaults. Prompt-prefix handling is a literal case-insensitive prefix plus word boundary, not an interpolated `RegExp`, so user-edited role names cannot trip `security/detect-unsafe-regex`. Where a role crosses the websocket ingress boundary, `openAcpTranscript` and `openConnectionRecord` accept a trimmed non-empty string rather than checking `ACP_ROLES` membership (`src/client-params/core.ts`), because the valid names come from the user's roles file; the `AcpRef` union is now two arms, tab and monitor, and every other discriminant check is unchanged.
- Core teardown is driven by the label's own held role map, not the built-in list: `closeTab` snapshots `this.sessions.get(label)?.keys()` before `close` settles sessions through `deleteSession`, so a custom role is killed alongside `ask` and `tell` while `close`, `closeAll` and `dispose` keep their own behavior.
- Persona queries and flushes use one core prompt per role; an overlap is settled by the core refusal and no queue or cancellation path is added. The persona body, hunk format, buffer block and request line are sent on every editor query; the role's own primer replaces the old per-persona priming and tool loop.
- The editor's `EditorAcpManager`, editor-scope `AcpRef`, transcript branch and `closeEditorConnection` message were removed end to end after both consumers moved off the old path; the client's connections panel is read-only for core rows.
- A monitor keeps its own framing, feeds, context snapshot and suggestion parsing. `MonitorSub` carries two pieces of session state: `resetGeneration`, which `reset` increments before closing the core session while each flush captures the value at send time, and the optional `coreSession`, the identity of the core session that answered the last flush. A generation mismatch discards a result that settled after a reset on both the failed path (no spurious error line or rate-limit notification) and the successful path (no stale suggestion, primer kept). A `coreSession` mismatch means another surface closed and reopened the shared role session: that one reply is dropped, the new identity adopted and the primer restored for the next flush. `reset` deletes `coreSession` alongside the first-prompt re-prime so the first flush on the fresh session seeds the new identity and delivers normally. The name-only `monitor:<name>` row still stops a monitor through `connections close monitor:<name>`.
- The legacy `PersonaHarness` type was relocated from the parser to `src/acp/launch.ts`, its only consumer; `acpLaunchFor`'s shape is unchanged.
- Documentation work is one follow-up feature candidate for the prose documentation page only. No `documentation/` file, in-app help page or key-binding row is written here.
- The pull request text was reconciled with the delivered code: the title uses a `feat` Conventional Commit type naming the feature; the description's close step names only `connections close acp:<role>:<provider/model>` and notes the editor window is read-only, and no change-set count is stated. The `acp.md` and `connection.md` prose was corrected for core-session monitor routing, the permission approvers, and the editor row's read-only close behavior.
- CI repair: the once-stale `role as AcpRole` cast in `resolvePersonaRole` was removed after `AcpRole` widened, and the shell history-recall test now dispatches its chord inside `act()` and awaits each selection move so the popup's effect-registered listener is live under CI timing.

## Preserved behavior

1. The query line opens when `>` is typed at the very start of an otherwise-empty line — not mid-line or on a line holding text — pinned by `web/src/editor/handleSuggestKeyDown.test.ts` ("opens the query line when > is typed as the first character of an empty line").
2. Enter, Ctrl+Enter (Cmd+Enter on macOS) and the `run` pill fire a runnable query without inserting a buffer newline — pinned by `web/src/editor/handleSuggestKeyDown.test.ts` ("fires on Enter when the query is runnable and never inserts a buffer newline").
3. The status pill keeps its labels and ordering — `agent?`, `query?`, `run`, `running...`, `no suggestion` — pinned by `web/src/editor/suggest-request.test.ts` ("shows agent? when no known persona is named yet").
4. Tab completes a persona name in the query text and yields to the pill once the request is runnable — pinned by `web/src/editor/handleSuggestKeyDown.test.ts` ("focuses the pill on Tab in priority over completion once the request is runnable").

## Assumptions

1. Personas are markdown files under `ai/personas/<kind>/`, named by filename, whose first line is a required role directive (`src/personas.ts:4-7`).
2. Role names are user-authored free text from the roles file in effect, project over home, read without creating a file (`src/plugins/roles/roles-file.ts`), so they are never interpolated into a regular expression.
3. Core sessions are per tab and per role (`src/acp/role-state.ts`); `managers.acp` owns `promptResult` (`src/managers.ts`).
4. `appendRefusalToTranscript: false` keeps a persona refusal in the `<persona>: <message>` notification rather than the transcript (`src/editor-suggest/handler.ts:70`).
5. A role's `entries` carry harness, model and optional effort; `commands` supply its native ACP grants and its web tools (`src/plugins/roles/shared.ts`, `src/plugins/roles/default-roles.ts`).
6. Editor in-buffer queries are typed `> <persona> <prompt>` and offer the editor-specific persona set (`product/specs/editor-tab.md`).

## Existing functionality

2. `AcpManager.promptResult` / `AcpManager.run` in `src/acp/manager.ts` and `afterRolePrefix` in `src/acp/role.ts` own the generic core prompt path for any role.
3. `readRolesFile` in `src/plugins/roles/roles-file.ts` resolves project over home without creating a file; `isKnownModel` in `src/models/manager.ts` filters disabled catalog entries.
4. `connectionCatalog` in `src/connection/catalog.ts` and `closeConnection` in `src/connection/close.ts` are the single list and close router for every connection surface.
5. `monitorFirstPrompt`, `frameUpdatePrompt`, `recordContext`, `recordReply` and `parseSuggestion` keep the monitor's framing, context and suggestion behavior unchanged while the transport is now core ACP.
6. `parseHunks` in `src/editor-suggest/reply-format.ts`, `notify` in `src/notifications/index.ts` and the unchanged web query-line components carry the editor result and failure reporting.

## Implementation steps

1. The parser and loader were changed first: `parseRoleDirective` replaced the harness/tools parser, `Persona` became `{ name, role, body }`, the eight shipped files were rewritten to `[//]: # role:ask` with no tools line, and the launcher reader was updated to the same directive with its own error wording while still returning only the body. `src/monitor/acp.ts` was later deleted; the legacy `PersonaHarness` type lives locally in `src/acp/launch.ts` beside `acpLaunchFor`.
2. `resolvePersonaRole` was added to `src/acp/ask-role.ts` and called from `editorSuggest` and `MonitorManager.start` before any connection opens, with a bound `isKnownModel` wrapper at both call sites and receiver-dependent regression tests.
3. Both consumers moved onto the core pipeline: editor queries call `managers.acp.promptResult` with the full prompt on every request; monitor flushes and asks call `managers.acp.promptResult` with the role and framed first prompt. `spawnMonitorSession`, its session/priming/respawn scaffolding and `MonitorSub.session` were removed; stopping a monitor only clears its own timers and subscriptions, and a reset closes the core session and re-primes. Monitor results are guarded by `resetGeneration` on both the failed and successful paths, and by the optional `coreSession` identity that detects a replaced session, discards its one reply and re-primes the new session; `reset` clears that identity so the first post-reset flush delivers on the fresh session.
4. `AcpRole` was widened to `string`; `afterRolePrefix`, the catalog's roles-file enumeration, the two plugin mirror guards and ACP-record validation accept any role name; `coreAcpTarget` resolves any roles-file role for `connections close acp:<role>:<model>` while keeping the legacy `ask` fallback and adding no reset command. The `openAcpTranscript` and `openConnectionRecord` decoders accept a trimmed non-empty role instead of `ACP_ROLES` membership, and `closeTab` tears down every held role from a snapshot of the label's role keys so custom-role subprocesses are killed with the built-ins.
5. Dead plumbing was removed: `EditorAcpManager`, its construction in `create-managers.ts`, the editor-scope `AcpRef` branches, `closeEditorConnection` end to end, the client-scope close handler, and stale `editorAcp`/`harness`/`tools` test fixtures. The four preserved-behavior web tests were left untouched.
6. The behavior specs were reconciled with the delivered routing, web tools as role grants, core role rows, generic close and the reset/lifecycle rules, including the `acp.md` monitor-session and permission-approver paragraphs and the read-only close claim in `connection.md`. The pull request title and description were brought in line with the delivered feature. The CI build was repaired by removing the stale type cast and making the shell history-recall test deterministic.

## UI design

1. Editor in-buffer persona queries remain on the ephemeral query line, with the persona name after `>`; this is the surface the feature operates on.
2. The connections window shows the tab's core `acp:<role>:<provider/model>` row used by the query — no `<persona> (acp)` row and no persona-specific close control. A monitor is addressed by a name-only `monitor:<name>` handle row.
3. Dismissal uses the generic core path: `connections close acp:<role>:<model>`, or the core row's existing Close control on surfaces that render one such as the connections tab; the editor connections window is read-only for core rows. No binding is added, so `help/keys.md` gains no entry.
4. Failures surface through notifications using the existing `<persona>: <message>` wording; the pill falls back to `no suggestion` and the query line stays open with its text for retry.
5. Visuals are unchanged: `EditorLine` keeps `editor-row-query`, the `editor-suggest-pill` badge keeps its style, and core rows keep their existing style; no new CSS or badge.
