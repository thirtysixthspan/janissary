# Connections list tab UI

**Complexity: 5/10** — a mixed-kind list UI plus one additive server intent for opening agent records, with row-specific actions, keyboard behavior, and lazy-bundle boundaries.

## Goal

Deliver the lazy client entry and the interactive singleton Connections list. Show the authoritative cross-kind rows, support keyboard and two-click opening, and expose the correct live close, tracked ACP close, and closed-record delete controls.

## Decisions and reuse

- Render `payload.rows` in exactly the order received. The server's `composeConnectionsTopicData` (`src/plugins/connections-topic-rows.ts:21`, `rows.sort`) supplies descending `orderingTimestamp` and deterministic kind/id tie order. Do not sort, reconstruct catalog rows, derive ownership, or calculate recency/status in the client.
- Render a live row's `display`, `kind`, `ownerName`, and `Open`; render a record row's `title`, `kind`, `ownerName`, and its supplied status. The shared payload guard in `src/plugins/connections/shared.ts:102`, `isConnectionRow`, requires these fields and status values. Empty text is exactly `No connections yet`.
- Opening live rows and core-ACP record rows sends the `open` intent with `{ kind, id }`; closing a row sends `close` with `{ kind, id }`. Do not send an owner label from the browser: `src/plugins/connections/activate.ts:46`, `intent`, re-resolves the current row from topic data and supplies its authoritative owner to the topic action. A live SQLite row is one per open database; its host-provided owner/focus behavior, including no-op when unattributed, is authoritative.
- Provide row close controls on all live rows, including monitor/editor-persona ACP rows, and on tracked core ACP records only while status is `Running` or `Idle`. A `close` intent on a record is resolved by 04a to `closeSession` for an open core ACP row. A `Closed` ACP record exposes a delete control only after confirmation text exactly `Delete "<title>"?`, with Delete and Cancel; its confirmed `close` intent is resolved against the current row and deletes the closed record. Agent record rows have no list action control. Do not offer deletion for non-closed records.
- Agent record rows still open on Enter or their second click. The 04a `open` intent accepts only `ConnectionKind` values (`src/plugins/connections/shared.ts:48`, `ConnectionsIntent`, and `:133`, `isKindIdIntent`), while agent rows have `kind: 'agent'`; add an `open-record` intent carrying only `{ id }`, validate it against current topic data as a record row, and open it through `ConnectionTabs.openRecord`. Do not weaken the live-row `open` guard or trust a client-supplied owner. This additive plugin-local intent is required by the authoritative source plan's agent-row opening behavior.
- List keyboard behavior matches the conversations list: focus while active, Up/Down/Home/End without wrapping, Enter opens the selected row, and mouse opening takes two clicks on the same row. Selection confirmation is keyed to stable row identity, not just array index: a topic update that reorders/replaces rows of the same length must not let a stale confirmation open a different row. Clear confirmation on keyboard navigation and when row identity/order changes. Row action buttons stop propagation so they cannot select or open the row.
- Route all list operations through `useConnectionsController` and plugin intents. Keep only ephemeral selection and delete-confirmation state in the browser; the server topic remains authoritative for stale/racing actions. Use the published `ConnectionsPayload`, `ConnectionsIntent`, and row types through the shared `@shared/plugins/connections/shared` contract; never redeclare wire/payload shapes.
- Reuse host `useListSelection` and `ConfirmDialog` from `web/src/plugins/api.ts`, and the conversations interaction precedent at `web/src/plugins/conversations/ConversationList.tsx:22`, `useListSelection`, and `:31`, `onKeyDown`. Keep implementation under `web/src/plugins/connections/`, import directly, and do not import from the conversations feature. Keep every production module under ESLint's 200 counted-line limit by extracting focused modules.
- Keep the component thin and decisions testable in `connection-list-keys.ts` or the controller adapter, following the shared → feature → app dependency direction. Import `../shared.css` and the feature stylesheet from the lazy entry; scope list styles to connections classes and do not reach into another feature's stylesheet.
