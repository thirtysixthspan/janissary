# Web search 7: the far side's `web-search` remote filesystem operation

**Complexity: 6/10** — ~50 added lines across 6 edited files plus one new module, 8 requirements, 24 test scenarios driven by the argument-validation table (p=6.05)

The seventh slice of the `web search` feature (source plan: `./product/plans/complete/web-search.md`). It adds the far-side half of a remote tab's typed search: a new path-free `web-search` read operation in `READ_OPERATIONS` that validates the parsed query and flags, runs `webSearch` on the remote machine with the workspace's tokens from the operation context, and returns `{ text }`. The operation context gains `tokens`, and `RemoteFileNavigators` takes them as a new constructor parameter. The protocol version moves only once for the whole feature: `./product/plans/complete/web-search-3-provider-tokens.md` already sets `REMOTE_PROTOCOL_VERSION` to 43, and this slice extends that version's comment and spec paragraph to name the `web-search` operation and the tokens on the operation context, so an older peer is refused at the handshake. The near side's port method and the provisioning wiring that hands real tokens to the context follow in `./product/plans/complete/web-search-8-remote-port.md`.

## Design decisions

Carried from the source plan where they apply.

- **Remote transport for a typed search (user decision).** A new path-free `web-search` read operation in `READ_OPERATIONS` (`src/remote/filesystem/operations.ts`), shaped like `git-pull` and `search`, carries the parsed query and flags and returns `{ text }`. The far side's operation context gains the workspace's merged token set.
- **One protocol bump for the feature (orchestrator decision).** The source plan says `REMOTE_PROTOCOL_VERSION` "goes up by one" for the feature. Slice 3 already takes it 42 → 43 for the two new token names, and all slices ship on one pull request, so this slice does **not** bump it again. It extends slice 3's version-43 comment in `src/remote/protocol.ts` and slice 3's "Protocol version 43 adds…" paragraph in `product/specs/remote-server.md` to also name the `web-search` operation and the tokens on the operation context. `src/remote/protocol.test.ts`'s version assertion stays at 43 as slice 3 left it. A version-42 remote would refuse `web-search` as an unknown operation after the handshake had passed, so the exact-version handshake refusing 42 is what protects this operation too.
- **Argument type (decision).** The `'web-search'` entry in `RemoteFilesystemArgumentsByOperation` (`src/remote/protocol-frames.ts`) is `WebSearchCommand` itself, imported as a type from `../web-search/command.js` beside the existing `import type { SearchRequest } from '../protocol.js'`. Slice 1 makes `WebSearchCommand` the one shape the core, this operation, and the typed command pass around, so the wire type cannot drift from the parser's output. All five fields are required; no field is optional on the wire, because `parseWebSearch` fills in every default.
- **Validation (decision).** `valid` accepts exactly when: `query` passes `nonEmptyString` (`src/remote/frame/decode-shared.ts`, length > 0; whitespace-only is not checked, since the parser never produces it); `numResults` is a safe integer from `WEB_SEARCH_MIN_RESULTS` to `WEB_SEARCH_MAX_RESULTS`; `maxChars` is a safe integer from `WEB_SEARCH_MIN_CHARS` to `WEB_SEARCH_MAX_CHARS`; `depth` is exactly `'basic'` or `'advanced'` (case-sensitive on the wire, because the parser lower-cases it); and `provider` is a string (`stringValue` from `./argument-checks.js`). `provider` is not checked against the provider names: an unknown name reaches `webSearch`, whose registry answers with the unknown-provider line listing the far side's names, so the line comes from the host whose catalog it describes. Extra keys are ignored by `valid`, as `globPathsOperation` ignores them.
- **Decoding (decision).** `decode` returns a fresh object with exactly the five fields, each through a `require…` helper that throws `'Invalid remote filesystem operation arguments.'` on a bad value — the same constant and shape as `requireLimit` in `src/remote/filesystem/glob-paths-operation.ts` — so an extra key in the frame never reaches `webSearch`. The integer check is written like `globLimit` there (`Number.isSafeInteger` plus the bounds), taking the bounds as parameters so one helper serves both ranges.
- **Descriptor shape.** Built with `descriptorFor<'web-search'>()` from `src/remote/filesystem/operation-types.ts`; `paths: () => []` (no path to contain, so `refusedPaths` in `src/remote/filesystem/refusal.ts` never refuses it); no `rootDestination`; no `refusal` (the `{ text }` result has no failure channel, so — like `glob-paths` and `read-lines` — a near-side send that cannot go out throws its connection reason through `unavailableResult` in `src/file-navigator/remote/port-requests.ts` rather than returning a value).
- **Far-side fetch and notifications.** `run` is `async` and returns `{ text: await webSearch(args, { tokens: context.tokens, fetch }) }`, passing the global `fetch`, no `signal` (a typed search is not cancellable), and no `reportDisabled`: on a remote machine a provider that fails as a plugin is disabled in the far-side process and its reason appears only in the failure lines, since the far side has no notifications tab. A rejection from `webSearch` (none is expected without a signal) becomes the request's error reply through the existing `.then(…, (error) => this.reply(frame, undefined, errorText(error)))` in `RemoteFileNavigators.request`; no new error path.
- **Result decoder.** `resultDecoders['web-search']` in `src/remote/filesystem/result-decoders.ts` accepts a record whose `text` is a non-empty string, and otherwise throws `'Invalid remote filesystem operation result.'` via the existing `decodeResult`. It is written beside `'glob-paths'` (`record(value) && typeof value.text === 'string'`) with the added length check, because `webSearch` always returns at least one line (results, a failure line, or `No results for "<query>".`).
- **Registration and the 200-line limit.** `src/remote/filesystem/operations.ts` is at 196 counted lines (ESLint `max-lines` with `skipBlankLines`/`skipComments`); the change is one import line and one `'web-search': webSearchOperation,` entry placed after `'glob-paths': globPathsOperation,`, giving 198. No other web-search slice edits this file. If the count would still pass 200 when this lands, move the `READ_OPERATIONS` table into a new `src/remote/filesystem/read-operations.ts` exporting it, imported by `operations.ts`, rather than compacting code.
- **Operation context.** `OperationContext` (`src/remote/filesystem/operation-types.ts`) gains `tokens: ProjectTokens` (type import from `../../project/tokens.js`). `RemoteFileNavigators` (`src/remote/serve-file-navigator.ts`) takes it as a new fourth constructor parameter `private tokens: ProjectTokens = {}` after `filesystem`, and `context(session)` adds `tokens: this.tokens`. The default keeps every existing caller compiling and unchanged: `src/remote/serve-provision.ts:99` (`new RemoteFileNavigators(emit, result.dir)`, wired with real tokens in slice 8), `src/remote/serve-file-navigator.test.ts`, and `src/remote/file-navigator-refusal-contract.test.ts`.
- **Where a typed search runs (user decision).** A remote tab's typed search runs on the remote machine with that host's merged tokens, so a person and an agent in the same tab get the same providers and tokens.
- **Near-side load cost.** `operations.ts` is also imported on the near side (`decodeFilesystemResult` in `src/file-navigator/remote/port-requests.ts`), so the new import loads `src/web-search/search.ts` and its manifest catalog there too. That is acceptable: slice 5's manifests import provider modules only on `activate`, as `glob-paths-operation.ts` already pulls `globWorkspace` into the same graph.

## Proposed changes

- **`src/remote/filesystem/web-search-operation.ts`** (new, ~35 lines) — exports `webSearchOperation`, the descriptor decided above, plus module-private helpers for the bounded integer check (valid and require forms, bounds as parameters) and the depth check (`'basic' | 'advanced'`, returning `WebSearchDepth`). Imports `descriptorFor` from `./operation-types.js`, `resultDecoders` from `./result-decoders.js`, `stringValue`/`requireString` from `./argument-checks.js`, `nonEmptyString` from `../frame/decode-shared.js`, the four range constants and the `WebSearchDepth` type from `../../web-search/command.js`, and `webSearch` from `../../web-search/search.js` — every relative import with `.js`.
- **`src/remote/filesystem/operations.ts`** — `import { webSearchOperation } from './web-search-operation.js';` and the `'web-search'` entry in `READ_OPERATIONS` after `'glob-paths'`.
- **`src/remote/protocol-frames.ts`** — `'web-search'` appended to the `RemoteFilesystemOperation` union after `'glob-paths'`; `'web-search': WebSearchCommand;` in `RemoteFilesystemArgumentsByOperation` after the `'glob-paths'` line; the type import.
- **`src/remote/filesystem/result-decoders.ts`** — the `'web-search'` decoder after `'glob-paths'`.
- **`src/remote/filesystem/operation-types.ts`** — `tokens: ProjectTokens` on `OperationContext`.
- **`src/remote/serve-file-navigator.ts`** — fourth constructor parameter `tokens: ProjectTokens = {}`, placed on the context.
- **`src/remote/protocol.ts`** — `REMOTE_PROTOCOL_VERSION` stays 43. Append to slice 3's version-43 comment, in the voice of the version-42 one: version 43 also adds the read-only, path-free `web-search` operation, so a typed `web search` on a remote tab runs on the remote machine with that workspace's tokens, which now travel on the far side's operation context; a version-42 remote would refuse it as unknown after the handshake had already passed, so the exact-version handshake refuses that pairing first.
- **`product/specs/remote-server.md`** — append to slice 3's "Protocol version 43 adds…" paragraph (after the version-42 paragraph): the same version adds `web-search`, the read-only, path-free filesystem operation behind a typed `web search` on a remote tab; it carries `query` (non-empty), `numResults` (1–20), `maxChars` (200–100000), `depth` (`basic` or `advanced`), and `provider`, and answers `{ text }` holding the rendered results or failure line; any other argument shape is an invalid request; the far side runs it with the merged token set of the workspace it serves (forwarded tokens win over the remote's own files), and a provider failure there is reported only in the failure lines.

## Tests

- **`src/remote/filesystem/operations.test.ts`** — `'web-search'` joins `ALL_OPERATIONS`; `PATH_CASES` gains `['web-search', { query: 'vitest', numResults: 10, maxChars: 10000, depth: 'basic', provider: 'auto' }, []]`; `VALID_RESULTS` (an exhaustive mapped type, so the file will not typecheck without it) gains `'web-search': { text: '1. [Vitest](https://vitest.dev)' }`; `INVALID_CASES` gains one row each for: missing `query`, `query: ''`, `query: 3`, `numResults` 0 / 21 / 1.5 / `'5'`, `maxChars` 199 / 100001, `depth: 'deep'`, `depth: 'Advanced'`, missing `provider`, `provider: 3`. A new `it` asserts both range edges are accepted (`numResults` 1 and 20, `maxChars` 200 and 100000, using the imported constants), that `decode` of a valid record plus an extra key returns exactly the five fields, and that `decode` of an invalid record throws `'Invalid remote filesystem operation arguments.'`. Another asserts the result decoder accepts `{ text: '…' }` and rejects `{}`, `{ text: 3 }`, and `{ text: '' }`, like the existing "rejects a glob-paths result without string text" case. The refusal-shape and root-destination lists stay unchanged (`web-search` is in neither), which those two existing tests now confirm.
- **`src/remote/serve-file-navigator.test.ts`** — `vi.mock('../web-search/search.js', …)` with a `webSearch` mock resolving to a fixed string. A navigator built with `{ tavily: 'tvly-key' }` as the fourth argument, after `open('files2')`, answers a `web-search` request with `{ result: { text: <the string> } }`, and the mock was called once with exactly the decoded command and deps whose `tokens` are that object, whose `fetch` is `globalThis.fetch`, and which have no `signal` and no `reportDisabled` key. A navigator built without the fourth argument passes `tokens: {}`. A mocked rejection becomes a `filesystem-reply` with `error` set to its message.
- **`src/remote/protocol.test.ts`** — the version assertion stays `toBe(43)` (slice 3's). "round-trips every client frame" gains a `filesystem-request` for `web-search` with valid arguments; the malformed-frame table gains `['filesystem request with out-of-range web search arguments', { type: 'filesystem-request', session: 'f1', request: 'q1', operation: 'web-search', args: { query: 'x', numResults: 0, maxChars: 10000, depth: 'basic', provider: 'auto' } }]`.
