# Remember instructions the user gives, and carry them in every prompt

`MAX_TURNS_IN_PROMPT` keeps the most recent twelve turns and nothing else, so every instruction the user has given the model is forgotten: "use the median, not the mean" or "always show region before service" is said once, works, and is silently dropped later in the same conversation — and neither the user nor the model can tell the difference between a forgotten instruction and one that was never followed. Power BI stores AI instructions on the model and injects them into every prompt, Databricks Genie supports per-agent general instructions plus a reserved trailing block for summary behaviour, and Hex has a workspace context file for the same reason.

- `instructions: string[]` on the record, guarded and bounded at ten in `store.ts`, because the list is prompt text on every turn and the bound is on what a conversation can accumulate rather than on what one message can say.
- `src/visualizations/instructions.ts` owns the whole rule. A rule is `remember: …` or `forget: …` **with the colon required** — a message that happens to begin "remember the first deploy of the day" is a question, and silently swallowing a question is worse than asking somebody to type one more character. A rule longer than 240 characters is a message for the same reason.
- `applied` puts the rule on the record and appends the turn that answers it, so the host doing something quietly is not a thing: the answer travels into the next prompt and a rule the user cannot check is a rule they will not trust. No model call is made — acknowledging a rule the host applied itself would cost a call and put a sentence in the exchange about something no model did.
- `forget` matches by containment rather than by equality, so a user forgetting "use the median" does not have to retype the rule as written, and a forget that matched nothing would leave them believing it had. It says what is still remembered instead.
- The rules are prepended to the chat prompt under a heading that says who set them, ahead of the conversation, with the conflict resolved in favour of the newer message: the user is the user, and they are here now. That ordering is the point — a model told a rule in the first message and then shown twelve turns that do not contain it has two sources of truth and no way to tell which is current.
- `VisualizationChat.tsx` lists them under the exchange, set apart from it and styled like the notices, because a standing instruction is a fact about the conversation rather than something having gone wrong. The tab still has no controls: the rules are typed.

`src/visualizations/instructions.test.ts` covers both commands, the required colon, a message that merely begins with the word, an empty and an over-long rule, adding without duplicating, the oldest going when full, and removal by containment and case. `src/visualizations/manager.test.ts` covers a rule applied without a model call, a rule reaching the next prompt, the forget, and a message beginning with the word being sent as a question. `src/visualizations/prompts.test.ts` covers the section and its absence. `VisualizationTab.test.tsx` covers the line on screen. The spec gains a paragraph.
