# Hold the stored-chart guard to the grammar's optional fields

`isChart` in `src/visualizations/chart-record.ts` checked `kind`, `aggregate`, `series` and the two labels as bare types and said nothing about `percentile`, `xUnit`, `stack` or `metric`, while the grammar in `src/visualizations/chart-spec.ts` is strict about all of them. Both file headers claim one grammar stated in three places; the third place was loose in exactly the fields the renderer reads rather than merely stores. A record read back from disk — or hand-edited — carrying `xUnit: 'fortnight'` passed the guard, reached `startOf`'s `default` branch and floored every row to the first of January: a chart that draws successfully and means something else. The same drift is what made four aggregates blank the tab earlier this cycle.

- `isOptionalShape` in `src/visualizations/chart-spec.ts` is the grammar's own answer to "is this optional half usable", exported as a boolean so a stored chart can ask rather than answer again. `isSpecified` calls it, and the four restated lines are gone, so the copy that can drift no longer exists.
- `metric` is checked with `isMetricName` — a metric is a name the conversation gave a column, so a stored chart naming something that is not a name would resolve to nothing when it was next drawn.

Two cases in `src/visualizations/store.test.ts`: one writing a record whose chart carries each of the wrong values in turn — an unknown `xUnit`, a `stack` the grammar has not got, a `percentile` beside an aggregate that is not one, an unknown `aggregate`, a metric that is not a name, an empty one — and asserting none of them reads back; one writing a chart carrying every field the grammar does have and asserting it reads back with them intact. The first fails against the previous guard, which accepted all of them.
