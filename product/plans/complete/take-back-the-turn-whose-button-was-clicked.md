# Take back the turn whose button was clicked, not the first that says the same thing

`reverted` in `src/visualizations/undo.ts` found its turn with `record.turns.find((one) => one.query === query)`, and the client sent only the query text, with a comment in `src/plugins/api-topics.ts` claiming a turn is identified by what it said and that a position moves as the conversation grows. Both halves of that are wrong. A position is the one thing that distinguishes two turns carrying the same sentence, whether re-sent or clicked twice from a re-offered row, and undoing under the second restored the state before the *first*: both charts vanished, the first turn's undo was consumed, and the second button stayed lit over a state that had never been on screen. The position does move as the conversation grows, and that is why it is read from the rendered turn's own index rather than from anything stored.

Reading the topic action while fixing this found the larger half: `actOnVisualizations` in `src/plugins/topics.ts` routed create, load, delete, send, cancel, setChartRefresh and refreshChart, and no undo at all. The action was published by the plugin and dropped by the host, so the button had never done anything end-to-end — the index was the second bug in a control that was already inert.

- The `undo` topic action carries an `index`, and `isUndoIntent` in `src/plugins/visualizations/intents.ts` guards it as a non-negative safe integer, which is what the browser's turn index is.
- `onUndo` in `web/src/plugins/visualizations/VisualizationChat.tsx` takes the index of the turn it is rendering, and `VisualizationTab.tsx` sends `{ index }`.
- `reverted` takes the index, looks the turn up by it, and refuses an index the record does not hold or a turn with nothing to take back, which returns false rather than restoring a second time.
- `actOnVisualizations` routes the action, and the routing case in `src/plugins/topics.test.ts` now includes it.

`src/visualizations/undo-revert.test.ts` is new: two turns with the same text, undoing the second, which restores the first chart rather than nothing at all; a refusal for an index past the end and for one already taken back; and a chart restored from a specification against a record holding newer rows, so it is shown the data the record holds now. The case for the button sits in `VisualizationTab.test.tsx`, clicking the second of two identical turns and asserting the intent carries index 1 — which fails against the previous wiring because the second button sent the first turn's position as nothing at all.
