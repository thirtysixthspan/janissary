# Add a `file grep` command for ACP ask and tell sessions

**Complexity: 7/10** — ~410 added lines, 17 files edited, 32 requirements, 45 test scenarios (p=8.09)

`file grep` lets a person or an autonomous ACP agent find where a pattern appears inside the workspace's files. Each matching line comes back as a path, a line number, and a short preview. `file glob` (delivered in `product/plans/complete/file-glob.md`) answers which paths exist; `file grep` answers what is inside them. An agent can then follow up with `file read --offset` or `file edit` on exactly the reported location. It joins `file read`, `file write`, `file edit`, and `file glob` as a subcommand of the existing `file` command and the existing ACP file tool. It runs against the same root those commands use: the local workspace, the launch directory, or a remote tab's remote clone. It never falls back to the local machine for a remote tab.

## Design decisions

Each decision comes from the feature text, from existing behavior ("from precedent"), or from a user answer ("user decision").

- **Built on the delivered `file glob` (user decision).** `file glob` landed first, and `file grep` slots in after it everywhere the two share a list: the native vocabulary, the default grants, the primer, completion, and the remote protocol version, which moves from 42 to 43.
- **Command name (feature text).** `file grep`, a subcommand of the existing `file` command (`src/commands/file.ts`).
- **Who can run it (feature text).** It is a native ACP command granted by default to the built-in `ask` and `tell` roles. It is also a typed application command, matching `file read` and `file glob`.
- **Syntax (user decision).** `file grep [--literal] [--word] [--case-sensitive] [--path <path>] [--include <globs>] [--exclude <globs>] [--limit <n>] [--] <pattern>`. Flags come first, in any order, and each may appear once. The first token that isn't one of these flags starts the pattern, and the pattern is the rest of the line from there, internal spaces kept exactly as typed. So `file grep --literal request timed out` searches for `request timed out`. Surrounding whitespace on the line is trimmed. Each flag value is one whitespace-free token, and a value that starts with `--` is read as a missing value, which prints the usage line.
- **Dash-led patterns (user decision).** A `--` token ends the flags, and everything after it is the pattern: `file grep --literal -- --limit` searches for `--limit`. Without `--`, a token before the pattern that starts with `--` but isn't a known flag prints the usage line, so a mistyped flag name is caught rather than searched for. Once the pattern has started, every later token is pattern text: `file grep x --path missing` has no selected path and searches for `x --path missing`.
- **Regular expression by default (feature text).** The pattern is a JavaScript regular expression, the engine `compileMatcher` (`src/search/compile-matcher.ts`) already uses for the search tab. Matching is line-oriented: each line is tested on its own, `^` and `$` anchor to that line, and no pattern spans two lines. `\s`, `\w`, `\b`, character classes, and lookaheads and lookbehinds are supported. No `u` flag is set.
- **Literal (feature text).** `--literal` matches the pattern as fixed text, so regex punctuation searches for itself. This is `compileMatcher`'s plain-text mode.
- **Case (user decision).** Matching is case-insensitive by default, like the search tab's Match case toggle. `--case-sensitive` turns case sensitivity on.
- **Whole word (user decision).** `--word` requires the match to sit on a word boundary, using `compileMatcher`'s whole-word mode. It composes with `--literal` and with a regular expression.
- **Output (user decision).** One line per matching line, `<path>:<line>: <preview>`, such as `src/file-read/command.ts:9: export const FILE_READ_USAGE = …`. The path is root-relative with forward slashes, even when `--path` narrows the search, so `<path>` can go straight to `file read`. Line numbers start at 1. The preview carries no match markers.
- **Order (from precedent).** Rows come in path order, then line order. Paths are in `listProjectFiles` order (sorted with `localeCompare`), the order the search tab lists them, after identical entries are collapsed keeping the first occurrence.
- **CRLF files (user decision).** Lines are split on `\n` only, as the search tab's `splitLines` (`src/search/search-files.ts`) does, so a line in a CRLF file keeps its trailing `\r` while matching. A pattern ending in `$` therefore doesn't match those lines, the same as in the search tab. The preview drops a single trailing `\r`.
- **Preview (user decision).** Leading whitespace is trimmed from the line. A trimmed line of 200 UTF-16 code units or fewer is shown whole. A longer one shows a 200-unit window that contains the line's first match, centered on it where the line allows, with `…` marking each end that was cut. A match longer than 200 units starts the window at the match.
- **Limit (user decision).** `--limit` defaults to 100 and accepts 1 through 250, the search tab's `SEARCH_MAX_RESULTS`. A value above 250, zero, a negative, a fraction, a non-integer form, or a repeated flag prints the usage line.
- **Truncation (user decision).** When more lines match than the limit, the output is the first `<n>` rows, then `(showing the first <n> matches; narrow the pattern or raise --limit)`. No total is computed. Exactly `<n>` matches with no further match end without a trailer.
- **Files searched (user decision).** The same set the search tab and Quick Open search, from `listProjectFiles` (`src/file-navigator/search.ts`): tracked files plus untracked files git doesn't ignore. Tracked dotfiles such as `.github/workflows/ci.yml` are searched. When the git invocation fails, its walk fallback searches every file except those under `.git`, `.svn`, and `.hg` (and `.DS_Store` and `Thumbs.db`). In that case `node_modules` is searched too. There is no `--hidden` flag. An unmerged index path returned once per stage is collapsed to one candidate.
- **Size and binary skips (from precedent).** A file over 2 MB (`SEARCH_MAX_FILE_BYTES`) is skipped, and so is a file with a NUL byte in its first 8 KB (`SEARCH_BINARY_PREFIX_BYTES`). Neither is reported. The NUL test reads bytes, not decoded UTF-16 units.
- **Secret files (user decision).** A file that `file read` would refuse as `Secret file:` (`.env`, `.env.*`, any path containing a `SECRET_DENY_PATHS` run, and a file under a matching location in the home directory) is skipped before it is read. It never yields rows and doesn't count toward the limit.
- **Symbolic links (user decision).** Never followed. A symbolic link candidate is skipped whether it points to a file or a directory, inside the workspace or out, and an ancestor link is never traversed. Directory links were already never entered, so cycles can't happen. A `--path` naming a link is handled by its real target: a dangling link or one that resolves inside the workspace is skipped and prints `(no matches)`, while one whose real target is outside the root is refused as `Outside the workspace: <path>.` before any search.
- **`--include` and `--exclude` (user decision).** Each takes the search tab's comma-separated globs, through `filterPaths` (`src/search/filter-paths.ts`). A pattern with no `/` names a file at any depth (`*.ts`). A pattern with a `/` is anchored (`commands/*.ts`). A plain name with no wildcard selects a whole directory (`src` means `src/**`). The comma always separates patterns, so write `*.js,*.jsx` rather than `*.{js,jsx}`. Exclude wins over include.
- **Anchoring with `--path` (user decision).** Include and exclude globs are matched against paths relative to the selected directory, or against the file's name for a single-file `--path`. So `file grep --path src --include commands/*.ts x` searches `src/commands/*.ts`. Output paths are still root-relative.
- **`--path` (user decision).** It names a directory to search beneath, or a single file to search on its own. With a single file, `--include` and `--exclude` are matched against the file's name. `.`, `./src`, and `src/` are accepted; the output prefix is the normalized root-relative directory (`src`), and `--path .` searches the whole root. Bad values print one line naming `--path` as typed: `Path not found: <path>.` when nothing exists there, and `Outside the workspace: <path>.` for an absolute path, a `..` escape, or a path whose real location is outside the root.
- **A named file that would be skipped (user decision).** A single file given to `--path` goes through the same filters as a directory search. If it is git-ignored, secret, a symbolic link, binary, over 2 MB, not a regular file, or excluded by `--include` or `--exclude`, the output is `(no matches)`. No reason is given.
- **No matches (feature text, from precedent).** The output is `(no matches)`, as in `file glob`. It is not an error.
- **Malformed regular expression (user decision).** Two lines. The first is the engine's own message for the pattern as typed, as the search tab shows it (for example `Invalid regular expression: /[unclosed/i: Unterminated character class`). The second is `Use --literal to search for the text as typed.` The diagnostic is produced before path policy and disk work.
- **Pattern that matches empty text (user decision).** A pattern that matches the empty string (`x*`, `^`) would match every line, so nothing is searched. The output is `Pattern matches empty text, so it would match every line: <pattern>.`, also before path policy and disk work.
- **Timeout (user decision).** One absolute 30-second budget (`GREP_TIMEOUT_MS`) covers target resolution, candidate discovery and filtering, and scanning. When it expires, the output is the rows found so far (or `(no matches)` if there are none), followed by `(search stopped after 30 seconds; narrow the pattern or --path)`.
- **Slow pattern (user decision).** Matching one file has the matcher worker's existing one-second deadline (`MATCHING_JOB_DEADLINE_MS`). If a file exceeds it, the search ends. The output is the rows found so far (or `(no matches)`), followed by `(search stopped: the pattern took too long on <path>; simplify it or use --literal)`, where `<path>` is root-relative.
- **Other matcher failures (from precedent).** Any other worker failure, such as the worker exiting, is not caught by the scan. It reaches the existing error handling, which prints the error's text: `CommandManager`'s catch (`src/command/manager.ts`, `errorText(error)`) for a typed command, and the far side's error reply for a remote one.
- **Which ending is printed.** Whichever comes first ends the search: the limit, the timeout, or a slow pattern. Only that ending's trailer line is printed. A filter that stalls consumes the same 30-second budget in its own worker, so the parent can stop at the deadline.
- **Usage line (user decision).** Malformed arguments print `Usage: file grep [--literal] [--word] [--case-sensitive] [--path <path>] [--include <globs>] [--exclude <globs>] [--limit <n>] [--] <pattern>`. That covers a missing pattern, an unknown flag before the pattern, a repeated flag, a flag missing its value, and a bad `--limit`.
- **Primer (user decision).** When a role grants `file grep`, the file tool's primer includes this text after the `file glob` primer and before the mutation primer, with a blank line between fragments:
  - `To find text inside workspace files, end your reply with one line:`
  - `file grep [--literal] [--word] [--case-sensitive] [--path <path>] [--include <globs>] [--exclude <globs>] [--limit <n>] [--] <pattern>`
  - `Flags come first; the rest of the line is the pattern, a case-insensitive regular expression unless --literal or --case-sensitive. Results are path:line: text, at most 100 by default; --include and --exclude take comma-separated globs such as *.ts,*.tsx.`
  - `Example: file grep --include *.ts function\s+parse`
- **Agent runs (user decision).** Not permitted in this version. An `agent` command run that requests `janissary file grep …` gets `Agent: command not permitted: <command>.`, with or without the `file` grant, at the shared gate and independently at the caller-command guard, the same way `file glob`, `file write`, and `file edit` are refused there. The guards normalize the incoming line by trimming it and removing one leading slash, then match `isFileGrepCommandLine`; the refusal interpolates the original command text.
- **Authorization (user decision).** The ACP gate grants or refuses `file grep` by its native command name, exactly like `file read` and `file glob`. There's no per-pattern rule and no new resource field. The pattern is visible in the full command text that the tool transcript entry and the connection record's `tool` activity lines already carry.
- **Completion (user decision).** Typing in the command bar completes `grep` after `file`. Before the pattern, a current `--` token completes to the seven lowercase flags, and the token after `--path` completes file and directory names. The pattern itself is never completed, and neither are the values after `--include`, `--exclude`, and `--limit`. A committed flag value is consumed as a value even when it looks like a flag, a terminator, or a pattern. On a remote tab, flags still complete but `--path` offers no paths.
- **Remote tabs (feature text, from precedent).** A typed grep on a remote tab searches the remote clone only through the read-only `grep-files` operation at protocol version 43. It can also print `Remote connection unavailable.`, `The remote connection ended.`, `The remote machine did not answer in time.`, or `The remote file navigator is closed.`, as `file read` does. The request keeps the ordinary 60-second deadline; the far side stops itself at 30 seconds.
- **Transcripts and history (from precedent).** A typed grep's output carries no host tag. In a remote ACP session loop, the workspace step is tagged `[<host>] ` on its transcript input and on both connection-record tool activity lines, like every other workspace step; its transcript output and provider feedback stay raw. Local sessions, caller steps, refusals, and a local fallback session on a remote tab stay untagged. History and transcripts record the command as typed.
- **Workspace root (from precedent).** The same root as `file read` and `file glob`: a local tab's workspace directory, or its launch or project directory when it has none; a remote tab's remote clone only; and in the ACP loop, the workspace of the host running the loop (`runsOn: 'workspace'`).

## Proposed changes

The change lives in a new `src/file-grep/` feature directory with its own scan loop. A remote tab reaches its clone through a new read-only `grep-files` remote operation that returns formatted text. It landed after the delivered `file glob`.

### Pure command module — `src/file-grep/command.ts`

- `FileGrepArgs` carries `pattern`, `literal`, `word`, `caseSensitive`, `path` (the `--path` value, or `undefined` for the root), `include`, `exclude` (empty strings when absent), and `limit`.
- `parseFileGrep(input)` returns `FileGrepArgs` or `{ error: FILE_GREP_USAGE }`, in the shape of `parseFileRead`. It trims the input, requires `file grep` case-insensitively, then walks the flag tokens from the front until `--` or the first token that isn't a known flag. A switch sets its boolean; `--path`, `--include` and `--exclude` take the next token unless it is missing or starts with `--`; `--limit` validates through `positiveInteger` and `SEARCH_MAX_RESULTS`. A repeated flag is usage. The pattern is the remainder of the trimmed input from the first pattern token's offset, so internal whitespace survives.
- `FILE_GREP_DEFAULT_LIMIT` is 100. `FILE_GREP_USAGE`, `FILE_GREP_PRIMER` (the four primer lines from Design decisions, joined by newlines with no trailing newline), and `isFileGrepCommandLine(line)`, which matches `^file\s+grep(\s|$)` case-insensitively, mirroring `isFileReadCommandLine`.

### Pure formatter — `src/file-grep/format.ts`

- `previewLine(line, start, end)` drops a single trailing `\r`, trims leading whitespace, shifts the span to match, and applies the 200-UTF-16-unit window rule with `…` on each cut end.
- `GrepEnding` is `{ kind: 'limit', limit }`, `{ kind: 'timeout' }`, or `{ kind: 'slow', path }`; normal completion is `undefined`.
- `formatGrepResult(rows, ending)` prints `<path>:<line>: <preview>` per row, or `(no matches)` when there are none, then the one trailer for `ending`.

### Deadline helper — `src/file-grep/deadline.ts`

- `withDeadline(deadline, operation)` takes an absolute `Date.now()` deadline and a zero-argument async thunk. An already-expired or exactly-equal deadline returns `{ kind: 'timeout' }` without invoking the thunk. Otherwise it races the operation against a timer for the remaining budget: a completed value is returned unchanged, an operation rejection before the timer rejects unchanged, and the timer returns the timeout variant. The timer is cleared on every settlement. A late resolution or rejection cannot replace the settled result.

### Candidate reader — `src/file-grep/read-candidate.ts`

- `createCandidateReader(root, signal?)` canonicalizes the root once, builds one `createRealTargetCheck` closure for its home-secret anchors, and returns a `CandidateReader` that resolves to the file's text or `null`. Root canonicalization or policy failure yields an always-null reader.
- For each relative candidate, the reader rejects empty, absolute, and escaping paths; requires strict containment under the canonical root; applies `isSecretPath` and the cached real-target policy before opening anything; `lstat`s every ancestor from the root outward and requires a real directory, so a link is never traversed; `lstat`s the final path and requires a regular file; rejects more than `SEARCH_MAX_FILE_BYTES`; resolves the candidate's real path and requires exact equality with the expected path plus a clean policy result; reads bytes; tests only the first `SEARCH_BINARY_PREFIX_BYTES` bytes for NUL; and decodes UTF-8. Any failure, including an aborted signal or a read failure, resolves to `null` without a reason and leaves the reader usable for the next candidate. Signal checks sit before and after each awaited filesystem boundary, and the signal is passed to `readFile`.

### Path target resolver — `src/file-grep/path-target.ts`

- `resolveGrepTarget(root, requestedPath)` returns a `GrepSearchTarget` (`kind: 'directory'` with `searchDir`, or `kind: 'file'` with `filePath`, both carrying the canonical `root` and normalized `prefix`), `{ kind: 'skip' }`, or `{ kind: 'failure', text }`. An omitted path acts as `.`, while diagnostics keep the typed spelling.
- Lexical policy runs first: an absolute path or a parent escape is `Outside the workspace: <path>.`, and a lexical secret is a skip without probing the filesystem. The root is canonicalized and itself checked against the real-target policy, so a workspace under a home-secret anchor skips.
- Descendant components are `lstat`ed from the canonical root outward. A link is never inspected beneath. The target is then canonicalized and checked by `checkRealTarget`: an outside real target is the outside failure even through a link, an in-root secret skips, and a link that is dangling or resolves inside the root skips. A canonical target that differs from the expected path skips. A FIFO or other nonregular target skips without an open. A missing ordinary target, a path through a regular file, failed metadata, a failed root canonicalization, or a non-directory root is `Path not found: <path>.`.
- Prefixes are normalized through native path operations, so `.`, `./`, `./src`, `./src/`, and `src/` produce an empty prefix or `src`.

### Candidate discovery and filter worker — `src/file-grep/candidates.ts`, `src/file-grep/filter-worker.ts`, `src/file-grep/filter-worker-protocol.ts`, `src/file-grep/filter-worker-entry.ts`

- `discoverGrepCandidates(target, include, exclude, signal)` lists `target.searchDir` for a directory, or the named file's parent for a file; collapses identical paths keeping the first occurrence; selects exactly the named basename for a file target; runs the include/exclude filter in the feature worker; checks the signal before listing, after listing, before filtering, and after filtering; then prefixes each selected path with the target's normalized prefix.
- `filterGrepPaths(paths, include, exclude, signal)` returns a copy after a signal check when the list is empty or both fields are exactly empty. Otherwise it starts one worker through `grepFilterWorkerEntry`, which selects the source or compiled entry beside the adapter, with `workerExecArgv` from `../search/matching-worker.js`, and sends the request through `workerData`. `filter-worker-entry.ts` validates its unknown payload with `isRecord` and string/string-array checks, calls the unchanged `filterPaths` once, and posts the response. The adapter validates the unknown response, settles once on result, error, exit, or abort, removes its listener, and terminates the worker once.
- The include/exclude strings are internal worker data, not command text, so they never reach the parent's glob evaluator, which is what keeps a hostile pattern from blocking the deadline.

### Scan — `src/file-grep/scan.ts`

- `grepMatcherModes(args)` maps `FileGrepArgs` to `MatcherModes` (`regex: !literal`, `matchCase: caseSensitive`, `wholeWord: word`), so validation and matching share one conversion.
- `scanFiles(root, relPaths, args, deadline)` returns `ScanResult` with `rows` and `ending`. Empty input completes with no reader or worker. Otherwise it creates one scan-owned `AbortController`, awaits one `createCandidateReader(root, signal)` through `withDeadline`, reads and matches candidates one at a time in the supplied order, and creates at most one lazy matcher worker at the first accepted text.
- A candidate is skipped when it reads as `null`; an empty string is matched. Each file's `rows()` call races the same absolute deadline. The scan keeps at most `limit + 1` rows; when the sentinel fills the cap it returns the first `limit` rows with the limit ending. Reaching exactly `limit` continues through the remaining candidates to discover whether a further match exists, and full exhaustion returns no ending. A timeout returns the earlier rows with the timeout ending and aborts the controller before returning. A `MatcherDeadlineError` returns the earlier rows with the slow ending naming the file. Any other failure propagates after the worker is disposed in `finally`. `GREP_TIMEOUT_MS` is 30 000.

### Workspace entry — `src/file-grep/grep.ts`

- `grepWorkspace(root, args, deadline)` validates the pattern first, with `grepMatcherModes` plus `patternError` and `compileMatcher`: a malformed pattern returns the engine message and the literal hint, and an empty-matching pattern returns the empty-match line, both before any path policy, listing, read, or worker.
- It then runs `resolveGrepTarget` through `withDeadline`; a timeout returns the no-match sentinel plus the timeout trailer, `failure` text is returned, `skip` returns `(no matches)`, and a success proceeds to discovery.
- Discovery is wrapped in its own `withDeadline` with the same absolute deadline and a discovery-owned `AbortController`; the controller is aborted in `finally`, before scanning. A discovery timeout returns the formatted timeout result.
- A completed discovery goes to `scanFiles(target.root, paths, args, deadline)`, and the result is formatted. The one absolute deadline is never reset or extended.
- `grepWorkspaceCommand(root, input)` parses and calls `grepWorkspace` with a fresh `Date.now() + GREP_TIMEOUT_MS` deadline, returning the usage line on malformed input. It is the far-side entry used by the remote ACP loop and the remote operation.

### Typed entry — `src/file-grep/tab-grep.ts`

- `grepFilesInTab(managers, label, input)` parses once, then uses `localReadRoot` to pick the local root, or `withRemoteTabPort` with prefix `file-grep` to send `grep-files` on a remote tab. A local root calls `grepWorkspace` with a fresh deadline and lets unexpected rejections reach `CommandManager`. The remote branch opens its own dedicated port session and disposes it after success or failure.
- A returned `Path not found: <sent>.` or `Outside the workspace: <sent>.` is rewritten to the typed `--path` only when it is the whole reply; a single row whose preview ends the same way, and any multi-line text, stay unchanged. Remote failures map through `rejectionLine`, so `OUTSIDE_ROOT_REASON` becomes `Outside the workspace: <typed>.` and connection failures keep their existing lines. A remote tab never searches local disk.

### Remote protocol

- `src/remote/protocol-frames.ts` adds `'grep-files'` with args `{ pattern, include, exclude, literal, word, caseSensitive, limit, path? }`.
- `src/remote/filesystem/grep-files-arguments.ts` exports `validFileGrepArgs` and `decodeFileGrepArgs`, requiring strings for pattern/include/exclude, booleans for the three switches, an optional string path, and a safe-integer limit from 1 to `SEARCH_MAX_RESULTS`. The decoder materializes its own path property and throws `Invalid remote filesystem operation arguments.` on invalid fields.
- `src/remote/filesystem/grep-files-operation.ts` registers `grep-files` with `rootDestination: true`, no refusal callback, paths `[args.path]` when present (including an empty string), and a run that constructs the full `FileGrepArgs` and returns `{ text: await grepWorkspace(context.root, args, Date.now() + GREP_TIMEOUT_MS) }`. It is in `READ_OPERATIONS`, with a `{ text: string }` decoder in `result-decoders.ts`.
- `src/file-navigator/remote/port-reads.ts` exports `remoteGrepFiles(request, paths, root, args)`: an absolute `--path` is refused locally with `Outside the workspace: <path>.` and no request; any other path is mapped once; the request always carries every switch and `limit`, omitting only an absent path; the reply returns the text and the sent path. `RemoteFileSystemPort.grepFiles` delegates to it in one statement. `createFile` and `createDirectory` moved to `remoteCreateItem` in `port-mapped.ts` to keep `port.ts` under its line limit, preserving their results and refusal mapping.
- `REMOTE_PROTOCOL_VERSION` is 43, with a comment that a version-42 peer would refuse the operation after connecting, so the handshake refuses it first. `grep-files` is not in the long-running list; the ordinary 60-second request deadline is enough because the far side stops at 30 seconds.

### Commands, roles, and the ACP tool loop

- `src/commands/file.ts` routes a `file grep` line (by `isFileGrepCommandLine`) to `grepFilesInTab` before the read fallback, and adds the samples `file grep TODO` and `file grep --literal --include *.md request timed out`.
- `NATIVE_ACP_COMMANDS` adds `file grep` right after `file glob`, and the built-in `ask` and `tell` command lists in `src/plugins/roles/roles-file.ts` add it in the same position, so ask grants nine commands and tell grants fourteen. Saved roles files are not changed, and `ROLES_PAYLOAD_SCHEMA_VERSION` stays where it is.

### Completion

- `src/completion/file-read.ts` adds `grep` to `FILE_SUBCOMMANDS` and delegates the `grep` subcommand to `completeFileGrepArgument`.
- `src/completion/file-grep.ts` classifies the committed tokens after `file grep`: the three switches consume nothing, the four valued flags consume exactly one following token, and any other committed token starts the pattern for good. Pending `--include`, `--exclude`, or `--limit` values return `unchanged`. Pending `--path` completes files and directories through `completeFilePath` against the same `fileReadRoot`, or returns `unchanged` when the root is undefined. In flag state, a current token starting `--` completes the seven lowercase flags; everything else, including a current `--` after a committed terminator or pattern, is left unchanged.

## Out of scope

- Editing or replacing text; `file grep` only reports locations.
- Any web UI beyond the command's transcript output.
- Context lines around a match, multi-line patterns, and count-only output.
- A total match count.
- A `--hidden` flag, or searching git-ignored files.
- Brace lists in `--include` and `--exclude`.
- Following symbolic links.
- Allowing `file grep` for autonomous `agent` command runs.
- Per-pattern authorization rules or a resource field.
- A `--limit` above 250.
- Making `$` match before a CRLF line ending.
- Cancelling an already-running grep when a prompt is cancelled; the existing late-result suppression applies, but the search is not promised to stop.
