# Pin the shared contract's aggregate list to the grammar's

The plugin contract validated `aggregate` against its own literal set of five while the grammar carried nine, and the projection passed the aggregate straight through to the wire. So a `median` chart was accepted, validated against the real table, stored, and projected — and then refused by the guard that should have allowed it, at which point `activate.ts` rejects the payload, `registry.tsx` throws `invalid plugin payload`, and the tab's error boundary renders `null`. The tab went blank and every intent with it, and only the console said why. The four aggregates affected are exactly the ones `AGGREGATE_RULE` tells the model to reach for on a long-tailed measure, and a record restored from disk holding one is dead on open.

The contract cannot import the grammar — it is the import-free copy the browser reads on every broadcast — so the two lists cannot be the same list. What can be true is that they agree, and the place to say so is a test. `src/plugins/visualizations/shared.test.ts` now imports `AGGREGATES` from the grammar and asserts the two sets are equal, so a grammar that gains an aggregate and a contract that does not fails the suite rather than the tab. The pin was verified by removing `distinct` from the grammar and watching exactly that case fail.

The second half of the pin is the case that missed it: "accepts every optional field a tab can be showing" passes `aggregate: 'sum'`, so it never walked a list that had grown. There is now a case that sends a payload for *every* aggregate the grammar has, with the `percentile` beside the one that needs it, and one that sends an aggregate the grammar has not got and is refused.

`shared.ts` was over the file-size limit once the comment went in, so the five intent guards and the five intent shapes they read moved to `src/plugins/visualizations/intents.ts` — the payload contract is about what a tab is shown and the intents are about what a tab asks for, and the second is read once when a button is pressed rather than on every broadcast. `intents.ts` carries its own `isRecord` rather than borrowing the contract's, so a guard there cannot be the reason the contract stops being checkable, and `activate.ts` imports each from where it now lives. Nothing about the payload changed.
