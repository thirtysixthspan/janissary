# Make a reply's effect on the charts undoable

A reply's `remove` was applied immediately and there was no history of any kind, so the model could remove charts and rewrite every transformation of one it misunderstood, and the only recovery was another sentence — which may be refused as a second message while the first is in flight, and which the twelve-turn window will eventually forget. A user who had built up a tab of eight charts had no way back from one careless turn. Deepnote's agent shows a before-and-after diff when a run finishes and offers a single control to undo all changes from that run; Hex shows a per-change diff to keep or discard.

- `VisualizationTurnView` gains `before`, a copy of the chart list as it stood, and `undo`, a sentence naming what changed. `apply` in `src/visualizations/agent.ts` takes the copy before anything moves and hands both lists to `keepUndoable`.
- The copy is of *specifications*, not of data: a restored chart brings its own resolved table, which is why nothing reaches into a dataset and why a snapshot costs what a list of specifications costs. A turn that changed nothing carries no copy and no label — a button that does nothing beside a label claiming something happened is worse than no button.
- `summaryOf` in `src/visualizations/undo.ts` reads the sentence from the two lists rather than recomputing it, because a label that disagreed with what the turn did would be worse than no label. `sameChart` compares what would be drawn and deliberately not the title: "just change the title" is a change the user asked for and taking it back would be tedious.
- `reverted` restores the copy, clears the turn's own claim, and rebuilds the notices, so a chart that is no longer there takes its finding with it. It names the turn by the query the user sent rather than by a position, because a position moves as the conversation grows and the user is looking at a sentence. A query the record does not hold, or one already taken back, changes nothing and returns false.
- `undo` joins the topic and the record tab\x27s intents. The snapshot never reaches the browser: `shownTurn` in `view.ts` strips it, because a browser holding the chart list of every one of the last twelve turns is holding a record it has no use for.
- Both guards hold the two halves together. The store refuses a turn that claims to be undoable with no copy behind it, and the shared contract refuses a label whose copy is absent — so a button that restores nothing cannot be shown.
- `VisualizationChat.tsx` renders the affordance as a line under the answer, reading as a continuation of that reply, and disabled while a reply is in flight.

`src/visualizations/agent.test.ts` covers a removal carrying a copy and a label, a turn that only answered a question carrying neither, and a change being named as a change. `src/visualizations/manager.test.ts` covers the revert and both refusals — a query not held, and a turn already taken back. `src/visualizations/store.test.ts` covers the round trip and the half-state being refused. `VisualizationTab.test.tsx` covers the button sending the turn\x27s own query and its absence on a turn that changed nothing. The spec gains a paragraph.
