# Complete the unified diff view

Complexity: 8/10. The user explicitly overrode the task's complexity cutoff for the remaining work.

## Goal

Complete the recorded Unified diff view requirement: show unchanged lines once, removed blocks before replacement additions, aligned gutters and markers, preserved whitespace and syntax colors, selectable code, inline comments, and context expansion within one vertical code display.

## Approach

Render unified lines in their original hunk order while retaining the split pairing used for character marks. Compute a shared gutter width from each file's largest visible original/new line number so digit boundaries do not shift code alignment. Add local, in-memory line comments in unified layout, anchored to file, side, and line number with the original text retained so changes to an annotated line can be identified. Comments survive refresh, file collapse, and switching layouts while the file entry remains mounted; closing or re-scoping the diff forgets them. Provide add, edit, cancel, and delete controls without writing files or sending comments anywhere.

Add a validated context-expansion intent. The server remembers requested context per file, initially three lines and increasing by twenty per request. Re-read only expanded tracked files with literal Git pathspecs and increasing context; Git merges neighboring hunks as their context connects. Probe one additional context line to hide expansion when no more can be revealed. Preserve expanded context through periodic refresh, clear it on re-scope or creation of a new tab through the host's factory, and queue a fresh computation when context changes during an in-flight read. Expanded results preserve counts, paths, syntax rendering, and original/new line numbers. Expansion failures remain recoverable and do not disable the plugin.
