# Subagent caller policy and human refusals
**Complexity: 6/10** — ~105 added production lines, 1 existing file, 10 requirements, 68 scenarios (p=6.18).

## Goal

Resolve caller-kind/form/role policy before invoking launch: only `invocation.acpTool === true` selects JSON, and every other caller uses flags. Even malformed or wrong-form input reports the caller's own exact usage line. Supply an independently testable command helper for the later registry unit, with immediate refusals and no run on policy failure.

Source: `product/plans/complete/subagent.md`, preserved unchanged as the canonical feature record. This is ordered subplan 20 of 23.

## Implementation steps

1. Export synchronous `runSubagentCommand` from command-policy.ts. It takes the resolved full command string, the same label/index tab argument as `Command.run`, `Managers`, then an optional `CommandInvocationContext`. Export `SubagentCommandResult` there as the union of string, the record arm of `AcpDispatchReceipt`, and undefined. The future command entry can delegate its run directly to this helper; this unit adds no registry entry, command-manager branch, command lookup or availability check. Keep one private `refuseSubagentCommand` helper for the common immediate refusal sink.

2. Determine caller kind exclusively by strict equality to true on the supplied invocation's `acpTool`; omitted invocation, omitted/false/nontrue markers, `acpRole` alone, `awaitResult`, an ACP-capable tab and a system schedule do not select JSON. Typed, scheduled, queued and plugin command-capability dispatches are people. Ask/tell tool loops and a plugin prompt's emitted tools are ACP callers by their marker, independent of the tab view. Parse the resolved command with `parseSubagentCommand`; select the caller's usage before examining the result. A parser error or a successful parse in the wrong form always uses that selected usage, even when malformed input appeared to choose the other form. Stop before role lookup and launch on every such refusal. Use plan 1's usage exports unchanged: `Usage: subagent --role <role> --task <file.md> [--context <text>]` for people and `Usage: subagent {"role":"<role>","task":"<file.md>","context":"<text>"}` for ACP callers.

3. For a valid caller/form pair, call `knownRoleSettings(managers.tab.launchDir, parsed.role)` once per invocation. Lookup stays fresh and retains the reader's canonical name, entries, effort and saved command grants; never read role descriptions or use caller cwd, execution clone or remote path as the settings root. Unknown returns exactly `Subagent: unknown role "<trimmed input>".`, trimming the decoded role only for this message. Filter a known settings object's entries with `managers.models.isKnownModel(harness, model)`. Zero enabled entries returns exactly `Subagent: the <canonical role> role lists no models.`. Neither refusal calls launch or creates a run/record. Preserve the enabled entries' order, duplicates and effort, including entries from any harness; do not use `attemptOrder`, deduplicate or fall back to built-ins after filtering. Leave the canonical settings object and saved grants unchanged. Check the first enabled entry exists and construct the launcher's nonempty readonly tuple from that entry and the remainder, rather than asserting a general filtered array is nonempty.

4. Call plan 19's `launchSubagent` once with its options object and Managers: label, parsed task, optional context preserved verbatim (including an empty string), commandText set to the resolved command, the supplied invocation when present, canonical settings and the nonempty enabled-entry tuple. Retain the distinction between parsed input and echoed input: `invocation.line` when present, otherwise the resolved command, is the original input for refusals and is also what plan 19 uses for its record/human replies. Return the launcher's actual record receipt unchanged to people. Return the empty string to ACP callers immediately after that synchronous call. Do not return a started object, serialize the receipt, await execution, add another started/completion producer, or link invocation.signal. Plan 19 uses plan 12's exact `Subagent <canonical role> started.` and completion wording.

5. A policy refusal is the exact refusal string for ACP, with no appended human reply. For a person it appends exactly one entry with original input, refusal output and a fresh `randomUUID()` background id; omit `backgroundRecord` and return undefined, so no receipt/marker is produced. Use the same sink for a synchronous exception from the `launchSubagent` call, converting unknown errors through `errorText` unchanged, without an added prefix or punctuation. This includes plan 19's `Subagent: caller session is not available.` for missing ACP role/internal identity/provider id, as well as the existing missing/closing/stale caller and disposed-manager errors. Catch only the synchronous launcher call, not reply appending or background work. No pre-run error schedules an asynchronous message. A missing, closing or stale human caller has no safe transcript recipient: suppress that append rather than writing into a reused incarnation, still return no receipt and start nothing. Check the current tab is open/nonclosing and matches a supplied caller incarnation before appending a refusal. After a receipt exists, provisioning/task/executor errors belong solely to plan 19's later completion and must not be converted into a second immediate refusal.

6. Import plan 1's `isSubagentCommandLine` into command-tools.ts. Test its normalized input beside the existing early file refusals, before `commands.find` and before reading `snapshot.grants` or skills. Return exactly `Agent: command not permitted: <command>.`, substituting the untouched command argument, not normalized input, invocation.line or a reconstructed first token. Bare, flags, JSON and malformed subagent arguments are all refused, case-insensitively and with the existing optional leading-slash normalization. Lookalike first tokens remain on the normal command path. This refuses a selected skill that explicitly grants subagent and a run with no skills/grants alike. The shared local/remote caller delegate needs no second check or nesting API. Plan 17 already excludes subagent from a subagent executor's tools/primer/extractor; do not duplicate that exclusion here.
