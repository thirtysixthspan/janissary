## Proposed changes

- Export async `remoteGrepFiles(request, paths, root, args)` directly from `src/file-navigator/remote/port-reads.ts`, with arguments in that order: `RemoteRequest`, `RemotePortPaths`, root string, and `FileGrepArgs`. Return a promise of an object with required `text` string and required `path` string-or-undefined properties, including an own undefined path property for omitted input. Do not introduce another argument/result type or re-export the helper elsewhere.
- Before awaiting path mapping, workspace readiness or the request, reject every POSIX absolute `args.path` with successful text `Outside the workspace: <typed>.` and return the same typed path in the pair. This includes an absolute child of the remote workspace. The helper sends no filesystem-request for that outcome; the shared port may already be opening its session, so do not promise no session frame. Do not compile the regex near side.
- For other inputs, omitted path stays undefined and is omitted from the wire args. A supplied path, including empty string, maps once through `paths.to(root, args.path)`; include the resulting wire path even when empty. With root `/remote/ws`, empty string, `.` and `src/..` map to `''`, and `./src/` maps to `src`; at a nested root `/remote/ws/sub`, `.` maps to `sub`. Do not pre-normalize, filter returned rows or call `paths.from` on text.
- Issue exactly one `grep-files` request with pattern, literal, word, caseSensitive, include, exclude and limit always present. Preserve false booleans and empty strings; glob's truthy optional-switch spreading is wrong for this strict protocol. Path alone is optional on the wire. Preserve the decoded text verbatim, including empty text, rows, diagnostics and partial-result trailers, and return the actual sent path in the pair. Let mapper/request/decoder rejections propagate from this helper.
- Add `RemoteFileSystemPort.grepFiles(root, args)` beside `globPaths`, taking a root string and `FileGrepArgs` and returning the identical required text/path pair. Its body is a single return delegation to `remoteGrepFiles(this.requester(), this.paths, root, args)`. Extend the direct helper import and add the direct type-only `FileGrepArgs` import. Do not add this method to `FileSystemPort` or `LocalFileSystemPort`, bump the protocol again, or edit the deadline list; plan 11 already registers version 43 and keeps the ordinary 60-second request deadline.
- Add `src/file-grep/tab-grep.ts`, exporting async `grepFilesInTab(managers, label, input): Promise<string>` with `Managers` and two string arguments. Parse once before any tab/remote lookup or filesystem work and return the parser's usage text immediately on error. Use `localReadRoot` unchanged: a local tab's workspace wins, otherwise use launchDir, including when the label has no tab. For a local root call `grepWorkspace` with the complete parsed args and exactly one fresh `Date.now() + GREP_TIMEOUT_MS` absolute deadline. Add no signal, new cancellation API, outer timeout, reparse or catch around local execution; preserve partial rows and let unexpected local rejections reach CommandManager.
- Keep the remote branch in a private `grepRemoteFiles` helper in the same module, following `globRemotePaths`. Call `withRemoteTabPort` with prefix `file-grep`, then `port.grepFiles(workspace, args)`. The shared helper owns a dedicated session and disposal on success or failure. A remote tab with no manager, channel, readiness or workspace prints `Remote connection unavailable.`; even if it carries workspaceDir, it never calls local grep or reads local contents.
- Rewrite only exact returned workspace path diagnostics `Path not found: <sent>.` and `Outside the workspace: <sent>.` through `asTyped`, and only when both sent and typed paths are defined. Leave all other successful text untouched. A blind call is unsafe for grep: a single row has no tab/newline and its preview can end `: <sent>.`, satisfying asTyped's generic suffix check. Do not alter that shared helper or rewrite a row's preview. Catch remote failures inside the callback and call `rejectionLine(error, args.path ?? '.')`, preserving its OUTSIDE_ROOT_REASON mapping and all other messages.
- Preserve `Remote connection unavailable.`, `The remote connection ended.`, `The remote machine did not answer in time.`, `The remote file navigator is closed.`, generic remote error text and invalid-result decoder text. Keep failures observable rather than converting them to no matches or searching locally. For successful no-match/secret output return exactly `(no matches)`.
- Preserve the actual preflight layers. Local grep and the later far-side ACP workspace entry validate malformed/empty-matching regex before policy or disk work. The typed remote helper rejects an absolute path before any request or far-side regex validation. A relative escape or path resolving outside the root reaches the existing generic containment guard, which may refuse before workspace run/regex, even for an outside-resolving secret spelling. Ordinary contained secrets with a valid pattern produce no matches without content reads; central metadata probes can precede workspace validation. Do not bypass the generic guard or duplicate the matcher near side to promise identical error ordering across routes.
- In `src/commands/file.ts:10`, `fileOutput`, route `isFileGrepCommandLine` to `grepFilesInTab` before the read fallback and keep the existing glob/mutation routes. Add samples `file grep TODO` and `file grep --literal --include *.md request timed out`. Retain the existing `command.run` and `appendCommandOutput` path, invocation context, command history and transcript input spelling. Output has no host tag and creates one command entry. There is already one file command registered at `src/commands/index.ts:31`, so add no registry entry or command-manager branch.
- In this implementation, update exactly `help/file.md`, the existing `file` row at `help/commands.md:21`, and `product/specs/acp.md`. Help must describe typed grep syntax, flags-first grammar, defaults/cap, directory/file scope, filtering/skips, row/trailer text, errors, root choice and remote-only behavior with runnable flags-first examples. Add grep in place to the command-table row that currently lists read/glob/write/edit; preserve alphabetical order. Extend or create `### File grep` immediately after `### File glob` in acp.md, preserving plan 11's workspace/transport description and adding typed behavior, exact diagnostic precedence, session/error mapping and untagged transcript behavior. Do not claim ACP grants, primer composition or loop execution are available before plans 14/15, or defer these typed docs to plan 17. Plan 17 audits the final combined documentation.
