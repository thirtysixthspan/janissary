- `$janissary/scripts/run.mjs check-diff` is the development gate. For a change touching both `src/` and `web/src/`, it lints the changed files, typechecks both projects incrementally (`typecheck:diff` runs `tsconfig.json` and `web/tsconfig.json`), and runs `test:diff:server` and `test:diff:web` (`package.json:46`–`:47`), which are `vitest run --project server|client --changed`: tests selected by import graph. `scripts/changed-files.mjs:8` (`changedFiles`) builds that file list from `git diff HEAD` plus `git ls-files --others`, so it sees only uncommitted and untracked work. The gate is meaningful only while the whole decomposition is still uncommitted; if any part was committed, say so in the report and lean on the by-path runs. The full `npm run check` is the human's once-at-the-end gate and is not run here.
- The named test files in Tests are run by path as well, because `--changed` selects by import graph and can miss a test whose subject changed indirectly. Run them with `npx vitest run --project server <files>` and `npx vitest run --project client <files>`, one invocation per project.
- `src/commands.test.ts` (`prints all key tables only from help keys`, line 135) renders the shipped `help/` pages through `help keys`, and `scripts/check-diff.mjs:32` (`touchesHelp`) makes any `help/` Markdown change run it through the `test:help` tool at `:68`–`:70`. It proves the edited page still loads; it does not assert the new row's text, so step 10 reads the rendered output against the wording. `src/help-pages.test.ts` exercises the loader against temporary directories only and never reads `help/keys.md`, so it neither covers nor can fail on this edit. `npm run docs:build` is the only check that catches a broken link in the edited `documentation/` pages.
- The walk runs in an app built from the checkout that holds the uncommitted change, started through `ai/tasks/workspace/start-application.md` with `<project-dir>` set to that checkout. Inside that app, `$root` is the checkout and `$workspace` is `$root/.janissary/workspace` (`workspacePath` in `src/workspace/index.ts:42`), so `src/file-navigator/remote/file-cache.ts` resolves under `$root`. Do not reuse the human's live instance: the lock is per project directory (`lockPath` in `src/instance-lock.ts:54`), and a different `<project-dir>` is a second, isolated instance. Commands expand only `$root` and `~` (`expandUserPath` in `src/paths.ts:15`), never `$workspace`; type a clone path as `$root/.janissary/workspace/<name>/...`.
- The walk needs three optional fixtures: a workspace clone under `$workspace` for step 2, a configured remote host with a workspace for steps 6 and 7, and a GitHub-synced file for step 9. When one is missing, record that step as not reached in the walk's result notes and name its covering tests: step 2's clone half with `open.test.ts` and `reveal-editor.test.ts`'s clone cases, steps 6 and 7 with `reveal-editor.test.ts`'s blocked and remote cases and `FileNavigatorTab.test.tsx`'s focus cases, and step 9 with `revealTargetFor`'s git-sync cases. Never mark a step passed from a test alone.
- A defect the walk finds is recorded as a repair against its owning subplan: the reveal target and blocked projection in `01`, open-or-retarget at a root in `02`, local reveal in `03`, remote reveal in `04`, the RPC in `05`, the held selection in `06`, the acknowledgement in `07`, the button in `08`, the chord in `09`, navigator focus in `10`, sidebar selection in `11`, and wording in `12`. Record the step number and the owning subplan in the walk notes. The orchestrator reruns the affected walk steps after a repair.
- The walk observes; it does not fix. Anything outside this feature goes to `product/backlog/`, not into this change.
- No file is written by this subplan, so the 200-line limit does not apply to it. The walk report, including not-reached steps and routed defects, is the output. A repair that adds code is subject to the owning subplan's limits.
