# Add a `file glob` command for ACP ask and tell sessions

**Complexity: 7/10** — ~365 added lines, 14 files edited, 25 requirements, 35 test scenarios (p=7.72)

`file glob` lets a person or an autonomous ACP agent list the files in the workspace whose paths match a glob pattern, without reading any contents. Agents could already `file read` a path they knew, but they had no cheap way to discover which paths exist, so they guessed names or asked. A glob tool closes that gap: discover names first, then read or edit them. It joins `file read`, `file write`, and `file edit` as a fourth subcommand of the existing `file` command and the existing ACP file tool, and it works against the same root those commands use — the local workspace, the launch directory, or a remote tab's remote clone — never falling back to the local machine for a remote tab.

## Design decisions

Each decision comes from the feature text, from existing behavior ("from precedent"), from a user answer ("user decision"), or was settled while building it ("settled in the build").

- **Command name.** `file glob`, a subcommand of the existing `file` command (`src/commands/file.ts`), alongside `file read`, `file write`, and `file edit`.
- **Who can run it.** It is a native ACP command granted by default to the built-in `ask` and `tell` roles, and it is also a typed application command, matching how `file read` is both.
- **Syntax (user decision).** `file glob <pattern> [--path <dir>] [--hidden] [--dirs] [--limit <n>]`, in the flag style of `file read`. The pattern is one whitespace-free token, the same rule `file read` applies to its path. Flags may appear in any order, before or after the pattern; each may appear once. The command words match case-insensitively; the pattern and the `--path` value keep their case.
- **Parser edge cases (settled in the build, matching `parseFileRead`).** Any token starting with `--` is a flag, so a pattern that starts with `--` is a usage error; a token starting with a single `-` is an ordinary pattern. `--limit=5` is an unknown flag. A `--path` value that starts with `--` counts as a missing value. `--limit` accepts only an all-digit token that is a safe integer, so `--limit 007` is 7 and `--limit -3`, `--limit 1.5`, and `--limit 1e3` are usage errors. That rule lives in one shared `positiveInteger` helper (`src/positive-integer.ts`) that `file read` and `file glob` both import, so the two commands cannot drift in how they accept a limit.
- **Glob semantics (settled in the build).** `**` matches zero or more directory segments, `*` matches within one segment, `?` matches one character, and `{a,b}` is alternation. Node's `path.matchesGlob` can't be used: even as `path.posix.matchesGlob` it folds case on macOS and Windows, with no option to turn that off. The matcher calls the `minimatch` package (`^10.2.5`, promoted from a dev-only transitive package to a runtime dependency) with Node's own option set except `nocase` — `nocase: false`, `nonegate: true`, `nocomment: true`, `windowsPathsNoEscape: true`, `optimizationLevel: 2`, POSIX platform — so it has `path.matchesGlob`'s semantics with case-sensitive matching on every host. `!x` and `#x` are literal patterns. The pattern is compiled once per search. A pattern minimatch rejects (over 64 KiB) matches nothing, so the command prints `(no matches)` instead of failing.
- **Anchoring (user decision).** The pattern is matched against each candidate's path relative to the `--path` directory (the root when `--path` is omitted). `file glob *.ts --path src` matches `src/a.ts` but not `src/x/b.ts`. A pattern with no `/` is not widened to any depth.
- **Output paths (user decision).** One root-relative, forward-slash path per line, even when `--path` narrows the search, so any line can be passed straight to `file read`.
- **Case (user decision).** Matching is always case-sensitive, on every host. `*.TS` does not match `a.ts`.
- **Hidden and ignored paths (user decision).** By default, dotfiles and dot-directories are excluded, and so are paths that git ignores (`.gitignore`, `.git/info/exclude`, the global excludes file) and `node_modules` at any depth. `--hidden` includes both dotfiles and ignored paths, so one flag widens the search to everything on disk. The `.git` entry is never listed, entered, or tested at any depth and whatever its type (a submodule or worktree has a `.git` file), even with `--hidden`. The skip rules apply only below the `--path` directory: `--path .github` without `--hidden` lists `.github/workflows/ci.yml`, and `--path dist` naming a git-ignored folder lists its contents.
- **Wildcards and dot-names (user decision, mechanism settled in the build).** Without `--hidden`, dot-names are pruned before matching, so the question doesn't come up. With `--hidden`, `*`, `**`, and `?` also match names that start with `.`, so `file glob **/* --hidden` lists `.github/workflows/ci.yml`. This is minimatch's `dot` option, set to the `--hidden` value; no leading-dot mask is needed. An explicit dot in the pattern (`.*`, `**/.github/**`) also matches under `--hidden`. Without the flag it finds nothing, because dot-names are pruned before matching.
- **Workspace outside git (user decision).** When the root is not inside a git repository, or whenever `git ls-files` fails, nothing counts as git-ignored (no gitignore parsing). Without `--hidden`, the search skips dotfiles, dot-directories, and `node_modules`. With `--hidden` it lists everything except `.git` and secret files.
- **Secret files (user decision).** A path that `file read` would refuse as `Secret file:` (`.env`, every `.env.*` name, any path containing a `SECRET_DENY_PATHS` run, or a home-directory secret) is silently left out of the results, and it doesn't count toward the limit. `.env.example` is an `.env.*` name, so it is never listed, even with `--hidden`. The same check applies to directories under `--dirs`, so a directory such as `.aws/` is never listed. A symbolic link to a file is judged by its resolved target as well as its own name: a link whose target is a secret file or lies outside the workspace, or whose target can't be resolved, is left out the same way. When `--path` is an in-root symbolic link, each match is also judged by its real location under the link's target, so a link such as `cfg` pointing at `.config` never lists `cfg/gh/hosts.yml`.
- **Limit (user decision).** `--limit` defaults to 100 and accepts 1 through 1000. A value above 1000, zero, a non-integer, or a repeated flag prints the usage line, matching how `parseFileRead` treats `--limit` above its maximum.
- **Truncation (user decision).** When more paths match than the limit, the output is the first `<n>` matches in sorted order, followed by the line `(showing the first <n> matches; narrow the pattern or raise --limit)`. No total is computed: the search stops reading directories once it holds one match past the limit.
- **Bad `--path` (user decision, order settled in the build).** Each failure prints one line naming `--path` as typed. The checks run in this order and the first failure wins: an absolute path or a lexical `..` escape prints `Outside the workspace: <dir>.`; a path that can't be resolved (missing, or through a file) prints `Directory not found: <dir>.`; a real location outside the root (a symbolic link resolving out) prints `Outside the workspace: <dir>.`; anything that isn't a directory prints `Not a directory: <dir>.`, so `--path .env` prints `Not a directory: .env.` rather than a secret line. `--path .` behaves like no `--path`, and `--path src/` like `--path src`.
- **Secret `--path` (settled in the build).** Once those checks pass, a `--path` that is a secret folder by its lexical or its real location, such as `.aws` or an in-root link to `.aws`, prints `(no matches)` with no error line, without loading the ignored set or walking.
- **Linked `--path` (settled in the build).** An in-root symbolic link to a directory is accepted as `--path` and walked under the link's name, so results read `linked/a.ts`. Its real location is used only for the containment, directory, and secret checks.
- **No matches (user decision).** When nothing matches, the output is `(no matches)`, in the style of `file read`'s `(empty file)`. This is not an error.
- **Timeout (user decision).** The search stops after 30 seconds (`GLOB_TIMEOUT_MS`). The output is then the matches found so far, sorted (or `(no matches)` if there are none), followed by the line `(search stopped after 30 seconds; narrow the pattern or --path)`. Whichever comes first, the limit or the timeout, ends the search; when the limit ends it, only the truncation line is printed. Time spent asking git for the ignored set counts against the same deadline.
- **Files or directories (user decision).** By default only files are listed: regular files, and symbolic links to files except those the Secret files decision leaves out. A `--dirs` flag lists matching directories instead of files. Sockets, FIFOs, and devices are skipped.
- **`--dirs` output (user decision).** Each matching directory is printed root-relative with a trailing `/`, such as `src/a/`. The pattern is matched against the directory's path without the slash, so the slash-terminated pattern `src/` matches nothing. Every directory on disk counts, empty ones included, subject to the same hidden and ignored rules as files (`--hidden` widens both). The `--path` directory itself is never listed. A directory is listed before its contents (pre-order), and a directory that survives pruning is entered whether or not it matched or was dropped as secret.
- **Primer (user decision).** When a role grants `file glob`, the file tool's primer includes this text, placed after the `file read` primer and before the mutation primer, each part separated by a blank line:
  - `To find files in the workspace by path, end your reply with one line:`
  - `file glob <pattern> [--path <dir>] [--hidden] [--dirs] [--limit <n>]`
  - `Patterns are case-sensitive and relative to --path (default: the workspace root): ** spans folders, * stays within one name, ? is one character, {a,b} is either. Results are workspace-relative paths, at most 100 by default; hidden and git-ignored paths are skipped unless --hidden is given, and --dirs lists folders instead of files.`
  - `Example: file glob **/*.test.ts --path src`
- **Usage line (from precedent).** Malformed arguments print `Usage: file glob <pattern> [--path <dir>] [--hidden] [--dirs] [--limit <n>]`, in the form of `FILE_READ_USAGE`. Bare `file` and `file globs x` still print the `file read` usage line.
- **Agent runs (user decision).** Not in this version. `gateAgentCommand` in `src/acp/tool-table.ts` refuses any `isFileGlobCommandLine` input, bare `file glob` and `/file glob x` included, with `Agent: command not permitted: <command>.`, with or without the `file` grant, the same way `file write` and `file edit` are refused there. The refusal names the command as given. That one gate covers local and remote agent runs, so `runGrantedAgentCommand` in `src/agent/command-tools.ts` and the `runWorkspace` in `src/agent/execute.ts` are unchanged and an agent's glob never falls through to the caller's directory. `file globs x` is not a glob line and keeps its `runsOn: 'caller'` result.
- **Completion (user decision).** Typing in the command bar completes `glob` after `file` (beside `read`), completes the flags `--dirs`, `--hidden`, `--limit`, and `--path` for a `--` token, completes directory names only after `--path`, and leaves the `--limit` value and the pattern token unchanged. Directories complete against the same root the glob uses; a remote tab completes no directories but still completes the subcommand and flags. Hidden directories are offered only when the typed name starts with `.`, as elsewhere.
- **Completion respects disabled rows (settled in the build).** The `file` subcommand words are filtered through the completion policy, as `browser` subcommands are, so `file ` offers only `read` while the `file glob` row is disabled. Arguments under a disabled `file glob` were already suppressed by the existing prefix guard in `completeCommandLine`.
- **Symbolic links (user decision).** A symbolic link to a directory is never entered, so cycles cannot happen. The link is not listed as a file, and with `--dirs` it isn't listed as a directory either. A broken link is skipped. A symbolic link to a file is listed like a file, unless its resolved target is a secret file, lies outside the workspace, or can't be resolved, as the Secret files decision states.
- **Results.** Paths only, never contents, in sorted, stable order: depth-first, with each directory's entries in code-unit order of their names (not `localeCompare`), and never re-sorted as whole strings. So `a/x` comes before `a-b/x`, `a/b.ts` before `a.ts`, and `B.ts` before `a.ts`, the way a file tree reads.
- **Read failures (settled in the build).** An unreadable directory is skipped and its siblings are still walked. A start directory removed between validation and walking, or a root that can't be resolved, yields `(no matches)` rather than an error.
- **Remote tabs (from precedent).** A typed glob on a remote tab can also print `Remote connection unavailable.`, `The remote connection ended.`, or `The remote machine did not answer in time.`, exactly as `file read` does. It never falls back to the local disk. A far-side line naming the sent `--path` spelling is rewritten to the path as typed, and a far-side containment refusal prints `Outside the workspace: <dir>.` with the typed `--path`. The request keeps the normal 60-second deadline, longer than the far side's own 30-second stop, so a slow remote glob prints the 30-second line.
- **Transcripts and history (from precedent).** A typed glob's output carries no host tag. In a remote ACP loop, the workspace step is tagged `[<host>] ` like every other workspace step. History and transcripts record the command as typed.
- **Authorization (user decision).** The ACP gate grants or refuses `file glob` by its native command name, exactly like `file read`: `Command is disabled: file glob.` for a disabled or agent-inaccessible row, `Command not allowed for role "<role>": file glob.` for an ungranted one. There's no per-pattern rule and no new resource field. The pattern is visible in the full command text that the tool transcript entry and the connection record's `tool` activity lines already carry. The backlog's "pattern as resource identifier" idea is out of scope. The file tool's line test is not grant-aware: on a table that includes the file tool, a trailing glob line from a role that doesn't grant it is extracted and answered with the role refusal, like an ungranted `file write`. A bare `file glob` line is gated like any other and, when granted, answers with the usage line.
- **Commands tab and typed refusal (settled in the build).** Adding `file glob` to the native vocabulary gives the Commands tab a `file glob` row with parent `file` and no other edit. A typed `file glob …` resolves to that row, so disabling it refuses the typed command as well as the agent tool, like `file read`; disabling `file` disables all four file rows. `commands disable agent file glob` resolves to the row.
- **Distinct from grep.** It matches path names only; content search is the separate `file grep` backlog item.
- **Workspace root.** It runs against the same root as `file read`: a local tab's workspace directory, or its launch/project directory when it has none; a remote tab's remote clone only; and in the ACP loop, the workspace of the host running the loop (`runsOn: 'workspace'`).

## Proposed changes

Implementation decisions (user): the code lives in a new `src/file-glob/` feature directory; candidates come from one async sorted `readdir` walk plus one git call for the ignored set; the walk runs on the main event loop with a deadline (no worker); a remote tab reaches its clone through a new read-only `glob-paths` remote filesystem operation.

### Pure command module — `src/file-glob/command.ts`

- `FileGlobArgs` carries `pattern`, `dir` (the `--path` value, or `undefined` for the root), `hidden`, `dirs`, and `limit`. The returned object always has all five keys.
- `parseFileGlob(input)` returns `FileGlobArgs` or `{ error: FILE_GLOB_USAGE }`, in the shape of `parseFileRead`: it splits on whitespace, requires `file glob`, accepts exactly one non-flag token as the pattern, and scans `--path <dir>`, `--hidden`, `--dirs`, and `--limit <n>` in any order, each at most once, through small per-flag helpers that keep each function under the complexity limit. `--limit` defaults to 100 (`FILE_GLOB_DEFAULT_LIMIT`) and must be 1 through 1000 (`FILE_GLOB_MAX_LIMIT`), read with the shared `positiveInteger`. An unknown flag, a missing value, or a second pattern is a usage error.
- `FILE_GLOB_USAGE`, `FILE_GLOB_PRIMER` (the four primer lines from Design decisions, joined by newlines), and `isFileGlobCommandLine(line)`, which matches `^file\s+glob(\s|$)` case-insensitively, mirroring `isFileReadCommandLine`.
- `formatGlobResult(paths, { limit, truncated, timedOut })` is a pure formatter: the paths one per line, or `(no matches)` when the list is empty, then the truncation line, else the timeout line. It never slices, sorts, or rewrites paths.

### Shared limit parser — `src/positive-integer.ts`

- `positiveInteger(value)` accepts only an all-digit token that is a safe integer of at least 1 and returns `undefined` for anything else, a missing token included. `src/file-read/command.ts` and `src/file-glob/command.ts` both import it; neither command module imports the other.

### Matcher and ignored set — `src/file-glob/match.ts`, `src/file-glob/ignored.ts`

- `createGlobMatcher(pattern, hidden)` builds one `Minimatch` with the option set in Design decisions plus `dot: hidden` and returns a predicate over forward-slash paths relative to the `--path` directory, with no leading `./` and no trailing `/`. A construction failure returns a predicate that always answers `false`. A comment records why `path.matchesGlob` isn't used.
- `loadIgnoredPaths(root)` runs one `git ls-files --others --ignored --exclude-standard --directory -z` with `execFile`, `cwd: root`, and a 64 MiB `maxBuffer`, in the style of `listProjectFiles`. Git prints paths relative to `cwd`, so they are already root-relative even when the root is a subdirectory of the repository. One trailing `/` is stripped from each collapsed directory, and a lone `.` entry (git's answer when the root itself lies inside an ignored directory) is dropped so such a root prunes nothing. A directory whose untracked contents are all ignored comes back collapsed and is pruned, matching `git status --ignored`. Tracked files are never in the set (`--others`), so a tracked file under an ignore rule is still listed. Any rejection — not a repository, git missing, a nonexistent root, output over the buffer — resolves to an empty set.
- `package.json` adds `minimatch` `^10.2.5` to `dependencies`; the lockfile drops the dev flag from `minimatch` and the two packages it pulls in, with no version changes.

### Walker — `src/file-glob/walk.ts`

- `walkGlob({ root, start, realStart?, pattern, hidden, dirs, limit, deadline, ignored })` returns `{ paths, truncated, timedOut }`. It builds the matcher once, resolves the root's realpath once (returning the empty result if that fails), and walks one directory at a time with promise-based `readdir({ withFileTypes: true })`, sorting each directory's entries by code unit and descending depth-first in a sequential `for … of` loop, so results come out in sorted path order without a final sort.
- `start` is the lexical `--path` directory, never a realpath, so the root-relative prefix stays correct when the root's own path runs through a symbolic link (macOS temporary directories under `/var`). Every candidate gets two forward-slash paths, relative to `start` for the matcher and relative to `root` for the ignored set, the secret check, and the output.
- Per entry, in order: skip `.git`; without `hidden`, skip a leading-`.` name, `node_modules`, or a root-relative path in the ignored set (an ignored directory is pruned without being entered; the set is not consulted under `hidden`); then classify, doing one `stat` only for a symbolic link (a file target is a `'link'`, a directory target, other target, or failed `stat` is skipped, and sockets, FIFOs, and devices are skipped); then test and record; then, for a directory, descend. The start directory itself is never tested against the skip rules or recorded.
- `record` runs the matcher on the start-relative path, then the secret check, then, for a `'link'`, the link target check, and only then pushes the path (with a trailing `/` under `--dirs`). The secret check runs `checkLexicalPath` on the root-relative path and, when the start's real prefix differs from its lexical one, `checkRealTarget` on the match's real location (the start's real path joined with the start-relative path, no I/O per match). The link target check resolves the link with `realpath` and runs `checkRealTarget` against the root's realpath; a failure or a rejected `realpath` drops the match. Regular files and directories pay no extra I/O. A dropped match never counts toward the limit.
- The walk stops once it holds `limit + 1` matches, and checks `Date.now() >= deadline` at the top of each directory read, the start's included. Once stopped it reads, stats, and tests nothing more. `truncated` and `timedOut` are never both true. An unreadable directory is skipped.
- Why not Node's `fs.promises.glob`: it yields matches in traversal order, not sorted order, so stopping at `limit + 1` would not give the first `<n>` sorted matches without walking the whole tree. The hand-rolled sorted walk is the smallest mechanism that keeps early stopping. `walkFiles` in `src/file-navigator/search.ts` isn't reusable: it isn't exported, collects every file, and can't prune.
- Deliberate ceiling: the walk runs on the main event loop. Each `readdir` await yields, but matching a very large directory runs in one turn. If that ever shows up as lag, move the walk behind the existing worker pattern in `src/search/matching-worker.ts`.

### Workspace entry — `src/file-glob/glob.ts`

- `globWorkspace(root, args, deadline)` is the one workspace entry. With a `--path`, a private `resolveStart` runs the four checks from the Bad `--path` decision in order (`checkLexicalPath`, `realpath` of root and target, `checkRealTarget`, `stat`), then returns the secret-start result or the lexical start plus its real root-relative path. A secret start returns `(no matches)` at once. Otherwise it loads the ignored set (skipped under `--hidden`), calls `walkGlob`, and returns `formatGlobResult` of the walk.
- `GLOB_TIMEOUT_MS` is 30 000. `globWorkspaceCommand(root, input)` parses and calls `globWorkspace` with a fresh deadline, returning the usage line on malformed input. It is the far-side entry used by the remote ACP loop.

### Typed entry — `src/file-glob/tab-glob.ts`

- `globFilesInTab(managers, label, input)` parses first and returns the usage line before looking up the tab. On a local root (`localReadRoot`) it calls `globWorkspace`. On a remote tab it uses `withRemoteTabPort` with prefix `file-glob` to call `port.globPaths(workspace, args)`, rewrites a one-line reply naming the sent `--path` back to the typed spelling with `asTyped` when `--path` was given, and maps a rejection with `rejectionLine(error, args.dir ?? '.')`. It does no containment or secret checks of its own.

### Remote protocol

- `src/remote/protocol-frames.ts` adds `'glob-paths'` to the operation union with args `{ pattern: string; dir?: string; hidden?: boolean; dirs?: boolean; limit?: number }`.
- `src/remote/filesystem/glob-paths-operation.ts`, modelled on `readLinesOperation`: `valid`/`decode` require a string pattern, an optional string `dir`, optional boolean `hidden`/`dirs`, and an optional safe-integer `limit` from 1 to `FILE_GLOB_MAX_LIMIT`, and `decode` copies only the optional fields the frame carried. `paths` returns `[dir]` when present (else `[]`) with `rootDestination: true`, so the far-side gate refuses a `dir` that escapes the root or passes through an outside link, and also a literal `.` or an absolute path naming the root, before `run`; an empty `dir` globs the root. A missing folder, a file, a secret folder, or an in-root link start passes the gate and is answered in the text by `globWorkspace`, the same as locally. `run` resolves to `{ text }` from `globWorkspace(context.root, …)` with the omitted fields defaulted and a fresh 30-second deadline. It's registered beside `read-lines` in `src/remote/filesystem/operations.ts`, and a `'glob-paths'` `{ text: string }` decoder goes in `src/remote/filesystem/result-decoders.ts`.
- `remoteGlobPaths(request, paths, root, args)` in `src/file-navigator/remote/port-reads.ts` answers an absolute `--path` locally with `Outside the workspace: <dir>.` before anything is sent, maps a relative one with `paths.to(root, dir)` (so `.`, `./`, and `src/..` become `''` and `./src/` becomes `src`), always sends `pattern` and `limit`, sends `hidden: true` / `dirs: true` only when set, and returns the reply text with the spelling it sent. Escaping paths are sent as is and come back as a rejection carrying the outside-root reason. `RemoteFileSystemPort.globPaths` in `port.ts` is a one-statement delegate. The request keeps the standard `REQUEST_DEADLINE_MS`; `glob-paths` is not in the long-running set.
- `REMOTE_PROTOCOL_VERSION` in `src/remote/protocol.ts` goes from 41 to 42, with a comment in the existing style: a version-41 remote would refuse `glob-paths` as unknown after the handshake had passed, so the exact-version handshake refuses the pairing first.

### Commands, roles, and the ACP tool loop

- `src/commands/file.ts` routes a `file glob` line (by `isFileGlobCommandLine`) to `globFilesInTab` ahead of the mutation and read branches, through a small `fileOutput` helper, and adds the samples `file glob **/*.ts` and `file glob *.md --path product --limit 20` after the `file read` samples.
- `NATIVE_ACP_COMMANDS` in `src/plugins/roles/shared.ts` adds `file glob` right after `file read`, giving thirteen native commands. The built-in `ask` and `tell` command lists in `src/plugins/roles/roles-file.ts` add `file glob` right after `file read`, so ask grants eight commands and tell grants all thirteen. Saved roles files are not changed or migrated: a saved `ask` or `tell` keeps the grants it lists. `ROLES_PAYLOAD_SCHEMA_VERSION` stays at 4: the payload's shape doesn't change, only the vocabulary's contents.

### Completion

- `src/completion/file-read.ts`: `FILE_SUBCOMMANDS` becomes `['glob', 'read']`, filtered by a new `policy` parameter (default `ALL_ENABLED_POLICY`). When the subcommand is `glob`, `completeGlobArgument` leaves the token unchanged after `--limit`, completes directories only after `--path` (none when the root is `undefined`, as on a remote tab), completes `--dirs`, `--hidden`, `--limit`, and `--path` for a `--` token, and otherwise leaves the pattern unchanged. Any other subcommand stays unchanged.
- `src/completion/fs.ts`: `completeFilePath` takes an optional `{ directoriesOnly }` that filters entries with `isDir` before the sort and common-prefix step, so a file never affects the completed prefix. Existing callers pass nothing.
- `src/completion/index.ts`: `completeCommandLine` passes its policy to `completeFileReadCommand`, and its doc comment covers `file glob`.

## Out of scope

- Searching file contents (the separate `file grep` backlog item).
- Reading, writing, or editing files; `file glob` only lists paths.
- Any web UI beyond the command's transcript output and the rows the Commands and roles tabs already build from the vocabulary.
- `file glob` for `agent` command runs.
- Per-pattern authorization rules or a resource field.
- Following symbolic links into directories, or printing real paths instead of link-named ones.
- Parsing `.gitignore` outside a git repository.
- A separate flag that includes ignored paths without dotfiles, or the reverse; `--hidden` covers both.
- Patterns containing whitespace, and completing the pattern token.
- A total match count.
- Running the walk in a worker.
- Migrating saved roles files.
- The same macOS case folding in `src/search/filter-paths.ts`, which still uses `path.matchesGlob`.
