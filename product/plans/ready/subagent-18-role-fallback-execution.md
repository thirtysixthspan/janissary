## Implementation steps

1. Export executeSubagentRun, readonly SubagentExecutionOptions and readonly SubagentExecutionResult from execute.ts. The function accepts one options object with fields named run, invocation, managers, settings, entries, executionDir, optional context, offline, optional remote and optional synchronous onStarted. Their types are the existing AgentRun, captured CommandInvocationContext, Managers, canonical AcpRoleSettings, a nonempty readonly list of already-enabled RoleEntry values, directory/context strings, the captured caller offline boolean or undefined, and plan 17's SubagentAttemptRemote. Encode the nonempty entry requirement in the options type; unknown/empty-role refusal and catalog filtering remain upstream. The remote target is plan 17's existing channel, host and already-provisioned workspace label, forwarded unchanged. The observer receives only the exact provider sessionId string and returns no execution decision. The returned promise supplies status using AgentOutcome, response, sessionId as string or null, and readonly cleanupWarnings. Do not expose an attempt lease, delivery message or run-settlement callback in this API.

2. Before admitting any attempt, return terminated with response `Subagent terminated.`, sessionId null and no warnings if the run has ended or its abort signal is set. Otherwise capture the options fields before the first await, copy each supplied entry and the settings' entries/commands arrays and canonical name once, preserving order, duplicate entries and stored/omitted effort. Use attemptOrder on the supplied entry copies without a current entry. Obtain managers.nativeCommandSettings?.current() exactly once for the execution, including retaining undefined when absent, and pass that same captured snapshot to every runSubagentEntry call. Recheck termination before registering the slot, since current() is an external call. Do not re-read roles, consult an existing caller session or refilter against changing model availability between entries. Forward captured invocation, executionDir, context, offline and selected remote target to the driver without recapturing mutable tab state or linking the invoking prompt's abort signal.

3. Export createSubagentSessionSlot and its readonly SubagentSessionSlot contract from execute-session.ts. The factory accepts only the existing run. Create one slot per admitted execution; it registers exactly one run.addResource with id `acp:<runId>` before the first runSubagentEntry call, even when every entry lacks an adapter. The slot exposes synchronous adoptSession taking a SubagentAttemptLease, synchronous clearAfterResult taking no arguments, and a readonly closed state. clearAfterResult only drops the retained lease; it neither disposes it nor reopens a closed slot. Resource cleanup marks the slot closed before awaiting the current lease's dispose. Adopt the exact lease supplied by plan 17, never a raw session or a second disposer. If the slot is closed or the run has ended/aborted at adoption, request that incoming lease's idempotent disposal immediately and return normally so the driver's terminal guard prevents callback replay or prompting. Do not reject adoption with a new failure string. Attach a rejection handler to this disposal request; the driver's finally awaits the same promise and owns its cleanup warning.

4. Pass the slot's adoptSession to every driver call. Retain its current lease until the driver result resolves, which already includes finally/disposal, then append that result's cleanupWarnings once and call clearAfterResult before checking the outcome or considering replacement. Never start overlapping attempts or add a coordinator shutdown/release/finally path. Run resource disposal and the driver's abort/finally paths may request disposal concurrently, but plan 17's shared lease promise performs the physical close once. The slot's cleanup consumes that promise's rejection without re-reporting it: the returned attempt cleanupWarnings are authoritative, so a later run finish cannot duplicate the same warning. The driver's abort/finally path must complete independently of the slot cleanup: AgentRun waits for allocations before running resource callbacks, so awaiting run.finish or resource cleanup from the driver/adoption path would deadlock. With no current lease, resource cleanup just closes the slot. Keep the resource registered until the launcher settles the run; it must not retain a disposed lease after the driver returns.

5. Recheck run outcome, its abort signal and the slot's closed state after each awaited driver result and immediately before admitting a replacement. A terminated result, closed slot or ended/aborted run returns terminated with `Subagent terminated.`, preserves the latest observed provider ID and accumulated cleanupWarnings, and never falls back. When replacing an entry, perform that guard and invoke runSubagentEntry with no await or external observation between them. Only after invoking the replacement driver, report fallbackNotice through run.reportActivity if the run and slot remain live, then await that driver result. This ordering prevents a synchronous activity subscriber from terminating the run before a replacement was admitted. The driver's guard handles a subscriber terminating during the notice. These checks plus plan 17's admission/allocation guard and late-adoption disposal close both gaps: termination after one result but before the next admission opens nothing and writes no notice, and termination during construction/adoption disposes any late-returned handle. The slot adds no abort listener or allocation of its own; the driver already supplies both.

6. Continue only for a failed/error SubagentAttemptResult whose replied flag is false. This includes undefined acpLaunchForEntry, constructor/spawn, connection onError and loop error failures handled by the driver. Await their cleanup before trying the next fresh session. Any endTurn, including empty or command-only display, sets replied and forbids fallback. Completed and partial results return immediately with the driver's response verbatim, including empty/whitespace display and no stopped-after suffix. A failed result after any endTurn returns only that attempt's source error, even when an earlier entry failed. For eligible failures, collect AttemptFailure entries in attempt order, report fallbackNotice(failed, next) with activity kind message under step 5's admission ordering, and use the last attempt's error unchanged when only one failed. Only exhausting two or more eligible failures uses exhaustedError(failures, captured canonical role name). Preserve source error text and multiline formatting without adding an Agent/Subagent/ACP prefix; an unsupported harness retains plan 17's exact `no ACP adapter for harness "<harness>".` text inside the appropriate single/exhausted result. Do not use finalAttemptResult, which owns ask/tell AcpPromptResult metadata.

7. Install one per-execution provider callback passed as each driver's onSessionStarted. Start latest sessionId at null; update it only from real provider callbacks accepted by the active driver. Latch first-started before invoking the optional onStarted observer, so synchronous reentry or an observer exception cannot emit started twice. A first handshake followed by an effort/connection error still reports that first ID. A later fallback handshake replaces latest ID without another observer call. A later prehandshake failure with result.sessionId null must not erase an earlier ID; do not assign the driver's nullable result ID back into this run-level state. Synchronous observer exceptions follow plan 17's failed/error path and pre-turn fallback rule while retaining the reported ID and first-started latch. Recheck termination after external observation through the driver's existing active guard; stale callbacks from disposed entries cannot update run-level identity.

8. Preserve warnings from failed attempts before a successful fallback and from a terminating attempt. Append rather than deduplicate: two separate leases may independently return the same warning text. Warnings never change fallback eligibility, status, response or sessionId and never enter distilled response or fallback error lists. Return a fresh execution result and warnings array with this aggregate and the chosen terminal status/text/latest provider ID. Do not call run.finish, set a terminal run status/response, close the record, call settleAgentRun, enqueue ACP deliveries or write human background replies. The later launcher owns those steps after this promise resolves. Update product/specs/subagent.md with this coordinator contract and the before/after-endTurn rule, first/latest provider identity, exact single/exhausted errors, termination priority and warning ownership.
