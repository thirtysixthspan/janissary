# Plugin API v3 and ACP response panel removal

**Complexity: 5/10** — coordinated wire/client API removal, docked-question ownership, reset-feedback preservation, and frozen-version compatibility across server and web tests; no new subsystem or ACP state machine.

## Goal

Remove the obsolete in-tab ACP response surface after shell replies move to the background channel, restore docked pending-question visibility through the core question panel, and publish the breaking tab-plugin API v3 contract with a frozen v2 fixture.

## Decisions and dependencies

- Covers source-plan product decision 3 and implementation decision 32 / proposed change 6, including panel and hook removals, docked question preservation, API version 3, and fixture compatibility. `product/plans/ready/connections-tabs.md:53` (`TAB_PLUGIN_API_VERSION` goes to 3) remains the full scope authority at 8/10; do not revise it or reopen completed subplans.
- Depends on completed `product/plans/complete/connections-tabs-05-shell-and-popup-integration.md:13` (panel removal belongs to 06). Original planning baseline is commit `58999a6` on `feature/connections-tabs`, with 05 focused-reviewed and repaired. This review uses the partial uncommitted v3 implementation, not a clean working tree; preserve that work and finish only the required seams below. Asynchronous replies and popup record opening already exist; do not implement them again. This subplan does not depend on documentation subplan 07.
- API v3 removes `useAcpResponse`, `TabView.acpResponse`, and the previously deprecated `launchShellHere()` shim. Preserve the frozen `fixture-v1` implementation byte-for-byte, migrate only its current-host test harness as decided below, and add `fixture-v2` as the frozen prior-version fixture.
- Pending questions on any active docked plugin tab remain visible through `PluginBody`'s core `QuestionPanel`, without an ACP response, terminal, command bar, or plugin hook being required. Hidden/inactive docked bodies show no question; centre questions remain owned by `MountedViewLayers`.
- Remove only the response projection and panel-specific actions. Preserve core ACP sessions, transcript tagging and replacement identity, prompt settlement, cancellation, record feeds, `backgroundReplies`, `openAcpTranscript`, and all other ACP consumers. Removing a client shim does not remove its still-used core RPC.
- Matching behavior specs ship with implementation here. Subplan 07 owns contributor/user documentation and guideline reconciliation plus full-feature verification, not deferred behavior-spec changes needed to describe this removal.
