# Background subagent launch and settlement
**Complexity: 7/10** — ~405 added production lines, 2 existing files, 24 requirements, 90 scenarios (p=7.36)

## Goal

Implement synchronous launchSubagent over validated canonical role settings and a nonempty list of enabled entries. Publish a durable run and return its record receipt before provisioning, task resolution or execution. Continue independently of the invoking prompt, and send the first started observation and one completion to the captured human or ACP caller.

Source: `product/plans/complete/subagent.md`, preserved unchanged as the canonical feature record. This is ordered subplan 19 of 23. Its Launch and execution, Human replies and Remote callers clauses at lines 92, 126 and 139 define this unit.

Complete `product/plans/ready/subagent-7-fresh-run-workspaces.md`, `product/plans/ready/subagent-10-record-receipt-markers.md`, `product/plans/ready/subagent-12-delivery-state-and-ownership.md`, `product/plans/ready/subagent-13-session-bound-delivery.md`, `product/plans/ready/subagent-15-remote-clone-frames.md`, `product/plans/ready/subagent-16-remote-workspace-selectors.md` and `product/plans/ready/subagent-18-role-fallback-execution.md`, including their earlier dependencies. These supply synchronous fresh creation, record receipts, immutable acpCaller, the complete delivery envelope, runClone/selected resolution and executeSubagentRun. They are prerequisite APIs, not existing checkout exports. Plan 14's clone service and plan 4's partial outcome arrive transitively.

The launcher takes validated inputs directly. Parsing, caller-form refusals, role lookup, enabled-model filtering, command registration and native vocabulary remain outside this unit; no API from a later command-policy or registry unit is needed. `invocation.acpTool === true` selects an ACP caller; acpRole is its ask/tell slot, independent of the configured subagent role. Other invocations use human replies. Snapshot invocation data, canonical role/entries/grants, exact command line, offline and remote target before background scheduling.

Plan 7's LocalAgentRunOptions currently promises only workspaceName, fresh and subagentRole. This unit adds optional acpCaller and forwards it to manager.create before synchronous publication. Never assign readonly run ownership afterward: plan 13's session-close hook must already see it during the creation state event.

## Implementation steps

1. Export launchSubagent and readonly SubagentLaunchOptions from launch.ts. Accept an options object with label, task, optional context, commandText, optional invocation, settings typed as canonical AcpRoleSettings and entries typed as a nonempty readonly enabled RoleEntry list; Managers is the second argument. Return the record arm of existing AcpDispatchReceipt synchronously: fresh replyId, kind record, actual run.recordId and name `subagent:<canonical role>`. Return no execution promise/tool-output object. Callers expose the receipt as appropriate. Use invocation.line when present, otherwise commandText, for both record command and human reply input. Copy settings/commands/entry arrays before scheduling, preserving order, duplicates and effort. Record model is the first enabled entry's model; record effort is its supplied effort or `default` when omitted. Do not override execution-entry effort or inherit ordinary agent defaults.

2. Use invocationFor and the real caller tab to capture runtime/incarnation, owner name, cwd/context, offline and existing remote channel/host. Missing/closing/stale tabs retain the helper's synchronous error and start nothing. For an ACP-tool invocation capture acpRole, managers.acp.sessionIdentity and managers.acp.providerSessionId before creation. Missing role/internal identity/provider ID throws exactly `Subagent: caller session is not available.` with no run or provisioning. Keep provider callerId separate from the internal lifetime token. Human calls omit acpCaller and require no invented IDs. Add optional acpCaller to LocalAgentRunOptions in workspace-types.ts and conditionally forward it through workspace-execution.ts's common createLocalAgentRun into manager.create. Ordinary launchAgent still omits it and retains its current behavior.

3. Local launch invokes startLocalAgentRun with literal fresh true, canonical subagentRole and captured optional acpCaller, using its plain run/workspace result without awaiting the start. Remote launch first constructs an inert prepareRemoteSubagentWorkspace handle in remote-workspace.ts, then calls managers.agent.create with captured caller/ACP ownership, empty task-text/skills/grants placeholder, original selector/command, first model/effort, canonical role, executionHost from the caller tab and the handle's final release as releaseWorkspace. Then start the handle with that run. No clone request/lease precedes publication. Until a directory is returned, immutable remote execution-location metadata uses captured caller cwd; actual resolution/execution receive the returned directory separately. Never infer a remote clone path or mutate readonly run fields. Manager-create failure cancels the inert handle and propagates its error with no remote operation.

4. Return the receipt in the same stack and schedule one observed continueSubagentLaunch operation. Provisioning/task/executor failures after creation become completion facts, never a rejected immediate receipt. For remote setup, start obtains run.beginAllocation and registers `remote-clone-provision` before queuing startup. Synchronous publication termination refuses admission and starts no lease/request, while the continuation still settles through its run reference. Queued startup checks outcome/abort/cancellation before acquiring anything; termination after admission but before that microtask rejects ready and ends allocation without a lease/request. Startup acquires managers.remote.acquireAgentLease(captured label, run.id), installs its release immediately, checks termination again before sending, then calls capturedChannel.runClone(create, `subagent-<runId>`). A missing channel or a label now pointing at a different channel fails with `Remote connection unavailable.` before lease/request; do not lease a replacement entry while sending on the captured channel. Other lease/request errors retain source text. Observe rejection immediately. End allocation after all request/cancellation/release ownership is installed, in every exit; never await clone readiness under that allocation. Remember reentrant cancellation and own a late-returned lease/request before ending allocation.

5. RemoteSubagentWorkspace exposes ready with the actual directory, start(run), cancel(), trackExecution(operation) and final release(). Refused allocation or cancellation before startup settles the observed ready rejection with `git clone cancelled.` and starts nothing; a cancelled late success never resolves ready or reaches lookup. Keep original create failures otherwise. Its pending-provision resource requests runClone(release, the same label) before awaiting a pending create, then drains both operations. Share one release promise with final cleanup; repeated finish, reentrant cancellation or late success cannot release twice or restart work. Mark create success ready before allowing lookup/execution. Once ready, provisioning cleanup does not release the clone; final releaseWorkspace owns it after ACP cleanup. Attempt clone release for submitted failed/late creates too, except conservative execution retention in step 10. Release the channel lease in finally after clone release/retention. Never hold allocation until readiness, wait for the whole launch continuation from a resource, add a create deadline, replay requests or open another connection. Plan 15 owns request correlation/failAll and the release deadline; a lost channel may leave the far-side clone until shutdown.

6. Await local workspace.ready or remote ready, then check run outcome/abort before lookup. Resolve locally with resolveAgentSnapshot(task, no skills, the fresh workspaceDir and janissaryRoot installationDir, empty canonical-command list); no skills require registry enumeration. Remotely await capturedChannel.resolveAgentSnapshot(task, empty skills, clone label) only after successful clone readiness. Check termination after awaited remote resolution and before setSnapshot/execution. Unknown, ambiguous, escaping, unreadable and uncommitted-only tasks fail with exact resolver text, null sessionId and no started. Preserve installed fallback. Resolve neither in caller/main workspace nor through local filesystem APIs for a remote root. Create no fabricated prompt for provisioning/task failure.

7. Call executeSubagentRun with exactly plan 18's options: run, captured invocation, managers, copied settings/entries, actual executionDir, optional context, captured offline, optional remote containing captured channel/host/clone workspace label, and onStarted. That dependency owns task prompt, native settings, fallback, session adoption and latest provider ID; do not duplicate them or wait for normal remote ACP ready. For remote calls, invoke only through handle.trackExecution's thunk so its barrier exists before the executor's synchronous callbacks can terminate the run. Never call linkRunToCaller, trustedParentRun or trackChildRun, and never listen to invocation.signal, even when already aborted. Terminate, caller tab close, captured session close and shutdown act through existing run owners.

8. createSubagentReplySink in replies.ts returns latched started/completion methods and captures the run, receipt, original input, runtime/incarnation and canonical role. Latch before external calls. Admit started only while the run is live; the executor already reports only the first real provider handshake. Human started appends subagentStartedText with a fresh background id/no record; completion appends subagentCompletionText with receipt replyId and backgroundRecord containing actual recordId/name. Gate human appends on the same open/nonclosing runtime/incarnation, including label reuse; do not manufacture an AcpPromptResult to call appendAcpBackgroundReply. ACP sinks submit plan 12's exact payload with captured provider callerId via deliver(label, captured caller role, full SubagentDelivery): runId, callerIncarnation, callerRole, callerSessionIdentity, canonical subagentRole and message. Plan 13 owns session admission, queue/coalescing and reset/shutdown drops. ACP callers receive no extra human subagent replies, and human sinks serialize no provider IDs.

9. Route post-creation results through one settleSubagentRun in settle.ts. Use errorText unchanged for thrown provisioning/resolution/unexpected execution failures; otherwise preserve the executor result. On an unexpected executeSubagentRun throw/rejection only, retain failed status and the original errorText, then call the owned run.abortController.abort() if its signal is not already set, before failed settlement. An executor rejection can leave plan 17's admitted driver/allocation active, for example when plan 18's fallback activity subscriber throws after replacement admission. This internal cancellation lets that driver's abort/finally dispose its lease and end its allocation independently; finish('failed') alone would wait for an allocation whose inactive callbacks cannot finish, before ever reaching the session resource. Do not use finish('terminated') to trigger this cleanup, link invocation.signal, or add cancellation for a normal returned failed result. Record first observed provider identity for a thrown failure without fabricating an ID; normal executor results supply the latest identity across fallback. Set Cleaning up with response only while outcome is unset; synchronous subscribers can terminate here. Await settleAgentRun once from the continuation to drain existing allocations/resources, including a run another owner already finished/removed. Only a recorded run.outcome === 'terminated' overrides the captured failure with exact `Subagent terminated.` text; an aborted signal alone, including the internal cleanup abort, never changes it to terminated. Preserve completed/partial/failed response verbatim, including empty/whitespace/Markdown/multiline errors. Aggregate executor/settlement cleanupWarnings separately in the internal settlement result. Add no prefix, warning suffix, JSON field, stopped-after suffix or extra reply. Latch completion before its sink, after cleanup has settled; late callbacks/reentry cannot publish again. Observe the entire background promise, with one result/settlement path rather than independent rejection/abort completion publishers.

10. In the remote handle, trackExecution installs an execution-only deferred barrier before invoking the supplied executeSubagentRun thunk. Resolve it with whether that executor returned with empty cleanupWarnings, or conservatively unsafe on any warning/rejection; observe rejection without changing the promise used by the launch continuation. On executor rejection, the barrier records unsafe retention, not driver disposal: step 9's owned-run abort and allocation/resource drain still precede final release. Await only this barrier during final release, never the launch continuation, settlement or manager.finish. Plan 17's driver closes independently on abort/finally, awaits local shutdown/remote acknowledgment and ends allocation before its result; plan 18 awaits those results without run settlement. Thus an active termination can complete execution while cleanup waits, without a cycle. Release a ready clone only after this independent execution finishes with no transport/session cleanup warning, or when no execution was admitted (for example a task error). A false/missing close acknowledgment, any executor cleanup warning or unexpected execution rejection retains the remote clone for the far-side owner's eventual successful shutdown: the API exposes warnings but no finer close-confirmation field, so retention conservatively avoids deleting a possibly live cwd. Do not match warning text or expand earlier execution APIs. Channel lease is last in every path, including retention/release failure. Outcome/output stay unchanged and warnings remain separate. Record this deliberate retention and FIFO/allocation/final-release ordering in the spec.
