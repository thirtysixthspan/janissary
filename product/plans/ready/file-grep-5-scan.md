## Proposed changes

- Export generic `DeadlineResult<T>` and `withDeadline<T>(deadline, operation)` from `deadline.ts`. The result is a discriminated union: `kind` is `completed` with the operation's `value` of type T, or `timeout` with no value. The helper accepts an absolute `Date.now()` deadline and a zero-argument thunk returning a promise of T; it returns a promise of `DeadlineResult<T>`. When `Date.now() >= deadline`, return timeout without invoking the thunk. Otherwise race its settlement against a timer for the remaining budget. The first observed settlement wins: completion preserves the exact value, an operation rejection before timeout rejects unchanged, and timeout returns the timeout variant. Clear the timer on every settlement, including a synchronous thunk throw. Observe the losing promise's later rejection without leaking an unhandled rejection or replacing the outcome. Own no persistent timer or cancellation API. Plan 8 must wrap target/discovery awaits with this same helper, without changing shared listing behavior.
- Extend plan 4's factory in `src/file-grep/read-candidate.ts` to accept `root` and an optional `AbortSignal`; existing `createCandidateReader(root)` calls remain valid. The returned `CandidateReader` still accepts only one relative path and resolves to text or null. Check the signal before and after each awaited root setup or candidate metadata boundary, and immediately before starting content I/O. Once aborted, return null without starting the next filesystem operation; an aborted factory resolves to an always-null reader. Pass the signal to the abortable content `readFile` call, retaining plan 4's silent-null failure behavior. A pending `lstat` or `realpath` may finish after timeout, but its continuation must never open contents or begin the next metadata step. Do not claim that already-issued OS metadata I/O is canceled. This narrow reader/test extension belongs to this plan; no shared policy or listing changes are needed.
- Export pure `grepMatcherModes(args)`, accepting `FileGrepArgs` and returning `MatcherModes`. Set `regex` to the inverse of `literal`, `matchCase` to `caseSensitive` and `wholeWord` to `word`; no other fields or effects. Use this helper when constructing the scan's worker. Plan 8 imports this same function for `patternError` and `compileMatcher` before disk access, preventing validation and matching modes from drifting.
- Export `ScanResult` with required `rows` of type `SearchMatch[]` and required `ending` of type `GrepEnding | undefined`. Import `GrepEnding` from `./format.js`; never redeclare its union. Its `limit` variant carries the requested numeric `limit`, its `timeout` variant has no payload and its `slow` variant carries the current root-relative `path`. Normal completion includes the ending property with value undefined.
- Export async `scanFiles(root, relPaths, args, deadline)`, accepting a root string, a readonly array of root-relative forward-slash path strings, `FileGrepArgs` and an absolute `Date.now()` deadline in milliseconds; resolve to `ScanResult`. Plan 8 supplies validated args and already discovered/filtered paths. Do not sort, deduplicate, normalize, list or refilter them, and do not reset or extend the caller's deadline. Empty paths complete normally with empty rows, without reader or worker creation.
- For a nonempty unexpired scan, create one scan-owned `AbortController`, await `createCandidateReader(root, signal)` once through `withDeadline` and reuse the returned `CandidateReader` for every candidate. Invoke it as `reader(relPath)`, never as a two-argument per-file factory; wrap each invocation in its own `withDeadline` call with the unchanged deadline. Read and then match one candidate at a time in supplied order, with no overlapping or speculative work. Only `null` skips a candidate and contributes no rows; `''` remains a successful read and goes to matching. A timeout result from setup or reading selects earlier rows with the timeout ending, then aborts the controller and returns immediately without awaiting the losing operation. Selection precedes abort so an induced ordinary cancellation rejection cannot replace timeout.
- Create at most one `createMatcherWorker(args.pattern, grepMatcherModes(args), signal)` per scan, lazily at the first accepted text, using that same scan-owned signal. Create it within the first matching operation's `withDeadline` thunk so an already expired deadline cannot start a worker. Enclose its entire lifetime in `try/finally` and call `dispose()` once on every subsequent normal, ending or exceptional exit. No worker is needed when all candidates skip. The reader owns no disposable resource. The helper's timers enforce the overall deadline; do not add a separate timer or public scan cancellation API.
- Call worker `rows(relPath, text)` with the candidate's supplied root-relative path. Preserve its row objects, line order, one-based line numbers, first-match UTF-16 span, untrimmed match text and context. Do not split lines, format previews or match on the main thread.
- The worker returns a whole file's rows as one batch, not a stream. Append only the prefix fitting the remaining `limit + 1` slots, retaining at most that many rows across files; do not append an arbitrarily large batch before slicing. Once the sentinel row is retained, immediately return the first `limit` rows with the limit ending and requested limit, without another read or matcher call. Exactly `limit` rows requires continuing through the remaining candidates to discover whether a sentinel exists; exhausting them yields undefined ending. No total is computed. This bounds the scan accumulator, not the existing worker's per-file response allocation; do not change that protocol here.
- Await every worker `rows` request through `withDeadline` using the same absolute deadline. If its timeout wins, select earlier rows with the timeout ending before aborting the controller or disposing the worker in `finally`; do not retain a late batch. The helper returns while already-issued metadata may still settle in the background; the reader's signal checks prevent those late continuations from starting content I/O. Late values never cause matching or subsequent candidate reads. Node timers cannot preempt a blocked event loop, but existing matching remains isolated in its worker; no main-thread matching or shared filesystem cancellation redesign is introduced.
- Catch only `MatcherDeadlineError` from the current matching operation using `instanceof`, and return the slow ending with that candidate's path and earlier rows intact when that rejection wins the race. The failed file supplies no partial rows because the worker returns a batch only on success. A completed batch that wins the race may supply the limit sentinel; return that ending immediately. A timeout that wins discards that batch; a slow rejection that wins remains slow. Unexpected reader/setup/worker creation failures and every other matcher rejection observed before timeout propagate unchanged after owned-worker disposal. Later failures are observed only by the helper. Do not match error text or return partial success for those unexpected failures. Return at the first observed stopping condition so later timer callbacks or cleanup cannot replace the single ending. Exactly-limit results still require scanning remaining candidates; expiration during that search gives timeout, and full exhaustion gives undefined ending.
