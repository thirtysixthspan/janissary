# Scripts tab row actions and delete dialog
**Complexity: 4/10** — three row buttons and a confirmation dialog copied from the schedules precedent, plus a narrower keyboard guard, a selection rule for a delete made from a row that is not selected, and focus return, each of which needs a test that pins it.

## Goal

Add the per-row action column with Run, Duplicate, and Delete. Add the Delete and Backspace path into a confirmation dialog with the spec's wording. Narrow the tab's keyboard guard so a focused row button keeps its own keys. Move the selection after a confirmed delete of the selected row, so the next row stays highlighted when the list drops the deleted one.

## Design decisions and dependencies

This subplan depends on `06-scripts-client-list`, now in `product/plans/complete/`, for the row component, the selection model, and the `ScriptsTab` key handler. It depends on `05-scripts-plugin-server` for the intent names and payload guards, and on `04-runscripts-topic-and-actions` for the host side of `execute`, `delete`, and `clone`. All three are complete. This subplan lands before `08-scripts-plugin-registration`, which names the modules created here.

- Run sends `execute` with `{ name }`. Duplicate sends `clone` with `{ name }`. Delete opens the dialog. The icons are `faPersonRunning`, `faClone`, and `faTrashCan` from `@fortawesome/free-solid-svg-icons`. I checked the installed package, and all three are exported. The tooltips are exactly `Run`, `Duplicate`, and `Delete`.
- The `aria-label` for each button carries the verb and the name, such as `Run deploy`, so a screen reader names the row. The source plan fixes the tooltips and says nothing about accessible names, so this is a decision made here. It is flagged for the owner.
- A click on a row button stops propagation, so pressing a button does not change the selection. The sessions action column does the same in `SessionRowActions.tsx`, and the schedules trash button does it in `SchedulesRows.tsx`. A button click skips the row's own click handler, which is what moves the selection and focuses the container, so the tab returns focus itself (see the focus bullet below).
- Each row keeps the `role="button"` that `06` gave it, with the row buttons nested inside it. The schedules rows do the same, and this subplan keeps that markup. Nested controls under a button role are an accessibility concern, so the owner may want to change it. It is flagged for the owner.
- The dialog's text is a pure function of the fields the server sends for the row. The title is `Delete runscript "<name>"?`. When `schedules` is 1, the first line is `Used by 1 system schedule. It will fire as missing after this.` When it is above 1, the line reads `Used by <n> system schedules. They will fire as missing after this.` When `open` is true, the second line is `Open in an editor tab. The tab keeps its text.` The wording comes from the Delete decision in `product/plans/ready/scripts-tab.md`. `src/plugins/scripts/shared.ts` carries no prose. The source plan says the dialog's lines "come from the server", and it also says the tests read them "from the row". The server sends counts and flags, and this module turns them into words. The payload `{ rows }` has no field for prose, so the server could supply the words only through a change to `04` and `05`. This is a reading of the source plan, and it is flagged for the owner.
- The dialog copies the keyboard contract of the schedules delete dialog in `web/src/plugins/schedules/DeleteScheduleDialog.tsx`. It takes focus when it opens. It listens on the window in the capture phase, so while it is open every keydown is swallowed, including keys meant for the tab behind it. Y confirms, N cancels, and Escape cancels. Enter runs the selected button. Left and Right toggle between the two buttons. Cancel starts selected. A click outside the dialog is swallowed, and a click inside it is left alone. The key-to-answer mapping is a pure function in `scripts-delete-keys.ts`, so the component holds only the listeners and the markup.
- This copy departs from `ai/guidelines/react-code-organization.md` §2, which says to promote code to a shared location on its second real consumer. The departure is deliberate here. A client plugin file may import only `../api`, `../shared.css`, and its own shared contract, as `eslint.plugin-boundaries.mjs` enforces. Promotion would therefore mean publishing the dialog through `web/src/plugins/api.ts`, which changes the published plugin surface. The two dialogs also differ in title and lines. Whether to promote is a call for the owner, and the spec that `09` writes records it.
- Confirming the dialog sends `delete` with `{ name }`. The selection moves before the send, but only when the deleted row is the selected one. It moves to the next row in the current order, or to the previous row when the deleted row was last, or to nothing when that row was the only one. A delete made from a row button names that button's row, and it leaves the selection alone unless that row is the selected one. Because selection is held by name, the highlight stays on the next name when the next list send drops the deleted row. If the delete later fails, the row stays and the highlight is on the next row. That is acceptable, and the feed explains the failure.
- The dialog holds a snapshot of the row (its name, schedule count, and open flag) taken when it opens, as `SchedulesTab.tsx` does with its `pendingDelete` entry. Confirm sends `delete` for that name even if the list has dropped the row in the meantime. The server's feed line answers it.
- Focus returns to the tab container, the same way `selectRow` in `ScriptsTab.tsx` returns it after a row click. A Run or Duplicate press returns focus when it sends its intent. Closing the dialog returns focus, whether by Delete or by Cancel. Without this, focus stays on a button or on the body, and the list keys stop working.
- The keyboard guard narrows in this subplan. Today `ownsKey` in `ScriptsTab.tsx` (lines 8-11) accepts a keydown whose target is the container, or whose target sits inside any `.scripts-row`, because its second clause calls `closest('.scripts-row')`. Once the row buttons exist, Enter on one of them would pass that guard and send `open` for the selected row, so the button would never press. The second clause changes so that the target must be the `.scripts-row` element itself. It is tested on the target's own class, with no walk up through its ancestors. The container and a row element keep their keys. A row button is a descendant of its row, so its keys belong to the button. A focused row button therefore does nothing for the list: Enter presses it, and Delete, Backspace, and the arrow keys are left to the browser. This supersedes the `closest` clause recorded in `product/plans/complete/scripts-tab-keydown-target.md`. The schedules tab's guard stays as it is, and the owner decides its row clause under `product/plans/complete/scripts-schedules-keyboard-divergence.md`.
- Delete or Backspace with no selection does nothing, as the source plan says. `keyMeaning` in `scripts-keys.ts` already maps both keys to `delete`, and the tab reads that meaning.
- Cancel, Escape, and a click outside leave the file in place and send nothing.
- A row whose file has gone is removed by the next list send, which is what the source plan requires. The client adds no logic for it.

## Proposed changes

- `web/src/plugins/scripts/ScriptRowActions.tsx` (new): renders the three buttons for one row. It takes the row's `name` and an `onAction` callback, which receives one of three actions: `run`, `duplicate`, or `delete`. The type of that action is exported from this file as `RowAction`. Each button is a `type="button"` element with `data-action` set to its action, a `title` of `Run`, `Duplicate`, or `Delete`, and an `aria-label` of the verb and the name. Each click stops propagation and calls `onAction`. The component sends no intent itself. The wrapping span has the class `scripts-row-actions`.
- `web/src/plugins/scripts/DeleteScriptDialog.tsx` (new): the modal with the title, the two optional lines, and the Delete and Cancel buttons. Its props are the row's `name`, `schedules`, and `open`, plus `onConfirm` and `onCancel`. It holds the selected option (Cancel by default), the window listeners, and the markup. It asks `scripts-delete-keys.ts` what each key means. Each optional line is a plain `div` with the class `scripts-delete-note`.
- `web/src/plugins/scripts/scripts-delete-text.ts` (new): pure functions that return the dialog text. `deleteTitle(name)` returns the title. `systemScheduleLine(count)` returns the schedule line for a count of 1 or more, and nothing for 0. `openEditorLine(open)` returns the open line when `open` is true, and nothing when it is false. It imports nothing.
- `web/src/plugins/scripts/scripts-delete-keys.ts` (new): a pure function that takes a raw key name and returns one answer: `confirm` for Y, `cancel` for N and Escape, `choose` for Enter, and `toggle` for Left and Right. Any other key returns nothing. The function lowercases the key itself, so Y and y both confirm. It imports nothing.
- `web/src/plugins/scripts/scripts-keys.ts` (from `06`): gains `nameAfterRemoval(rows, name)`. It returns the name of the next row in the current order, or the previous row's name when the removed row was last, or nothing when it was the only row. It imports nothing.
- `web/src/plugins/scripts/ScriptRows.tsx` (from `06`): each row gains the `ScriptRowActions` column, rendered after the name and the clock marker. The component takes one more callback, `onRowAction(name, action)`, and passes it to each row's column with that row's name. It currently takes `rows`, `selectedIndex`, `onSelect`, and `onOpen`.
- `web/src/plugins/scripts/ScriptsTab.tsx` (from `06`): the second clause of `ownsKey` changes as the design decisions say. Delete and Backspace with a selected row open the dialog for that row, and the open dialog holds the row's snapshot in a pending state. The `onRowAction` handler sends `execute` and `clone` with `{ name }` and returns focus to the container. For `delete`, it opens the dialog for the named row and does not change the selection. Confirming moves the selection, sends `delete`, clears the pending state, and returns focus. Cancelling clears the pending state and returns focus. The planned size is about 130 code lines, below the 170 threshold that `06` set and well below the 200-line limit, so no extraction is needed now. If the file passes 170, the pending state and its handlers move into `web/src/plugins/scripts/useScriptDelete.ts`, the hook file name the repo uses for its hooks (`web/src/pickers/useAppThemePicker.ts` is one example).
- `web/src/plugins/scripts/scripts.css` (from `06`): `.scripts-row-actions`, which is transparent and muted, turns to `--fg` on hover, has `cursor: pointer`, and does not shrink (`flex-shrink: 0`), so the name truncates first. `.scripts-delete-note` is muted. The header's button rule is scoped under `.scripts-header`, so it does not reach row buttons, and the row buttons need their own rule. The dialog adds no modal rules, because `theme.css` supplies them.

## Tests

- In `web/src/plugins/scripts/ScriptRowActions.test.tsx` (new): each button calls `onAction` with its action, and the row name is part of its accessible name, such as `Run deploy`. The tooltips are exactly `Run`, `Duplicate`, and `Delete`. A click does not reach a parent element's click handler, which the test checks with a spy on a wrapping element. This file asserts no intents, because the component sends none. The intent assertions are in `ScriptsTab.test.tsx`.
- In `web/src/plugins/scripts/scripts-delete-text.test.ts` (new): the title for a name. The schedule line for 0, 1, and 2 schedules, with the singular and plural forms. The open line for `open` true and false.
- In `web/src/plugins/scripts/scripts-delete-keys.test.ts` (new): Y and y confirm. N and n cancel. Escape cancels. Enter chooses. Left and Right toggle. Every other key, such as Tab or a letter, returns nothing.
- In `web/src/plugins/scripts/scripts-keys.test.ts` (from `06`, extended): `nameAfterRemoval` returns the next row for a removed row in the middle, the previous row for a removed last row, and nothing for a removed only row.
- In `web/src/plugins/scripts/DeleteScriptDialog.test.tsx` (new): the title and the lines render from the given values. A zero count and a false flag leave their lines out. Cancel starts selected, and the selected button carries the `selected` class. Clicking Delete confirms, and clicking Cancel cancels. Cancel, Escape, and N close without sending. Y confirms. Enter runs the selected button, and Left and Right toggle it. A key with no answer is swallowed and does not reach a listener on the tab behind. A key pressed on the tab behind reaches the dialog. Unmounting releases the keyboard. A click outside the dialog is swallowed and does nothing else, and a click inside it is left alone.
- In `web/src/plugins/scripts/ScriptsTab.test.tsx` (from `06`, extended):
  - The existing test "sends nothing and leaves the selection in place on Delete and Backspace, without preventing their default" (lines 203-213) is split. The no-selection half stays as it is: with no selection, Delete and Backspace send nothing and are not prevented. The selection half is replaced by the dialog cases below, because a selected Delete now opens the dialog and is prevented.
  - Delete and Backspace with a selected row open the dialog for that name, which the test checks by the title text `Delete runscript "b"?`, and they send nothing.
  - Confirming a delete sends `delete` with that name.
  - After a confirmed delete of a selected row in the middle of the list, the selection moves to the next row.
  - After a confirmed delete of the last row, the selection moves to the previous row.
  - After a confirmed delete of the only row, nothing is selected.
  - A confirmed delete of a row that is not selected leaves the selection where it was.
  - After a rerender that drops the deleted name, the highlight is still on the next name.
  - After a confirm or a cancel, `document.activeElement` is the `.scripts-tab` container.
  - Run sends `execute`, and Duplicate sends `clone`, each with the row's name, from a click on that row's button. A button click leaves the selection on the row that was selected before.
  - A Delete button click opens the dialog for its own row and not for the selected row, and sends nothing.
  - With `a` selected, Enter pressed on the Run button of row `b`, using `userEvent` so the native press runs, sends `execute` with `{ name: 'b' }` and does not send `open`. This test fails while the guard still uses `closest`, because the container then sends `open` for `a` and prevents the press. It passes once the second clause is narrowed.
  - Enter pressed on a row's Delete button opens the dialog for that row and sends nothing.
  - ArrowDown pressed on a focused row button leaves the selection where it was.

## Verification

Run `./scripts/run.mjs check-diff` during development. Lint enforces the import rule: the dialog and the action column must not import from `../schedules` or `../sessions`, and `eslint.plugin-boundaries.mjs` rejects those imports in client plugin files. Reading the new imports is a second look at the same rule.

Then do a manual check in a project with at least two runscripts, one of them used by a system schedule. Open `scripts`, press Run on the second row, and confirm its lines run in the system shell and nothing else appears. Press Duplicate, and confirm `<name>-2.rs` appears within about a second and opens in an editor. Tab to a row's Delete button, press Enter, and confirm the dialog names that row and shows the schedule line. Press N, and confirm the file stays and the highlight does not move. Select a row, press Delete, then Y, and confirm the file is gone and the highlight is on the next row.
