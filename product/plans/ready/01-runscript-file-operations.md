# Runscript file operations for the scripts tab
**Complexity: 4/10** — one existing module, but the Git-exclusion split sits under every existing runscript read and catalog call, and the exclusive-create rule must hold for both create and clone.

## Goal

Add to `src/schedule/system/runscript-files.ts` the file operations the scripts tab needs: a public directory setup for when the tab opens, the raw file text on `readRunscript`, a listing that skips the Git step for the tick, and delete, clone, and untitled create. Every existing caller keeps its current behavior.

## Design decisions and dependencies

This subplan depends on nothing earlier. `03-runscript-tick-refresh` and `04-runscripts-topic-and-actions` import its exports, so this subplan lands before them. `02-shared-runscript-execution` can land before or after it. `execute` (`src/commands/execute.ts`), `edit` (`src/commands/edit.ts`), `create script` (`src/commands/create.ts`), completion (`src/controller/completion.ts`), and system schedule firing (`src/schedule/system/firing.ts`) keep calling the same functions and get the same results. The `schedule system ... script` add (`src/commands/schedule.ts`) reads only `exists` from `readRunscript`, and the state listing (`src/state/listings.ts`, `cachedRunscripts`, read by `src/schedule/manager.ts`) gets the same names from `catalogRunscripts`.

- The Git-exclusion step stays on every path that reads, catalogs, or creates runscripts. `product/specs/scheduling.md` requires it for reads and cataloging (its durable system schedules paragraph says that inspecting a runscript for reading or cataloging ensures both paths are ignored), and `product/plans/complete/exclude-runscripts-on-execution-only-paths.md` sets that boundary. Creation has it today through `scriptsDirectory`, and it keeps it. The step becomes its own function, `excludeScriptsFromGit`, which `scriptsDirectory` still calls, so the listing can run without it. The reason is cost: `ensureSystemScheduleExcluded` runs at least five `git` processes per call in a Git project (`rev-parse --show-toplevel`, two `ls-files`, two `check-ignore`), so a tick that called it would spawn those once a second for every open scripts tab.
- One listing serves both paths. `listRunscriptNames(projectRoot)` is exported and skips the exclusion step. `catalogRunscripts` runs the exclusion and then returns that same list, so the sort-and-filter rule has one definition.
- `ensureScriptsDirectory(projectRoot)` is exported. It runs `excludeScriptsFromGit` first and then the existing private `makeScriptsDirectory`, whose body does not change. That is the order `createRunscript` uses today. Exclusion failures keep their current handling: they are written to stderr and do not stop the directory from being made, as the spec says for exclusion failures.
- `readRunscript` gains a `text` field, the raw file contents, or an empty string on both of its missing-file returns. `lines` is parsed from that same `text`, so the two cannot disagree. Clone needs the comments and blank lines that `parseRunscriptText` drops. The existing callers listed above ignore the field.
- `deleteRunscript(projectRoot, name)` calls `readRunscript` first, so a symlink or non-regular file throws before anything is removed. It returns `true` when it removed a file and `false` when the file was already absent, including when the unlink itself reports `ENOENT` after the check passed. Other unlink errors propagate. An invalid name throws, as `readRunscript` does.
- `cloneRunscript(projectRoot, name)` reads the source through `readRunscript`. It returns `undefined` when the source is absent. An invalid name, a symlink, or a non-regular source throws, as `readRunscript` does. Otherwise it picks the target with `nextFreeName` on `<name>.rs`, passing the runscripts directory as the directory argument. The source exists at that point, so `nextFreeName` starts counting at `-2` and then `-3`. It writes the raw `text` through the exclusive-create helper and returns the new name without its `.rs` extension, the same form `createRunscript` takes. If the exclusive create finds the target taken, the function throws and writes nothing. That covers a race, and it covers a dangling symlink, which `nextFreeName` reads as free. The function never tries the next number in that case. Rejected: building `<name>-2` by hand, which would duplicate `nextFreeName`'s counting.
- `newUntitledRunscript(projectRoot)` first calls `ensureScriptsDirectory`, so the directory is checked and made before `nextFreeName` looks in it. It then picks `untitled.rs` through `nextFreeName`, strips the extension, calls `createRunscript` with the result, and returns the name without its extension. If a race makes the name taken, `createRunscript` returns the existing file, and the function returns that name without overwriting it. If `createRunscript` throws, the function sets a `runscriptName` property on that same error to the chosen name and rethrows it, so the caller can name the file in its failure text. Errors from `ensureScriptsDirectory` and `nextFreeName` propagate without that property, because no name has been chosen yet.
- The exclusive create is written once and used by `createRunscript` and `cloneRunscript`, so the `wx` flag and its `EEXIST` handling are not duplicated.
- The runscripts directory path is computed by one private helper, `runscriptsDirectoryPath(projectRoot)`, so `nextFreeName`, the reads, and the writes all agree on it. Every file path is built from it. The `.janissary` literal is written only in that helper and in the two state-directory checks, because the file already repeats that literal four times, and `sonarjs/no-duplicate-string` (threshold 5 in `eslint.config.mjs`) would flag a fifth.
- A symlinked or non-directory `.janissary` keeps throwing from `assertDirectory`, as it does today. Callers decide what that means. The tick treats it as an empty list, and the actions report it.

## Proposed changes

In `src/schedule/system/runscript-files.ts`:

- Split `scriptsDirectory` into two private functions. `excludeScriptsFromGit(projectRoot)` holds the existing try and catch around `ensureSystemScheduleExcluded`, with the same stderr line. `inspectScriptsDirectory(projectRoot)` holds the existing two `assertDirectory` checks and returns the path and whether it exists, with no Git. `scriptsDirectory` calls the exclusion and then the inspection, so `readRunscript` and `createRunscript` run what they run today.
- Add the private `runscriptsDirectoryPath(projectRoot)` helper described under Design decisions. The inspection, the reads, and the writes all use it.
- Add `listRunscriptNames(projectRoot)`, exported. It calls `inspectScriptsDirectory` and returns the sorted valid runscript names by the filter rules `catalogRunscripts` already applies. Symlinks, directories, non-`.rs` files, and invalid names are left out. It throws what `assertDirectory` throws, and it runs no Git.
- Make `catalogRunscripts` call `excludeScriptsFromGit` and then return `listRunscriptNames`. Its behavior and callers do not change.
- Export `ensureScriptsDirectory(projectRoot)`, which calls `excludeScriptsFromGit` and then `makeScriptsDirectory`. `makeScriptsDirectory` stays private and unchanged.
- Add the `text` field to the object `readRunscript` returns, on its existing return and on both missing-file returns.
- Add a private exclusive-create helper that writes a new file with the `wx` flag. It returns `true` when it created the file, `false` when the path already exists (the `EEXIST` case), and rethrows any other error. `createRunscript` writes its empty file through it and, on `false`, validates the existing entry through `readRunscript` as it does today. `cloneRunscript` writes the copied text through it and throws on `false`.
- Add `deleteRunscript`, `cloneRunscript`, and `newUntitledRunscript` with the behavior described under Design decisions. `deleteRunscript` returns a boolean, `cloneRunscript` returns a name or `undefined`, and `newUntitledRunscript` returns a name.
- Add `unlinkSync` to the existing `node:fs` import, and import `nextFreeName` from `../../editor/next-free-name.js`, with the `.js` extension.

## Tests

In `src/schedule/system/runscript-files.test.ts`, as added cases beside the existing ones. The file uses vitest `describe`, `it`, and `expect`, real temporary directories from `mkdtempSync(path.join(tmpdir(), '<label> '))` removed in a `finally`, and full-sentence test names. Real-Git cases follow `src/schedule/system/storage.integration.test.ts`, which runs `git init -q` in a temporary root through a local `execFileSync` helper. The race cases mock `nextFreeName` the way `src/state/listings.test.ts` mocks `catalogRunscripts` (a `vi.mock` factory around a `vi.fn`), with the `vi.fn` defaulting to the real function through `importOriginal`. Each race case therefore sets one `mockReturnValueOnce`, and the other cases run the real counting. One existing assertion changes: line 17 checks `readRunscript(root, 'missing')` with `toEqual`, so its expected object gains `text: ''`. The other existing cases stay as they are.

- `ensureScriptsDirectory` creates `.janissary/` and `.janissary/scripts/` in a plain temporary directory. A second call changes nothing. A symlinked `.janissary` throws.
- In a real temporary Git repository, after `ensureScriptsDirectory`, `git check-ignore --quiet -- .janissary/scripts/` succeeds and `.git/info/exclude` contains the line `/.janissary/scripts/`. The end state does not show the order, so the order is checked by reading the diff, as the Verification section says.
- `listRunscriptNames` returns sorted valid names and leaves out invalid names, non-`.rs` files, directories, and symlinks. It writes nothing to `.git/info/exclude` in a Git repository.
- `readRunscript` returns `text` with full-line comments, inline comments, blank lines, and CRLF endings intact, and its `lines` are unchanged. For a missing file, `text` is an empty string.
- `deleteRunscript` removes a regular file and returns `true`. For a missing file it returns `false`. For a symlink it throws and leaves the link target in place. For a non-regular file, such as a directory named `<name>.rs`, it throws.
- `cloneRunscript` on `deploy` creates `deploy-2.rs`. With `deploy-2.rs` already present it creates `deploy-3.rs`. The copy's bytes equal the source's, comments and blank lines included. It returns `deploy-2`. A symlinked source throws. A missing source returns `undefined`. A dangling symlink at the target makes the call throw, and the link stays in place untouched.
- `cloneRunscript` never overwrites: with `nextFreeName` mocked to return a name that already exists, the call throws and the existing file keeps its bytes.
- `newUntitledRunscript` returns `untitled` on the first call and `untitled-2` on the second. With `nextFreeName` mocked to return a name that appears between choosing and writing, it returns that name and does not overwrite the file. A symlinked `.janissary` makes it throw before any name is chosen, and it creates nothing.
- The existing `createRunscript` cases pass unchanged.

## Out of scope

- No file watcher, no timer, and no change to the catalog rule, the name grammar, or `parseRunscriptText`.
- No change to any caller listed under Design decisions. Their code stays as it is, and their tests change only where this plan says.
- No topic, action, plugin, or UI code. The new functions are used by `03-runscript-tick-refresh` (the listing and the directory setup) and `04-runscripts-topic-and-actions` (the file actions), so until both land, some of them are exported but unused. ESLint does not flag that. `knip`, run only by `npm run check:full`, does.
