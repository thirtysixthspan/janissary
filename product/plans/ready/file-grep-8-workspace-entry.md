## Proposed changes

- Export async `grepWorkspace(root, args, deadline)`, taking a root string, the actual `FileGrepArgs` and a required absolute `Date.now()` deadline in milliseconds, returning `Promise<string>`. Export async `grepWorkspaceCommand(root, input)`, taking two strings and returning `Promise<string>`. These are the only new public functions. Do not add an optional deadline, signal, dependency-injection parameter or another result shape.
- Before any disk access or policy initialization, obtain modes from plan 5's pure `grepMatcherModes(args)` and call `patternError(args.pattern, modes)`. A non-null error returns exactly that engine message, a single newline, and `Use --literal to search for the text as typed.`, with no trailing newline. The engine message names the user's pattern, not the whole-word wrapper. Do not call the resolver, listing, reader or worker for this outcome, even with an already expired deadline or a missing/secret path.
- Only after no syntax error, call `compileMatcher` with the same pattern and modes. If it returns null, return exactly `Pattern matches empty text, so it would match every line: <pattern>.` with no filesystem/policy work. Treat null as the helper's refusal, without a second regex implementation or a narrower heuristic. The compiled object is used only for validation, never to test file contents. Literal punctuation stays valid; default regex is case-insensitive and case/word modes compose through the same scan-owned helper. Do not add the `u` flag.
- For a valid pattern, pass `withDeadline` a zero-argument async thunk invoking the whole `resolveGrepTarget(root, args.path)` call, using the caller's unchanged absolute deadline. The helper's result has `kind` equal to `completed` with `value`, or `timeout` without a value. On timeout return `formatGrepResult` with empty rows and the timeout ending immediately; do not await the losing operation. An already expired deadline invokes no resolver thunk, including its synchronous policy setup. Pattern diagnostics still take precedence because they run first.
- Narrow the completed resolver value, which is plan 6's `ResolvedGrepTarget`: `failure` returns its `text` unchanged, `skip` returns `formatGrepResult` with empty rows and undefined ending, and `directory` or `file` supplies the success-only `GrepSearchTarget`. Both successes carry canonical `root` and normalized `prefix`; directories carry `searchDir`, files `filePath`. Do not infer outcomes from missing fields, use another sentinel, format diagnostics again or repeat path/policy checks.
- For a successful target, create one discovery-stage `AbortController` and wrap the complete `discoverGrepCandidates(target, args.include, args.exclude, controller.signal)` invocation in a zero-argument thunk passed to a second `withDeadline` with the very same absolute deadline. The fourth argument is required; forward the success target and both strings unchanged. An already expired discovery deadline must not invoke the thunk or acquire a filter worker. Discovery returns `Promise<string[]>` of workspace-root-relative paths; it owns selected-directory anchoring, exact named-file selection, stable identical-path deduplication retaining first-occurrence order, and worker-owned filtering. Do not list/filter again, reconstruct prefixes, sort, deduplicate or bypass discovery for a named file.
- Enclose only the discovery stage in `try/finally` and abort its controller once on every completed, timeout or unexpected-error exit. On timeout select and construct the empty-row formatted timeout result before entering cleanup, then abort and return without awaiting losing listing/filter work or worker shutdown. On completion preserve the selected candidate array before aborting and proceed to scan only after discovery cleanup; on rejection retain the original error before cleanup and propagate that same error. A default abort supplies the standard `AbortError` reason; discovery rejects with that exact `signal.reason`, but an induced cancellation or late cleanup failure must never replace the result/error already selected by `withDeadline`. Plan 7's adapter owns worker termination on every acquired-worker exit, observes termination rejection and releases its listeners; this entry owns the discovery controller, not another worker or worker-disposal path.
- After completed discovery, call `scanFiles(target.root, discoveredPaths, args, deadline)`. Use the target's canonical workspace root, not its selected directory or file parent; forward the original args and absolute deadline without modification. Its `ScanResult` has required `rows` and required `ending`, whose value is `GrepEnding` or undefined. Return `formatGrepResult(result.rows, result.ending)` directly. Empty discovery uses the scan's normal empty-path behavior. Keep `GrepEnding` in the formatter and `ScanResult` in the scan, without duplicating either contract.
- Preserve the scan's first selected limit/timeout/slow ending and any earlier rows. Do not put an additional timeout race around scanning or the whole pipeline: scan already bounds setup, reads and matching and owns its internal reader/matcher controller and disposal lifecycle. An outer scan race could discard its partial rows. Its abort signal prevents late reader metadata continuations from starting contents. The discovery signal is already aborted before scan starts and must never be passed to scan or its reader/matcher.
- Reuse `withDeadline`'s losing-promise observation for resolver/discovery late resolutions and rejections. Late results cannot start discovery, scanning, content reads, matching or publication, or replace the settled timeout text. Resolver remains metadata-only with no controller or signal. Shared listing is unabortable and may continue metadata traversal; already-issued OS metadata calls may settle later. Plan 7 checks the discovery signal after listing and immediately before worker acquisition, so late listing cannot start a filter worker. Aborting an active hostile filter requests its termination promptly, keeping the parent's deadline callback runnable. Nonempty filters run solely in that feature-owned worker with unchanged `filterPaths` semantics; only exact-empty fields or empty paths may use its fast path. No parent glob compilation/evaluation, one-second filter timer or pattern cap is allowed. Synchronous policy setup, linear parent deduplication/selection/prefixing and worker transport still cannot be preempted by Node timers; retain that practical limit without claiming cancellation of already-issued OS metadata or redesigning shared listing/search/filter modules.
- Propagate unexpected resolver, discovery or scan rejections that win before timeout unchanged. Do not catch broadly and convert them to no matches, timeout or slow. Resolver domain failures already arrive as values; only the scanner distinguishes the typed matcher deadline. The formatter owns the no-match sentinel, preview and exact single trailer, including after empty rows.
- The command entry calls `parseFileGrep(input)` once and returns its error text on malformed input without calling workspace services. Otherwise create one fresh `Date.now() + GREP_TIMEOUT_MS` deadline and delegate to `grepWorkspace`. The constant remains defined/exported only by `scan.ts`. Callers that already parsed arguments use `grepWorkspace` and create their deadline once at the local typed or remote-operation boundary; no stage resets or extensions occur here.
- Matching remains line-oriented, splits only on newline, uses one row per matching line and the first span, keeps trailing CR while matching and removes it only in previews. `^`/`$` are per-line and `$` does not match before the CR in CRLF content. Preserve this through the reader/scan/formatter integration rather than changing shared matching.
