# End-to-end verification

**Complexity: 1/10** — 0 added lines, 0 production files, 2 requirements (p=2.35). The work is a diff-scoped run plus the source plan's manual walk, with any defect routed to the subplan that owns it.

## Goal

Show that the feature works in the running app and that every diff-scoped check passes. This is the last subplan and runs after every code, test, and documentation change is in.

## Design decisions and dependencies

This subplan depends on every earlier subplan, from `./product/plans/ready/add-a-folder-icon-button-in-the-editor-tab-1-reveal-target-and-blocked-state.md` through `./product/plans/ready/add-a-folder-icon-button-in-the-editor-tab-12-specs-help-and-docs.md`, and on all of them still being uncommitted (see the first bullet). It edits no source, test, spec, or doc file. The source plan is `./product/plans/complete/add-a-folder-icon-button-in-the-editor-tab.md`; it is moved there unchanged when this decomposition finishes, and this is its "Verification" section expanded into an ordered walk.

- `$janissary/scripts/run.mjs check-diff` is the development gate. For a change touching both `src/` and `web/src/`, it lints the changed files, typechecks both projects incrementally (`typecheck:diff` runs `tsconfig.json` and `web/tsconfig.json`), and runs `test:diff:server` and `test:diff:web` (`package.json:46`–`:47`), which are `vitest run --project server|client --changed`: tests selected by import graph. `scripts/changed-files.mjs:8` (`changedFiles`) builds that file list from `git diff HEAD` plus `git ls-files --others`, so it sees only uncommitted and untracked work. The gate is meaningful only while the whole decomposition is still uncommitted; if any part was committed, say so in the report and lean on the by-path runs. The full `npm run check` is the human's once-at-the-end gate and is not run here.
- The named test files in Tests are run by path as well, because `--changed` selects by import graph and can miss a test whose subject changed indirectly. Run them with `npx vitest run --project server <files>` and `npx vitest run --project client <files>`, one invocation per project.
- `src/commands.test.ts` (`prints all key tables only from help keys`, line 135) renders the shipped `help/` pages through `help keys`, and `scripts/check-diff.mjs:32` (`touchesHelp`) makes any `help/` Markdown change run it through the `test:help` tool at `:68`–`:70`. It proves the edited page still loads; it does not assert the new row's text, so step 10 reads the rendered output against the wording. `src/help-pages.test.ts` exercises the loader against temporary directories only and never reads `help/keys.md`, so it neither covers nor can fail on this edit. `npm run docs:build` is the only check that catches a broken link in the edited `documentation/` pages.
- The walk runs in an app built from the checkout that holds the uncommitted change, started through `ai/tasks/workspace/start-application.md` with `<project-dir>` set to that checkout. Inside that app, `$root` is the checkout and `$workspace` is `$root/.janissary/workspace` (`workspacePath` in `src/workspace/index.ts:42`), so `src/file-navigator/remote/file-cache.ts` resolves under `$root`. Do not reuse the human's live instance: the lock is per project directory (`lockPath` in `src/instance-lock.ts:54`), and a different `<project-dir>` is a second, isolated instance. Commands expand only `$root` and `~` (`expandUserPath` in `src/paths.ts:15`), never `$workspace`; type a clone path as `$root/.janissary/workspace/<name>/...`.
- The walk needs three optional fixtures: a workspace clone under `$workspace` for step 2, a configured remote host with a workspace for steps 6 and 7, and a GitHub-synced file for step 9. When one is missing, record that step as not reached in the walk's result notes and name its covering tests: step 2's clone half with `open.test.ts` and `reveal-editor.test.ts`'s clone cases, steps 6 and 7 with `reveal-editor.test.ts`'s blocked and remote cases and `FileNavigatorTab.test.tsx`'s focus cases, and step 9 with `revealTargetFor`'s git-sync cases. Never mark a step passed from a test alone.
- A defect the walk finds is recorded as a repair against its owning subplan: the reveal target and blocked projection in `01`, open-or-retarget at a root in `02`, local reveal in `03`, remote reveal in `04`, the RPC in `05`, the held selection in `06`, the acknowledgement in `07`, the button in `08`, the chord in `09`, navigator focus in `10`, sidebar selection in `11`, and wording in `12`. Record the step number and the owning subplan in the walk notes. The orchestrator reruns the affected walk steps after a repair.
- The walk observes; it does not fix. Anything outside this feature goes to `product/backlog/`, not into this change.
- No file is written by this subplan, so the 200-line limit does not apply to it. The walk report, including not-reached steps and routed defects, is the output. A repair that adds code is subject to the owning subplan's limits.

## Verification

Pass criteria:

- `$janissary/scripts/run.mjs check-diff` exits 0 for the whole uncommitted change, and the server and client files in Tests pass by path.
- `src/commands.test.ts` passes and `npm run docs:build` exits 0.
- Every reachable manual step below produces its stated result; every unreachable part of a step is recorded as not reached and names the tests that cover that behavior.
- No reveal outcome reports a notification. Each is a visible tree change or silence.

Manual walk, in this order. Start the app as Design decisions describes, and stop it through `ai/tasks/workspace/stop-application.md` when the walk ends.

1. Local open. Close every file navigator, then from an agent tab's command bar run `edit $root/src/file-navigator/remote/file-cache.ts`. `edit` opens the editor without creating a navigator (`src/commands/edit.ts:11`); do not open the file from a navigator, or the fresh-open rule is not what you are checking. Click the folder button in the editor's metadata row. A navigator opens docked in the left sidebar, rooted at `$root`, with `src`, `src/file-navigator`, and `src/file-navigator/remote` expanded and `file-cache.ts` selected. Arrow keys move the tree's cursor, and the editor is still visible in the centre. Proves the button, the local `$root` rule, the ancestor expansion, the selection, the left-dock placement (`setDock(..., 'left')` in `src/file-navigator/open.ts:72`), and the focus.
2. Retarget and the chord. With the step 1 navigator still open at `$root`, open a file inside a workspace clone without touching that navigator: from an agent tab's command bar run `edit $root/.janissary/workspace/<name>/<path>` (the app displays this as `$workspace/<name>/<path>`; a command does not expand `$workspace`). Switch to that editor and press Cmd+Shift+E. The docked navigator retargets in place to `$workspace/<name>`, keeps its label and dock placement, clears its old `src/...` expansions, and selects the file. Proves the chord, the clone-first root rule, and the retarget. If no clone exists, run the same chord and retarget from a second local file under a different `$root` subdirectory, and record only the clone-first half as not reached; name its covering tests (Design decisions).
3. Ctrl+Shift+E. In the same buffer, press Ctrl+Shift+E. The selection extends to the end of the line and no navigator change occurs. Proves the preserved Ctrl meaning (`ctrlAction` in `web/src/editor/keys.ts`).
4. Centre strip. Click the navigator header's dock-cycle control (`web/src/file-navigator/FileNavigatorHeader.tsx:77`, `.files-dock-cycle`) until the navigator sits in the centre strip, switch back to the editor, and click the button. The navigator becomes the active tab with the file selected and focused, and the editor goes behind it. Proves that a centre-strip navigator is brought forward: `setActiveTabOp`'s guard (`src/tab/navigation-commands.ts:25`) skips only docked tabs, and the selection and focus still land.
5. New file. In a shell tab run `mkdir -p $root/temp` if the checkout has no `temp` directory, then from an agent tab's command bar run `newfile $root/temp/untitled-reveal-check.md`. The server resolves a free name in `$root/temp`, so the tab may be named `untitled-reveal-check-2.md`; assert the button, not the name. Its button reads `Reveal in file navigator (save the file first)` in both tooltip and accessible name, is dimmed, and does nothing on click or Cmd+Shift+E. Type a character, then save it (Cmd+S). The button becomes the enabled `Reveal in file navigator`; clicking it retargets the most recently focused navigator to `$root`, expands `temp`, and selects the file. Proves the unsaved state and its clearing on save (`newFile: false` in `src/editor/save.ts:79`).
6. Orphaned remote file. With a remote navigator open, open a nested file from it in an editor, then close that navigator. The editor's button reads `Reveal in file navigator (reopen from a remote navigator)` in both tooltip and accessible name, is dimmed, and is inert on both click and Cmd+Shift+E. Proves the no-route projection and that it is recomputed on the next broadcast rather than stored: the editor is not reopened. This and step 7 need a configured remote host with a workspace; if none is available, record both as not reached and name their covering tests (Design decisions).
7. Remote reveal. Dock a second, local navigator on an unrelated root (the step 5 navigator will do) and note its root. Open a nested file from a remote navigator, collapse everything in that navigator, then click the editor's button. The remote navigator's ancestors expand as their listings arrive, the file is selected, and its tree has focus; the local navigator does not move and is not retargeted. Click into the editor's buffer, then use the navigator header's dock-cycle control to dock and undock the remote navigator: focus may stay on the control you clicked, but it never jumps back into the tree. Then move that navigator's root into a sibling folder of the file's directory (Enter on its `..` row, then Right Arrow on the sibling until it becomes the root) and click the button again: the navigator reroots to its remote workspace root (`remoteRoot`) and selects the file there. Proves the remote source navigator, the no-retarget rule, the held selection, the acknowledgement, and the outside-current-root reroot. If no remote host is available, record this step as not reached and name its covering tests.
8. Missing file and ancestor. In a shell tab run `mkdir -p $root/temp/reveal-missing`, then from an agent tab's command bar open `edit $root/temp/reveal-missing/note.md`, type a character and save it once, then delete the directory from the shell tab (`rm -r $root/temp/reveal-missing`). Click the editor's button. The navigator opens or retargets to `$root`, expands `temp`, drops the vanished `temp/reveal-missing`, selects nothing, and reports nothing. Proves the silent missing-file outcome and the missing-ancestor prune, with no notification for either.
9. GitHub-synced file, if a synced editor is available. Click the button and confirm the navigator roots at `$workspace/git-sync` (`SYNC_WORKSPACE_NAME` in `src/git/sync.ts:11`) and selects the file being edited, with the main checkout not shown in that navigator. Proves the unchanged local rule for a synced file. If no synced file is available, record the step as not reached and name `revealTargetFor`'s git-sync cases.
10. Help and docs. From an agent tab's command bar run `help keys`: the `Cmd+Shift+E` row appears under **Editor tab controls**, directly after the save row, and reads `Reveal the file in the file navigator`. Read the editor page's new section in the docs preview (`npm run docs:dev`) and follow its link to the file navigator page. Hover the folder button in the step 5 editor and confirm its tooltip matches the spec word for word. Proves the help row renders, the docs page reads correctly, and the spec's wording matches the component; `npm run docs:build` already proves the links resolve.
