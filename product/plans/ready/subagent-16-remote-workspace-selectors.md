# Resolve tasks and ACP sessions in remote run clones
**Complexity: 7/10** — ~80 added production lines, 11 existing files, 14 requirements, 75 scenarios (p=7.14)

## Goal

Add an optional `workspace` run-clone label to `acp-open`, `agent-resolve`, `RemoteAcpOptions` and the existing near-side task request methods. A selected ACP session spawns and runs its file commands in that ready clone, and selected task/skill resolution uses the same clone. Absence preserves the provisioned main workspace.

Source: `product/plans/complete/subagent.md`, preserved unchanged as the canonical feature record. This is ordered subplan 16 of 23.

## Decisions and dependencies

Dependencies: `product/plans/ready/subagent-6-remote-provider-session-ids.md` supplies provider-ID notifications and owns the feature's single protocol-version increment; `product/plans/ready/subagent-8-workspace-loop-foundations.md` supplies the root-taking command runner; `product/plans/ready/subagent-14-remote-clone-service.md` supplies `ProvisionedWorkspace.runClones`, `RemoteRunClones.lookup` and `dispatchAcpFrame`; `product/plans/ready/subagent-15-remote-clone-frames.md` supplies clone requests and the channel's size-saving navigator extraction. Complete these before this unit. Extend their same unreleased protocol version and comment without another bump.

The selector contract is the Remote callers clause at `product/plans/complete/subagent.md:144`, beginning `Selector`. A selector names only a ready clone owned by this provisioned workspace's `RemoteRunClones`; it never names the main workspace, another peer's clone or a caller-supplied directory. `lookup` already validates labels and hides pending, releasing, failed, released and stopping entries. Use its result directly without filesystem discovery, waiting for readiness, normalization or fallback to the main directory. A previously opened ACP record keeps its selected directory even if later lookup changes; this unit adds no clone lease or release ordering.

Implement and verify only against existing repository code and the completed earlier dependencies. Other units own their own changes; references to them explain integration boundaries and do not authorize future API calls. Every new production module stays within 200 counted lines, source imports name defining modules directly with .js extensions, and shared wire definitions are imported by the client.
