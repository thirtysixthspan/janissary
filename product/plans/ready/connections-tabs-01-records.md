# Connections session records

**Complexity: 5/10** — a bounded server record subsystem with versioned persistence, prompt-state transitions, crash recovery, retention, and manager lifecycle wiring; no transport or UI integration.

## Goal

Add project-scoped durable records for tracked ACP sessions and agent runs. A record survives its tabs, ACP process, and application restart; closed records expire after 30 days. Deliver the storage service and its tested contracts first. Production sessions do not start recording until subplan 02 wires the feeds.

Preserve that order. The later documentation pass consolidates feature-wide docs; this step documents only the backend contract it delivers.

- Persist one versioned JSON record at `.janissary/connections/<id>.json`. Startup recovery closes leftover open ACP records as `Closed` and agent records as `Terminated`. - Keep all methods synchronous, matching `createManagers` construction and the later synchronous topic actions. Persistence uses the existing synchronous atomic writer. No timers, subscriptions, subprocesses, label-keyed state map, or loaded-window registry are needed in this service. Records are keyed by their durable UUID.

## Record and API contracts

### Model, identity, titles, and status

- Define `AcpRecordSource`, `AcpRecordOutcome`, `AcpRecord`, `AcpRecordBlock`, `AcpRecordEntry`, `AcpRecordRow`, and `AcpRecordWindow` in the new `src/acp-records/types.ts`. These are server service shapes at this checkpoint, not a new RPC or plugin API. Subplan 03 exposes the appropriate projections through the existing shared protocol boundary instead of introducing browser-side copies.
- `begin(source)` takes a discriminated source: `kind` is `acp` or `agent`; both include `model`, `ownerLabel`, and `ownerName`; an agent also includes `runId` and `taskPath`. `ownerLabel` is the original stable tab label; `ownerName` is a copied display name (`title ?? label`) supplied by the feed, not a live Tab reference. Retain this provenance after the tab disappears and never resolve a closed record against a new tab reusing its label. The agent `runId` is linkage for the later terminate action, not the record id.
- Schema version 1 stores `schemaVersion`, `id`, the source metadata, `title`, `startedAt`, `updatedAt`, optional `endedAt` and `outcome`, and chronological `blocks`. A block has `prompt`, `startedAt`, chronological `entries`, and optional `answer` and `endedAt`. Each entry has `kind`, `text`, and its first chunk's `timestamp`. Use finite nonnegative epoch milliseconds throughout. Record `endedAt` and `outcome` occur together; a completed block's answer and end time occur together. An unanswered block may remain only as the newest block, including when a session closes during it.
- Derive status, never persist a separate mutable status field. An open core ACP record with no prompt is `Idle`; it is `Running` while its newest block has no answer, then `Idle` after settlement. An open agent record is always `Running`, including before its first prompt and after `answer` until `close`. This source decision 21 distinction overrides the draft's incorrect shared `Idle` rule. Terminal outcomes are `Closed`, `Completed`, `Failed`, and `Terminated`.
- Before its first prompt, a core record's title is `ACP`. Its first accepted prompt fixes the title to `ACP: <first line>`, with the whole title capped at 60 JavaScript string characters, including the prefix. Strip a CR line terminator and trim that first line; an empty first line keeps `ACP`. Do not retitle on later prompts. An agent title is `Agent: <task filename>`, using the task path's final filename, without the ACP-only cap. Preserve the original prompt and activity text separately from title formatting.
- Each accepted begin/prompt/activity/answer/close uses the injected clock, defaulting to `Date.now`. Clamp each mutation time to at least the record's previous `updatedAt`, and use that time for both `updatedAt` and any block/entry/end timestamp created by the mutation. This preserves chronological validation if the clock moves backwards. `startedAt` never changes, and the first close fixes `endedAt`. Sort rows by descending `updatedAt`, then ascending id for deterministic ties. `rows()` contains only recorded ACP/agent summaries, not other live connection kinds.

### Mutations and reads

| Method | Contract |
| --- | --- |
| `begin(source)` | Validate required nonempty metadata, mint and return a UUID, create the empty record, and persist its header immediately. A session that has never completed a prompt must still be recoverable after a crash. Invalid source input throws `Invalid ACP record source.` without adding a record or file. |
| `prompt(id, text)` | Return true only when a non-whitespace prompt starts on an open record without an unanswered block. Append one block; preserve the supplied text. Reject overlapping prompts without queuing or disturbing the running block. Persist header/title metadata and already-completed blocks at this boundary, not the new in-flight block. |
| `activity(id, kind, text)` | Return true only for nonempty text of an existing activity kind on the open unanswered block. Preserve whitespace-only chunks because spaces can be meaningful between streamed words. Concatenate text verbatim only when the immediately previous entry has the same kind and that kind is `message` or `thought`. Keep the first entry timestamp. Kind changes, non-foldable kinds, and prompt boundaries break a fold. |
| `answer(id, text)` | Settle only the current unanswered block, assigning its answer and end time, and persist the record. An empty string is a valid settled answer, so distinguish absence from falsiness. Errors/cancellation can be passed as settlement text by the later feed; settlement alone does not close the session or change an agent's terminal outcome. A second answer is a no-op. |
| `close(id, outcome)` | First close wins; set terminal outcome and end time, then persist all blocks, including any unanswered block's current activity. Core records accept `Closed`; agent records accept `Completed`, `Failed`, or `Terminated`, plus `Closed` for the required disposal fallback. Reject an incompatible outcome. Closing never invents a final answer or discards partial activity. |
| `delete(id)` | Return false for a missing or open record. For a terminal record remove its file first, then remove the in-memory record and return true. An already-absent file counts as successful removal, including when every save failed. Another removal failure leaves the row and file eligible for retry. No confirmation UI belongs in this API. |
| `rows()` | Return detached summaries containing id, source kind, title, model, owner label/name, optional run id, start/update/end times, and derived status. Include metadata needed by the later host catalog without prompt text or entries. |
| `window(id, count)` | Return a detached metadata projection plus chronological `blocks`, `totalBlocks`, `offset`, and `hasOlder`, or undefined for a missing id. Default count is 20; require a positive safe integer when supplied, otherwise throw `Invalid ACP record window count.`. Select the newest min(count, totalBlocks) blocks, including a running block. `offset` is their zero-based start position and `hasOlder` means offset is positive. No read emits an event or remembers a requested size. |

Except for the explicit validation errors above, all id-taking mutators return false with no change for unknown ids, invalid ids, closed records, or inapplicable operations. `close` and `delete` have the terminal-record exceptions stated in their rows. Successful prompt/activity/answer/close return true. A valid `window` read of an unknown or invalid id returns undefined. Never interpolate an unvalidated id into a filesystem path. Return copies of nested blocks/entries and source metadata so callers cannot mutate the recorder by editing projections.

The later topic owns which open tabs requested windows and the requested counts. Its initial count is 20, increasing by 20 for `loadOlder`; calling `window` here is a pure suffix read. This step neither broadcasts every full record nor adds a dependency on a plugin that does not exist yet.

### Persistence, startup, errors, and disposal

- Split storage into `AcpRecordStore` in `src/acp-records/store.ts` and runtime validation in `src/acp-records/validation.ts`. Store construction accepts `projectDir` and an injectable atomic writer/remover for failure tests. The root is `path.join(projectDir ?? process.cwd(), '.janissary', 'connections')`. Create it lazily on the first write; missing storage is an empty history, not a warning. Use `atomicWriteFile` for pretty JSON with a trailing newline. Do not create workspaces, trust entries, migration files, an index, or configuration.
- Scan only regular UUID-named `.json` files. Ignore directories, symlinks, temporary files, and unrelated names. Validate parsed `unknown` against schema version 1, source discriminants, required strings, UUID identity matching the filename, activity kinds, timestamps/order, block settlement pairing, and allowed source/outcome combinations. Reject arrays/null, malformed JSON, and unknown schema versions. Leave invalid files untouched and warn once per file for the manager instance; no speculative migration or deletion.
- Durability boundaries are begin, prompt metadata, answer, and close. While a prompt runs, its block and activity live only in memory; an answer writes the completed block. Ordinary close/disposal writes an unanswered block too. A crash can lose the in-flight prompt/activity but retains the record header, title, and previously completed blocks. This makes the source's completion-only block persistence and startup recovery compatible even for a never-used session.
- The manager constructor scans, recovers, and prunes synchronously before it can serve rows. Recover each still-open stored record as `Closed` for core ACP or `Terminated` for agent. Set `endedAt` and `updatedAt` to the greater of a single captured startup time and that record's previous `updatedAt`, without changing `startedAt` or completed history. Atomically rewrite that recovered record. Never restart a provider or reinterpret its old run/session id as live.
- Prune terminal records only when startup time minus `endedAt` is strictly greater than 30 days (30 × 24 × 60 × 60 × 1000 milliseconds). Exactly 30 days old and future-dated records stay. Use closure time, not last activity, filesystem mtime, or start time. Pruning runs at startup; this step adds no periodic expiry timer.
- The store propagates filesystem failures. The manager catches them per record so one bad file or failed recovery/prune cannot prevent construction or another record's recovery. A root scan failure reports once and yields an empty loaded history without deleting anything. A failed write preserves the latest in-memory result, marks that record dirty in nonserialized runtime bookkeeping, and retries at its next durability boundary or disposal. `begin` still returns its id and accepted state mutations still return true. A failed delete/prune keeps the record visible. Do not emit a second change event merely for a storage warning or successful retry with no state change.
- Accept an injectable `reportStorageError(id, detail)` callback, isolating a throwing reporter as `ConversationResponder.report` does. Default reporting is one stderr line: `warning: ACP record "<id>" <operation> failed: <reason>`. Use `scan` in place of the id for a root scan failure; `<operation>` is `read`, `scan`, `write`, or `delete`, and `<reason>` is `errorFirstLine(error)` from `src/error-text.ts:9`. A rejected record uses operation `read` and reason `Invalid or unsupported record`. This service does not invent a notification type or call UI-dependent notification code during partially constructed startup.
- `dispose()` is idempotent: flush already-dirty terminal records, close every remaining open record with `Closed`, attempt every save even when one fails, and mark the service disposed. Reads remain available afterwards; `begin` then throws `ACP session records are disposed.`, and other mutations return false. It owns no live ACP resource and never deletes retained records. It is not a tab-release participant.
- Add channel `connections` with event shape containing only type `changed` to `BusChannels`. Emit once after each actual accepted begin/prompt/activity/answer/close/delete mutation, including a memory mutation whose save fails. Each startup recovery and successful expiry deletion also emits once. Rejects, duplicate closes/answers, failed deletions, reads, and an empty or repeated disposal emit nothing. Disposal emits once per record it newly closes, not an extra batch event. Coalescing at 100 ms belongs to subplan 03, not this manager.
