## Proposed changes

1. Add `grep` to `FILE_SUBCOMMANDS`, retaining `policy.allows` filtering and `completeWord` sorting. `file ` offers glob/grep/read; `file g` now offers glob and grep without extending beyond g, `file gl` uniquely completes glob and `file gr` uniquely completes grep. A disabled grep child disappears without removing read/glob; a disabled file parent continues to suppress all arguments through the existing dispatcher guard. Do not add a second settings check in the grep helper.
2. Add `src/completion/file-grep.ts` exporting only `completeFileGrepArgument`, taking `cursor: CompletionCursor` then `root: string | undefined`, and returning `CompletionResult` synchronously, never null. Import it directly as `./file-grep.js` in file-read.ts and call it only after the existing file-command check when lowercased `preceding[1]` is grep. No global dispatcher route, command registry change or parser call is needed.
3. Keep state classification pure in private `grepArgumentState` in the same new module. It takes the complete `preceding` array as readonly strings and returns one of four literal states: flags, path-value, other-value or pattern. Scan from index 2. Exact lowercase `--path`, `--include`, `--exclude` and `--limit` consume exactly one following committed token; an unmatched final valued flag leaves the corresponding pending value state. Exact lowercase `--literal`, `--word` and `--case-sensitive` consume no value. The first other token, including a committed `--`, unknown flag or single-dash token, returns pattern permanently. A consumed value never becomes a switch, terminator or pattern, even if it looks like one. For example `file grep --include --word --p` may complete --path because --word was consumed as a value; plan 1's parser still refuses that malformed invocation. Do not add duplicate-flag, value or regex validation to completion.
4. Preserve the exact case boundary: committed file/grep keywords are case-insensitive through existing cursor/subcommand normalization, while committed flags are lowercase exactly. Never copy completeGlobArgument's preceding-token lowercasing. A committed `--PATH` or `--Literal` is an unrecognized token and ends flag completion. For current partial tokens, use completeWord unchanged with lowercase canonical candidates: `--p` completes --path, `--P` has no matches. Subcommand prefixes retain the same case-sensitive completion convention; accepting mixed-case committed keywords does not imply uppercased prefixes complete.
5. In flags state, only a current token starting `--` goes to completeWord with all seven canonical flags: --literal, --word, --case-sensitive, --path, --include, --exclude and --limit. Do not filter already used flags. A current `--` offers all seven because it is not committed; `file grep -- ` has a committed terminator and offers nothing. Empty tokens, plain pattern prefixes, single-dash prefixes and unmatched uppercase/unknown current prefixes remain unchanged.
6. Pending value state takes precedence over current flag-prefix completion. For path-value and a defined root, call completeFilePath(cursor, root) with default options, including files and directories. Keep its existing unique-file space, unique-directory slash and ambiguous common-prefix behavior; never use glob's directoriesOnly option. The root is the existing fileReadRoot, never cwd or a new root lookup. Completion does not enforce execution's workspace containment or add a separate filesystem filter.
7. Pending include/exclude/limit values always return unchanged, including empty values and values starting `--`. Once any committed pattern token or terminator has been seen, return unchanged for every current token, even flag-looking or path-looking text. No fallback to cwd paths is allowed in these states.
8. For path-value with undefined root, return unchanged before any path helper or filesystem access, including for absolute or tilde-prefixed current tokens. Remote tabs still receive subcommand and flag candidates; add no remote lookup or local fallback.
9. Return the existing CompletionResult shape throughout, preserving text after the cursor and the existing newCursor placement, match sorting and suffixes so the command bar's selection behavior continues to work. Keep read/glob argument behavior unchanged, including glob's existing case convention and directory-only path completion.

During implementation, add completion behavior to the `### File grep` section of `product/specs/acp.md` created by plan 12, after the existing `### File glob` anchor at `:139`. State flags-first suppression, lowercase flags, both path kinds, remote no-path behavior and disabled-subcommand behavior. `help/file.md` currently makes no completion claim, so this slice needs no help edit. Recheck that specific page after prerequisites land and change it only if their actual completion wording contradicts the behavior above; no speculative documentation expansion or generated documentation changes.
