# The `sql file` and `sql database` command grammar

**Complexity: 6/10** — ~30 added lines in two production files, 16 requirements and 24 test scenarios, driven by the keyword grammar, its two exact refusal lines and the path-resolution edge cases (p=5.98).

## Goal

Replace `sql [name] [left|right]` with explicit keywords: `sql file <path>` opens a database by filesystem path, `sql database <name>` opens one by registry name with all of today's name behavior, and bare `sql` keeps its last-opened-or-first choice. Unknown arguments and missing values get one exact usage line; a missing path gets one exact error line. No form docks, and every SQL tab opened by the command lands in the centre.

## Design decisions and dependencies

The source plan is `./product/plans/complete/sql-path.md`. This subplan depends on `./product/plans/ready/sql-path-1-connection-identity.md` (the browser can read a path) and `./product/plans/ready/sql-path-2-tab-opening.md` (`openDatabase` can open and title a path tab). Land it after subplan 2 (and so after subplan 1) and before subplan 4: subplan 4 deletes the `dock` parameter this plan still passes as `undefined`, so reversing the order breaks the typecheck. Subplan 4 (`./product/plans/ready/sql-path-4-dock-removal.md`) removes the now-dead dock parameter and manifest capability; subplan 5 (`./product/plans/ready/sql-path-5-payload-and-switcher.md`) adds the client marker.

- The grammar is inline in `runCommand`: trim the whole argument, take the text up to the first whitespace run as the keyword, compare it with the lower-case literals `file` and `database`, and take the remainder after that run, trimmed at the ends, as the value. A keyword with no separating whitespace (`file/path`) is not the `file` keyword and falls through to usage. Route the value to the file opener, the unchanged name opener, or the existing `lastOpened ?? databases[0]` choice. This replaces the old dock/name routing with a comparable amount of code, so `src/plugins/sql/activate.ts` (about 110 counted code lines with blanks and comments skipped, against the 200-line `max-lines` at `eslint.config.mjs:62`) stays under the limit; no new parser module is warranted. Drop `parseSqlArgument` from the `./shared-intents.js` import in `src/plugins/sql/activate.ts:11` when the function is deleted.
- `parseSqlArgument` is deleted from `src/plugins/sql/shared-intents.ts`, along with the imports of `parseDockArgument` and `Dock` that only it used. `parseDockArgument` itself stays in `src/plugins/api.ts` for launcher, schedules, conversations and the other plugins that share it. `isValidDatabaseName` stays for the `database` form and for the `isOpenIntent` guard the dropdown uses.
- Keywords are recognized in lower case only: `file` and `database` must match exactly as typed. This is a deliberate choice for the new grammar, not a carry-over — the old dock words were case-insensitive, because `parseDockArgument` (`src/plugins/dock-argument.ts:5`) lowercases its token, so `sql shop LEFT` docks today and will now report usage. Anything else — an old bare name such as `sql shop`, a removed dock word such as `sql left` or `sql right`, an upper-case `FILE`/`DATABASE`, or a keyword with no separating whitespace — falls through to `capabilities.rejectRequest('Usage: sql [file <path>|database <name>]')`, with no special-casing. A keyword with no value (`sql file`, `sql database`, or a value that is only whitespace) gets the same usage line and opens no tab. The value is the remainder after the keyword, trimmed at the ends and taken verbatim, so a path holding interior or repeated spaces survives; there is no trailing dock word to separate.
- A name that fails `isValidDatabaseName` still gets `Invalid database name "<name>".` from the existing branch, and a name the registry has never heard of still gets `UNKNOWN_DATABASE` from `openDatabase`. That is name behavior the `database` form keeps, not an unrecognized argument.
- The file form resolves the value with `path.resolve(process.cwd(), value)` — the same base `initDbDir(process.cwd())` uses for `.janissary/db/sqlite/` — independently of which tab the command was typed in, and checks it with `existsSync` from `node:fs` before opening. Both are Node built-ins, allowed by the plugin boundary in `eslint.plugin-boundaries.mjs`, unlike a host import such as `../connections.js`. A missing path rejects `No database file at "<path>".` and opens no tab; no file is created. The `<path>` in that line is the resolved absolute path that was checked, which makes the message identical for a relative argument and an absolute one.
- A path under `.janissary/db/sqlite/` is a path like any other: `sql file .janissary/db/sqlite/shop.sqlite` opens a path-keyed tab distinct from `sql database shop` even though both resolve to the same file. The grammar does no special-casing of that directory.
- All three routes call `openDatabase(..., undefined, capabilities, tabs)` for now, so the command never docks and the existing dock parameter stays alive until subplan 4. `dockTab` is consequently never reached from a command.

## Proposed changes

- `src/plugins/sql/shared-intents.ts`: delete `parseSqlArgument` and its comment block, and drop the now-unused `parseDockArgument` and `Dock` imports. Keep `isValidDatabaseName` and `isOpenIntent`.
- `src/plugins/sql/activate.ts`: drop `parseSqlArgument` from the `./shared-intents.js` import at `:11`, import default `path` from `node:path` and `existsSync` from `node:fs`, and rewrite `runCommand` to split the first word from the remainder, handle `file` and `database` as described, reject everything else with the usage line, resolve and check the path for `file` before calling `openDatabase`, and keep the existing bare-choice branch. Update the two stale comments above `activate` (`:15`) and `runCommand` (`:44`) that still describe `sql <name> [left|right]` and docking. Keep the signature and all other functions unchanged.
- `src/plugins/sql/activate.test.ts`, first block: cases for the two forms and their values, a path with interior and repeated spaces preserved, upper-case keywords and upper-case dock words (`FILE`, `LEFT`) falling through to usage, a keyword with no separating whitespace (`file/path`) producing usage, the old bare name and `left`/`right` producing usage, a missing or whitespace-only value producing usage, and a relative path resolving against the project directory before the existence check. Use a real temporary file for the existing-path case; for the missing relative path, assert the resolved absolute path in the error line instead of creating a file under the project directory.
- `src/plugins/sql/activate.test.ts`, command cases using the existing fake capabilities: `sql file <existing>` opens a tab keyed `sqlite:<absolute path>` and titled by subplan 2's rule (basename with one trailing `.sqlite` removed case-insensitively, so `shop.sqlite` titles the tab `shop`); `sql database <name>` behaves exactly as the old name form, including `Invalid database name "<name>".` from `isValidDatabaseName` and `UNKNOWN_DATABASE` from `openDatabase`; bare `sql` chooses the last-opened database, or the first by name when none is open; an unrecognized argument, including `sql file <path> left`, reports `Usage: sql [file <path>|database <name>]` and opens no tab; a missing path reports `No database file at "<path>".` and opens no tab; `dockTab` is never called. Add a case where the same path is opened twice (one tab) and one where two paths share a basename (two tabs). Remove the one old case that asserts docking from the command, `it('docks the named database and undocks it on a bare argument', ...)` at `src/plugins/sql/activate.test.ts:181`; its `docks` assertions are replaced by the never-called assertion.
- `src/plugins/sql/shared.test.ts`: remove the `parseSqlArgument` describe block (about lines 273–293); leave the name-guard and intent-guard cases as they are.

## Tests

The cases are listed under Proposed changes and mirror the source plan's test section. They use the existing colocated conventions (`src/**/*.test.ts`, vitest `describe`/`it`/`expect`) and the fake capabilities already in `activate.test.ts`. Use a real temporary file made with `mkdtempSync` under `tmpdir()` and removed in teardown, the pattern in `src/database/query.test.ts:2`; do not mock `node:fs`, because `existsSync` is a module import in `activate.ts` and the fake capabilities object cannot supply it.
