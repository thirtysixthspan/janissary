# One role entry executing a subagent task
**Complexity: 7/10** — ~360 added production lines, 0 existing files, 18 requirements, 63 scenarios (p=6.53)

## Goal

Implement a single-entry driver accepting an existing run, captured invocation, known role settings/entry, execution directory and optional existing remote channel/workspace label. Report its result and whether any endTurn occurred; do not choose a fallback model or settle the run.

Source: `product/plans/complete/subagent.md`, preserved unchanged as the canonical feature record. This is ordered subplan 17 of 23.

## Implementation steps

1. Export `runSubagentEntry` returning a promise of `SubagentAttemptResult`, and readonly `SubagentAttemptOptions`/`SubagentAttemptResult`, from attempt.ts. Options carry the existing `AgentRun`, captured `CommandInvocationContext`, `Managers`, canonical `AcpRoleSettings`, exactly one `RoleEntry`, execution directory, optional context, captured caller offline flag, captured `CommandSettingsSnapshot | undefined`, optional remote target, optional `onSessionStarted` observer and optional synchronous `adoptSession` hook. Define `SubagentAttemptRemote` beside the session helper with the existing channel, host and already-created workspace label; never discover a channel or provision a clone here. Use `run.snapshot.taskText` with plan 1's `subagentTaskPrompt` to form the logical prompt and call `run.record?.prompt` once per admitted entry. The logical record/loop input excludes automatic `corePrimer`; the raw provider's first prompt still includes that ordinary primer exactly once through the loop. Skills and role descriptions do not enter the prompt.

2. The result carries `status` using the existing `AgentOutcome`, `response`, `replied` (whether any `endTurn` happened), `reason` (`answered`, `capped`, `error` or `terminated`), `sessionId` (the callback's exact provider string or null), and `cleanupWarnings`. Map answered to completed and capped to partial; use only the latest `endTurn` display verbatim, including whitespace or an empty string. Every `endTurn` sets replied, even a command-only/empty display; chunks, thoughts and tool results never become response. Connection `onError`, loop `error`, a synchronous launch/constructor/driver exception or an adoption/observer exception yields failed/error with the source text (`errorText` for a thrown value) unchanged. An undefined launch yields exactly `no ACP adapter for harness "<harness>".` A failed result with replied false is eligible for the next layer's fallback; replied true forbids fallback. This unit neither selects another entry nor changes the run's terminal outcome.

3. Export synchronous `openSubagentAttemptSession` returning `SubagentAttemptLease` from attempt-session.ts. The helper takes the launch/target options and narrow callbacks from the driver. A lease exposes the existing local/remote session union and idempotent `dispose`, whose shared promise calls local `shutdown` or remote `release`; a false remote acknowledgment is a cleanup failure using the adapter's existing `Remote agent close was not acknowledged.` text. If no terminal result has been chosen, external disposal first chooses terminated with `Subagent terminated.`; then invalidate activity, provider and loop callbacks before closing. The driver always closes its acquired lease in finally, records disposal failures only in cleanupWarnings, removes its abort listener and ends its allocation before resolving. Disposal cannot replace an already-chosen status, text, replied flag or provider ID.

   Call `run.beginAllocation` before construction and release that allocation only after disposal; a refused allocation or an already-ended/aborted run returns terminated with `Subagent terminated.` without opening a session. Install the abort listener and attempt state before calling either transport. Abort chooses terminated immediately and requests disposal even when the constructor has not returned; await construction assignment/failure before completing that disposal so a late-returned handle is still closed. For synchronous constructor callbacks, buffer callback observations in order until the returned session is installed and adoptSession has been called. Then replay only while active: provider ID followed by an effort error must publish/retain the ID, while an earlier failure/abort suppresses later callbacks. If construction throws, replay observations that preceded the throw while still active before classifying that exception, preserving an already-reported ID. There is no returned handle to adopt/release in that case; finally still removes listeners/releases allocation.

   The optional adoptSession hook receives the lease once, after construction but before callback replay or prompting. Plan 18 will install that same lease in its current-session slot and register exactly one `acp:<runId>` resource for the slot before invoking this API. It may dispose the lease concurrently with the driver's abort/finally path; all calls share one close. It clears/replaces the slot only after this promise resolves. This driver registers no second ACP resource and remains safe when no adoption hook is supplied: its own abort/finally cleanup plus the allocation guard cover the full acquired lifetime. A thrown adoption hook also closes the handle. No module imports a later execute, launcher or registry API.

4. Use `acpLaunchForEntry` without a harness filter or effort override. Forward command/args/env/sessionMeta unchanged; do not pass a separate transport `effort`, `allowedTools`, installed skills or `autonomous`. Local `cwd` and `workspaceDir` are both the supplied clone and offline is the captured caller flag. The remote open uses the supplied channel and selected workspace label, the same offline flag and launch, and transport address `subagent-<runId>-<fresh UUID>` unique to this attempt; a timed-out close cannot collide with a later attempt's open. This address is never used as a provider ID. It stays non-run-only because autonomous is absent. Start `runToolLoop` immediately after adoption and callback replay, before awaiting normal remote ready. Observe readiness rejection through the same first-failure path without blocking the first run, and retain any early provider ID even if effort/readiness fails. Plan 6's provider hook is the only identity source; onConnect, transport ids and internal caller identities cannot fabricate a provider ID. Report one live ID through onSessionStarted and in the result; first/latest bookkeeping across entries remains plan 18's responsibility.

5. Build one core snapshot per entry with role ask, canonical roleName, copied role commands minus exactly `subagent`, `coreSnapshotRows` of the supplied captured native settings, and withoutTools false. Do not read mutable role/native settings during the attempt, reuse caller role grants, or add subagent/native command rows. This accepts an earlier dependency state where subagent is not yet in the vocabulary and still removes it if present in the supplied grants. Call `runToolLoop`, never `runCorePrompt` or `runAcpToolLoop` directly, so tool extraction, permission gating, remote handoff, ordinary core primers and the eight-command cap remain shared. No stopped-after suffix is added.

6. Export `createSubagentAttemptHost` from attempt-host.ts. Its local runWorkspace delegates only to `runWorkspaceCommandIn(executionDir, command, run.abortController.signal)` for all five granted file commands; remote file steps remain on the selected far-side clone through the existing snapshot path. Both host methods reject new work after the attempt ends or aborts. For runCaller, derive a fresh child invocation from the captured invocation for the actual command, then freeze a replacement with runId set to run.id, caller set to run.caller, signal set to the run's abort signal, acpTool true, acpRole ask and awaitResult true. Preserve captured schedule provenance; never copy the launching invocation's abort signal or recapture mutable tab cwd/context. Dispatch through `managers.command.dispatchNativeLine(run.caller.label, command, invocation)`, preserving db/browser/question ACP behavior and the real run's created-tab attribution. While an admitted question is pending use Waiting for answer and restore Running only while the attempt remains active.

7. Map caller results exactly like plan 9's private dispatchNative, without exporting or editing that helper: reject undispatched with `No ACP tool matched command: <command>`; return any string result verbatim first, including empty core-response strings; otherwise coreResponse or undefined result returns captured output; otherwise use JSON serialization with its existing String fallback. A dispatch exception becomes the loop's error without an added prefix. Use `guardAcpHandlers` plus a local raw-session wrapper with the same active predicate, covering the paths that can launch another turn as well as visible callbacks. The predicate includes the one-entry terminal state, run outcome and run abort; callbacks from an old entry cannot act during a later attempt. Recheck after external observers, adoption and awaited caller tools. A settled/aborted attempt cannot launch another prompt, dispatch, restore Running or write activity.

8. Convert local provider updates with `acpActivity` (`src/acp/activity.ts:37`) and accept remote classified activity through the same active guard, using `run.reportActivity`. Record native start/result activity with `run.record?.activity('tool', ...)` as `src/agent/execute.ts:164` does, tagging remote workspace steps with the supplied host only. Activity remains separate from terminal response. Update product/specs/subagent.md for this API's local/remote options, prompt boundary, before/after-turn failure, empty/partial output, callback identity and symmetric cleanup; keep fallback, run settlement and delivery documented as their owners' later work.
