# Web search 12: `web search` as a native ACP command with its own tool entry

**Complexity: 5/10** — ~14 added lines across 4 production files, 10 requirements, 16 test scenarios over six suites (p=5.59)

The twelfth slice of the `web search` feature (source plan: `./product/plans/complete/web-search.md`). It offers the search to ACP `ask` and `tell` sessions. `web search` joins the native ACP vocabulary, so a role grants it by name, the Roles tab offers it, and the Commands tab shows a `web search` row under `web`. `web` becomes a native tool owner. A `web` entry joins the ACP tool table with the web primer, the case-sensitive reply-line predicate, and `runsOn: 'workspace'`, which hands a gated line to the routes added in `./product/plans/ready/web-search-11-workspace-routes.md`. Nothing grants it by default yet; the built-in roles gain it in `./product/plans/ready/web-search-13-default-grants.md`.

Before this slice, `gateCoreCommand` (`src/acp/tool-table.ts`) throws `No ACP tool matched command: …` for a `web` line, because `nativeCommandName` finds no `web search` in `NATIVE_ACP_COMMANDS` (slice 11's note). This slice is what makes a `web search` reply line extractable and gateable, so it is also where the end-to-end test through the gate lives.

## Design decisions

Carried verbatim from the source plan where they apply.

- **Agent access (feature text).** The same capability is offered to ACP `ask` and `tell` sessions as a callable tool taking a required query plus optional result count (default 10), context character budget (default 10000), and provider (default auto-selected).
- **How an agent calls it (user decision).** A native ACP command, `web search`, in the same grammar as the typed command: the agent ends its reply with one `web search <query> [--results n] [--max-chars n] [--depth basic|advanced] [--provider name]` line, a role grants it by its native name, and a primer teaches it. The feature text's tool schema maps onto that grammar: `query` is the query words, `numResults` is `--results`, `contextMaxCharacters` is `--max-chars`, `provider` is `--provider`. No harness function-calling tool, MCP server, or JSON argument form is added.
- **Vocabulary.** `'web search'` appended to `NATIVE_ACP_COMMANDS` (`src/plugins/roles/shared.ts`) as its last entry, after `'file edit'`. Every consumer reads the array, so this one edit gives the Commands tab a `web search` row (the loop in `buildApplicationCommands`, `src/application-commands.ts`, `for (const name of NATIVE_ACP_COMMANDS)`, computes `parent` as every word but the last, so `web`), the Roles tab a grant option (`nativeCommands: [...NATIVE_ACP_COMMANDS]` in `src/plugins/roles/activate.ts`), the role-restriction reader its new name (`NATIVE` in `src/plugins/roles/command-policy.ts`), and the core snapshot a `web search` row (`coreSnapshot` in `src/acp/run-prompt.ts`). None of those files is edited.
- **Native tool.** `'web'` appended to `APPLICATION_COMMAND_NATIVE_TOOLS` (`src/shared/application-commands.ts`) after `'file'`; `NATIVE_TOOLS` in `src/plugins/commands/shared.ts` and the payload guard in `src/plugins/commands/payload.ts` read it, so a `nativeTool: 'web'` row passes both guards with no edit. `nativeCommandTool` (`src/acp/native-commands.ts`) returns `'web'` for a native name starting with `web `, checked beside its `file ` check and before the final `return 'question'`. This edit is required, not cosmetic: without it the fall-through returns `'question'`, the `web search` row's `nativeTool` becomes `question`, and `createAcpToolTable` would include the question owner instead of the web owner for a `web search` grant.
- **Tool table entry.** A `{ owner: 'web', tool: … }` entry in `ownedTools` in `createAcpToolTable` (`src/acp/tool-table.ts`), directly after the `file` entry and before the `database` entry: `primer: WEB_SEARCH_PRIMER`, `match: (command) => isWebCommandLine(command)`, `isCommandLine: (line) => isWebSearchReplyLine(line)`, `runsOn: 'workspace'` — written in the same arrow style as the other entries. The table order becomes browser, question, file, web, database; the database entry stays last as the fall-through. The existing `.filter(({ owner }) => allowed.some((command) => nativeCommandTool(command) === owner))` includes the web entry exactly when the grants contain `web search`; nothing else changes in the function.
- **Primer (user decision).** When a role grants `web search`, the web tool's primer is exactly `WEB_SEARCH_PRIMER`; when it does not, the web owner is filtered out and no web primer appears. The allow-list sentence lists `web search` in vocabulary order, so last. As with every other owner (`corePrimer` in `src/acp/drive-loop.ts`), a granted `web search` whose row has agent access off keeps its primer but is left out of the allow-list sentence; extraction still finds it and the gate refuses it.
- **Reply-line rule.** Only a line starting with lowercase `web search` is extracted as a command, because a model's final answer often begins a sentence with "Web search …" and the extractor reads the reply's last recognized line as a command. Mechanically: `toolExtractor` requires `nativeCommandName(line) !== undefined` (case-insensitive, so `Web search found …` passes this half) and some tool's `isCommandLine(line)`; only the web entry's `isWebSearchReplyLine` can claim a `web` line, and it refuses the capitalized form, so `Web search found three results.` on the last line yields `null` and the loop treats the reply as the final answer. Bare `web search` on the last line is extracted, gated, and, when granted, answered with the usage line by slice 11's route.
- **Gate (from precedent).** The ACP gate grants or refuses `web search` by its native command name like every other native command: `Command is disabled: web search.` when the Commands tab turns it off or turns off its agent access, and `Command not allowed for role "<role>": web search.` when the role does not grant it. Turning off the parent `web` row also disables `web search` (the parent inheritance in `src/native-commands/manager.ts`, `isEnabled`/`isAgentEnabled`), as disabling `file` disables the four file rows. `gateCoreCommand` needs no edit: `nativeCommandName` now resolves `web search`, and `tools.find((candidate) => candidate.match(command))` reaches the web entry before the database fall-through. A granted step returns `{ runsOn: 'workspace' }`, so the local loop calls its `runWorkspace` and the far side reports the step with `workspace: true`, which is what earns it the `[<host>] ` tag (slice 11, `tagged` in `src/acp/run-prompt.ts`).
- **Role sessions keep built-in tools denied (from precedent).** A harness's own web search stays off (`src/acp/internal-tools.ts`); agents search only through Janissary's command, so grants, command settings, and connection records govern every search. `internal-tools.ts` is not edited, and `NO_BUILTIN_TOOLS_LINE` is unchanged.
- **Loop limits.** The loop's reply-line protocol and eight-step cap apply unchanged (`src/acp/command-protocol.ts`, `src/acp/loop.ts`, `CORE_MAX_STEPS` in `src/acp/drive-loop.ts`).
- **Vocabulary count in docs.** The native vocabulary goes from thirteen to fourteen commands here (one more than whatever it is when this lands, if `file patch` lands first). The Roles tab's **Add command** is hidden only when all fourteen are granted. Until `./product/plans/ready/web-search-13-default-grants.md`, the built-in tell role grants thirteen of the fourteen — every native command except `web search` — so its Roles card shows **Add command** offering only `web search`; specs written here say that, and slice 13 rewrites them to "all fourteen".
