**Complexity: 6/10** — ~102 added production lines, 4 existing files, 10 requirements and 28 scenarios (p=6.248)

## Goal

Offer names wherever the feature accepts a saved host. Source plan is `product/plans/complete/hosts-tab.md`. Depends on `product/plans/ready/hosts-tab-2-effective-file.md`, `product/plans/ready/hosts-tab-5-remote-shell-and-harness.md`, `product/plans/ready/hosts-tab-6-remote-agent.md`, `product/plans/ready/hosts-tab-8-ssh-tab-launch.md` and `product/plans/ready/hosts-tab-14-host-edit-controls.md`.

## Implementation

Add a pure slot predicate and `completeSavedHost` in `src/completion/hosts.ts`. Use the command, argument index and token boundaries exposed by `readCompletionCursor` in `src/completion/cursor.ts:3`. Require an empty token or a bare prefix accepted by the shared host-name character predicate. Leave an address containing `@` or `:`, an unfinished quoted token, or a cursor with more characters in the same token to the existing completion chain. Offer saved names at argument one of `ssh` only when the rest of the line is whitespace, and at argument two of `hosts remove`, matching the subcommand case-insensitively. A leading hyphen is valid in a saved name, so a bare `ssh -…` prefix can match the catalog. An invocation with flags and a separate destination or with trailing remote command text keeps its existing completion behavior.

For `shell`, `harness` and `agent`, the word immediately before the token must be `on` case-insensitively. Verify that it introduces a host clause by probing the applicable pure parser with the input through `on` and a distinct valid placeholder in place of the current token. Use `parseShellArgument` in `src/plugins/shell/parse-argument.ts:41` with the argument tail, `parseHarnessCommand` in `src/harness/command-parse.ts:168` with the command line, and `parseAgentCommand` in `src/agent/command-parser.ts:88` with a synthetic final `execute` clause and task. The parser must report the placeholder as the remote selector. Choose a placeholder absent from the earlier text and preserve that text verbatim so quoted launch clauses stay intact. This excludes shell group names, harness capture and transcript targets or trailing `with` prompts, and text in the agent task or its parameters. Only the prefix through the current token participates in this check. Preserve text after the cursor so a host can be completed before later launch clauses.

`parseNamedClause` in `src/agent/command-parser.ts:51` currently treats `execute` as a missing value even after `on`. Support the valid saved name `execute` when a separate final `execute <task>` clause follows it, with or without other valid launch clauses in between. Keep the existing `Agent: missing value for on.` error for `agent on execute task.md`, and keep other clauses' reserved-word rules. The parser still works entirely from the input, with the same saved-name resolution as every other selector in the executor.

Follow `completeMonitorCommand` in `src/completion/handlers.ts:12` and reuse `completeWord` in `src/completion/helpers.ts:48`. Add a case-insensitive option for this call, preserving the default matching for existing callers. Compare folded prefixes and sort by folded name. A unique match inserts its stored spelling. Multiple matches extend the typed prefix using the folded common prefix's length and the first match's spelling for any additional characters. Preserve the untouched suffix through `replaceToken`. Omit the usual appended space when the cursor already precedes whitespace. Return `null` for no saved matches so the ordinary fallback remains available.

Extend `completeCommandLine` in `src/completion/index.ts:56` with an optional trailing saved-host names provider. Keep the existing command-enabled policy and earlier completion handlers. Check the slot and resolve its names immediately before filesystem fallback so unrelated or disabled completions do no catalog I/O. Have `complete` in `src/controller/completion.ts:11` supply a provider that calls `readHostsFile` for `managers.tab.launchDir` and the OS home without a notification callback.
