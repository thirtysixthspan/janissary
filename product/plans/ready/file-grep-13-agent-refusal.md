## Goal and decisions

Keep file grep unavailable to autonomous `agent` command runs, locally and remotely, even after later slices enable it for core ACP ask/tell roles. Both independent guards must refuse grep with and without the whole-command `file` grant before dispatch or workspace content access. A remote host forwarding a grep caller request must meet the same local refusal independently of its own gate.

## Proposed changes

- Import `isFileGrepCommandLine` directly from `../file-grep/command.js` into both production modules. Add it to each existing mutation/glob refusal condition. Keep the guards independent; do not rely on the gate to protect a directly delivered caller request or merge the guards into a new abstraction.
- Preserve normalization exactly: trim the incoming command and remove one slash only when it is its first character after trimming. Do not trim again after the slash, strip multiple slashes, collapse internal whitespace or lowercase the original text. Plan 1's predicate accepts case-insensitive `file`/`grep` with whitespace between keywords and a whitespace-or-end boundary after `grep`; it does no normalization itself. Bare and syntactically malformed grep lines are refused before parsing. No parser, regex validation, path lookup or file grant can turn this refusal into execution.
- Return exactly `Agent: command not permitted: <command>.`, interpolating the guard's original incoming command unchanged, including case, slashes, internal/trailing whitespace and punctuation. At the provider-reply boundary the existing extractor removes the `janissary` prefix and trims the reply line; preserve that established behavior rather than promising to retain discarded provider whitespace. The guard must not add a `refused: 'disabled'` marker; that belongs to disabled core commands.
- Preserve ordinary read and neighboring-command behavior. At the gate, `file read a.md` runs on the workspace with `file` and refuses without it. At the caller guard, a directly delivered `file read a.md` with `file` still dispatches in the caller invocation context; without it, it refuses before dispatch. This plan does not turn caller reads into workspace reads. `file greps x` and `file grep-x x` are not grep: the gate routes both to caller with either grant set, and the caller guard dispatches them with `file` or refuses them through its ordinary grant check without it. The typed file command's read fallback remains responsible for their eventual read usage output.
- Keep refusals as ordinary tool results. The local loop invokes neither host runner and feeds the refusal into its next turn. The remote loop emits one `acp-tool-step` with `workspace: false` and no `refused` property, sends no `acp-tool-request`, then feeds back the refusal. A directly delivered remote caller request passes the real local guard, returns `acp-tool-result.output` with the same text, and records command/result activity without a host tag. No dispatcher, workspace reader or grep engine runs for these refusals.
- Leave all three workspace-runner implementations unchanged, especially `src/agent/execute.ts:146`, the third `runWorkspace`. The gate prevents autonomous grep reaching its read fallback; plans 14/15 later expand the core ACP path without changing this autonomous prohibition. Leave `createAcpToolTable`'s file `isCommandLine`, `filePrimer`, native command names, grants and registries unchanged here.
- During implementation update `product/specs/agent-command.md:77`, the local execution paragraph, and `:91`, the remote execution paragraph: add grep beside glob/mutations, both grant states, the independent caller-side refusal and untagged behavior. Add the matching autonomous refusal note beside grep's section in `product/specs/acp.md` (extend the section introduced by plan 12 if present; otherwise add only this refusal note after File glob). This does not document core ACP availability ahead of plans 14/15. Reviewed `help/agent.md`, `documentation/user-documentation/advanced-agents/agent-command.md` and `documentation/user-documentation/advanced-agents/remote-agents.md`: none currently promises autonomous grep support, so no user-doc edit is required by this slice. Typed grep help and final documentation integration stay with plans 12/17.
