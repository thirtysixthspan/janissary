## Implementation steps

1. Replace `startLocalAgentRun`'s trailing selector with optional `LocalAgentRunOptions` carrying `workspaceName`, `fresh` and `subagentRole`. Use overloads so a literal `fresh: true` returns `LocalAgentRunStart` synchronously, while omitted/false freshness returns the existing Promise result; a boolean whose value is not statically known has the union result. The public implementation is no longer async. Retain the asynchronous ordinary branch in a private `startOrdinaryLocalAgentRun`, and share placeholder-run option construction in a private `createLocalAgentRun`. Update `launchAgent` to pass an options object containing only its selected `workspaceName` and retain its current await and caller-signal linkage. Forward `subagentRole` to manager creation only when defined. No parsing or caller changes beyond that single production call site belong here.

2. For fresh mode, create an inert handle through `prepareFreshAgentWorkspace`. Choose `agent-<UUID>` with `randomUUID` and derive its immutable `dir` through `workspacePath`; use that same label for eventual creation. Fresh mode takes precedence even when `workspaceName` is supplied: neither `acquireAgentWorkspace` nor caller-directory borrowing runs. Do not call `WorkspaceManager.preflight`, `create`, or filesystem provisioning while constructing the handle. Initialized workspace paths remain the existing app-startup precondition; do not manufacture a directory from the caller or manager's project path.

3. Create the placeholder run synchronously with the original task selector, empty task text/skills/grants, captured caller, model/effort and optional role metadata. Pass the predetermined directory as both `executionDir` and `executionWorkspace` and the inert handle's late-bound release wrapper as `releaseWorkspace`. Do not pass `workspaceDir`: manager creation would try to lease an untracked directory before it exists. The run, its durable record and caller ownership must be observable before any clone preflight or spawn. If manager creation rejects stale caller/provenance/model state, cancel the inert handle and propagate that original error with no scheduled clone. Ordinary mode retains its existing cancel, readiness wait and workspace release when manager creation fails after workspace preparation.

4. After successful run creation, the fresh handle's `start(run)` obtains `run.beginAllocation`, registers the `workspace-provision` cancellation/readiness resource, and schedules clone startup in a microtask. The helper returns the plain run/workspace pair before that microtask executes. `AgentRunManager.create` emits synchronously: if a subscriber already ended the run, allocation admission fails, readiness rejects with the existing `git clone cancelled.` text, and no clone is scheduled. Termination before the queued startup has the same result. A fresh helper itself neither settles the run nor attaches the invocation's signal; later execution owns failure settlement and subagent ownership rules. Existing ordinary agent signal behavior stays in `launchAgent`.

5. In the admitted startup, call the existing synchronous `WorkspaceManager.create` with the selected label, no forwarded GitHub token, and `workspaceCloneOptions(AGENT_CLONE_DEPTH)`. Convert an error object to an Error carrying its original message; retain thrown errors and asynchronous `created.ready` rejections unchanged as rejections of the public `workspace.ready`. All occur after the run exists and never escape as synchronous clone failures from the fresh start call. Observe deferred and underlying readiness rejections immediately without replacing the rejecting promise, so a receipt consumer may attach its failure handler later. Success resolves only after clone follow-up setup finishes. No task resolution, provider handshake, started message or fake prompt belongs in this helper.

6. Once `create` returns its handle, capture its cancellation and underlying readiness and immediately account for its creator reference. Acquire the run lease, then drop only the creator reference with `WorkspaceManager.release`, as ordinary preparation at `workspace-execution.ts:32-33` already does. Install the lease on the release wrapper supplied at run creation before ending the allocation. If lease acquisition throws, reject public readiness with that original startup error and retain the creator-reference release as the cleanup fallback. The already-registered cleanup cancels and waits for underlying readiness before releasing that reference. An already-ended run still owns an allocation admitted while live, so register its acquired handle/lease before ending that allocation; never discard a late acquisition.

7. End the allocation in every startup exit once cancellation, readiness and release ownership are installed. Do not hold it until clone readiness: `cleanupAgentRun` waits for allocations before calling `workspace-provision`, so doing so would prevent cleanup from cancelling a pending clone. Cleanup cancels once using `created.cancel` or the existing `WorkspaceManager.cancel(label)` fallback and waits for underlying `created.ready`, even if public readiness already rejected on acquisition failure. Only then invoke the late-bound release. For a create refusal with no handle, wait for the settled public readiness instead. Keep cancellation and the readiness wait in a try/finally relationship so a cancellation error cannot skip the wait; provisioning rejection is expected here and is not a cleanup warning. Cancellation before a handle exists is remembered; neither late readiness nor repeated cancel/finish calls can restart creation or acquire a second lease. A final strict lease-removal error remains a cleanup warning and cannot replace a provisioning error or an earlier terminated outcome. Borrowed workspaces keep no-op cancellation and release only their own lease, leaving other holders intact.

8. Update the two named specs with the synchronous fresh-mode contract and ownership/error ordering, without describing a public subagent launch as shipped. Keep every new module below 200 counted lines and use direct defining-module imports with `.js` extensions and typed promise/error handling. The existing workspace-execution.ts and launch.ts count 69 and 166 nonblank/noncomment lines; the fresh lifecycle and workspace types have named extraction destinations to keep those files below 200. Keep lifecycle logic out of launch.ts and do not compact code to fit. No changes to WorkspaceManager, AgentRun or their cleanup APIs are needed.
