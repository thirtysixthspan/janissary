# System schedules 01: hidden tab placement and user-close semantics

**Complexity: 6/10** — shared placement and user-close rules cross server selection, split/docked presentation and retained client mounts; startup/recovery, queue provenance and project scheduling remain separate contracts.

## Goal

Provide the tab-state foundation for a hidden system shell: explicit focus reveals it, navigation skips it, and user close hides it while preserving its resources. This is the first subplan of `product/plans/ready/add-system-schedules.md` (the authoritative 7/10 plan). All thirteen drafts are already published on `feature/system-schedules`, PR #1729. Implement in filename order, improving and publishing each plan immediately before its implementation. This step is independently executable using manager-owned fixture tabs; it adds no startup shell.

## Decisions and dependencies

- Dependencies: none. Plan 03 owns real startup, actual PTY-exit replacement, generation checks, shell-specific focus behavior and profile capture/relaunch exclusions. Plans 05/06 own queue provenance and 11 owns project-schedule row actions. None is needed to verify this foundation.
- Add optional `hidden?: true` and `systemShell?: true` fields to server `Tab` and shared `TabView`; broadcast each only when true. Reveal deletes `hidden`, never `systemShell`. These fields are in-memory only. Lifecycle identity survives aliases, order and pane changes; never infer it from a title or label alone.
- Keep every tab in the complete server/client array. Hiding preserves order, numbers, RPC indices, runtime/queue identity, payload, served-file references, PTYs and tab timers. Only a real reorder/removal changes indices. Filter strip/nav eligibility, never `view()` or queue data.
- Extend `PlacedTab` and the shared predicates in `placement.ts`. Hidden tabs are neither center action nor reporting entries and cannot be split or selected by cyclic navigation. Keep `isReportingTab` a view-kind classifier; reporting-entry consumers also check visibility. Quit counting is a separate predicate: count visible, non-docked, non-system tabs of any existing view kind, including reporting tabs. A system target never causes quit, even revealed or the only record.
- `TabManager.setActiveTab` is the common explicit reveal seam. Validate the index before mutation, delete `hidden`, and undock a docked target using the existing `applyDock`/focused-pane placement behavior before selection repair and the final dirty emit. `setActiveTabOp` currently ignores docked tabs; undocking is a new coordination step, not an existing focus behavior. Apply the complete transition before broadcasting so no intermediate state selects a hidden tab. Passive repair, next/Shift+arrow navigation and reorder never reveal hidden tabs.
- Add `TabManager.userCloseTab(index)` backed by `user-close.ts`: no-op for an absent/already-closing tab, hide a system tab, otherwise delegate to destructive `closeTab`. Repeated hide is idempotent. Hiding does not enter `closeTabOp` or `closeTabResources`, invoke agent close hooks, delete schedules, discard queues, notify or request exit. Destructive callers keep their existing method.
- Hiding preserves `dock`; a docked hidden plugin remains mounted in its existing sidebar, inactive and absent from its switcher. A center hidden plugin stays in its existing center layer. Neither hide nor an ordinary focus change adds a consumer. Explicit focus of a docked tab moves it back to center through the ordinary docking relocation; retention across that existing cross-parent relocation is not a new promise.
- For a hidden active/secondary center tab, remove its history entries and restore the most recent eligible tab in the vacated pane, then the nearest eligible tab in that pane, then the nearest visible center action tab if that pane emptied. Measure distance in full-array order, preferring the next tab on a tie. Preserve an unaffected selection, repair the opposite pane, collapse an empty split and start dwell only on the final selection. Destructive close must also resolve history labels against the surviving array, not reuse an old numeric index after removal.
- With no eligible center selection, use `activeTab = -1` and clear secondary selection; hiding alone never quits or creates a replacement tab. Cancel pending dwell. The client keeps its existing composition mounted with an absent `current`, empty visible-label set and no focused controls. This is reachable by docking the remaining user tab before hiding system. Keep the pre-first-state connecting display, but do not let the current early return unmount retained bodies after state arrives. Preserve ordinary unsplit reporting-tab behavior when the selected tab is still visible.
- Reserve the normalized exact name `system` case-insensitively for user launch labels and user-assigned aliases, even before a managed shell exists. Refusal: `Cannot use "system": that name is reserved for the system tab.` Use `checkLaunchName` for explicit refusal and default-candidate skipping, and `uniquePluginLabel` for non-launch prefix allocation. `system-2` and filenames such as `system.md` are allowed. The existing host-only fixed launch origin bypass remains the exemption; do not add a user-supplied bypass or plugin API field.
- Check rename after the existing trim/50-character normalization but before the editor/disk branch. Empty aliases still clear; the managed system tab may clear its alias back to its own canonical label. Return the refusal from `renameTabOp` through operations and the manager so the command prints it instead of false success; retain the existing file-operation notification channel for RPC/strip refusals. Do not reserve names in file open/save or unrelated file-navigator rename operations.
