### Application config

Application settings are stored in `.janissary/config.json`. On first launch a default config is created if the file does not exist. The config is loaded after the `.janissary/` subdirectories are initialized and before the `App` component renders.

| Setting | Type | Default | Description |
| ------- | ---- | ------- | ----------- |
| `transcriptMaxLines` | `number` | `25000` | Maximum number of `LogEntry` objects retained per tab's transcript. When exceeded, the oldest entries are dropped (the most recent N are kept). Applied in both `appendLog` and `updateCurrentTab` so all log mutation paths are capped. |
| `tabNameMaxLength` | `number` | `16` | Maximum displayed length of an inactive tab name, including its trailing ellipsis when shortened. It also remains the creation limit for agent and harness routing labels. File-backed tabs retain their full filename and shorten it only for display. |
| `activeTabNameMaxLength` | `number` | `50` | Maximum displayed length of the focused tab name, including its trailing ellipsis when shortened. The active central tab and the visible entry in each sidebar use this limit. |
| `sandboxWorkspaces` | `boolean` | `true` | Whether workspaced tabs (`agent --workspace`, `harness --workspace`) are confined to their workspace clone by a Seatbelt sandbox (macOS only). The escape hatch for when confinement causes trouble. |
| `interactiveShellDetection` | `boolean` | `true` | Whether each tab's shell runs inside a pseudo-terminal so programs that take over the screen can be spotted and moved into a full-tab terminal mid-command (see `shell.md`). With it off, shells are plain pipes and only the built-in interactive-program list applies; programs already remembered in `.janissary/interactive-commands.json` still open a terminal either way. |
| `syntaxTheme` | `string` | `"github-dark"` | The active syntax-highlighting theme for editor tabs, set via `syntax theme <name>`. Applies globally across every open editor tab. |
| `theme` | `string` | `"dark"` | The active application color theme, set via `theme <name>`. Applies to the entire window chrome — see `application-themes.md`. Independent of `syntaxTheme`. |
| `notifications` | `object` | all events off | Which background events feed the notifications tab (see `notifications.md`). Shaped as `{ "events": { "stateChange": bool, "incomingMessage": bool, "scheduleFire": bool, "agentStart": bool, "rateLimited": bool } }`, each defaulting to `false` (opt-in). There is no runtime command to change these — the user edits `.janissary/config.json` directly. The `manual` event (an agent-triggered `notify`) has no toggle and always fires. |
| `syncPaths` | `string[]` | `["product/backlog/", "product/plans/"]` | Project-relative paths kept automatically synced with GitHub (see `editor-tab.md` → "GitHub syncing"). Each entry is an exact file path, a directory path ending in `/` (covering every file under it, at any depth), or a `*` wildcard pattern matching one path segment. There is no runtime command to change this — the user edits `.janissary/config.json` directly. |
| `externalViewers` | `object` | `{ "video": "QuickTime Player" }` | The external application each opener hands a file to, keyed by opener name (see `open.md`). Each value is a macOS application name; an empty or missing entry means the file goes to the operating system's default handler for its type. Only the `video` entry is read today. A user-supplied map replaces the default wholesale, like `notifications`. There is no runtime command to change this — the user edits `.janissary/config.json` directly. |

If `.janissary/config.json` exists but is not valid JSON, a warning is printed to stderr and the application falls back to defaults for that session. The corrupt file is left on disk untouched, so a user's edits are not silently discarded. A valid JSON file is decoded setting by setting: a value with the wrong type falls back to that setting's default without discarding valid neighbors. Missing or invalid notification event toggles likewise default individually, so a partial `notifications.events` object remains safe and opt-in.

Some settings can be changed at runtime through a command (currently `syntaxTheme`, via `syntax theme <name>`, and `theme`, via `theme <name>`). A change like this atomically replaces `config.json`, preserving any other keys already in the file, and updates the running application only after that replacement succeeds. If the write fails, the file and running setting both keep their previous value and a warning reports the failure.
