# Connections tab and connection tabs

The connections tab is the app-wide list of connections. A connection tab shows one tracked ACP session or one agent run. The pair follows the conversations list and conversation tabs: a singleton list tab plus one tab per record, fed by the connections topic. See [[connection]] and [[acp-records]].

### The connections tab

The connections tab is titled `connections`, matching the other list tabs. Bare `connections` opens or focuses it, `connections left` and `connections right` dock it, and bare `connections` returns a docked list to the centre. It lists every connection kind — sqlite, shell, acp, browser, ssh, and terminal — plus every retained ACP and agent record across every tab, ordered by most recent activity.

Non-ACP connections appear only while live and leave the list when they close. Tracked core ACP sessions and agent runs stay listed after they close. Monitor and editor-persona ACP rows are live-only: they leave the list when their connection closes and are not retained. The list is a table like the sessions tab's. A heading row names its columns in order: Host, Tab, Connection Name, Connection State, Last activity, and an unlabeled actions column. The heading row appears only when the list has rows. Host is the bare host the connection runs on. A connection held by a remote tab reads that tab's host, an ssh tab's connection reads its destination's host, and every other connection reads `Local`, including every SQLite row. A tracked ACP or agent record keeps the host it started on after its tab closes. Tab is the owning tab, Connection Name is the connection's title, and Connection State is its status. Last activity reads how long ago the row's record last changed, or its owning tab was last active, in the sessions tab's wording (`just now`, `3m ago`, `2h ago`, `1d ago`), and is empty when no activity is known. The connection's kind appears in the row's tooltip under its title. A live SQLite row is titled `sqlite:<name>`, and its owning-tab column reads exactly `global`, whether or not any tab has the database attributed. A tracked core ACP record reads `Running` while a prompt runs, `Idle` between prompts, and `Closed` once it ends. An agent run record reads `Running` until it finishes, then `Completed`, `Failed`, or `Terminated`. Every live row reads `Open`.

The list header is a full-width metadata bar matching the sessions tab's, containing only **Refresh** and **Split** controls together at the right edge. It appears above the empty message and the heading row, so an empty list has it too. A docked list combines Refresh and the dock-switch control at the right edge of one metadata bar, with no second header and no Split control, in either sidebar. The list already updates as connections change, so Refresh is for re-reading on demand: it reads the current connections again and redraws the list from them, leaving the selection where it was and opening nothing. Refresh is refused with `invalid refresh payload` when sent with arguments, and with `refresh applies only to the connections list` when sent from a connection tab; neither changes anything. Enter or Space on Refresh or Split acts on that control alone and never opens the selected row.

The list carries each connection's summary only. A record tab's loaded prompt history belongs to that tab and is never part of the list, so opening or paging a record leaves the list's own data unchanged.

Keyboard movement uses Up, Down, Home, End, and Enter. Enter on a row's **Close** or **Delete** control, or on a confirmation dialog button, performs only that control's action and never opens the row. A row opens on a second click on the same row, matching the conversations list. A row's identity includes its owner, so two tabs' rows with the same kind and id stay distinct: confirming one never opens the other, and a pending confirmation is discarded when the rows are reordered or replaced, even when the list keeps the same length. Opening a non-ACP row focuses the tab that owns the connection: for a SQLite row, the first tab in strip order that has the database attributed, or no tab when none does. Opening an ACP row opens or focuses its connection tab. Live-only monitor and editor-persona rows focus the tab that owns them and never open a record tab. A row's open and close controls act on that row's owning tab, so two tabs that hold the same kind and id act on their own rows rather than the first matching row. A SQLite row's close control closes the database app-wide, exactly like `connections close sqlite:<name>`, including when no tab is attributed and the owning-tab column still reads `global`. A non-ACP row's close control acts exactly like `connections close <kind>:<id>` and reports the same notification. A row action carrying an owner from before an attribution or strip-order change is refused: it changes nothing, shows the refusal inline in the list, and never opens or closes another row. A pending `Delete "<title>"?` confirmation is discarded when its row disappears or is replaced, so it cannot send an intent for a row that is gone. An open ACP row's control closes its session, but a Close on a record that has since closed or whose owning tab no longer holds it is refused and changes nothing; only a closed ACP row's confirmed `Delete "<title>"?` deletes it. A live row offers **Close**, a closed ACP record row offers **Delete**, and an agent record row offers no list control; its **Terminate** lives in its connection tab. Both controls are icon buttons in the actions column, using the sessions tab's glyphs: a circled cross for Close and a trash can for Delete. Each names its verb and the row's title as its accessible label. An empty list reads `No connections yet`. The command grammar and reference lookup are described in [[connection]].

Closed ACP records are kept per project; records closed more than 30 days before startup are removed at startup, not on a rolling timer. See [[acp-records]]. An open or missing record cannot be deleted: a confirmed Delete that no longer applies is refused, shows its error in the list, and changes nothing.

### The connection tab

A connection tab is titled by its kind and owning tab: `acp:<tab name>` for an ACP session and `agent:<tab name>` for an agent run. The tab name is the owning tab's name when the record began, so the title stays the same after that tab is renamed or closed. The row and the tab's metadata keep the record's own title. An ACP session's is `ACP: <first line of its first prompt>`, capped at 60 characters, and an agent run's is `Agent: <task filename>`. The tab opens with its metadata row and its prompt blocks. The metadata shows the title, model, owning tab, status, started and ended times, and the controls available for its status.

A core ACP connection tab offers **Cancel** and **Close session**. Cancel stops the running prompt and leaves the session open and `Idle`; Close session ends the connection as `acp reset` does. Cancel appears only while the session is `Running`, and Close session while it is `Running` or `Idle`. An agent run's tab offers **Terminate** instead, while the run is `Running`; it ends only that run, exactly like the agent monitor's Terminate. The record tab's control is disabled from the click until the record reports its terminal status and is then removed, while the monitor's own **Terminate** stays visible and disabled through cleanup. A closed session's connection tab is read-only and has no prompt input. A closed record's row can be deleted from the list. A refused control action shows its error in the tab and leaves the record unchanged. Cancel is refused unless the record is `Running`, Close session unless it is `Running` or `Idle`, and Terminate unless the run is still live; any of them is refused when the owning tab no longer holds the record. A stale live-row open or close target is a no-op rather than a refusal.

Each prompt block holds the prompt, then its activity entries in order, each labelled `message`, `thought`, `tool`, `plan`, or `permission`, then the rendered final answer. Clicking a web link in a rendered answer opens it as a page tab through the application and never navigates the app window; see [[embedded-web-page]]. Thought and tool entries start collapsed. An active connection tab follows its newest activity while the reader is at or near the bottom. This includes streamed text updates to the latest activity entry, even when no new entry is added. Scrolling away from the bottom pauses following until the reader returns. The tab opens on the newest history window. It loads older blocks when the reader reaches the top, and automatically while the loaded history fits the viewport, including when a resize makes it fit, until the history scrolls or no older blocks remain. It preserves their viewport even while new activity streams in or new prompt blocks arrive before the older blocks; see [[acp-records]] for the window and its paging. A record with no older blocks ignores the request and keeps its current window, including the empty window of a record with no blocks. A loaded window is held only while its connection tab is open, including while docked or hidden: closing the tab releases it, so later connections deliveries carry no window for that record, and reopening the tab loads the newest history window again.

### Opening a connection tab from the popup

The connections popup in shell, editor, and harness tabs opens record tabs. A row carrying a durable record id opens or focuses that record's connection tab. A row carrying the popup-owning tab's own live ACP reference resolves to that tab's current record and opens or focuses its connection tab. Rows are operable by pointer and by Enter or Space.

A running agent run started from the caller appears in the caller's popup as an ACP-kind row titled `Agent: <task filename>` as soon as the run starts, its title following the resolved task path. It carries the run's durable record id and no ACP reference, so it opens the run's record tab and has no transcript snapshot button. It leaves the popup as soon as the run ends. Ownership is the caller identity captured at launch: a run appears only under the open tab whose incarnation matches that captured caller incarnation, so a run from a closed tab does not appear under a later tab that reused its label.

A row that already offers a transcript snapshot keeps that separate button. Pressing the snapshot button opens the point-in-time transcript and never opens the record tab. Monitor and editor-persona rows stay snapshot-only and do not open a record tab. Surfaces that render no snapshot button today gain none.

The popup never opens a record tab by a second path. Opening a row dispatches the same connection record opener the rest of the app uses, so the connections plugin remains the sole owner of record tabs. A target whose tab or live record binding has disappeared does nothing. A durable record id still opens after its session, run, or caller has ended; only a missing or expired record is refused.
