# Connections tab and connection tabs

The connections tab is the app-wide list of connections. A connection tab shows one tracked ACP role session or one agent run. The pair follows the conversations list and conversation tabs: a singleton list tab plus one tab per record, fed by the connections topic. See [[connection]] and [[acp-records]].

### The connections tab

The connections tab is titled `connections`, matching the other list tabs. Bare `connections` opens or focuses it, `connections left` and `connections right` dock it, and bare `connections` returns a docked list to the centre. It lists every connection kind — sqlite, shell, acp, browser, ssh, and terminal — plus every retained ACP and agent record across every tab.

Rows are sorted by status first. Every open row comes before every closed row, so closed connections always form a separate grouping below the rest, whatever their host or activity. A row is closed when it is a record that reads `Closed`, `Completed`, `Failed`, or `Terminated`. Every live row and every `Running` or `Idle` record is open. Within the open grouping and within the closed grouping, rows are grouped by host. The `Local` group comes first, then every other host in alphabetical order, ignoring case. The host groups keep that order whatever their activity, so a group never moves when another host becomes busy. Within each host, the most recent activity comes first, and rows with equal activity order by kind and then id.

Non-ACP connections appear only while live and leave the list when they close. Tracked core ACP sessions and agent runs stay listed after they close. Monitor and editor-persona ACP rows are live-only: they leave the list when their connection closes and are not retained. The list is a table like the sessions tab's. A heading row names its columns in order: Host, Tab, ID, Name, State, Last activity, and an unlabeled actions column. Every row is a connection, so no heading repeats the word. The heading row appears only when the list has rows. Host is the bare host the connection runs on. A connection held by a remote tab reads that tab's host, an ssh tab's connection reads its destination's host, and every other connection reads `Local`, including every SQLite row. A tracked ACP or agent record keeps the host it started on after its tab closes. Tab is the owning tab, and ID is the row's id: a tracked record's UUID, or a live connection's id exactly as `connections close <kind>:<id>` accepts it. It ellipsizes when the column is too narrow. Name reads like the connection tab's title for a tracked record: `acp:<role>:<tab name>` when an ACP record has role metadata, `acp:<tab name>` for a legacy role-less ACP record, and `agent:<tab name>` for an agent run, using the tab name captured when the record began. A live row's Name is its connection string, such as `acp:ask:<provider/model>`, `acp:tell:<provider/model>`, `sqlite:<name>`, or `shell:<cwd>`. Several records from one tab share a name, and the ID tells them apart. State is the row's status. Last activity reads how long ago the row's record last changed, or its owning tab was last active, in the sessions tab's wording (`just now`, `3m ago`, `2h ago`, `1d ago`), and is empty when no activity is known. The row's tooltip reads its Name, then a tracked record's own title (`ACP: …` or `Agent: …`), then the connection's kind. A live row's tooltip has no record title line. A live SQLite row is titled `sqlite:<name>`, and its owning-tab column reads exactly `global`, whether or not any tab has the database attributed. A tracked core ACP record reads `Running` while a prompt runs, `Idle` between prompts, and `Closed` once it ends. An agent run record reads `Running` until it finishes, then `Completed`, `Failed`, or `Terminated`. Every live row reads `Open`.

Rows look like the sessions tab's rows. They run the full width of the list, with 12px horizontal padding shared with the heading row and 12px text. Hovering a row and selecting it shade it differently, and the selected row has no accent stripe. The whole list scrolls as one column, header included. A row's status changes how it reads, using the sessions tab's split between working, parked, and over. An `Idle` row's State takes the accent colour, as a detached session's state does. A `Closed`, `Completed`, `Failed`, or `Terminated` row reads muted throughout, as a terminated session row does. `Open` and `Running` rows keep the ordinary treatment.

A docked list stacks each row onto two lines with no heading row, like a docked sessions list. The first line holds the Name and its actions. The second holds the State, Host, Tab, and Last activity, with no ID, wrapping between whole fields as the sidebar narrows. A field wider than its line ellipsizes, and the Name ellipsizes so the actions stay visible. The kind stays in the row's tooltip. Placement picks the rendering, so the list returns to the table in the centre, however narrow that pane is. Keyboard movement, Enter, and the two-click open work the same docked.

The list header is a full-width metadata bar matching the sessions tab's, containing only **Refresh** and **Split** controls together at the right edge. It appears above the empty message and the heading row, so an empty list has it too. A docked list combines Refresh and the dock-switch control at the right edge of one metadata bar, with no second header and no Split control, in either sidebar. The list already updates as connections change, so Refresh is for re-reading on demand: it reads the current connections again and redraws the list from them, leaving the selection where it was and opening nothing. Refresh is refused with `invalid refresh payload` when sent with arguments, and with `refresh applies only to the connections list` when sent from a connection tab; neither changes anything. Enter or Space on Refresh or Split acts on that control alone and never opens the selected row.

The list carries each connection's summary only. A record tab's loaded prompt history belongs to that tab and is never part of the list, so opening or paging a record leaves the list's own data unchanged.

Keyboard movement matches the sessions tab. Up and Down move the selection one row without wrapping, Home and End jump to the ends, and Enter opens the selected row. Enter on a row's **Close** or **Delete** control, or on a confirmation dialog button, performs only that control's action and never opens the row. A row opens on a second click on the same row, matching the conversations list. A row's identity includes its owner, so two tabs' rows with the same kind and id stay distinct: confirming one never opens the other, and a pending confirmation is discarded when the rows are reordered or replaced, even when the list keeps the same length. Opening a non-ACP row focuses the tab that owns the connection: for a SQLite row, the first tab in strip order that has the database attributed, or no tab when none does. Opening an ACP row opens or focuses its connection tab. Live-only monitor and editor-persona rows focus the tab that owns them and never open a record tab. A row's open and close controls act on that row's owning tab, so two tabs that hold the same kind and id act on their own rows rather than the first matching row. A SQLite row's close control closes the database app-wide, exactly like `connections close sqlite:<name>`, including when no tab is attributed and the owning-tab column still reads `global`. A non-ACP row's close control acts exactly like `connections close <kind>:<id>` and reports the same notification. A row action carrying an owner from before an attribution or strip-order change is refused: it changes nothing, shows the refusal inline in the list, and never opens or closes another row. A pending `Delete "<title>"?` confirmation is discarded when its row disappears or is replaced, so it cannot send an intent for a row that is gone. An open ACP row's control closes its session, but a Close on a record that has since closed or whose owning tab no longer holds it is refused and changes nothing; only a closed ACP row's confirmed `Delete "<title>"?` deletes it. A live row offers **Close**, a closed ACP record row offers **Delete**, and an agent record row offers no list control; its **Terminate** lives in its connection tab. The managed `system` tab's shell rows, its `terminal:` and `shell:` connections, are the exception among live rows: they offer no list control, because a user close of that tab only hides it (see [[tabs]]). The server marks those rows permanent, and a close sent for one changes nothing, while opening one still focuses the system tab. Its other connections keep their **Close**. Both controls are icon buttons in the actions column, using the sessions tab's glyphs: a circled cross for Close and a trash can for Delete. Each names its verb and the row's title as its accessible label. For a tracked record that's the record's own title rather than its Name, so two records from one tab stay distinct, and the `Delete "<title>"?` confirmation uses the same title. An empty list reads `No connections yet`. The command grammar and reference lookup are described in [[connection]].

Closed ACP records are kept per project; records closed more than 30 days before startup are removed at startup, not on a rolling timer. See [[acp-records]]. An open or missing record cannot be deleted: a confirmed Delete that no longer applies is refused, shows its error in the list, and changes nothing.

### The connection tab

A connection tab is titled by its kind and owning tab: `acp:<role>:<tab name>` for an ACP record with role metadata, `acp:<tab name>` for a legacy role-less ACP record, and `agent:<tab name>` for an agent run. The tab name is the owning tab's name when the record began, so the title stays the same after that tab is renamed or closed. The list row's Name takes the same form. The tab's Connection Name tooltip, the row's tooltip, and the row's controls keep the record's own title. An ACP session's is `ACP: <first line of its first prompt>`, capped at 60 characters, and an agent run's is `Agent: <task filename>`. The tab opens with its metadata bar and its prompt blocks. A live popup reference opens the current record for its named role. Cancelling or closing a retained ACP record resolves its stored role and verifies that the owning tab still holds that role's exact record; a legacy record without role metadata uses ask. A tell action therefore leaves ask's session alone.

The metadata bar is a full-width band matching the connections list's header. It shows Host, Tab, Connection ID, Connection Name, model, Connection State, and `Started <local time>`, in that order: the list row's facts in the list's order, with the model before the state and the start time in place of Last activity. The bar keeps the longer names that the list's headings drop, because a field stands alone there with no heading row above it. Each field's tooltip names it, such as `Host: Local` or `Connection ID: <uuid>`. The Connection Name's tooltip adds the record's own title on a second line, the way a list row's tooltip does; the bar doesn't show that title as text, because the tab is already titled with the Connection Name. The bar shows no ended time, run id, or task path. The id and name ellipsize when the tab is too narrow. The controls available for the record's status sit at the bar's right edge as icon buttons in the list header's muted treatment. Each one names its verb as its accessible label and tooltip. A focus icon, a crosshair, comes first and is **Focus tab**: it brings the record's owning tab forward, as opening a live row does. It appears whatever the record's status, but only while the tab the record began in is still open. A record's owner is the tab whose session or run created it in this run of the app, not merely a tab with the same label, so a tab that later reuses a closed tab's label never becomes the owner, and a record from before a restart has no focus icon. A focus sent once the owning tab has closed is refused with `The owning tab is no longer open.` and focuses nothing, and a focus sent with anything but a record id is refused with `invalid focus payload`. A stop icon, a circled square, stops the work in progress. It is **Cancel** on a core ACP record and **Terminate** on an agent run. A close icon, the list's circled cross, is **Close session** on a core ACP record. An agent run has no close icon, because ending the run is what its stop icon does. A disabled control is dimmed.

A core ACP connection tab offers **Cancel** and **Close session** for its own role. Cancel stops that role's running prompt and leaves that session open and `Idle`; Close session ends only that role's connection. On ask, this is the same session action as `ask reset`. Cancel appears only while the session is `Running`, and Close session while it is `Running` or `Idle`. An agent run's tab offers **Terminate** instead, while the run is `Running`; it ends only that run, exactly like the agent monitor's Terminate. The record tab's control is disabled from the click until the record reports its terminal status and is then removed, while the monitor's own **Terminate** stays visible and disabled through cleanup. A closed session's connection tab is read-only and has no prompt input. A closed record's row can be deleted from the list. A refused control action shows its error in the tab and leaves the record unchanged. Cancel is refused unless the record is `Running`, Close session unless it is `Running` or `Idle`, and Terminate unless the run is still live; any of them is refused when the owning tab no longer holds the record in the matching role slot. A stale live-row open or close target is a no-op rather than a refusal.

Each prompt block holds the prompt, then its activity entries in order, each labelled `message`, `thought`, `tool`, `plan`, or `permission`, then the rendered final answer. Clicking a web link in a rendered answer opens it as a page tab through the application and never navigates the app window; see [[embedded-web-page]]. Thought entries start collapsed and tool entries start expanded; either can be toggled, and a reader's toggle survives later streamed updates. An entry whose whole text is a JSON object or array reads as indented, multi-line JSON, and every other entry's text reads exactly as recorded. An active connection tab follows its newest activity while the reader is at or near the bottom. This includes streamed text updates to the latest activity entry, even when no new entry is added. Scrolling away from the bottom pauses following until the reader returns. The tab opens on the newest history window. It loads older blocks when the reader reaches the top, and automatically while the loaded history fits the viewport, including when a resize makes it fit, until the history scrolls or no older blocks remain. It preserves their viewport even while new activity streams in or new prompt blocks arrive before the older blocks; see [[acp-records]] for the window and its paging. A record with no older blocks ignores the request and keeps its current window, including the empty window of a record with no blocks. A loaded window is held only while its connection tab is open, including while docked or hidden: closing the tab releases it, so later connections deliveries carry no window for that record, and reopening the tab loads the newest history window again.

### Opening a connection tab from the popup

The connections popup in shell, editor, and harness tabs opens record tabs. A row carrying a durable record id opens or focuses that record's connection tab. A row carrying the popup-owning tab's own live ACP reference resolves to that tab's current record for the reference's role and opens or focuses its connection tab. Rows are operable by pointer and by Enter or Space.

A running agent run started from the caller appears in the caller's popup as an ACP-kind row titled `Agent: <task filename>` as soon as the run starts, its title following the resolved task path. It carries the run's durable record id and no ACP reference, so it opens the run's record tab and has no transcript snapshot button. It leaves the popup as soon as the run ends. Ownership is the caller identity captured at launch: a run appears only under the open tab whose incarnation matches that captured caller incarnation, so a run from a closed tab does not appear under a later tab that reused its label.

A row that already offers a transcript snapshot keeps that separate button. Pressing the snapshot button opens the point-in-time transcript and never opens the record tab. An ask or tell row snapshots the whole shared tab transcript. Monitor and editor-persona rows stay snapshot-only and do not open a record tab. Surfaces that render no snapshot button today gain none.

The popup never opens a record tab by a second path. Opening a row dispatches the same connection record opener the rest of the app uses, so the connections plugin remains the sole owner of record tabs. A target whose tab or live record binding has disappeared does nothing. A durable record id still opens after its session, run, or caller has ended; only a missing or expired record is refused.
