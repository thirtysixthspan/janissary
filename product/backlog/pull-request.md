# pull-request

* Keep reveal focus working after a server restart, when the revision counter restarts below the client's acknowledged floor.

Existing Issue: `web/src/file-navigator/useFileNavigatorRevealFocus.ts` remembers each navigator label's highest acknowledged revision in a module-level map that is never cleared, and `nextRestoreRevision` in `src/file-navigator/restore.ts` starts its counter at 1 in every server process, so after a restart with the page still open a reveal on the reused `navigator` label can carry a revision at or below the old floor and both the focus effect and the acknowledgement effect skip it; the selection still applies, but the tree never takes focus and the hint is never acknowledged. Severity: 3/10

Existing Risk: 3/10 - The first reveal after a server restart silently loses its focus guarantee for that label, and the unacknowledged flag can later replay focus on a mount, which is the failure the floor exists to prevent.

Proposal Risk: 1/10 - A process-unique revision base leaves every client comparison and every hint consumer intact; the only exposure is a test that assumes the server counter starts at 1.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 2009 "keep reveal focus working after a server restart". In `src/file-navigator/restore.ts`, keep the module-level monotonic counter but start it from a per-process unique integer, such as `Date.now()`, instead of 1, so a new server process's first revision is above any revision the client remembered from the previous process; leave `nextRestoreRevision`'s signature, the hint shape, and `clearRevealFocus` unchanged. Do not reset the client's floor on a transient reconnect: `useFileNavigatorRevealFocus.ts` compares `revision <= floor`, and a reconnect to the same server must keep a stale hint from refocusing. Add a small `src/file-navigator/restore.test.ts` (or extend the nearest existing test) asserting that two successive `nextRestoreRevision()` calls return integers and the second is greater than the first, and add a `web/src/file-navigator/FileNavigatorTab.test.tsx` case that acknowledges a high revision, then mounts a hint with a lower revision and asserts neither `focus` nor `fileNavigatorRevealApplied` runs, followed by a higher revision that does both; these pin the comparison the server base relies on. The existing `reveal-editor.test.ts` `before = nextRestoreRevision()`/greater-than assertions and the client's fixed-revision tests must pass unchanged because the hint consumers treat revisions as opaque. Verify with `$janissary/scripts/run.mjs check-diff` and `npx vitest run --project server src/file-navigator/restore.test.ts src/file-navigator/reveal-editor.test.ts` plus the client file above.
