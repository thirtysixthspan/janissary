# pull-request

* Close the security gap where a case-folding alias of the protected Janissary control folder name slips past the mutation-only protected-path check on case-insensitive macOS volumes.

Existing Issue: The protected-path check compares path segments with plain `toLowerCase()` against `.janissary` and `.git`, and the real-path checks see names from Node's JavaScript `realpathSync`, which keeps the requested spelling, so a path such as `.janiſſary/roles.json` (U+017F LONG S, which `toLowerCase()` leaves unchanged but APFS case-folds to `s`) passes every check on a default macOS volume and `file write` or `file edit` replaces the real `.janissary/roles.json`, `commands.json`, `system-schedules.json`, or a runscript under `.janissary/scripts/`. Severity: 8/10

Existing Risk: 8/10 - A prompt-injected or misbehaving `tell` agent can rewrite the grants and command settings the plan names as the only check on agent mutations, or plant a runscript or system schedule that later runs outside any sandbox, on the platform Janissary's Seatbelt sandbox targets, through the exact boundary the PR describes as closed.

Proposal Risk: 2/10 - Folding segments to their compatibility case-folded form and checking canonical on-disk names closes the known alias; a residual risk remains only if a filesystem folds a character that NFKC plus lowercasing does not, which a test against a real case-insensitive volume would expose.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 1996 "refuse case-folding aliases of .janissary and .git in file write and file edit".
