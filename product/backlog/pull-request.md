# pull-request

* Refuse a write or edit path that ends in a path separator instead of silently treating it as a file name.

Existing Issue: A functionality gap: `resolveMutationTarget` in `src/file-write/target.ts` resolves the requested path with `path.resolve`, which drops a trailing `/`, and the remote port's `RemotePortPaths.to` drops it too, so `file write {"path":"notes/","content":"x"}` creates a regular file named `notes` and prints `Wrote notes/.`, and `file edit` on `a.txt/` edits `a.txt`, where an ordinary filesystem write would fail because the path names a directory. Severity: 2/10

Existing Risk: 3/10 - An agent that writes to a folder path by mistake gets a success line, a file squats on the folder name, and its later nested writes under that folder fail with `ENOTDIR`, which is confusing to recover from in an unattended tell loop.

Proposal Risk: 1/10 - Only paths ending in a separator change behavior; a regression would show as a refused ordinary path, which the existing write and edit tests would catch.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 1996 "refuse file write and file edit paths that end in a path separator". Leave `parseFileMutation` in `src/file-write/command.ts` unchanged so usage errors stay as they are. Add the check where every route passes before any port is called: in `applyMutation` in `src/file-write/tab-write.ts` (which serves typed commands, the local ACP route, and the remote-hosted loop in `src/remote/serve-acp-loop.ts`) return `mutationFailureLine('Is a directory', request.path)` when `request.path` ends in `/` (and in `path.sep`), before the lone-surrogate check, so local and remote tabs refuse identically and no remote frame is sent. Also add the same refusal at the top of `resolveMutationTarget` in `src/file-write/target.ts` against the raw `requested` string, so direct `LocalFileSystemPort.writeFile(..., 'tool-text')`, `editFile`, and the far-side `write-file`/`edit-file` callers get the same answer; note the remote port maps paths with `path.posix.relative`, which strips the slash, so the near-side check in `applyMutation` is the one that covers remote tabs. Add tests: `src/file-write/tab-write.test.ts` (local write to `notes/` refused with `Is a directory: notes/.` and nothing created; remote tab refused with no frame sent), and `src/file-write/target.test.ts` (`resolveMutationTarget(root, 'a.txt/')` refused for an existing file and for a missing one). Update the failure list in `help/file.md` and the typed write/edit paragraph in `product/specs/acp.md`. Existing tests in `filesystem.test.ts`, `edit.test.ts`, and `serve-file-navigator.test.ts` must keep passing unchanged; `file read` behavior is out of scope and stays unchanged.
