# pull-request

* Handle a transcript failure that arrives after its tab was closed, so a later tab reusing the label is still notified once as the subplan's once-per-tab rule promises.

Existing Issue: `ShellTranscriptManager.closeTab` disposes the label's writers without awaiting and then forgets the label from its notified set, but a released writer can still fail during its asynchronous finishing path (the final row tripping the pending-byte cap, or the stream erroring on `end()` against a full or stalled disk), and that late `onFailure` calls `reportFailure(label)`, which posts a notice for a tab that no longer exists and re-adds the label to the set where nothing will ever remove it again. Severity: 3/10

Existing Risk: 3/10 - On a disk that fails at close time, the next shell tab given the same label has its own transcript failure silently suppressed, so its user is never told the file stopped being written, and the notified set keeps the stale label for the life of the process.

Proposal Risk: 2/10 - The late failure is no longer reported at all, which is acceptable because its tab is gone, but a regression would be visible only through the new test, since nothing user-facing exercises failures on the close path.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 1675 "ignore transcript failures from writers already released by closeTab so the notified-label set is not repopulated". In `src/shell/transcript/manager.ts`, make the `onFailure` callback built in `install` skip `reportFailure(label)` once its writer has been released by `closeTab` or by a reinstall under the same id, while still reporting for a writer released by the PTY's `exit` (its tab is still open, so its failure is still worth a notice). The simplest shape is a per-manager `WeakSet` of writers released through the private `release` method, checked in the callback; leave the exit-release path, `closeTab`'s non-awaiting disposal, and `ShellTranscriptWriter` unchanged. Add a case to `src/shell/transcript/manager.test.ts` that installs a writer, opens its file, calls `closeTab`, then forces a failure after release (for example by spying on `BoundedAppendFile.prototype.dispose` to invoke the file's failure path, or by locking the transcript directory so only the drained flush fails), and asserts `notify` is not called and that a new tab with the same label still notifies once on its own failure; the existing "notifies a tab's failure once across its writers, and again after the tab is closed" case must keep passing unchanged.
