# pull-request

* Close the workspace reader's secret-file gap for a root that itself sits at or inside a secret location, so a server-side read cannot hand out files the sandbox denies.

Existing Issue: The reader matches `.env` and `SECRET_DENY_PATHS` only against path segments relative to the root, so when the root is itself a secret directory or splits a multi-segment entry — a project opened at `~/.config` (a common dotfiles layout), `~/.aws`, `~/.ssh`, or `~/.local/share` — `gh/hosts.yml`, `credentials`, `id_rsa`, and `opencode/auth.json` read normally, even though the Seatbelt profile built from the same table denies them to a sandboxed agent and this read runs in the unsandboxed janissary process on the agent's behalf. Severity: 6/10

Existing Risk: 6/10 - Once later subplans route an agent's `file read` through this reader with the project directory as root, an agent working in a dotfiles-style project reads a plaintext GitHub OAuth token or cloud credential that the sandbox exists to keep from it, with nothing in the result marking it as a secret.

Proposal Risk: 2/10 - The rule then also judges the file's physical absolute location, so the remaining exposure is a secret under a name the table does not list, plus the stat-to-read race the plan already defers.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 1992 "apply the file read secret rule to the file's real absolute path, not only the path relative to the root". In `src/file-read/read.ts`, keep the two existing root-relative `isSecretPath` checks (the lexical one in `checkLexical` must stay so a missing secret still reports `Secret file` before any disk access, preserving the subplan's check order), and add a third check in `loadBytes` right after the existing real-path secret check: run the contiguous-run part of the rule over the segments of `realFile` itself (split on `path.sep`, lowercased, empty leading segment dropped) so a `SECRET_DENY_PATHS` run such as `.config/gh/hosts.yml` or `.ssh` matches even when part of it lies above the root, and return `'Secret file'` when it does. Let `isSecretPath` take a segment array or add a sibling `hasSecretRun(absolute)` helper, keeping `readWorkspaceLines` under the cognitive-complexity limit and the import list within the subplan's allowed set (no `node:os` is needed, since the absolute path already carries the home prefix). Add a short comment saying why the absolute check exists: the reader runs outside the sandbox, so it must not be weaker than the Seatbelt deny built from the same table. In `src/file-read/read.test.ts`, add tests that create `.config/gh/hosts.yml` and `.ssh/id_rsa` inside the temp directory and call `readWorkspaceLines` with the root set to `<temp>/.config` (reading `gh/hosts.yml`) and to `<temp>/.ssh` (reading `id_rsa`), each expecting `Secret file: <path as given>.`, and assert that an ordinary `<temp>/.config/other.txt` read with root `<temp>/.config` still succeeds, so the rule does not refuse a whole dotfiles project. All existing tests in `src/file-read/read.test.ts` must keep passing unchanged; verify with `$janissary/scripts/run.mjs check-diff`.
