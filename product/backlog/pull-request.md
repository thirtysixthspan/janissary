# pull-request

* Unified diff view — Render the original and modified versions of a file in a single, vertically scrolling code display. Unchanged lines appear once, deleted lines appear with a red-tinted background and a − marker, and added lines appear with a green-tinted background and a + marker. When code is replaced, show the removed lines immediately before the added lines. Each row must maintain consistent alignment between its line numbers, change indicators, and code content. Preserve indentation and whitespace using a monospaced font. The unified view should support line selection, syntax highlighting, inline comments, and context expansion.

* Syntax highlighting — Apply syntax highlighting independently to each line of code using the language detected from the file extension or explicitly supplied language metadata. Highlight keywords, strings, comments, literals, operators, and identifiers while preserving addition and deletion background colors. Support common programming languages and a plain-text fallback. Keep syntax colors consistent between the old and new versions, and ensure the highlighting layer does not interfere with mouse selection, line targeting, copy-and-paste, or commenting controls.

* Expandable context — At each boundary where unchanged lines have been omitted, display a compact context-expansion control in the gutter or between hunks. Clicking the control should reveal additional unchanged lines above, below, or between change groups without navigating away from the diff. If the expanded lines connect two hunks, merge them visually into a continuous section. Use a subtle background to distinguish the expansion control from ordinary code rows. Expanded lines should support syntax highlighting, line numbers, selection, and comments just like the initial diff.

* Full-file expansion — Provide a way to reveal all unchanged lines within a changed file rather than limiting the display to the original diff context. When activated, render the complete file with existing additions, deletions, and modifications still clearly highlighted. Allow users to navigate to and comment on unchanged lines that were not originally visible. Preserve the user's current scroll position as closely as possible, and provide a way to return to the condensed diff. Do not confuse this functionality with opening a separate, read-only file viewer.

File presentation and navigation

* Keyboard file navigation — Provide keyboard shortcuts for moving between files without using the mouse. Follow GitHub's J and K convention for next and previous file navigation where appropriate. Keyboard navigation must respect filters and current navigation mode. Do not trigger file-navigation shortcuts while focus is inside a text input, comment editor, dropdown, or other editable element. Provide discoverability through tooltips or a keyboard-shortcut help menu.
