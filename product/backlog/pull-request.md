# pull-request

* Refuse file write and edit paths whose last segment is `.`, which today silently write or edit a file named after the parent folder, the same defect the trailing-separator fix closed.

Existing Issue: A path such as `notes/.` or `a.txt/.` passes `endsInSeparator`, and `path.resolve` in `resolveMutationTarget` (and `RemotePortPaths.to` on a remote tab) then normalizes it to `notes` or `a.txt`, so `file write` creates or overwrites a file named `notes` and `file edit` edits `a.txt`, where the filesystem itself would refuse the path. Severity: 3/10

Existing Risk: 3/10 - An agent or user who means a folder writes a stray file under the parent's name, or replaces an existing file whose name it only used as a folder, and no error explains what happened. This is the silent rename the trailing-separator fix was meant to stop, reached through a spelling it does not check.

Proposal Risk: 1/10 - The only remaining hazard is an over-broad check that refuses a legitimate name, such as a file literally named `.x` or a `./a.txt` prefix, which the proposed tests pin as still accepted.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 1996 "refuse file write and edit paths whose last segment is a dot". In `src/file-write/target.ts`, extend the exported `endsInSeparator(requested)` into a check that is also true when the raw path's last segment, split on `/` and `path.sep`, is exactly `.` or `..`. Rename it to fit the wider check, such as `namesDirectory`. Update both callers: the first statement of `resolveMutationTarget`, which covers direct `LocalFileSystemPort` calls and the far-side `write-file`/`edit-file` handlers, and the first check in `applyMutation` in `src/file-write/tab-write.ts`. The `applyMutation` check is the one that covers remote tabs, because `RemotePortPaths.to` in `src/file-navigator/remote/port-paths.ts` normalizes the dot away before sending. Both keep answering `Is a directory`. Leave `parseFileMutation` and `file read` unchanged. Add tests to `src/file-write/target.test.ts`: `a.txt/.` for an existing file and `notes/.` for a missing one are refused with `Is a directory` and nothing is created or changed, while `./a.txt` and a file named `.x` still resolve. Add tests to `src/file-write/tab-write.test.ts`: a local write to `notes/.` prints `Is a directory: notes/.` and creates nothing, and on a remote tab the same write and an edit to `a.txt/.` are refused with no frame sent. Extend the trailing-separator bullet in `help/file.md` and the matching clause in the Typed file writes and edits section of `product/specs/acp.md` to name a final `.` segment too. The existing trailing-separator tests in both files must keep passing unchanged.
