# pull-request

* Handle a late transcript failure from a writer whose shell exited just before its tab closed, which the released-writer guard misses because shell tabs close themselves when their shell exits.

Existing Issue: The guard only covers writers released through `closeTab` or a reinstall, and the fix plan leaves the exit path reporting on the premise that "its tab is still open", but a shell tab closes itself as soon as its shell exits (`web/src/plugins/shell/useShellTabTerminal.ts` `onExit`), so after a user types `exit` the manager has already dropped the writer, `closeTab` finds nothing to mark and clears the label from the notified set, and a failure surfacing afterwards on the writer's still-running finishing path (the stream erroring on `end()` against a full or stalled disk) notifies for the closed tab and re-adds the label, which is the very outcome the repair set out to prevent and contradicts the "nothing for a failure that surfaces only after the tab has closed" wording the commit adds to subplan 08's spec text. Severity: 3/10

Existing Risk: 3/10 - On a disk that fails as a shell exits, a stale notice is posted for a vanished tab and the next shell tab given the same label has its own transcript failure silently suppressed for the life of the process.

Proposal Risk: 2/10 - Late failures from exited writers of a closed tab are dropped as intended, but a writer whose tab stays open after exit (none today) would also have to be handled by the same label-keyed bookkeeping, and a mistake there would show only through the manager's unit tests, since nothing user-facing exercises close-time disk failures.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 1675 "ignore late transcript failures from writers whose PTY exited before their tab closed". In `src/shell/transcript/manager.ts`, keep the exited writers of each still-open tab so `closeTab` can mark them released too: for example, have the `pty` `exit` subscription move the dropped entry's writer into a per-label collection (a `Map<string, Set<ShellTranscriptWriter>>`, removing a writer from it once its `dispose()` promise settles so finished writers are not retained), and have `closeTab(label)` add every writer in that label's collection to the existing `released` `WeakSet` before deleting the label from `notified`, then drop the collection; leave the exit path's no-dispose behaviour, the reinstall path and shutdown's `dispose()` unchanged, and update the class comment's once-per-tab paragraph so it no longer implies exited writers always report.
