Existing Issue: `noteFailure` resets the budget for any dead generation whose `spawnedAt` is thirty seconds or more in the past, and `waitForListening` only gives up after thirty seconds, so every launch that hangs until the probe's bound is judged "a browser that ran" and resets the count to zero, although the harness spec says a start that ends in a failure counts against the tab. Severity: 5/10

Existing Risk: 5/10 - A Chromium that hangs at launch every time (a stuck sandbox profile, a slow or wedged disk) turns a retrying script into an unbounded loop of spawned children, kept scratch directories, log files and notifications at one per thirty seconds, which is the exact stream the restart budget was added to stop.

Proposal Risk: 2/10 - The reset now keys on how long a browser was listening rather than how long ago it was spawned, so a browser that genuinely ran is still forgiven; the remaining exposure is a browser that listens and then crashes after just over thirty seconds every time, which is the plan's accepted trade-off and stays visible in the notifications.
