# pull-request

* Strip embedded credentials from the origins and error text the remote echoes back in its root refusals, closing the security gap that lets the host's own git credentials reach the notifications feed.

Existing Issue: The `different-origin` refusal carries the remote repository's own origin verbatim and `clone-failed` carries git's first stderr line, and neither is scrubbed before the local side composes them into the placeholder display and the notifications feed, although both strings may embed a username or password. Severity: 4/10

Existing Risk: 4/10 - A token embedded in the remote repository's origin, the `https://<token>@github.com/...` form git writes into `.git/config`, is written into the local notifications feed and the placeholder where it persists in janissary's state and is readable by every process that can read the feed or tab logs, long after the ssh channel that carried it is gone.

Proposal Risk: 2/10 - Scrubbing could over-strip a display URL the user needs to compare, but `withoutCredentials` already defines exactly which parts are credentials and keeps the rest, so the readable shape survives; the risk is limited to a wording test noticing the stripped form.

Proposal: Execute ./ai/tasks/work-an-issue.md "PR 1200: scrub embedded credentials from refusal strings echoed back to the local side". The PR scrubs credentials outbound (`provisionOrigin` in src/remote/entry-factory.ts) but not inbound: `repositoryRoot` in src/remote/serve-root.ts puts the remote repository's raw `getRemoteUrl` answer into the `different-origin` refusal's `other` field, and `offer()` in src/remote/serve-root-offer.ts puts git's unfiltered first stderr line into `clone-failed`'s `reason`. Apply `withoutCredentials` (src/git/repository-url.ts) to `other` where the refusal is built in src/remote/serve-root.ts, and to `reason` where the `clone-failed` refusal is built in src/remote/serve-root-offer.ts, so the frame carries the scrubbed strings and the local wording in `rootRefusalMessage` (src/launch-name/messages.ts) needs no change. The offer prompt's `url` is already built credential-free through `cloneUrl`, so nothing else composes a raw origin. Extend src/remote/serve-root.test.ts with a different-origin case whose remote origin embeds a credential, asserting the refusal's `other` arrives stripped, and pin the `clone-failed` reason scrubbing in src/remote/serve-root-offer.test.ts with a failing clone whose URL carries userinfo. The existing refusal-wording tests in src/launch-name/fail-remote.test.ts keep passing unchanged, since they already use credential-free fixtures.
