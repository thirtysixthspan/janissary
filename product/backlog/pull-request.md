Existing Issue: The repair's home-anchored check runs only inside the disk-access step after `realpathSync` succeeds, so with a root at `~/.ssh`, `~/.config`, or `~/.local/share` an existing `id_rsa`, `gh/hosts.yml`, or `opencode/auth.json` reports `Secret file` while a missing one reports `File not found`, breaking the subplan's stated guarantee that a missing secret reports `Secret file` so the reader never reveals whether a secret exists (the Seatbelt deny answers ENOENT for exactly this reason). Severity: 4/10

Existing Risk: 3/10 - An agent reading through a dotfiles-style root can probe which credential files the user has (an SSH key, a GitHub token, cloud credentials) by comparing the two messages, an existence oracle the sandbox deliberately withholds, though no secret content leaks.

Proposal Risk: 1/10 - Existence is then hidden for every home-anchored entry reached lexically, leaving only a secret reached through an in-root symlink whose target is missing, which already reports `File not found` under the subplan's existing rule, and a test would show any regression in the message order.
