# pull-request

* Refuse a dangling symlink in the ancestor walk of the contained mutation-target resolver instead of recording it as a missing folder that passes containment.

Existing Issue: The resolver's nearest-existing-ancestor walk treats every `ENOENT` from `realpathSync` as a missing segment, so an ancestor that exists as a dangling symlink (for example `link -> /outside/new` inside the root) is recorded in `missingSegments`, checked for containment only as the lexical string `<realRoot>/link/...`, and returned as an accepted `WriteTarget` whose `realPath` is not the real destination, contrary to the subplan's rule that an ancestor symlink resolving outside the root refuses with `Outside the workspace`. Severity: 4/10

Existing Risk: 4/10 - The only thing stopping parent creation from following that symlink out of the workspace is an undocumented detail of Node's recursive `mkdirSync` (it stats an `EEXIST` component and fails with `ENOENT` while the link dangles), so if the link's outside target appears between resolution and creation the parents are created outside the root before the recheck refuses, and in the static case the caller gets the misleading navigator text "The source or destination no longer exists; refresh the file navigator" instead of a policy refusal.

Proposal Risk: 1/10 - Dangling ancestor symlinks are refused up front by the resolver, leaving only the concurrent-swap window the subplan explicitly placed out of scope; a regression would show as the new tests resolving the dangling-ancestor case successfully.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 1996 "refuse a dangling ancestor symlink in resolveMutationTarget instead of recording it as a missing segment". In `src/file-write/target.ts`, change `findAncestor` so that on an `ENOENT` from `realpathSync(candidate)` it first `lstatSync`s the candidate: if the lstat succeeds (the entry exists, so the `ENOENT` came from a dangling symlink at the candidate or further along its link chain), stop the walk and return a refusal instead of recursing to the parent; only when `lstatSync` also fails with `ENOENT` (the entry truly does not exist) is the segment recorded as missing and the walk continued upward, and any other `lstatSync` error returns `fileOperationReason(error)`. Refuse with `Outside the workspace` when the symlink's `readlinkSync` text, resolved against the link's directory, fails `checkRealTarget` against the real root, and otherwise with `Not a text file`, matching how `followSymlink` already treats a dangling final symlink; extract the dangling-entry decision into its own private helper to stay under the cognitive-complexity limit, and keep every filesystem call wrapped so nothing throws. In `src/file-write/target.test.ts`, under the `resolveMutationTarget ancestors` describe, add cases where `symlinkSync(path.join(outside, 'new'), path.join(root, 'link'))` makes requests `link/a.txt` and `link/sub/a.txt` refuse with `Outside the workspace`, where a dangling ancestor symlink pointing at a missing path inside the root refuses with `Not a text file`, and where `existsSync(path.join(outside, 'new'))` stays false in each case; the existing destination, ancestor, existing-target, and `createTargetParents` tests in that file must keep passing unchanged, and verify with `$janissary/scripts/run.mjs check-diff`.
