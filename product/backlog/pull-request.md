# pull-request

* Add a test that ties the role launch commands to the bin names the pinned adapter packages declare, so a bump that renames either bin can't silently move role launches off the bundled copy.

Existing Issue: The role launch names its adapters by the string literals `claude-agent-acp` and `codex-acp`, and nothing checks them against the `bin` fields of the exact-pinned packages, so every existing test passes even if the installed tree no longer has those names. Severity: 3/10

Existing Risk: 3/10 - A later update that renames either adapter's bin passes every test, after which each claude or codex role launch finds nothing in the install's `.bin` and quietly runs whatever unpinned copy is on PATH or the interactive shell's PATH, or fails to start, which undermines the exact pin the deny-all configuration of later subplans is checked against.

Proposal Risk: 1/10 - The contract is pinned for the tree a checkout installs, but a hoisted layout where the adapters sit outside the install's own `node_modules` would still go unchecked and would show up only as this test failing to find the adapters' `package.json`.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 1983 "add a test that pins the role launch commands to the bundled adapters' declared bin names". `acpLaunchForEntry` in `src/acp/launch.ts` returns `command: 'claude-agent-acp'` for a claude entry and `command: 'codex-acp'` for a codex entry. `locateAcpCommand` in `src/acp/command-path.ts` resolves those names in `path.join(janissaryRoot(), 'node_modules', '.bin')`, and when that misses it falls through to the PATH and interactive-shell lookups. Add a colocated server test, for example `src/acp/bundled-adapters.test.ts`, that does not mock `../janissary-root.js`. For each of `@agentclientprotocol/claude-agent-acp` and `@agentclientprotocol/codex-acp`, it reads `package.json` under `path.join(janissaryRoot(), 'node_modules', '@agentclientprotocol', '<name>')` with `readFileSync` and `JSON.parse`. Reading the file path directly avoids the package's `exports` map blocking a `require.resolve` of `package.json`. The test asserts three things: `Object.keys(bin)` contains the command `acpLaunchForEntry` returns for that harness, the root `package.json`'s `dependencies` entry for that package is an exact version with no `^` or `~`, and the installed `version` equals that pinned version. Do not change production code. The existing `src/acp/launch.test.ts`, `src/acp/command-path.test.ts`, and `src/acp/manager-fallback.test.ts` assertions stay as they are and must keep passing. Verify with `$janissary/scripts/run.mjs check-diff`, and confirm the new test fails if the expected command in it is temporarily changed to a name neither package declares.
