* Close the security gap where a backslash before a `{` lets a file glob pattern slip past the alternatives and combined star caps that the matcher then expands in full.

Existing Issue: `isGlobPatternTooComplex` brace-expands the raw pattern, where brace-expansion reads `\{` as an escaped literal brace, but `createGlobMatcher` builds minimatch with `windowsPathsNoEscape: true`, which first rewrites every `\` to `/` and then expands the brace, so a pattern such as `x` followed by `\{a,b}` sixteen times (97 characters) passes the cap as one alternative while minimatch compiles 65,536, and `*a*a*\{b,c,d}` passes the three-star rule while minimatch tests that three-star name against three alternatives. Severity: 8/10

Existing Risk: 7/10 - A careless or prompt-injected agent line, a typed line, or a far-side `glob-paths` request (whose `valid` uses the same predicate) can block the server's main event loop for seconds to minutes while minimatch compiles and matches the expanded set, freezing every tab, which is exactly what the pattern-caps and combined-star-budget repairs promised to prevent.

Proposal Risk: 2/10 - The cap and the matcher would read the same normalized pattern, so the remaining exposure is a future minimatch preprocessing change the cap does not mirror, which the new tests would catch only for the backslash case.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 2001 "make the file glob pattern caps judge the backslash-normalized pattern that minimatch actually expands". In `src/file-glob/pattern-limits.ts`, have `isGlobPatternTooComplex` keep the raw length check, then build `const normalized = pattern.replace(/\\/g, '/')` (the same rewrite minimatch applies under `windowsPathsNoEscape`) and pass `normalized` to `braceExpand` and to the per-name star count, so `hasTooManyStars` can split on `/` alone; extend the module comment to say the cap mirrors the matcher's backslash-as-separator preprocessing and why. `createGlobMatcher` in `src/file-glob/match.ts`, `parseFileGlob` in `src/file-glob/command.ts`, and `valid` in `src/remote/filesystem/glob-paths-operation.ts` all call this one predicate, so no call site changes. Add to `src/file-glob/pattern-limits.test.ts`, writing each pattern with `String.raw` so the backslash reaches the predicate: `x` followed by seven copies of backslash-`{a,b}` is refused, `*a*a*` followed by backslash-`{b,c,d}` is refused, `*a*a*` followed by backslash-`{b,c}` is allowed, and the existing `*a*` backslash `*b*` case stays allowed; add to `src/file-glob/match.test.ts` that `createGlobMatcher` for `x` followed by sixteen copies of backslash-`{a,b}` is built and answers `false` against a 60-character name in well under 100 ms; add a `glob-paths` invalid-argument case with the same escaped-brace pattern to `src/remote/filesystem/operations.test.ts`. The existing cap, matcher, parser, and operation tests must keep passing untouched. `help/file.md`, `product/specs/acp.md`, and `product/specs/remote-server.md` state the caps in terms of `{a,b}` combinations and need no wording change; do not change the caps' values or the refusal text.
