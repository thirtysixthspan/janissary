# pull-request

* Give the delegation tool's `agent` verb an explicit creator, so a worker's depth and group come from the tab that delegated rather than from whichever tab happened to be focused, which is why the documented depth cap does not engage.

Existing Issue: `runAgent` in `src/acp/delegation.ts` measures the cap against the right tab — `managers.tab.byLabel(label)?.agentDepth`, where `label` is the tab running the tool loop — but then calls `managers.profile.newAgent(command)`, which reaches `newAgentOp` in `src/profile/new-agent.ts`, where `const creator = managers.tab.cur()` decides the new tab's parent, and `placeAgent` in `src/profile/place-agent.ts` then computes `tab.agentDepth = (creator?.agentDepth ?? 0) + 1` and inherits `group` from the same creator. Nothing ties that creator to the delegating tab, so a worker opened by a depth-1 agent is recorded as a child of whichever tab was focused — normally the root — and its depth is 1 rather than 2. Reproduced live: a root tab opened `kaptan`, drove `kaptan`'s own ACP session to emit `agent mihri --no-workspace`, then drove `mihri`'s to emit `agent halil --no-workspace`; `mihri` was recorded at depth 1, so `halil` opened and no `Cannot delegate: this tab is already 2 agent launches deep` was ever produced, across two fresh app instances. The same root cause decides `group`, so a worker can also land outside its delegator's group, where the `Cannot delegate to "<name>": it is not one of your own agents.` check would then refuse the delegator's own `msg` to the worker it just opened. Severity: 7/10

Existing Risk: 7/10 - The depth cap is the bound that keeps one prompt from growing a tree of workspace clones and model sessions, and the primer, the skill, the documentation page, and `product/specs/acp.md` all state it as holding; a worker that delegates further spends a clone and a model call per level unbounded, and nothing in the transcript says the cap was skipped.

Proposal Risk: 3/10 - With the creator threaded through, depth and group follow the delegation tree rather than the focus order, so the cap engages on the second level and a worker's group is the one its delegator can address; the residual is that a person focusing a tab before typing `agent` by hand still parents the tab where they typed it, which is unchanged and intended.
