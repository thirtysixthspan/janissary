# pull-request

* Handle plans with no running app in the guidance's Verification requirement, which currently demands a concrete end-to-end check against a running app for every plan.

Existing Issue: The canonical plan template requires every plan to end with a concrete manual end-to-end check a reader can perform against the running app, but a documentation-only change has no running app to check, so the rule cannot be satisfied by the very class of plan this change is. Severity: 5/10

Existing Risk: 5/10 - Agents drafting documentation, spec, or configuration plans either invent a meaningless running-app check or silently omit a section the template calls required, so the template's authority erodes and improvement passes flag otherwise conforming plans as incomplete.

Proposal Risk: 2/10 - The verification rule becomes satisfiable for both code-bearing and no-code plans, with the only residual risk that the boundary for which plans count as having a runtime surface must be stated clearly enough that an agent does not guess.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 2165 "make the plan template's Verification section accommodate plans with no running app". In `ai/guidelines/plan-template.md`, extend the `Verification` section so the required manual check is defined by the plan's surface: a plan that adds or changes application behavior still ends with `$janissary/scripts/run.mjs check-diff` followed by a concrete end-to-end check against the running app, naming the exact interaction, what the reader should see, and what failure looks like; a plan that changes no application behavior and adds no code ends with that same command followed by a concrete reading-based check naming the files to read and the specific consistency claims to confirm. State explicitly why both forms exist and that every plan still needs one concrete, reader-performable manual check, so the diff-scoped command is never mistaken for sufficient proof on its own. Use the Verification section of `product/plans/complete/plan-template.md` itself — a documentation-only change whose manual checks are reading and scratch-plan checks rather than a running-app check — as the worked example, and keep the "concrete manual end-to-end check" wording in `ai/tasks/planning/improve-plan.md` compatible with both forms. No source, test, or config files change; verify by reading the revised template beside the own plan and the two improvement tasks to confirm a no-code plan can satisfy the section without inventing a check.
