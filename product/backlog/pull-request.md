# pull-request

* Close the secret-name leak that an in-root symbolic link given as the glob start opens when it points at the first segment of a multi-segment secret path.

Existing Issue: The workspace glob entry accepts an in-root directory link as `--path` and walks it under the link's name, so a link such as `cfg` pointing at the workspace's `.config` lists `cfg/gh/hosts.yml` and `cfg/gcloud/...` (and, under `--hidden`, a link to `.claude` lists `c/.credentials.json`), because the secret-start check only classifies the start itself and the walk's per-entry secret check runs on the link-named lexical path, which no longer contains the `.config/gh/hosts.yml`, `.config/gcloud`, `.claude/.credentials.json`, `.cargo/credentials`, `.m2/settings.xml`, or `.local/share/opencode/auth.json` segment run. Severity: 5/10

Existing Risk: 4/10 - An agent able to create a symbolic link in its workspace can enumerate the names of credential files the glob promises to omit, and when the workspace is the home directory those names are the user's real credential stores, contradicting the guarantee that secret files are never listed.

Proposal Risk: 2/10 - Secret names are then judged by their real root-relative location, though only names (never contents) were ever exposed and the check still depends on SECRET_DENY_PATHS staying complete, so a regression would show only through the new link-to-ancestor tests.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 2001 "filter secret matches by their real location when --path is an in-root symbolic link". In `src/file-glob/glob.ts`, have `resolveStart` return the real start's path relative to the real root (from the `realRoot`/`realTarget` pair it already computes in `resolveReal`) alongside the lexical `start`, and pass it to `walkGlob` as a new optional `GlobWalkOptions` field in `src/file-glob/walk.ts` (for example `realStartRelative`). In `record` in `walk.ts`, when that field is set and differs from the lexical prefix, also run `checkRealTarget(state.realRoot, path.join(state.realRoot, realStartRelative, startRelative))` (from `src/file-read/policy.ts`) and drop the entry on `'Secret file'` before it is pushed, so secret matches still never count toward `--limit`; keep the lexical start and the link-named output exactly as the plan's lexical-start decision requires. Add tests to `src/file-glob/glob.test.ts`: an in-root link `cfg` to `.config` holding `gh/hosts.yml`, `gcloud/x`, and `ok.txt` gives `cfg/ok.txt` alone for `** --path cfg`, with and without `--hidden`; and an in-root link `c` to `.claude` holding `.credentials.json` and `settings.json` gives `c/settings.json` alone under `--hidden`, with `--limit 1` printing no truncation line. Existing tests that must keep passing unchanged: `lists through an in-root link under the link name`, `gives (no matches) for an in-root link to a secret directory`, and the whole of `src/file-glob/walk.test.ts` and `src/file-glob/walk-modes.test.ts`.
