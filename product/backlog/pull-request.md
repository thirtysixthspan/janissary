# pull-request

* Keep the editor in front when a reveal opens a fresh navigator docked in the sidebar.

Existing Issue: When a reveal opens a new navigator rather than retargeting one, the navigator is activated and then docked left, and `applyDock` hands activation to the nearest non-docked tab after it in strip order, which the end-to-end walk observed as a `janus` tab becoming active while the editor at `src/file-navigator/remote/file-cache.ts` went hidden; retargeting an already-open navigator leaves the editor active as intended. Severity: 7/10

Existing Risk: 7/10 - The first reveal from an editor with no navigator open pulls the editor out of sight and puts an unrelated tab in front, which is the one visibility outcome the plan's fresh-dock decision exists to prevent.

Proposal Risk: 2/10 - Restoring the editor's activation after a docked reveal is a one-line branch in the reveal's own final step and leaves the shared open-or-retarget helper untouched, though it relies on the editor still being open at that point, which the same call already used to find it.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 2009 "keep the editor in front when a reveal opens a fresh docked navigator". In `src/file-navigator/reveal-editor.ts`, make the reveal's final activation dock-aware in both directions: compute `const index = port.managers.tab.findIndex(label)` once and, when `port.managers.tab.tabs[index]?.dock === undefined`, activate the navigator as today, otherwise activate the editor tab with `port.managers.tab.setActiveTab(port.managers.tab.findIndex(editorLabel))`. The docked branch is why the editor stays visible in the centre: `applyDock` in `src/tab/dock.ts` calls `nearestNonDocked` when the tab being docked is the active one, and a freshly opened navigator is active until that dock, so the strip's next centre tab wins. A retargeted docked navigator never changed activation, so the editor activation is a no-op there. Do not change `openOrRetargetLocalAt`, `registerOpenedTab`, `openFilesTab`, `applyDock`, or `nearestNonDocked`; the shell and harness button reaches `openOrRetarget`, which activates its own source tab afterwards and must keep its behavior. In `src/file-navigator/reveal-editor.test.ts`, extend the fake so an editor tab exists in `tabs`, and change the docked activation case from "no activation recorded" to "the editor's index is activated and the navigator keeps its dock", plus a fresh-open case where the fixture's `activate` mimics `nearestNonDocked` picking an unrelated tab before the reveal restores the editor.
