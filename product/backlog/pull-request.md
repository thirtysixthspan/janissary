# pull-request

* Deliver the plan's repaint rule for PDF find marks, which also repaints every drawn page each time another page's text is read.

Existing Issue: The plan says the marks repaint when the query, the highlighted row, or the text-layer counter changes, but `usePdfFind` builds `current` as a new object whenever `lines` or `results` change, so while the overlay is open with matches and reading is unfinished, every page read reruns `usePdfFindMarks`' effect, which deletes and repaints the ranges of every drawn text layer even when the highlighted occurrence is unchanged. Severity: 3/10

Existing Risk: 3/10 - In a long document scrolled through in continuous layout, typing a query before the read finishes re-walks every drawn layer once per page read, which can make typing and the read itself sluggish on exactly the documents find is most useful for.

Proposal Risk: 1/10 - `current` changes only when the highlighted occurrence's page, line, or start changes, so the remaining cost is the repaint on real changes the plan already accepts; a missed dependency would show as a stale current mark, which the existing mark tests catch.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 1958 "keep PDF find marks from repainting on every page read". In `web/src/plugins/pdf/usePdfFind.ts`, keep `current`'s identity stable while its values are unchanged: derive the highlighted occurrence's `page`, `line`, and `start` (or `null`) first, then memoize the returned object on those three primitives, so a page read that leaves the highlighted occurrence where it was returns the same object; when re-ranking makes row 0 a different line, the new values still produce a new object and the marks follow. Leave `web/src/plugins/pdf/usePdfFindMarks.ts`, its dependency list, and `PdfTab.tsx` unchanged. Add a case to `web/src/plugins/pdf/usePdfFind.test.ts` under `usePdfFind revealing`: with a deferred three-page document, set the query, resolve page 1 with a matching line, capture `result.current.current`, resolve page 2 with a non-matching line, and assert `current` is the same object (`toBe`); then resolve page 3 with a shorter matching line that `contiguousMatch` ranks first and assert `current` is a new object reporting page 2 (0-based). Optionally add a `web/src/plugins/pdf/usePdfFindMarks.test.tsx` or `PdfTab.test.tsx` case showing a page read leaves the painted `Range` objects in place. Existing `usePdfFind`, `usePdfFindMarks`, and `PdfTab find marks` cases cover current-mark movement and must stay green under `$janissary/scripts/run.mjs check-diff`.
