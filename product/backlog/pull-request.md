* Correct the plan's testing step that expects a `Schema` / `Data` switch the SQL tab does not draw

Existing Issue: The plan's Verification section tells a tester to confirm a `Schema` / `Data` switch when `sql shop` is docked, or a navigator beside the grid in the centre, and the tab draws neither, so the step cannot be followed as written. Severity: 4/10

Existing Risk: 4/10 - A tester or reviewer following the step gets stuck on a control that is not there and reads the mismatch as a missing feature rather than as stale wording.

Proposal Risk: 1/10 - Correcting the step changes no behaviour; the only thing it can cost is another correction if a future change really does add a view switch.

Proposal: Execute ./ai/tasks/work-an-issue.md "PR 1467: correct the plan's Verification step that expects a Schema / Data switch the SQL tab does not draw". Step P1, from the plan `product/plans/complete/sql-database-browser.md`'s `## Verification` section, verbatim: "Run `db sqlite create shop`, then `sql shop` and confirm a tab opens with a `Schema` / `Data` switch (docked) or the navigator beside the grid (centre), and that a fresh database shows `No tables.`" Replicate by starting this branch's app against a scratch project directory (`node bin/janus.mjs --no-open <scratch-dir>`), running `db sqlite create shop` and then `sql shop` from an agent tab, and reading the tab's own controls. The metadata row carries a database `<select>`, a table `<select>` holding the navigator's four groups (Tables, Views, Indexes, Triggers), **Insert row**, **Columns**, **CSV**, **JSON** and the split control; below it are the search field, the grid, the pager and the `SQL >` console. Expected, from `product/specs/sql-database.md`: "Docked in a sidebar — which is narrow — it is the same tab, narrower; there is nothing to switch between, so there is no view switch." Observed, the same on both runs: no control reading `Schema` and none reading `Data`, and no navigator or second pane beside the grid. Root cause: the navigator shipped as a `<select>` — `web/src/plugins/sql/TableSwitcher.tsx`, drawn by the metadata row in `web/src/plugins/sql/SqlTab.tsx` — where the plan's step was written against a two-pane `SchemaNavigator.tsx`; the two layouts collapsed into one, so the step names a control that was never shipped. The description's own **How to verify** has already been corrected to "confirm a tab opens and shows `No tables.`", while the plan's section was deliberately left as the historical record of what was planned, which is why the stale wording still stands. Fix the step as it should read in the description's **How to verify**: "Run `db sqlite create shop`, then `sql shop`, and confirm a tab opens showing `No tables.`, with its table dropdown listing the database's objects under `Tables`." Leave the tab itself alone — it does what the spec says. A regression test should assert that every control a **How to verify** step names is present in the rendered tab, so a step that cannot be followed fails a test rather than a reader.
