# pull-request

* Share the file navigator's three-state button-flash machine between the pull and the commit rather than keeping two copies of it.

Existing Issue: `src/file-navigator/manager-commit.ts` restates `src/file-navigator/manager-pull.ts` almost line for line — its own `FLASH_MS`, its own `settle`, its own `rest`, its own still-rooted guard, and its own entry guard — differing only in which pair of `FilesTabState` fields it writes, so one state machine now exists in the tree in two independent copies that know nothing of each other. Severity: 3/10

Existing Risk: 4/10 - Each copy reasons only about its own field pair, which is precisely how the two actions came to coalesce against themselves and not against each other (already on file above), and a third such button — fetch, sync, stash — would copy the machine a third time and introduce a third pair the first two would likewise not know about.

Proposal Risk: 3/10 - A shared helper is more indirect than two plain modules, and written as a generic keyed by field-name strings it would erode the checking that currently makes each status field's name meaningful, so the value of the change depends on keeping the parameterization concrete rather than clever.

Proposal: Execute ./ai/tasks/work-an-issue.md "PR 1128: share the file navigator's button-flash state machine between pull and commit". Extract a module beside the two — `src/file-navigator/manager-flash.ts` — holding `FLASH_MS`, the `settle`/`rest` pair, and the still-rooted guard, parameterized by a small descriptor of explicit read/write functions over a `FilesTabState` rather than by string keys, so the field names in `src/file-navigator/state.ts` stay checked by the compiler. Rewrite `manager-pull.ts` and `manager-commit.ts` to hold only what is genuinely each one's own: the entry guard's subject, the port call, the report text from `pull-report.ts` or `commit-report.ts`, and what a settled outcome triggers — `clearFilesystemCache` plus `refreshGit` for the pull, `refreshGit` for a landed commit, and neither for a nothing-to-commit result, which settles straight to rest. Have `closeTabState` in `src/file-navigator/manager-profile.ts` clear its timers through the same descriptor list, so a future third status cannot be forgotten there the way it currently could be. The separate `PullContext` and `CommitContext` types stay separate, as the plan decided. This is a refactor with no behavior change: the existing pull cases in `src/file-navigator/manager.test.ts` and the commit cases this pull request added there — flash timing, settle-to-rest, coalescing, tab-closed-mid-flash, notification-posted-after-close — are the contract, and passing them untouched with no new assertions is what finishing this looks like.
