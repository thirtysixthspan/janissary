# pull-request

* Let the search tab be reached, since its `search` command claim is refused against the built-in transcript search and the whole tab is disabled on every start.

Existing Issue: The search plugin declares `command: 'search'`, and `createPluginCommands` in `src/plugins/command-adapter.ts` builds its `reserved` set from every core command's `name`, which for the built-in transcript search in `src/commands/search.ts` is the bare string `search` even though the command it actually matches is `search transcript <pattern>`. The claim is therefore refused with `reserved tab plugin command claim "search"`, the plugin is recorded disabled at module load, and neither its command nor its Cmd+Shift+F chord can open the tab. Severity: 9/10

Existing Risk: 9/10 - The pull request ships a feature no user can reach: the tab never opens from any route, the chord silently does nothing, and the failure surfaces only in `plugins` output, so the feature reads as complete to anyone checking the diff and the specs.

Proposal Risk: 3/10 - Whatever name the plugin claims is free once the reservation stops treating the transcript search's two-word form as a claim on the bare name; the residual risk is that a future core command reintroduces a real collision, which the duplicate-claim check still refuses.

Proposal: Execute ./ai/tasks/work-an-issue.md "PR 1481: stop refusing the search plugin's command claim against the built-in transcript search". Reproduce with the scratch project the run used: start the app on a directory whose launch root holds a file containing the text `NEEDLE_ONE`, press Cmd+Shift+F, and observe no tab opens; then run `plugins` and observe `search 1.0.0 api=1 state=disabled reason=reserved tab plugin command claim "search"`. The cause is in `src/plugins/command-adapter.ts`, where `createPluginCommands` builds `reserved` from `coreCommands.map((command) => command.name.toLowerCase())`; the built-in in `src/commands/search.ts` has `name: 'search'` and `match: (command_) => /^search\s+transcript\b/i.test(command_)`, so it reserves the bare token while only ever consuming `search transcript`. Reserve what a command actually matches rather than what it is named: have the reservation test the built-in's own `match` against the claimed name, or narrow the transcript search's reservation to the two-word form it claims, so `search` alone is free for a plugin. Whichever route is taken, add a case to the adapter's test file asserting that a declaration claiming `search` is admitted while one claiming a genuinely colliding name is still refused with its recorded reason, and keep the existing duplicate-claim case passing untouched. Then re-run the manual steps: Cmd+Shift+F opens the tab, `search` opens it, and `search transcript foo` still reaches the built-in — that last one matters, because the two must coexist rather than one shadowing the other. Finally, `product/specs/search-tab.md` and `product/specs/tab-plugins.md` describe the tab as reachable by `search`, so if the claim is renamed rather than unreserved, both need the new name.
