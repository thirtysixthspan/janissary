* Handle a launched shell that closes and is reopened under the same name, so the first launch's delayed close and failure line can no longer act on the second shell.

Existing Issue: The host launch finds its tab again by plugin id and label alone, both in the provisioning wiring's tab-exists check and in the timer that closes a failed launch after `PROVISION_FAILURE_CLOSE_DELAY_MS`, so a failed `zsh docs` that the user closes and retypes within those three seconds has its replacement `docs` shell closed, and its new clone cancelled, by the first launch's timer. Severity: 4/10

Existing Risk: 4/10 - A user retrying a failed workspaced shell under the same name loses the fresh shell, its in-flight clone and any lines already queued for it, with a stale `Failed to create workspace` line in the feed that looks like the retry failed too.

Proposal Risk: 2/10 - Lookups keyed by the launch's own instance key cannot reach a different tab, but the same label-keyed pattern remains in the agent path and could still bite there until it gets its own fix.

Proposal: Execute ./ai/tasks/work-an-issue.md "PR 1569: key launchTab's provisioning and failure lookups by instance key, not label". In `src/plugins/launch-tab.ts`, every later lookup of the launched tab goes through `ownTabExists(managers, pluginId, label)`, which matches any tab of the plugin carrying that label. That covers the `tabExists` callback passed to `wireProvisioning` in `awaitClone`, the delayed close in `failLaunch`, the `busy` reset at the top of `runReady`, and the rejection check after the deferred ready call. The launch already holds a unique `instanceKey`, so resolve the tab with `managers.tab.pluginTabByInstanceKey(declaration.id, instanceKey)` instead (the lookup `notifyUser` and `setBusy` already use in `src/plugins/context.ts`). Thread `instanceKey` into `failLaunch`, and have its timer close the tab only when that lookup still finds it, using the found tab's label for `managers.tab.findIndex`. Keep the `label` argument `wireProvisioning` takes for its own bookkeeping, but give it a predicate that ignores the label and checks the instance key. Keep `openLaunched`'s post-open check as it is, because it runs synchronously right after the open. Add cases to `src/plugins/launch-tab.test.ts` using its existing fake-timer setup. In one, the clone fails, the tab is closed, a second launch under the same typed name opens, and once the delay passes the second tab is still open. In another, a cancelled clone's rejection arrives after a same-named relaunch and posts no failure line. The existing cases there ("posts the failure and closes the tab after the delay when the clone fails", "cancels the clone when the tab closes first…", "closes only its own tab when the ready handler rejects…") must keep passing unchanged. `startWorkspaceAgent` in `src/profile/new-agent.ts` has the same label-keyed shape, but it predates this pull request and has no instance key. Leave it alone here; it belongs in `./product/backlog/technical-debt.md`.
