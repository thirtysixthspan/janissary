# pull-request

* Handle saving the shell transcript from the editor tab that Open transcript opens, which today silently cuts the live transcript off from every later row.

Existing Issue: Open transcript opens the shell transcript in an ordinary editable editor tab while the shell's writer is still appending to it through a long-lived stream, and saving that tab replaces the file by an atomic rename, so after a save made while the shell is idle (the stale-save hash check still passes) the writer keeps appending to the orphaned inode and every later row of the session silently vanishes from the file on disk. Severity: 4/10

Existing Risk: 4/10 - A user who opens the transcript, jots a note or tidies a line and presses Cmd+S loses the rest of the session's transcript with no `shell transcript failed` notice, and the button keeps opening the truncated file as if nothing happened.

Proposal Risk: 2/10 - The refusal closes the silent-loss path, but the transcript is still shown in an editor that accepts typing, so a user may still be surprised that a save is refused, and a refusal keyed on the directory would also block saving an old transcript a user deliberately wanted to edit.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 1675 "stop an editor save from orphaning a live shell transcript". `src/controller/transcript.ts` `openTranscriptFileFor` opens the shell tab's `tab.transcript` through `managers.openFile.edit`, and the editor's save path in `src/editor/save.ts` writes local files with `atomicWriteFile` (`src/atomic-write.ts`, a temp-file write then `renameSync`), while `ShellTranscriptWriter` (`src/shell/transcript/writer.ts`) keeps appending through the single `BoundedAppendFile` stream (`src/bounded-append-file.ts`) it opened on the first output. Make a save of a transcript that is still being written refuse with a clear message rather than replace it: give `ShellTranscriptManager` (`src/shell/transcript/manager.ts`) a narrow `isWriting(path)` query answered from the `openedPath()` of the writers it holds (a deliberate, documented exception to the plan's "the manager exposes no path lookup", since the tab record cannot answer whether the writer is still alive), and have `saveFile` consult it on its local path before `atomicWriteFile`, refusing in the same shape as the existing `refuseOrphanedRemoteSave` in `src/editor/save.ts` and `refuseStaleSave` in `src/editor/stale-save.ts` (a `file-operation` notification for the tab, then a thrown error) with text such as `This shell transcript is still being written; copy it to another file to edit it.` The existing stale-save hash check refuses a save once a new row has landed since the editor loaded the file, but the overwrite prompt's own write omits the hash and a save made while the shell sits idle at its prompt passes it, after which every later command's rows reach only the orphaned inode; the new refusal must cover both, including the overwrite path. Do not change `BoundedAppendFile` or the writer's behavior. Add a case to `src/shell/transcript/manager.test.ts` that `isWriting` is true for an installed writer's opened path and false after its PTY exits or its tab closes, and a case beside the existing editor save tests that a save of a live transcript path is refused and leaves the file's bytes untouched. Update `product/specs/shell-tab.md` § Text transcript and the "Read a shell session's transcript" section of `documentation/user-documentation/command-bar/shell.md` with one sentence saying a transcript cannot be saved over while its shell is running. The existing `src/controller/transcript.test.ts` and `src/shell/transcript/writer.test.ts` cases must keep passing unchanged.
