# pull-request

* Handle a double-click on a row's Run or Duplicate button so it runs or duplicates once and does not open the runscript in an editor tab.

Existing Issue: A double-click on a row's Run button sends execute twice and also opens the runscript in an editor tab, and a double-click on its Duplicate button creates two copies and opens the source, because the row buttons stop only the click event while the row's double-click handler still receives the double-click. Severity: 5/10

Existing Risk: 5/10 - A double-click on Run runs a runscript twice, so any side effect in a deploy-style script repeats, and a double-click on Duplicate leaves an extra copy such as deploy-2.rs and deploy-3.rs behind for the user to clean up.

Proposal Risk: 2/10 - The only hazard left is a second press that the browser counts as part of the same double-click, which the guard ignores by design, so a user who wants two runs must press again after a pause.

Proposal: Execute ./ai/tasks/feature/work-pull-request-issue.md 1739 "handle a double-click on a row's Run or Duplicate button so it sends one intent and opens nothing". In web/src/plugins/scripts/ScriptRowActions.tsx, give each button an onDoubleClick handler that calls stopPropagation, so a double-click that starts on the button never reaches the row's onDoubleClick in web/src/plugins/scripts/ScriptRows.tsx, and make the existing onClick return early when event.detail is greater than 1, so the second click of a double-click sends no second execute or clone. Keep the Delete button's click path unchanged, since its second click lands on the modal backdrop that web/src/plugins/scripts/DeleteScriptDialog.tsx already swallows. Do not touch web/src/plugins/schedules/SchedulesRows.tsx, whose trash button has the same leak but is outside this pull request. Add a test to web/src/plugins/scripts/ScriptRowActions.test.tsx that fires a doubleClick on the Run button inside a wrapping div with an onDoubleClick spy and expects the spy not to be called. Add a test to web/src/plugins/scripts/ScriptsTab.test.tsx that uses userEvent.dblClick on the Run button of a row that is not selected and expects intent to have been called once with execute and { name }, never with open, and the selection to be unchanged. Add a second test in the same file that double-clicks a row's name and expects open to be sent once, so the row's own double-click open path stays pinned. The existing tests that must keep passing untouched are the click-propagation test in web/src/plugins/scripts/ScriptRowActions.test.tsx, and the single-click Run and Duplicate tests, the userEvent Enter tests, and the Delete button tests in web/src/plugins/scripts/ScriptsTab.test.tsx.
