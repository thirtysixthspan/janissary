## deferred

* Split `src/tab/manager.ts` and retire its parallel per-label maps: the file is 451 lines and opens with `/* eslint-disable max-lines */`, suppressing the project's own 200-line guideline rather than following the guideline's stated remedy of extracting a cohesive module. It also still holds `cwd`, `busy`, `context`, and `queue` as separate `Map`/`Set` keyed by label — the exact "parallel maps keyed by label" pattern architecture principle 2 says to replace with state owned by the agent's own session object, now simply relocated from `Controller` to `TabManager`. Extract the split-pane/focus-selection logic (`repairSelections`, `focusedPane`, `recentLabel`, `moveTabToOtherPane`, `placeProfileTabs`) into its own module and move the per-label maps onto the tab object, then delete the suppression. Severity: **high**.

* Replace the callback-injection style in `src/tab/manager.ts`'s delegation to `src/tab/close.ts`, `rename.ts`, and `navigation-commands.ts`: `closeTabOp` takes seven positional arguments including three lambdas, and `renameTabOp`, `reorderTabOp`, `reorderTabToOp`, and `finishTabRunning` each take four to six more, so the extraction moved lines out of the manager without reducing the coupling — every helper still needs the manager's persistence, state-building, focus-history, and unread-marking behavior, just passed in positionally where the compiler cannot catch a swapped pair of same-shaped callbacks. Give these helpers a single named context/options object (or make them methods on a state object they own) so the dependencies are named at the call site. Severity: **medium**.

* Give the managers a real teardown contract instead of `Controller.shutdown()`'s hand-maintained list: `src/controller.ts:228-241` calls twelve differently-named cleanup methods (`closeAll`, `dispose`, `stop`, `removeAll`, `clear`) across 22 managers, from memory, exactly as architecture principle 6 warns. `HarnessManager` (`src/harness/manager.ts`) holds `screenReaders`, `recorders`, and `autoApprovers` maps whose entries are only ever released on a per-PTY `exit` event and is never called during shutdown at all, and `CaptureManager` has no teardown path either. Add an optional `dispose()` to the `Managers` shape and have `shutdown()` iterate, so adding a resource-owning manager cannot silently skip teardown. Severity: **medium**.

* Cover the sandbox policy tables with tests that run in the default suite: `src/sandbox/paths.ts` is 194 lines defining every write carve-out, read carve-in, secret deny path, and env-scrub pattern the Seatbelt profile is generated from, and it has no colocated test file — while the two tests that do exercise real deny/allow behavior, `src/sandbox/live.sandbox.test.ts` and `src/sandbox/keychain.sandbox.test.ts`, are scoped to a separate `sandbox` vitest project excluded from `npm test` and `npm run check` and only reachable via a manual `npm run test:sandbox`. This leaves the boundary architecture principle 9 calls the strongest in the system unpinned in CI, where a one-line table edit that widens access past a `SECRET_DENY_PATHS` entry would go unnoticed. Add a colocated `paths.test.ts` asserting the invariants that hold without a real sandbox (every secret path stays outside every carve-in, no carve-out grants a whole `.claude`/`.cache`/`.npm` root, param counts match table lengths). Severity: **medium**.
