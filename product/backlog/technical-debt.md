* Move `isReportingTab` and the `TabEntry` type into one pure module: `web/src/ReportingSection.tsx:12` declares the three-line `isReportingTab(tab)` predicate inside a component file that imports React, `MonitorTab`, `TabStrip`, `ResizeButton`, and `drag-resize`, and two hook modules import it back up the stack — `web/src/useTabEntries.ts:3` and `web/src/useSectionNav.ts:3` — along with `web/src/TabNavPicker.tsx:5`, while `ReportingSection.tsx:7` imports `type { TabEntry }` from `useTabEntries.ts` in the other direction. That is §8 (each layer imports downward only; a hook may import services and pure modules, never a component), and it has already closed a loop: the component and the hook module each import the other. The cost is that asking "is this a monitor tab?" drags the whole reporting UI subtree into the asker's module graph — `useSectionNav.ts`'s `getPresentSections` and `resolveCurrentSection` are pure functions with no JSX, yet cannot be typechecked or tested without `MonitorTab` and FontAwesome coming along — and `ReportingSection.tsx` is one of the more churned files in `web/src/`, so each edit to it re-touches the module every tab hook depends on. Create `web/src/tab-entries.ts` holding `TabEntry` and `isReportingTab`, move both declarations there, and repoint `ReportingSection.tsx`, `useTabEntries.ts`, `useSectionNav.ts`, `TabNavPicker.tsx`, and `ReportingSection.test.tsx`. Four production files and one test import the two symbols, and nothing about the reporting section's rendering changes. Severity: **high**.

The rules cannot be exercised without React and FontAwesome in the module graph, and the list is computed twice: `TabNavPicker.tsx:62` calls `filterTabs(tabs, query)` in its own render body while `useTabNav` has already produced the same list as `navTabs` for the key handler that indexes into it, so the list the user sees and the list Return selects from are derived independently and can disagree. Move `filterTabs`, its `displayLabel` helper, and the `TabNavEntry` type into `web/src/tab-nav-match.ts` and point all four files at it; passing `navTabs` down to the picker instead of re-filtering is the natural follow-on. Four production files and two tests reference the two symbols. Sequence it after the `isReportingTab` entry above, which also rewrites `TabNavPicker.tsx`'s import block. Severity: **medium**.
