* Give the syntax-highlight memo an owner instead of a module global: `web/src/editor/highlight/tokenize.ts` holds `previousLanguage`, `previousLines`, and `previousTokens` as module-level `let`s (lines 53-55) that `tokenizeDocument` reads and overwrites on every call, so one cache is shared by every editor tab — a stateful cache is a service, and §7 (services are instantiated at the edge, not imported; a module-level singleton cannot be swapped in tests and silently couples every importer to one instance) is the rule it breaks, while §8 puts cross-call state below the pure-module row this file otherwise sits in. The cost is concrete and contradicts the code's own comment: `useSyntaxHighlight.ts` says it "owns the tokenize schedule for one editor tab", but two tabs open on the same language interleave into that single cache, each call resetting `previousLines` to the other tab's document, so every line misses and the referential reuse that `EditorLine`'s `React.memo` depends on stops working for both. `tokenize.test.ts`'s reuse case at line 70 reads the same global, so its cases leak into each other. Replace the module state with a `createTokenizer()` factory returning a `tokenize(text, language)` closure, and have `useSyntaxHighlight` hold one per tab in a `useRef`. Four files import from `tokenize.ts` and three of those take only the `TokenRange` type, so `useSyntaxHighlight.ts` and the test are the only callers to update. Severity: **medium**.

* Move the file-navigator's four overlay components into `web/src/file-navigator/`: `FileNavigatorOverlays.tsx` (lines 2-4) pulls `MoveConflictDialog` from `../MoveConflictDialog/MoveConflictDialog`, `DeleteFileDialog` from `../DeleteFileDialog`, and `FileSearchPopup` from `../FileSearchPopup`, and `FileNavigatorOpenerOverlay.tsx:2` pulls `FileOpenerPicker` from `../FileOpenerPicker` — and grepping each name shows the navigator is the only consumer of all four, which violates §2 (colocate; promote to shared only on a second real consumer). These are not generic primitives that merely lack a second caller yet: `DeleteFileDialog.tsx`'s own comment says it is "shown when Backspace/Delete is pressed on a selected file-navigator row", and `FileSearchPopup.tsx` imports `file-search-match.ts`, which nothing else in the app uses either. The cost is that gathering the feature into its directory left its dialogs behind, so the directory still does not answer "what is in the file navigator?", and the four look shared enough that the next feature will reuse one and cement the wrong boundary. Move all four with their colocated tests into `web/src/file-navigator/`, take `file-search-match.ts` and its test along with `FileSearchPopup.tsx`, and delete the emptied `web/src/MoveConflictDialog/` directory. Nothing outside the navigator imports any of them, so only the two overlay files' import paths change. Severity: **medium**.

* Finish gathering the editor feature into `web/src/editor/`: `web/src/EditorTab.tsx` — the feature's top-level component, whose import block is eighteen `./editor/…` lines — sits in the flat `web/src/` root next to `EditorTab.test.tsx` and the editor-only `OverwriteConflictDialog.tsx` and its test, which `EditorTab.tsx:191` is the only render site for, while the feature's other fifty-nine files live under `web/src/editor/`. That is §1 (organize by feature, not by file type): the directory named for the feature does not contain the feature's entry point, so its edge is invisible and every new editor file has to guess which side of the line it belongs on. Move all four files into `web/src/editor/`, flip the eighteen `./editor/…` imports to `./`, and repoint the thirteen other root files that import `./EditorTab` — `App.tsx`, `AppMain.tsx`, `AppShell.tsx`, `Sidebar.tsx`, `MountedViewLayers.tsx`, `CloseSaveGuard.tsx`, `dirtyTabs.ts`, `useUnsavedQuitGuard.ts`, and their tests — at `./editor/EditorTab`. It is all import-path churn with no behavior change; sequence it after the drop-handle entry above, which also rewrites `EditorTab.tsx`'s import block. Severity: **medium**.

* Delete one of the two identical latest-value ref hooks: `web/src/useLatestRef.ts` and `web/src/useLiveRef.ts` have byte-identical bodies — `const ref = useRef(value); ref.current = value; return ref;` — under two names and two differently worded comments, and neither is actually shared: `useLiveRef` has exactly one consumer (`useAppWindowKeys.ts:14`) and `useLatestRef` has none at all outside its own test. Both sit at the shared flat root, which is what §2 (colocate; promote to shared only on the second real consumer) exists to prevent — a shared layer filling with single-consumer code nobody dares change. The cost is small but compounding: an author needing a latest-value ref finds two equally blessed options with no signal which is canonical, so the split perpetuates, and any correctness fix to the pattern has to be made twice or the two silently diverge. Keep `useLatestRef.ts` and its test, point `useAppWindowKeys.ts` at it, and delete `useLiveRef.ts`. One production file changes. Severity: **low**.
