* Route the file navigator's clipboard reads and writes through the paste hook that already subscribes to the clipboard store, so the tree's components stop reaching into a module-level global.

Existing Debt: The navigator's overlays component calls `getClipboardSnapshot()` during render to decide whether the context menu offers Paste, and the tab component calls `setClipboard('cut', …)` itself, so two components reach straight into the module-level clipboard store past `useFileNavigatorPaste`, the hook that owns its subscription, which §7 (services are injected, never imported into components) and §8 (no component reaches past its hook into a service) both forbid. Severity: 5/10

Existing Risk: 4/10 - The menu's Paste entry reads the store without subscribing to it and stays current only because a sibling hook re-renders the whole tab on every clipboard change, so memoizing the overlays or moving the menu under another component would offer or withhold Paste against a stale clipboard, in a feature that changed in two of the last four commits.

Proposal Risk: 2/10 - The store is still a module-level singleton, so a test that sets it and forgets to clear it still leaks into the next case in the same file; this narrows who touches the store without making it injectable.

Proposal: `web/src/file-navigator/useFileNavigatorPaste.ts` already calls `useSyncExternalStore(subscribeClipboard, getClipboardSnapshot, getClipboardSnapshot)` but throws the result away. Keep that snapshot and add three things to the hook's return: `armed` (true when the snapshot isn't null), `cut(paths)` (calls `setClipboard('cut', paths, host)` with the hook's own `host`), and `disarm()` (calls `clearClipboard()`). In `web/src/file-navigator/FileNavigatorTab.tsx`, replace the `cutSelection` chord handler's `setClipboard('cut', clipboardPaths(), files.remote?.host)` with `paste.cut(clipboardPaths())` and drop the `./file/navigator-clipboard` import. In `web/src/file-navigator/FileNavigatorOverlays.tsx`, which already receives `paste`, pass `paste.armed` to `fileNavigatorMenuItems` in place of `getClipboardSnapshot() !== null` and drop the import. In `web/src/file-navigator/useFileNavigatorKeyDown.ts`, take the paste hook's result as a parameter and have `clearSelectionAndClipboard` use `paste.armed` and `paste.disarm()`, so the paste hook becomes the only file outside `file/` that touches the store. Leave `web/src/file-navigator/file/navigator-copy.ts` alone; it's the copy path's own module and already sits below the hooks. Four source files change, all inside `web/src/file-navigator/`, and `FileNavigatorTab`'s props don't move, so its mount points `web/src/Sidebar.tsx` and `web/src/ViewTabBody.tsx` are unaffected. The `makePaste` helper in `web/src/file-navigator/FileNavigatorOverlays.test.tsx` needs `armed: false` added, and `web/src/file-navigator/useFileNavigatorPaste.test.ts` should gain cases for `armed`, `cut`, and `disarm`. `web/src/file-navigator/FileNavigatorTab.test.tsx` drives the real store with `setClipboard` and `clearClipboard` and pins cut, paste, and Escape end to end; it must pass unchanged. Turning the store into an instance created at the app edge and provided through context is the larger follow-up, and it stays out of this change.

* Lift the close-tab rules out of the App component into a hook and a pure decision function beside it, so the terminal-exit, last-tab, system-shell, and unsaved-work rules can be tested without rendering the whole app.

Existing Debt: The App component decides how a tab closes in its own body, sending a terminal-exit close straight through, turning a close of the last counted tab into the quit prompt via `closeQuitsApp`, skipping the save guard for the system shell, and otherwise asking the save guard before it sends `closeTab`, which §5 (components render, they do not decide) puts in the wrong place, and the only tests of that cascade render all of App. Severity: 5/10

Existing Risk: 5/10 - With no seam to call, the sidebar already closes docked tabs with its own bare `closeTab` send that drops the terminal-exit reason a docked plugin body passes up, so a docked shell tab whose process exits is closed as an ordinary user close that skips the server's check that its terminal really stopped, and the next close path added will most likely fork the same way.

Proposal Risk: 2/10 - The decision becomes a function anyone can call, but the sidebar keeps its own close path until a follow-up wires it in, and App's terminal-exit branch has no test today, so a slip while moving that branch would go unnoticed until a shell tab failed to close on exit.

Proposal: `web/src/App.tsx` builds `closeTab` with `useCallback` from `tabs`, `client`, `guardedOpenQuitConfirm`, and `guardRef`. Extract the branch logic into a new `web/src/close-tab-rules.ts` as a pure `closeTabAction(tabs, index, reason)` that returns what should happen: nothing for a missing tab, a terminal-exit close carrying the pty id, the quit prompt when `closeQuitsApp(tabs, index)` holds, a direct close for a `systemShell` tab, or a guarded close for everything else. Add a new `web/src/useCloseTab.ts` hook that takes `client`, `tabs`, `guardedOpenQuitConfirm`, and `guardRef`, calls `closeTabAction`, performs the result (including the `guardRef.current?.(index)` check for a guarded close), and returns the same `(index, reason?) => void` callback. App then calls `useCloseTab(...)` and passes the result on exactly as it does now, to `web/src/AppMain.tsx` (which hands it to the center area, the reporting section, and `MountedViewLayers`) and to `useCmdW`. App's only export and its props don't change, so no import path moves. Keep the change to App: `web/src/Sidebar.tsx` sends `closeTab` directly from its tab strip and from `DockedPluginBody`'s `onClose`, and routing those through the hook is a follow-up that has to thread the callback through `web/src/AppShell.tsx`. `web/src/App.test.tsx` pins the system-shell close and the last-tab quit prompt from both the strip's × and Cmd+W, and `web/src/CloseSaveGuard.test.tsx` and `web/src/CloseSaveGuard.named-close.test.tsx` pin the guarded path; none needs an edit, and all must keep passing. Resolve by running the `ai/tasks/hygiene/improve-modularity.md` task against `web/src/App.tsx`.
