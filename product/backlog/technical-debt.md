# technical-debt

## ready

* Make the RPC dispatcher in `src/message-handler.ts` exhaustive over `ClientMessage['method']`: `CLIENT_METHOD_CONTRACTS` in `src/client-message.ts` is compile-checked with `satisfies Record<ClientMessage['method'], ClientReplyMode>`, but `dispatch` is a bare switch with no `default` and an `unknown` return type, so adding a method to the protocol union and the contract table while forgetting its `case` compiles cleanly and answers the client with a successful `rpc-reply` carrying `'ok'` or `undefined`. Give `dispatch` a `default` branch that assigns `message` to `never` (or a return type the switch must satisfy) so a missing handler is a build failure rather than a silent no-op that looks like success. Severity: **high**.

* Collapse the eight parallel picker prop groups threaded through `web/src/App.tsx`, `web/src/AppMain.tsx`, and `web/src/pickers/PickerOverlays.tsx` into one state object per picker: route, syntax theme, app theme, history, tab-nav, queue, task, profile, and quick-open each contribute their own `open`/`index`/`setIndex`/rows/`onPick` props, producing a 45-field `PickerOverlays` props type, a ~60-prop `AppMain` signature, a third partial copy inside `AppCenterActionArea`'s `mountedProps`, and a fourth inside the `useAppWindowKeys` argument bag. The design has already drifted: `AppMain`'s hand-maintained `blockingOverlayOpen` ORs seven of the flags and omits `quickOpenOpen`, so the command bar is not told it is blocked while quick-open is on screen. Have each `use*Picker` hook return one object, pass that single value down, and derive `blockingOverlayOpen` from the collection rather than from a hand-written expression. Severity: **high**.

* Derive the remote filesystem protocol's operation handling from one table instead of six hand-synchronized lists in `src/remote/protocol.ts`, `src/remote/frame-decode-filesystem.ts`, `src/remote/serve-file-navigator.ts`, and `src/file-navigator/remote-port.ts`: the seventeen operations are spelled out separately in the `RemoteFilesystemOperation` union, the `OPERATIONS` set, the `validArguments` switch, the `decodedArguments` switch, the `requestPaths` switch, and the `ROOT_DESTINATION_OPERATIONS` set, so adding one operation means editing six places and forgetting any of them fails quietly rather than at compile time. The `requestPaths` fall-through is the sharp edge — its `default` returns only `[args.path ?? args.destination ?? '']`, so a new operation that carries paths under any other key (a `sources` array, a `from`/`to` pair) passes `validatePaths` without a single path being checked against `containedPath`, silently losing the workspace-containment guarantee that is the whole point of the far-side validator. Replace the parallel switches with one operation descriptor table that names each operation's argument validator, decoder, path extractor, and dispatch target, so a missing entry is a type error. Severity: **high**.

## deferred

* Move the cross-feature primitives out of the flat `web/src/` root into `web/src/shared/` and extend the lint zones to cover the root, per `ai/guidelines/react-code-organization.md` §1 and §3: about 130 files sit directly in `web/src/`, and feature directories reach into a dozen of them — `ws.ts`, `icons.ts`, `ModalDialog.tsx`, `StatusWindowButton.tsx`, `status-button.ts`, `useStatusWindows.ts`, `useDialogKeyboard.ts`, `fuzzy-match.ts`, `drop-handles.ts`, `tab-handles.ts` — so the app-shell layer is serving as an unpoliced shared bucket. The `clientFeatureZones` in `eslint.config.mjs` only forbid feature-to-sibling-feature and shared-to-feature imports, so none of this is caught, and `web/src/plugins` is missing from `clientFeatureDirectories` entirely, leaving that feature free to import any sibling. Promote the genuinely shared modules, then add the root and `plugins` to the zone list so the boundary is enforced rather than remembered. Severity: **high**. — deferred: complexity 8/10, promoting a dozen modules and adding the `web/src` root to the lint zones is a layering change that rewrites imports across roughly 130 app-shell files and every feature directory at once.

* Give RPC failures and connection loss an explicit result path in `web/src/ws.ts`: `JanusClient.request` ignores the `error` carried by `rpc-reply`, resolves `undefined as T` when the socket is not open, and leaves every pending promise unsettled if the socket closes, while callers such as `web/src/useQuickOpen.ts`, `web/src/file-navigator/useFileNavigatorSearch.ts`, and `web/src/file-navigator/useFileNavigatorMoveOperations.ts` immediately dereference the declared result. Reject or return a typed result on server errors and disconnection, settle pending calls on close/dispose, and make callers handle that shared failure contract. Severity: **high**. — deferred: complexity 8/10, requires a shared RPC failure contract and coordinated lifecycle/error handling across ten client call sites. decision: a lot of work and perf issue - defer until needed.


## declined

* Protect user edits made after a copy-paste before undo deletes its destination in `src/file-navigator/moves.ts`: `undoCopyPaste` records only absolute source and destination paths and unconditionally removes each destination, so editing or replacing a copied file before pressing undo silently deletes the newer content. Record enough identity or content metadata with each copy history entry to detect divergence and surface a conflict instead of removing a changed destination. Severity: **high**. — deferred: complexity 8/10, requires recursive destination identity tracking plus new undo conflict semantics across server history and client conflict handling.

* Stop the sandbox-confinement tests from passing vacuously off darwin in `src/sandbox/index.test.ts`: seventeen cases open with a bare `if (!sandboxAvailable()) return;`, and `sandboxAvailable()` requires `process.platform === 'darwin'` plus `/usr/bin/sandbox-exec`, so on the `ubuntu-latest` runners every job in `.github/workflows/ci.yml` uses, all of them return before their first assertion and are reported as *passing* rather than skipped. Every assertion about the Seatbelt profile the security model rests on — the `-D` param bindings, the secret-deny paths, the credential scrub, the `TMPDIR` override, the offline variant — therefore only ever runs on a developer's Mac, and CI would stay green if the confined path were deleted outright. Convert them to `describe.skipIf(!sandboxAvailable())` (or `it.skipIf`) so a run that cannot exercise confinement reports skips instead of green passes. Severity: **high**. declined: this application is currently limited to running on mac os x.
