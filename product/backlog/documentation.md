Missing: that `plugins` takes no arguments and activates nothing, its exact line format `<id> <plugin-version> api=<required-api> state=<declared|active|disabled>` with `activation=<milliseconds>ms` on an active plugin and `reason=<recorded reason>` on a disabled one, that state lasts only for the server process and restarting returns every bundled plugin to `declared`, which six plugins are bundled (image, markdown, page, schedules, video, audio), that a plugin activates lazily on first use of its extension, command, or web-address claim, the verbatim failure line `Tab plugin "<id>" disabled: <reason>.`, that a fatal failure closes every tab that plugin owns and only restarting Janissary retries it, that a bad request is answered without disabling anything, that plugin tabs are live views not restored by `--relaunch` but captured by a profile, and that a plugin tab can be docked into either sidebar and share that sidebar with a different plugin's tab. Most of `product/specs/tab-plugins.md` is architecture that belongs in the spec per `ai/guidelines/developer-documentation.md`; only the user-facing subset above should be written up. Ground truth is `product/specs/tab-plugins.md`, `src/commands/plugins.ts`, `src/plugins/catalog.ts`, and `src/plugins/failure.ts`. Fix by adding a short page under `documentation/user-documentation/command-bar/` covering the command, the bundled set, and what a disabled plugin looks like.

Ground truth is `product/specs/send.md`, `src/commands/send.ts`, and `src/completion-handlers.ts`. Fix by adding a `send` page under `documentation/user-documentation/command-bar/` covering both routing kinds and the error table, and by adding `send` to the `help.md` tab-completion paragraph.

* shell (4/10) — `documentation/user-documentation/command-bar/shell.md` covers routing, persistence, and PTY takeover well, but omits the one fact most likely to confuse a new user: 1 of 14 facts is missing and none are wrong. Missing: a tab's shell is the user's login shell (`$SHELL`, falling back to `bash`) started with its startup files suppressed — `bash` with `--norc --noprofile` and `zsh` with `--no-rcs` — so aliases, `PATH` edits, functions, and prompts from `.bashrc`/`.zshrc`/`.profile` do not apply inside a tab, which is deliberate so an interactive rc file cannot leak banners or traps into captured command output. A login shell that is neither bash nor zsh gets no suppression flags and does read its own startup files, which is worth stating because the behavior differs by shell. Ground truth is `product/specs/shell.md` and `src/shell-startup.ts`. Fix by adding a short paragraph to the "One shell per tab, and it persists" section of `shell.md`, naming the workaround of sourcing an rc file explicitly when a tab needs it.

* editor-tab (4/10) — `documentation/user-documentation/tab-types/editor.md` is comprehensive, but 2 of roughly 26 facts are missing and none are wrong. Missing: the whole `Cmd+F` fuzzy line-search overlay added to the editor tab — a `Search buffer` input at the bottom of the tab that fuzzy-matches the buffer's own lines, lists the ten best-scoring ones with dimmed 1-based line numbers and emphasized match characters, moves the caret live as you arrow through them, needs no commit step because the jump already happened, closes on `Escape` leaving the caret where the last preview put it, shows `No matching lines` on a miss and `type to search` when empty, and never records an undo step; `help.md`'s `Cmd+F` row says only "Open the search bar in the transcript", which does not describe what the chord does in an editor tab. Also missing: the mouse selection detail that a double click selects the word under the pointer while a triple click selects the whole line (matching a gutter click), and that dragging after either extends the selection a line at a time. Ground truth is `product/specs/editor-tab.md`, `web/src/editor/useEditorFind.ts`, `web/src/editor/EditorFind.tsx`, and `web/src/editor/keys.ts`. Fix by adding a "Finding a line" section to `editor.md`, extending the `help.md` `Cmd+F` row to name both behaviors, and adding the click behaviors to the "Focus stays in the buffer" section.

* application-config (3/10) — The configuration reference table in `documentation/user-documentation/getting-started/startup.md` lists seven of the eight settings the app reads, so 1 of about 12 facts is missing and none are wrong. Missing from the table: `externalViewers`, the object mapping each opener name to the macOS application that receives the file (defaulting to `{ "video": "QuickTime Player" }`, with an empty or missing entry handing the file to the OS default handler, and a user-supplied map replacing the default wholesale rather than merging with it). The key is documented in `documentation/user-documentation/tab-types/video-player.md`, so this is a completeness gap in the reference table rather than an undocumented feature — but a reference table a reader consults to see every available setting has to be exhaustive. Note also that `product/specs/application-config.md` is itself stale in the other direction: it omits `sandboxWorkspaces`, which the app does read and which the docs do list. Ground truth is `src/config.ts`. Fix by adding one `externalViewers` row to the config table in `startup.md`, cross-linking the video page for the worked example.
