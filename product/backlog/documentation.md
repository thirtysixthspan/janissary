* tab-completion (7/10) — 4 of 16 facts are missing and 1 is wrong, and the wrong one is on the page's core workflow. `documentation/user-documentation/command-bar/tab-completion.md` says the `Tab` candidate for `msg` and `broadcast` is "Active agent names", but the app offers **every open tab's label**: `src/controller/completion.ts` passes `managers.tab.allLabels()` as the candidate array and `src/completion/target-handlers.ts` routes both commands' first argument through it, so a `msg` recipient can be an image or PDF tab, and messaging resolves a target on label or alias with no view check. The same wrong claim appears at the `Tab` row in `help.md` and in its closing paragraph, and in `documentation/user-documentation/command-bar/messaging.md`, so all four surfaces need the correction together; the page already contradicts itself, since its `send`/`queue`/`close` row correctly says "Every open tab's label, not just agents". The 4 missing facts are completion rules that exist in the app but appear in no doc: `harness … --model <partial>` completes against that harness's known model names and the flag may sit anywhere after the harness name, `schedule … in <tab>` completes its target against open tab labels, `syntax theme` completes `theme` at the first argument and theme names at the second, and `search` completes `transcript` as its only subcommand. `product/specs/tab-completion.md` carries the same wrong `msg`/`broadcast` claim and is behind the app on the other rules; the app is the ground truth, so fix the doc and note the stale spec. Ground truth is `src/completion/` and `src/tab/manager.ts`. Fix by rewriting the `msg`/`broadcast` rows, adding the four missing rules, and correcting both `help.md` mentions.

Ground truth is `src/plugins/pdf/manifest.ts` and `src/plugins/*/manifest.ts`. Fix by correcting the "one file type with an editor" sentence and its example list in `documentation/user-documentation/tab-types/opening-files.md`, and adding a `pdf` row to `help.md`.

Ground truth is `product/specs/image-tab.md`, `src/plugins/image/`, and `web/src/TabItem.tsx`. * browser (6/10) — 7 of 20 facts are missing and none is wrong, and the largest of them is the one that changes what a user expects to work. `documentation/user-documentation/command-bar/browser.md` documents every subcommand, the window ids, the per-tab Chromium, and headless-by-default, but never mentions that the headless browser is built to avoid looking automated: a headless Chromium channel, automation-controlled features disabled, an init script pinning `navigator.webdriver` to `false` in every frame, and a per-window random fingerprint whose user agent is pinned to the real engine major with matching platform, language, timezone, and viewport. Zero occurrences of "bot", "webdriver", or "fingerprint" appear anywhere under `documentation/`, so a user hitting a site that blocks automation has no way to know why. The other 6: each `browser` command shows a `Running…` entry while the async action finishes; a tab never launches more than one browser and concurrent first uses share the launch, and closing the tab mid-launch reports a browser error to the uses still waiting instead of running them; `browser goto` returns a `title — url` summary; headed mode needs a display, so on a headless host the launch fails and is surfaced rather than crashing; two tabs can be headless and headed at the same time; and `browser open` prints `Opened browser window w1 (headless).`. Note that `browser open`'s `name` argument is parsed and then never read by the host, and that the page's "what a reader would see" claim about `browser content` rests on `innerText` while the app reads `textContent` — both belong in the spec, not here. Ground truth is `product/specs/browser.md`, `src/browser/`, and `src/user-agent.ts`. Fix by adding a section on bot-detection evasion to `documentation/user-documentation/command-bar/browser.md` and correcting the remaining claims.

* database (6/10) — 4 of 19 facts are missing and 1 is wrong, and the wrong one sends a user straight into an error. `documentation/user-documentation/command-bar/database.md` says "Prefix a statement with `db ` to bypass recognition and choose the database explicitly", but `src/database/parsing.ts` strips the leading `db` and then reads the **next token as the engine name**, so `db SELECT * FROM t` returns `Unsupported engine "select". Only "sqlite" is supported.` The working explicit form is `db sqlite query <name> <sql>`, which is what the chooser itself builds. `product/specs/command-routing.md` makes the same claim, so the spec is the origin of the error; the app is the ground truth. The 4 missing facts: the exact engine-rejection text, which the page quotes for name validation but only paraphrases here; the two messages a missing database produces, `Database "<name>" does not exist.` and `Database "<name>" does not exist. Create it with: db sqlite create <name>`; that `db create` opens — and lazily creates the file for — a connection, which is why it leaves an entry in `connections`; and that a project with no databases prints `No databases.` Ground truth is `product/specs/database.md` and `src/database/`. Fix by correcting the `db ` prefix sentence in `documentation/user-documentation/command-bar/database.md` and adding the missing messages.

* history (4/10) — 4 of 26 facts are missing and none is wrong. `documentation/user-documentation/command-bar/history.md` covers the per-tab and global caps, the two pickers, the ghost text, and the recall keys, but leaves out three things a user notices: the draft restored by an arrow-key recall is never itself recorded, so it neither enters persisted history nor appears in the `hist` picker; a typed string identical to a history entry shows no ghost, because there is nothing left to suggest; and ACP prompt lines keep their single-click collapse toggle, so the "a single click does nothing" rule applies only to ordinary prompt lines. The fourth gap is that a command is stored after `##` comment stripping, so `ls # note` is remembered as `ls` — a fact `product/specs/history.md` does not state either. Ground truth is `product/specs/history.md` and `src/tab/history.ts`. Fix by extending the recall and ghost-text sections of `documentation/user-documentation/command-bar/history.md`.
