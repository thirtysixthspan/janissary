## development

* agents (8/10) — Agent launch name clashes are documented wrongly and only partly at all: 4 of 15 facts are missing and 2 are wrong, both on the core `agent` launch path. `documentation/user-documentation/getting-started/tabs.md` still says a duplicate name prints `Agent "<name>" is already active.` in the tab's transcript, and `documentation/user-documentation/getting-started/agents.md` says bare `agent` prints `All agent names are in use.`, but the app no longer prints either line anywhere — a refusal and the pool-exhausted notice go only to the notifications feed, attributed to the tab the command was typed in, and nothing is written to the transcript. Also undocumented: that a name counts as taken when the sessions tab holds a live harness or agent row with it on any host, that a typed name is refused when a local workspace folder of that name is still held by a live janissary owner, that a default name already running on a remote host is retried silently over a fresh connection up to five attempts before one refusal is posted, and that a leftover workspace folder with nothing running in it is removed before the clone and announced. Ground truth is `product/specs/agents.md` and `src/launch-name/`. Fix by rewriting the name-clash paragraphs in `documentation/user-documentation/getting-started/agents.md` and `documentation/user-documentation/getting-started/tabs.md` to route every refusal to the notifications feed with the current `Cannot launch "<name>": …` wording, and to state that nothing lands in the transcript.

* harness (7/10) — 3 of 23 facts are missing and 1 is wrong, and the wrong one is on the core launch path. `documentation/user-documentation/advanced-agents/harness.md` says a colliding `as <label>` "gets the same `-2` suffix", but a name you typed (`harness claude as foo`) is now refused outright, no tab opens, and `Cannot launch "foo": a tab named "foo" is already open.` is posted to the notifications feed; only a default name still walks to `claude-2`, and it now also skips live sessions-tab rows. 2 of the 3 missing facts are new: a codex tab always runs its session in its own process instead of codex's shared background server, probed against the installed codex so a release from before the flag launches unchanged (this is what stops a workspaced codex tab failing at startup with `failed to invoke ps for pid-managed app server: Operation not permitted`), and claude's four-option permission gate is approved by injecting Enter onto the highlighted `❯ 1. Yes` — never a "Yes, and don't ask again" or "Yes, and switch to auto mode" option, which the page spells out only for codex. The third missing fact is that a refused launch writes nothing to the transcript. Ground truth is `product/specs/harness.md` and `src/harness/manager.ts`. Fix by correcting the `as <label>` paragraph and extending the auto-approval section of `documentation/user-documentation/advanced-agents/harness.md`.

* remote-server (6/10) — 6 of 20 facts are missing, all in the remote launch-name path. `documentation/user-documentation/advanced-agents/remote-agents.md` documents one `Cannot launch "<name>": …` line (a project root that is a clone of the wrong repository) and the missing-clone `y`/`n` prompt, but nothing about what a remote launch does when its name is already in use on the far host. Undocumented: the host is asked before cloning and answers with a name-refusal instead of a clone; a typed name refused that way closes the placeholder tab at once and posts `Cannot launch "<name>": "<name>" is already running on <host>.`; a default name is retried silently over a fresh ssh connection up to five attempts before one exhaustion line is posted; a leftover workspace folder with nothing running in it is removed first and announced as `Removed leftover workspace "<name>" on <host> (<path>) before launching.`; a leftover which cannot be removed refuses the launch instead of proceeding; and an unreachable host adds a `could not check <host> for an existing "<name>"` refusal. Ground truth is `product/specs/remote-server.md` and `src/remote/serve-provision.ts`. Fix by adding a launch-name subsection to `documentation/user-documentation/advanced-agents/remote-agents.md`.

* messaging (6/10) — 4 of 13 facts are missing and none is wrong. `documentation/user-documentation/command-bar/messaging.md` covers the three kinds, the `i`/`r`/`c` aliases, the sender-side `→ <to> (<kind>): <text>` record, the `response from <agent>` block, broadcasting, and completion, but four behaviors are absent. A messaged command is never moved into a terminal: an interactive program is refused with `Cannot run interactive command remotely: <cmd>`, and a forced-terminal form (`shell --pty <cmd>`, `!!<cmd>`, or a bare `shell --pty`/`!!`) is refused too, naming `$SHELL` — the first thing a user hits when they message an editor or a REPL to another agent. A message carrying `acp` or `browser` is answered through that command's own capture hook rather than by returning the last transcript entry it appended. Closing a tab releases its message queue, discarding messages still waiting for it and ignoring a completion that arrives late, so a later tab reusing the same name still receives `msg` or `broadcast`. Ground truth is `product/specs/messaging.md`, `src/agent/communication-manager.ts`, and `src/capture/manager.ts`. Fix by adding these to `documentation/user-documentation/command-bar/messaging.md`.

* notifications (4/10) — 3 of 15 facts are missing. `documentation/user-documentation/tab-types/notifications.md` documents the five toggled events, `notify`, three diagnostics, and defers everything else to the owning feature page, but never names the four explicit events that have no toggle: `launch-refused` (a harness or agent launch refused because the name is in use), `launch-workspace-cleaned` (a leftover workspace folder removed so a launch could go ahead), `launch-root-cloned` (a missing remote project root cloned after the user accepted the offer), and `remote-refused`. A user whose launch was refused sees the line in the feed with no way to tell which of these it is, because the page's "What it reports" section lists only the five toggles. Ground truth is `product/specs/notifications.md` and `src/notifications/format.ts`. Fix by extending the diagnostics section of `documentation/user-documentation/tab-types/notifications.md` to list the four untoggled events and say they bypass the toggles and focus suppression, the way the `harness recording failed` lines already do.

* keyboard-navigation (4/10) — 4 of 32 facts are missing. `documentation/user-documentation/getting-started/keyboard.md` and the `help.md` key-binding tables cover the command-bar chords, the four application sections, the file navigator's captured keys, and the terminal's `Escape` and copy-chord exceptions, but leave four gaps. `Cmd+W`/`Ctrl+W` and `Shift+Tab` are documented as inert only while a picker, the route chooser, or the quit dialog is open; they are now inert behind every modal dialog too — a save-changes prompt, a launch or schedule dialog, a file-navigator conflict dialog, or any confirmation. The nine modal overlays are mutually exclusive under a fixed priority order and an open overlay claims every keystroke, so the shortcut that opens another overlay does nothing until it is dismissed. A two-button confirmation dialog takes `y` and `n` as direct shortcuts, `←`/`→` to move the selection, `Enter` to run the selected option, and `Escape` to cancel, with Cancel selected by default. `Ctrl+B` and `Ctrl+F` move the input cursor alongside `←` and `→`. Ground truth is `product/specs/keyboard-navigation.md`, `web/src/shared/useConfirmDialogKeys.ts`, and `web/src/useWindowKeys.ts`. Fix by widening the modal-dialog sentence and adding these to `documentation/user-documentation/getting-started/keyboard.md`.

* workspaced-agent (4/10) — 3 of 18 facts are missing, all about a workspace folder left behind by an earlier run. `documentation/user-documentation/advanced-agents/workspaced-agent.md` explains when a clone is created and when it is removed, but never what happens when one already exists at launch. Undocumented: a folder under the chosen name with nothing running in it is a leftover, removed before the clone starts even with uncommitted or unpushed work in it, and announced as `Removed leftover workspace "<name>" (<path>) before launching.`; a folder a live janissary owner still holds is not a leftover, and the launch is refused with `Cannot launch "<name>": "<name>" is already running (<path>).` (a plain shell sitting in the folder does not count); and a leftover that cannot be removed refuses the launch with a `could not remove leftover workspace` reason, leaving the rest in place for the next attempt. Ground truth is `product/specs/workspaced-agent.md` and `src/launch-name/leftover.ts`. Fix by adding a leftover-workspace paragraph to `documentation/user-documentation/advanced-agents/workspaced-agent.md`.

* monitoring (4/10) — 4 of 30 facts are missing. `documentation/user-documentation/automation/monitoring.md` is otherwise close to the spec: both modes, targets and aliases, naming and completion, the reporting tab's metadata line and its two buttons, every target type, the flush cycle, the marker grammar, rating, `monitor ask`, the web-tool opt-in, and stopping are all documented. Undocumented: a reply or error arriving after `unmonitor` stopped the monitor, or after its session was replaced by a reset or an error recovery, is ignored and restarts nothing, with `monitor ask` the one exception where the late reply still closes the running `monitor ask` entry; a monitor's own suggestions never appear in another monitor's feed; the reporting strip's tabs can be reordered by dragging a label; and a persona naming an unsupported tool fails to load with `Persona "<name>" requests unknown tool "<x>" (supported: web_search, web_fetch).`, with only the claude adapter able to grant them. Ground truth is `product/specs/monitoring.md` and `src/monitor/manager.ts`. Fix by extending the stopping and persona sections of `documentation/user-documentation/automation/monitoring.md`.

* profiles (3/10) — 3 of 40 facts are missing. `documentation/user-documentation/automation/profiles.md` documents the relaunch rule and its one exception — the tab `profile launch` was issued from is spared and a like-named entry is reported and skipped — but not what happens when an entry's name is still in use after that rule has closed the matching tabs. Undocumented: an entry's `name` is treated as a typed name and never gets a `-2` suffix; an entry refused that way is listed under `Skipped:` as `<name> (launch refused — see notifications)` with the `Cannot launch "<name>": …` line going to the notifications feed, and the remaining entries still open; and a leftover workspace folder under an entry's name is removed before its clone. Ground truth is `product/specs/profiles.md` and `src/profile/entry-openers.ts`. Fix by adding these to the relaunching section of `documentation/user-documentation/automation/profiles.md`.

* editor-tab (3/10) — 3 of 25 facts are missing and none is wrong. `documentation/user-documentation/tab-types/editor.md` covers the bundled chords, multi-caret editing, saving, find, the external-change reload, closing with unsaved changes, tab renaming, git sync, and, on its own page, the `>` persona query line. The gaps are all plain editing keys the page waves at as "the usual editing keys": `Cmd+A` to select all and `Cmd+C`/`Cmd+X` to copy and cut are never named, nor are `Cmd+←`/`Cmd+→` and `Cmd+↑`/`Cmd+↓` for line and document edges; the editor also answers an emacs-style subset — `Ctrl+A`, `Ctrl+E`, `Ctrl+F` (which moves right rather than opening find; `Cmd+F` opens find), `Ctrl+B`, `Ctrl+N`, `Ctrl+P`, `Ctrl+D`, `Ctrl+K`, `Ctrl+Y`, `Ctrl+S`, `Ctrl+Z`/`Ctrl+Shift+Z`, and `Ctrl+Home`/`Ctrl+End`. The editor-controls table in `help.md` has the same gap. Ground truth is `product/specs/editor-tab.md`, `product/specs/editor-plugins.md`, and `web/src/editor/keys.ts`. Fix by naming these chords in `documentation/user-documentation/tab-types/editor.md` and adding them to the editor-controls table in `help.md`.
