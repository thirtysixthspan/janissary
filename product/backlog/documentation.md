* context-menu (8/10) — The application's own right-click menu has no page anywhere under `documentation/user-documentation/` and no `help.md` row; 9 of 14 facts are missing and 1 is wrong. Missing: that right-clicking any surface without a menu of its own (editor tab, terminal, command line, transcript) opens a Copy/Paste menu at the pointer; that arrow keys and `Enter` activate an entry while `Escape` or a click away dismisses it and returns the keyboard where it was; that **Copy** appears only when page or editor text is selected and **Paste** only where text can go; that when neither applies no menu opens and the browser's own menu appears instead; that an editor right-click with nothing selected opens no menu at all, not even the browser's; and that a terminal's menu offers Paste but never Copy. The wrong fact is in `documentation/user-documentation/advanced-agents/harness.md`, which still says right-clicking a harness selection "offers your browser's own **Copy**" — the app now draws its own menu there, which offers **Chat about this** (also reachable with `Cmd+I`/`Ctrl+I`) and no Copy. Documented already: the Option-drag/Shift-drag selection modifier in `harness.md`, `Cmd+I` in `getting-started/keyboard.md` and `tab-types/editor.md`, and the file navigator's own row menu in `tab-types/file-navigator.md`. Ground truth is `product/specs/context-menu.md` plus the sources behind it in `web/src/` (the context-menu components and the conversations plugin's contributed entry). Fix by adding a short page under `documentation/user-documentation/getting-started/` covering the default menu and cross-linking it from the editor, harness, and file-navigator pages, and by correcting the harness.md sentence.

* editor-git-sync (8/10) — `documentation/user-documentation/tab-types/editor-git-sync.md` predates the branch gate added in `feat(git): disable GitHub syncing off the primary branch`; 6 of 15 facts are missing and 1 is wrong on the core workflow. The wrong fact is the page's claim that a file "syncs if and only if its project-relative path matches one of these entries; there's no other way to turn syncing on or off for it" — `syncPaths` is now necessary but not sufficient. Missing: that syncing happens only when the governing checkout is confirmably on its repository's primary branch; that off the primary branch the same listed file opens as an ordinary editor tab at its real path, with saves landing in the branch working tree and no sync status icon; that the governing checkout is the file navigator tab's own root repository for a file activated from a tree, and the app's launch directory for any other open (a shell tab's `edit`, a profile restore, a plugin opener); that a detached HEAD, a non-repository checkout, or any git failure counts as unconfirmable and disables syncing; that the primary branch is the detected default branch from `origin/HEAD`, falling back to exact `master`/`main` membership when it is unset; and that the decision is made once at open time, so a tab already open when the checkout switches branches keeps its behavior until closed and reopened. Ground truth is `product/specs/editor-tab.md` (the "GitHub syncing" section), `product/specs/file-navigator-tab.md` (branch metadata), `src/open/file-manager.ts`, `src/open/launch-dir-branch.ts`, and `src/git/status.ts`. Fix by rewriting the "Configuring which files are synced" section of the existing page to state both conditions and adding a short section on which checkout governs.

* task-picker (7/10) — `documentation/user-documentation/command-bar/tasks.md` still describes a single-source picker; 7 of 14 facts are missing and 1 is wrong. The wrong fact is that `Return` inserts `execute ./ai/tasks/<filename>` — that holds only for a project task, while a task shipped with the app inserts `execute $janissary/ai/tasks/<path>`. Missing: that the picker draws from two sources and shows them as a **Project** section followed by a **Janissary** section under non-selectable headers; that a project copy of the same task path hides the built-in one; that a section with no tasks is omitted entirely; that row labels hide the `.md` extension while the inserted command keeps it; that `Ctrl+A` on a shell tab reaches the terminal instead of opening the picker; that on a harness tab the selected command is typed straight into the harness terminal since there is no command line; and what `$janissary` is — the install-root environment variable given to every process the app spawns, which is what makes a shipped task resolve correctly inside a sandboxed workspace or on a remote host. The page's "Only `.md` files under `ai/`" wording is also stale: the listing walks `ai/tasks/` only. Ground truth is `product/specs/task-picker.md`, `src/tasks.ts`, `src/janissary-root.ts`, and `web/src/pickers/useTaskPicker.ts`. Fix by rewriting the existing page's "What gets listed" and picker-behavior sections and adding a short `$janissary` explanation.
