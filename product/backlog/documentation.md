* notifications (4/10) — 5 of 35 facts missing and none wrong: the page never says what a toast actually shows, which is the originating tab's colored dot, its label, and the message, and nothing more, since it describes only what a toast omits. Three smaller states a user meets are absent too: an empty feed shows nothing at all, not the hint an agent tab's empty transcript carries; clicking any toast clears every toast on screen, not just the one clicked; and a toast never survives a reload or a reconnect, so a window that comes back has an empty corner while the feed still holds everything. The fifth gap is the tab's label, which is always `notifications` with no type or status marker appended. The remote-session lines this run re-checked are already documented in `documentation/user-documentation/tab-types/sessions.md`, so nothing belongs here for them. Ground truth is `product/specs/notifications.md`, `src/notifications/deliver.ts`, `web/src/NotificationsTab.tsx` and `web/src/toasts/ToastStack.tsx`. Fix by adding the toast's own line format and the click behavior to the paragraph that introduces toasts, the empty-feed clause beside "The feed has no command line", the reload clause to the record-file section, and the label rule where the page first says there is only ever one notifications tab.

* sessions-tab (4/10) — 6 of 40 facts missing and none wrong: the page covers the rows and the actions well but never the chrome, starting with the centre list's own metadata bar, which carries only Refresh and Split at its right edge, and the docked list's single bar, which pairs Refresh with the dock-switch control and has no Split at all; the page says Refresh shares a bar with the dock control but never mentions Split or its absence. Also missing is what each of a docked row's two lines holds, the tab's name with right-aligned actions above the plug and state word, host, and relative last activity, along with the fact that a field too wide for the line ellipsizes while the tooltip keeps the full destination, so the tab's name gives way before its actions do. Three behaviors are absent as well: a row still `provisioning` or `reconnecting` has a muted plug, so the word is the only thing telling those two apart; attaching works from a machine where the remote workspace path does not exist locally, the restored tabs going back to the saved workspace on the host; and when the launching tab has been closed but joined tabs still hold the connection, the surviving rows carry the launching row's actions. The last gap is that a terminate leaves its row on screen marked as terminating with its terminate and attach controls unpressable until the host answers, which can take minutes, while a host that never answers leaves the row parked with its failure reported. Ground truth is `product/specs/sessions-tab.md`, `web/src/plugins/sessions/SessionList.tsx` and `web/src/plugins/sessions/`. Fix on the existing page: the header and row-layout facts in the row-columns and keeping-the-list-current sections, the muted plug beside the state colours, the local-path attach beside the Attach action, the surviving-rows rule beside Detach, and the terminate row under Actions.
