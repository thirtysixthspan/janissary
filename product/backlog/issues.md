# issues

## ready

* Limit merge-change-to-master.md's checks to the changes being merged, so a merge no longer runs the entire test suite. When Step 6 rebases onto master, `scripts/pr-rebase.sh` calls `scripts/pr-check-gate.sh`, and that runs the full `npm run typecheck`, `npm run lint`, and `npm run test` every time. A plan-only PR (one plan file and `product/backlog/features.md`) just spent about 63 seconds on 20,916 tests when it could not have broken any code. Swapping in `check-diff` as it is won't work. `changedFiles()` in `scripts/changed-files.mjs` reads only uncommitted and untracked files, and `test:diff:*` uses `vitest --changed`, which also defaults to uncommitted work. After `git rebase --continue` everything is committed, so `check-diff` would print `check:diff: no changes` and pass without checking anything. The fix is to scope the checks to the merge's own changes. Give `changedFiles()` and `check-diff` an optional base ref that adds `git diff --name-only <base>...HEAD`. Pass the same ref to vitest as `--changed <base>`, so related tests are found through the import graph in both directions. Then have the merge path run `check-diff` against `<remote>/master` in place of `pr-check-gate.sh`. A PR whose changes lint and typecheck nothing and reach no tests then passes in seconds. Keep it limited to merge-change-to-master.md: `pr-rebase.sh` is also used by `resolve-conflicts.md` and `update-pull-request.md`, and `pr-check-gate.sh` is called from about ten task files, and none of those should change silently. Keep in mind that merge-change-to-master.md merges without waiting on PR checks, so this gate is the last check before master. CI (`.github/workflows/ci.yml`) still runs the full suite, but only after the merge. Breakage the import graph can't see, such as config or fixtures read from disk, would show up on master rather than on the branch. Estimated complexity is low-medium: one new option threaded through three scripts, their `scripts/**/*.test.mjs` tests, and one task step.
